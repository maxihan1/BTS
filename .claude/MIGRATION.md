> **하네스**란 Claude Code 가 이 저장소에서 일할 때 매번 읽고 따르는 것들의 총칭이다 —

## 1. 무엇을 왜 바꿨나

### 1.1 문제 — 측정이 드러낸 7가지 (Phase 0, 2026-08-13)

추측이 아니라 실측이다. 트랜스크립트 100파일 793MB · 머지 PR 60건 · CI 런 23건을 셌다.

| # | 발견 | 수치 |
|---|---|---|
| 1 | **하네스를 고치는 PR 은 CI 가 하나도 안 돈다** | `CLAUDE.md`·`DEVELOPMENT.md`·`.claude/agents/**` 만 바꾼 PR → 발화 워크플로우 **0개** |
| 2 | **선언과 실행이 이미 갈라져 있다** | 스킬이 「호출한다」고 적어 둔 하위 스킬의 실제 발동률 — 3.0% · 0% · 0% |
| 3 | **매 세션 고정 비용의 81%가 프로젝트 밖** | 14,794토큰 중 프로젝트 `CLAUDE.md` 는 2,854(19%)뿐 |
| 4 | **CI 시간을 지배하는 건 코드가 아니라 러너 동시성** | 같은 12잡이 병렬 13.8분 ↔ 직렬 39.8분 ↔ 큐 경합 132.7분 |

| 6 | **지침끼리 모순 20건, 그중 15건은 우선순위 미명시** | 대조 57행 — 모순 20 · 부분 10 · 일치 27 |
| 7 | **메모리 중복은 한 카테고리에 몰려 있다** | 중복률 30% — `fr-history` 60% vs 나머지 **0%** |

여기서 나온 결론이 재설계의 방향을 결정했다. **문제는 「규칙이 부족하다」가 아니라 「규칙이 균일하게 무겁다」였다.**
CSS 한 줄을 고칠 때와 마이그레이션을 추가할 때가 같은 절차를 밟고 있었다.

### 1.2 설계가 스스로에게 건 제약

바꾸는 김에 늘리는 것을 막기 위해 네 가지를 걸었다.

- **순증 대차(원칙 ④).** 새로 만드는 것은 반드시 「무엇을 대체하는가」를 적는다. 대체가 없으면 순증으로 세고 사유를 남긴다. 이번 순증은 **11건 전수 열거**돼 있다(설계본 §D-2).
- **사고 이력이 있는 규칙은 삭제하지 않는다(원칙 ③).** 과거에 사고가 나서 생긴 규칙은 「지금 안 쓰는 것 같다」로 지우지 않는다. 축소만 한다.
- **판정을 뒤집지 않는다(원칙 ②).** 실현 못 한 판정은 조용히 빼지 않고 **미실현으로 표시**한다(§6).
- **비-공허 확인.** 새로 만든 가드는 **일부러 끊어서 빨간불이 나는지 1회 확인**한다. 확인 전에는 「가드가 있다」고 말하지 않는다. 15건 전수는 §4 에 있다.

> **왜 이렇게까지 하나.** 이 저장소의 지배적 결함 양식이 **「두 목록이 서로를 검사하지 않는다」**였다.
> 목록 A 와 목록 B 가 같아야 하는데 아무도 대조하지 않으면, 한쪽만 고쳐진 채 몇 달이 지나간다.
> 그리고 그것을 지키라고 만든 가드가 정작 **아무것도 검사하지 않는 상태(공허)** 로 초록불을 내는 사고가 반복됐다.

### 1.3 핵심 변경 6줄

1. **티어 도입.** 변경한 **경로**가 절차를 정한다. `docs/**` 는 T0, `apps/web/src/**` 는 T1, 보안·API·마이그레이션은 T2/T3. 판정 정본은 `scripts/workflow/surfaces.ts` 의 `SURFACES` 15키 **한 곳**이고 다른 파일은 글로브를 다시 쓰지 않는다.
2. **스킬 9종 → 8종.** `bts-domain` 을 `bts-spec` 으로 합쳤다. T0/T1 은 spec·plan·게이트 1 을 아예 밟지 않는다.
3. **에이전트 718줄 → 368줄.** `designer` 를 `frontend-engineer` 로 합치고, 리뷰 전용 `code-reviewer` 를 플러그인에서 저장소 안으로 옮겼다. **회귀 방지 절은 한 글자도 안 줄였다.**
4. **CI 를 도메인 한정으로.** backend 는 바뀐 모듈과 그 역의존만, 프론트는 프론트만. 하네스 파일도 이제 CI 가 본다.
5. **고정 컨텍스트 절반 이하로.** `CLAUDE.md` 축약 + 자동 메모리 ★ 정리 + 전역 스킬·플러그인 비노출.
6. **시각 회귀 안전망 신설.** 4화면 스크린샷 비교를 파일럿으로 도입한다(중단 기준은 §5).

## 3. 롤백

### 3.1 언제 되돌리나

되돌림은 「불편하다」가 아니라 **아래 셋 중 하나가 관측될 때**만 한다.

1. **재작업률이 티어와 반대로 움직인다.** T0/T1 에서 머지 후 재작업이 몰리면 절차를 너무 깎은 것이다. 신호는 `.claude/pilot-log.md` 의 재작업 열이다.
2. **가드가 거짓 초록을 낸다.** §4 의 비-공허 확인이 하나라도 「끊었는데 초록」이면 그 가드는 없는 것과 같다.
3. **스냅샷 파일럿이 헛 빨간불을 반복한다.** 판정 기준은 §5.

되돌림은 **전량 아니면 부분** 둘 다 가능하다. 커밋을 K0~K10 으로 쪼갠 이유가 이것이다.

### 3.2 저장소 안 — `git revert` 또는 아카이브 복원

```bash
# (a) 통째로 되돌린다. <base> = 재설계 첫 커밋의 부모
git log --oneline <base>..HEAD        # 되돌릴 범위를 먼저 눈으로 확인한다
git revert --no-commit <base>..HEAD   # 범위 전체를 역순으로 작업 트리에 되돌린다
git status                            # 커밋하기 전에 무엇이 되돌아갔는지 확인한다

# (b) 한 덩어리만 되돌린다 (예 — 티어 체계만 빼고 나머지는 유지)
git revert <K1 커밋 해시>

# (c) 물러난 파일을 원위치로 (deny 때문에 맨 mv 가 아니라 git mv 를 쓴다)
git mv .claude/_archive/20260813/designer.md .claude/agents/designer.md
```

`.claude/_archive/20260813/README.md` 와 `docs/_archive/20260813/` 에 물러난 파일 원본이 그대로 있다.
**파일만 되돌리면 안 된다** — 그 파일을 부르던 배선(참조 문구·CI `paths`·판별식 상수)이 함께 지워졌기 때문이다.
배선 지점의 전수는 아카이브 README 의 `git log --diff-filter=R` 명령이 알려 준다.

**되돌리는 순서에 하나만 주의한다.** K7(메모리 신규 생성)보다 K8(`learnings.md` 읽기 배선 제거)을 **먼저** 되돌린다.
반대로 하면 참조가 없는 상태가 잠깐 생긴다.

### 3.3 git 밖 자산 — **이번에 0바이트도 고치지 않았다**

이것이 이번 재설계의 안전판이다. 되돌릴 때 가장 무서운 것은 **git 이 추적하지 않는 파일**인데,
이번에는 그 영역을 **읽기만 했다**.

| git 밖 자산 | 이번에 한 일 | 되돌림 |
|---|---|---|
| `~/.claude/CLAUDE.md` (전역 지침) | **읽기만** — 편집 0줄 | 불필요 |
| `~/.claude/settings.json` (전역 설정) | **읽기만** — 편집 0줄 | 불필요 |
| `~/.claude/skills/**` (전역 스킬 65종) | **읽기만** — frontmatter 무편집 | 불필요 (비노출은 **프로젝트** 설정으로 한다 — 부록 A) |
| superpowers 플러그인 캐시 | **읽기만** | 불필요 (비활성도 **프로젝트** 설정 1줄) |
| 자동 메모리 `memory/**` | 이번 머지분은 **무편집**. ★ 강등은 K9(벤치마크 후) | **`git checkout` 이 안 듣는다** — 아래 참조 |

**전역 스킬 비노출과 플러그인 비활성을 프로젝트 파일 1개로 하는 이유가 이것이다.**
전역 파일을 고치면 다른 프로젝트까지 영향을 받고, `gstack-upgrade` 같은 도구가 조용히 되돌려 놓는다.
프로젝트 `.claude/settings.json` 안에 두면 **되돌림이 `git revert` 한 번**이다.

> **⚠ 딱 하나, git 이 못 지키는 되돌림이 있다 — 자동 메모리의 ★ 강등(K9).**
> `memory/**` 는 저장소 밖이라 `git checkout --` 로 원복되지 않는다.
> **강등 전에 디렉터리를 통째로 복사해 두고, 되돌릴 때 그 사본으로 역방향 복원**한다(부록 B 1단계).
> 대조용 백업 위치는 `~/.claude/_backup/20260813/` 이다. 2026-08-13 현재 `learnings.md` 만 복사돼 있고
> `settings.json`·`installed_plugins.json`·`memory/` 는 **아직 복사되지 않았다** — 부록 B 가 이것을 첫 단계로 잡고 있다.

### 3.4 파일럿 산출물 처리 체크리스트

되돌릴 때 **하네스만 되돌리고 그 하네스로 만든 결과물은 남겨야 한다.** 둘을 같이 되돌리면 2주치 제품 작업이 날아간다.

- [ ] **앱 커밋은 유지한다.** 파일럿 기간에 머지된 `backend/**`·`apps/web/**` 커밋은 **되돌리지 않는다**. 절차가 가벼웠다고 결과가 틀린 것이 아니다. 되돌릴 대상은 `.claude/**`·`scripts/workflow/**`·`.github/workflows/**`·정본 문서뿐이다.
- [ ] **`TODOS.md` 티어 열을 역이관한다.** 되돌리면 제목 말미 괄호의 `· T«n»` 표기가 사라진다. 그 사이 새로 등록된 부채 항목에도 티어가 붙어 있으므로, **revert 후 새 항목의 제목이 깨지지 않았는지** 확인한다(부채 대장 매핑 판별식이 제목을 키로 쓴다).
- [ ] **`learnings.md` 로 되돌릴 것과 남길 것을 가른다.** K7 이 만든 개별 메모리 파일은 git 밖이라 revert 로 안 지워진다. 남겨 두면 `learnings.md` 와 내용이 겹친다. **둘 중 하나를 정본으로 정하고 나머지에 「정본 아님」 배너를 단다** — 그냥 두면 두 정본 문제가 재발한다.
- [ ] **파일럿 기간에 생긴 `docs/plans` 단일 파일(T2 형태)을 확인한다.** 되돌려도 파일은 남는다. 형식이 옛 규칙(spec + plan 2파일)과 달라도 **과거 문서는 고치지 않는다** — 이 저장소는 과거 문서 일괄 수정을 금지한다.
- [ ] **스냅샷 baseline PNG 를 지운다.** 파일럿이 미채택으로 끝나면 `apps/web/e2e/visual/__screenshots__/**` 와 `visual` 잡을 함께 제거한다. baseline 만 남기면 아무도 안 보는 이미지가 저장소에 쌓인다.
- [ ] **`.claude/pilot-log.md` 는 지우지 않고 아카이브한다.** 되돌리기로 한 **판단의 근거**가 그 안에 있다. 근거를 지우면 6개월 뒤에 같은 재설계를 다시 제안하게 된다.
- [ ] **되돌린 이유를 ADR 에 Superseded 로 남긴다.** `docs/adr/2026-08-13-*.md` 세 건의 상태를 고치고, 무엇이 관측돼서 되돌렸는지 한 문단 적는다.

### 5.2 시각 회귀 스냅샷 파일럿

- 1차 2화면(이슈 목록 · 이슈 상세) → 2차 2화면(백로그 · 이슈 생성 다이얼로그).
- **판정.** 코드 무변경 상태에서 **연속 20회** 실행한다.

| 20회 중 diff 발생 | 판정 | 처방 |
|---|---|---|
| 0회 | **채택** | 4화면으로 확대하고 차단 모드로 전환 |
| 1회 (5%) | 보류 | 마스킹·시각 고정 보강 후 **재측정 1회**. 그래도 1회 이상이면 미채택 |
| **2회 이상 (10%)** | **그 화면 미채택 · 파일럿 중단** | 해당 테스트를 **머지하지 않는다** |

- **실패 횟수만 세지 않는다. 실패했을 때의 diff 픽셀 수를 같이 적는다.** 횟수만 세면 임계값을 정할 수 없다.
- **10% 를 선으로 잡은 이유.** 이 저장소에서 머지를 실제로 막는 것은 **사람이 빨간불을 보는 것**뿐이다. 주 1회 이상 헛 빨간불이 나면 빨간불을 무시하는 습관이 생기고, 그러면 스냅샷이 다른 가드까지 무력화한다.
- **채택되지 않은 화면의 테스트를 「쓰지 않는 것」은 테스트 skip 금지 위반이 아니다.** skip 금지는 **머지된 초록 테스트를 사후에 끄는 행위**를 막는 규칙이다. 나중에 「그때는 안 썼잖아」가 근거로 쓰이는 것을 막기 위해 여기 못 박는다.
- 채택 후 흔들리면 허용 처방은 **마스킹 추가 · 시각 고정 보강** 둘뿐이다. **원인 규명 전에 baseline 재생성이나 임계 완화는 금지**한다.

### A.1 왜 지금 적용하지 않나

`.claude/settings.json` 은 **저장소 안 파일**이다. 그래서 브랜치를 바꾸는 것만으로 하네스가 바뀐다 —
`main` 을 보면 옛 하네스, 이 브랜치를 보면 새 하네스다. **벤치마크의 구/신 대조가 이 성질에 기대고 있다.**
지금 이 파일을 고치면 대조군이 오염된다. 그래서 **내용만 여기 적어 두고 적용은 벤치마크 뒤**로 미룬다.

### A.3 `.claude/settings.local.json` — 55 → 33

이 파일은 **git 이 추적하지 않는다**(`.gitignore` 등재). 그래서 아카이브가 아니라 **다시 쓰는 것**이고,
사고 이력이 없어 삭감 예외에 해당하지 않는다.

| 종류 | 현재 → 잔존 | 무엇을 지우나 |
|---|---|---|
| `Skill` | 17 → **12** | 이미 비활성되는 것(`superpowers:writing-skills`) · 발동 0% 4종(`plan-devex-review`·`design-shotgun`·`autoplan` 2형태) |
| `Bash` | 17 → **1** | 끝난 세션의 임시 경로 `touch` · 특정 파일 고정 `grep` · 일회성 설치 명령. **잔존은 `Bash(gh pr *)` 하나** |
| `Read` | 2 → **1** | 미활성 플러그인 캐시 경로. 잔존은 `Read(//private/tmp/**)` |
| `WebFetch`·`WebSearch` | 19 → **19** | 유지. 다시 승인받는 비용이 실재한다 |

**~~Bash 를 1건만 남겨도 되는 이유.~~ ★2026-08-13 실측으로 반증됨 — A.3 의 Bash 항은 폐기한다.**

원래 근거는 「전역이 `Bash(*)` 상위집합이라 프로젝트 부분집합은 파일만 자라고 효과 0」이었다.
전역에 `Bash(*)` 가 있는 것은 사실이다(실측 확인). **그런데 실제로 55 → 33 을 적용한 직후
명령 하나가 auto mode 분류기에 거부됐다.** 즉 승인 경로는 「전역 allow 상위집합」 한 층이 아니라
**분류기가 별도 층으로 작동**하고, 프로젝트 `settings.local.json` 의 구체 항목이 그 층에서 신호가 된다.

- **조치.** 백업(`~/.claude/_backup/20260813/settings.local.json`)에서 **55건 그대로 복원**했다.
- **교훈.** 「상위집합이 있으니 부분집합은 무의미」는 **권한 모델이 한 층일 때만 참**이다.
  이 파일은 토큰에 실리지 않아(세션 컨텍스트 밖) 감축 이득이 원래 0 이었고, 정리의 유일한 이득은
  파일 위생이었다. **이득 0 · 리스크 실재이므로 손대지 않는 것이 맞다.**
- Skill·Read 항의 삭감도 같은 이유로 보류한다. 되살릴 근거가 생기면 그때 다시 판단한다.

### A.4 「안전 명령 allowlist」는 신설하지 않는다 — 보관용 최소 집합 16종

전역 `Bash(*)` 가 사라지는 날에만 붙일 목록이다. **지금 설치하면 중복이다.**

```jsonc
// 읽기
"Bash(git status:*)", "Bash(git diff:*)", "Bash(git log:*)",
"Bash(ls:*)", "Bash(grep:*)", "Bash(rg:*)",
// 테스트
"Bash(pnpm test:*)", "Bash(./gradlew test:*)",
// 빌드
"Bash(pnpm build:*)", "Bash(./gradlew build:*)",
// 포맷·타입
"Bash(pnpm lint:*)", "Bash(pnpm typecheck:*)",
"Bash(./gradlew ktlintCheck:*)", "Bash(./gradlew detekt:*)",
// 재설계가 새로 쓰기 시작한 두 명령
"Bash(node -e:*)", "Bash(git mv:*)"
```

**승인이 계속 필요한 것(자동 허용하지 않는다)** — 마이그레이션 실행 · 의존성 설치/변경 · 파일 삭제 ·
외부 네트워크 · `main` 직접 push. 작업 브랜치 push 는 목록에 넣지 않는다 — 전역 설정 때문에 이미 프롬프트가 없어 이득이 0 이다.

### A.5 적용 명령 · 검증 · 되돌림

셸에서 하는 것 두 가지.

```bash
# 1) 적용 — 위 A.2 를 그대로 반영한다 (편집기로 연다)
$EDITOR .claude/settings.json

# 2) JSON 문법을 먼저 확인한다. 깨진 JSON 은 조용히 무시될 수 있다
node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json','utf8')); console.log('JSON OK')"
```

세션 안에서 하는 것 두 가지 — 아래는 셸 명령이 아니라 **Claude Code 세션에 타이핑하는 슬래시 커맨드**다.

- `/reload-plugins` — 바뀐 설정을 반영한다(세션 재시작도 같은 효과다).
- `/skills` — 55종이 비노출 상태인지, 목록 길이가 줄었는지 **눈으로 확인**한다(기계 방어가 없는 구간 · §4 #14·#15).

**검증에서 무엇을 보나.**
① `/skills` 목록 길이가 눈에 띄게 짧아졌는가 ② `superpowers:` 로 시작하는 항목이 사라졌는가
③ 유지 10종은 그대로 있는가 ④ 세션 시작 주입 문구가 사라졌는가.

**⚠ 가장 흔한 실패 — 키 이름 오타는 에러 없이 조용히 무효**다. 「설정을 넣었으니 됐다」로 넘어가면
아무것도 안 바뀐 채 절감이 실현된 줄 안다. 그래서 눈확인이 선택이 아니라 절차다.

**되돌림.** `git revert` 1회 또는 `enabledPlugins`·`skillOverrides` 두 키 삭제 → `/reload-plugins`.
플러그인 캐시는 건드리지 않았으므로 재활성은 즉시다.

## 부록 B. S3 — 벤치마크 후 **한 세션에** 끝낼 5단계

쪼개면 위험해진다. **★ 강등과 정원 판별식 활성이 갈라지면 둘 중 어느 쪽도 상대를 지켜 주지 못하고,
먼저 판별식만 켜면 그 순간부터 모든 커밋이 막힌다.** 그래서 한 세션에 붙여서 한다.

- [ ] **0. 백업 먼저.** git 밖 자산을 `~/.claude/_backup/20260813/` 에 복사한다 — `memory/` 디렉터리 전체 · `settings.json` · `installed_plugins.json`. (2026-08-13 현재 `learnings.md` 만 복사돼 있다.) **이 단계를 건너뛰면 ★ 강등을 되돌릴 방법이 없다.**
- [ ] **1. K9 브랜치를 머지한다.** `.claude/settings.json`(부록 A.2) + `settings.local.json`(A.3) + 정원 판별식 활성.
- [ ] **2. 자동 메모리 ★ 63건을 강등하고 인덱스를 재생성한다.** 개별 메모리의 `priority` 를 `normal` 로 바꾸고 `node scripts/build-doc-index.mjs` 를 돌린다. **1단계와 같은 세션에서** 한다.
- [ ] **3. `/reload-plugins`** (또는 세션 재시작).
- [ ] **4. `/skills` 눈확인** — 비노출 55종 · 유지 10종 · `superpowers:` 소멸. 결과를 §4 #14·#15 에 적는다.
- [ ] **5. 실측을 기록한다.** 고정 컨텍스트 측정 스크립트(`scripts/workflow/measure-context-budget.mjs`)를 돌려 §2.2 의 `실측(Phase 4)` 열을 채운다. **2026-08-13 현재 이 스크립트는 아직 없다 — 없으면 이 단계에서 먼저 만든다.** 재현 가능한 측정 없이는 §2.2 의 어느 값도 검증되지 않는다. **설계치와 다르면 설계치를 고치지 말고 실측을 적는다.**

**되돌리기 지점.** 1~3 단계는 `git revert` 로 되돌아간다. **2단계만 git 밖**이라 0단계의 백업이 유일한 복구 수단이다.
