# ADR — 워크플로우 편집 캔버스는 `@xyflow/react` 를 도입한다 (Gantt 선례와 갈리는 이유)

> 날짜. 2026-08-18
> 상태. **채택 (Active)** — 신규 의존성이므로 절대 규칙 17 에 따라 Maxi 승인을 받았다 (2026-08-18)
> 관련 FR. FR-WF-04 (D6 편집기 화면) · FR-WF-05 (전환 그리기)
> 관련 문서. `docs/design/jira-parity-contract.md` · `apps/web/src/components/workflow/WorkflowDiagram.tsx`
> 대체 관계. **대체하는 ADR 없음.** 다만 `docs/adr/2026-06-26-gantt-rendering-self-svg.md` 가 세운 「시각화는 자체 SVG, 라이브러리 미도입」 선례와 결론이 갈리므로, 아래 §선례와 갈리는 지점에서 그 차이를 명시한다. 그 ADR 은 타임라인 영역에서 **계속 유효하다.**

## 맥락

워크플로우 편집기는 다이어그램 모드와 목록 모드를 탭으로 갖는다(Jira Cloud 동일). 목록 모드는
기존 shadcn 프리미티브와 `@dnd-kit` 으로 충분하다. 문제는 다이어그램 모드다.

현재 `WorkflowDiagram.tsx` 는 **mermaid** 로 `stateDiagram-v2` 텍스트를 만들어
`mermaid.render()` 결과 SVG 를 `innerHTML` 로 주입한다. 레이아웃 계산은 전부 mermaid 내부에
위임돼 있고, 노드를 클릭하거나 끌거나 노드 사이를 이어 전환을 만들 수단이 없다. **읽기 전용
렌더러라 편집기의 출발점이 될 수 없다.**

편집 캔버스가 실제로 요구하는 것은 다음과 같다.

- 노드 드래그 배치와 좌표 영속
- 노드 핸들에서 끌어 다른 노드에 놓아 전환 생성 · 기존 전환의 재연결
- 같은 상태쌍의 다중 전환을 겹치지 않게 그리는 간선 경로 계산
- 자기 자신으로 도는 전환(self-loop) 렌더
- 팬 · 줌 · 뷰포트 컬링 · 미니맵
- 그래프 키보드 항법과 스크린 리더 대응

## 선례와 갈리는 지점

`2026-06-26-gantt-rendering-self-svg.md` 는 Gantt 에서 전용 라이브러리를 **기각**하고 자체
SVG/CSS 를 택했다. 근거는 「의존성 0」 · 「완전한 커스터마이징」 · 「BTS 단순성 철학」 · 「환각 위험」
이었다. 그 판단은 그 문제에 대해 옳았고 지금도 유효하다. 이 ADR 이 반대 결론을 내는 이유는
**문제의 성질이 다르기 때문**이다.

| | Gantt (자체 SVG 채택) | 워크플로우 편집 캔버스 (라이브러리 채택) |
|---|---|---|
| 성격 | 읽기 전용 렌더 | 상호작용 편집 |
| 핵심 기하 | 날짜 → x, 행 → y **단방향 매핑** | 임의 노드쌍 간 간선 경로 · 재연결 · 겹침 회피 |
| 입력 | 없음 (스크롤뿐) | 드래그 · 핸들 연결 · 선택 · 삭제 · 팬 · 줌 |
| 상태 | 없음 | 뷰포트 · 선택 · 드래그 중 임시 간선 |
| 자체 구현 시 | 순수 함수 3개 (`lib/timeline-layout.ts`) | 그래프 편집 엔진 한 벌 |

Gantt 는 "데이터를 좌표로 바꾸는 함수"였다. 편집 캔버스는 "사용자 입력을 그래프 변경으로 바꾸는
상태 기계"다. 전자를 직접 쓰는 것은 라이브러리보다 싸고, 후자를 직접 쓰는 것은 비싸다.

**단순성 철학은 「라이브러리를 쓰지 않는다」가 아니라 「규모에 맞는 최소 해법을 쓴다」이다.**
Gantt 선례가 인용한 「Kafka/OpenSearch 금지(1K 규모 오버킬)」도 같은 문장이다. 여기서 최소 해법은
그래프 편집을 직접 구현하는 쪽이 아니다.

## 결정

### D1. `@xyflow/react` (React Flow v12) 를 도입한다

MIT 라이선스, React 19 지원. 노드/간선 렌더는 우리 컴포넌트로 하고 라이브러리는 상호작용과
뷰포트만 맡는다.

### D2. 좌표 계산은 순수 함수로 분리한다 — `src/lib/workflow-layout.ts`

`lib/timeline-layout.ts` 가 세운 관례를 그대로 따른다. 자동 배치(좌표가 없을 때 카테고리별로
TODO → IN_PROGRESS → DONE 열 배치)와 간선 경로 산출을 순수 함수로 두고, 컴포넌트는 결과를
렌더만 한다.

**이것은 스타일 통일이 아니라 테스트 가능성의 문제다.** jsdom 은 SVG 측정 API(`getBBox`, 레이아웃
width)를 구현하지 않는다 — mermaid 와 recharts 에서 이미 물린 함정이고 Gantt ADR 이 같은 처방을
적어 뒀다. React Flow 는 여기에 `ResizeObserver` 의존이 더해져 jsdom 에서 노드가 0×0 으로 잡힌다.
따라서 **픽셀은 순수 함수를 vitest 로, 실제 렌더는 Playwright 로** 나눠 검증한다.

### D3. mermaid 는 제거하지 않는다

읽기 전용 상세 화면(`routes/workflows.$key.tsx` + `WorkflowDiagram.tsx`)에 그대로 둔다.
제거하면 `apps/web/e2e/workflow.spec.ts` 4건과 스냅샷이 함께 깨지는데, 그 파손은 이 작업이
만들어 낸 가치와 무관한 순수 비용이다. mermaid 는 링크 그래프에서도 쓰이므로 의존성이 줄지도 않는다.

편집기는 `/admin/workflows/{key}` 라는 **별도 라우트**로 들어간다. 두 화면이 공존한다.

### D4. 노드 좌표는 `workflow_statuses.layout_x/y` 에 저장한다

발행본도 다이어그램을 보여줘야 하므로 초안 JSONB 에만 두지 않는다. 좌표가 없으면 D2 의 자동 배치가
초기값을 만든다.

## 근거

1. **직접 구현의 비용이 이 문제에서만 뒤집힌다.** 간선 경로·재연결·겹침 회피·뷰포트는 각각이
   작은 알고리즘이 아니다. 이것을 만들고 테스트하는 시간이 편집기 본체보다 커진다.
2. **접근성을 공짜로 얻지 못한다.** 그래프 키보드 항법은 직접 구현 시 가장 먼저 빠지는 부분이고,
   `jira-parity-contract §2` 는 aria 계약을 즉사 조건으로 둔다.
3. **번들 비용이 작다.** 압축 후 약 50KB 이며 편집기 라우트에서 지연 로드한다. 관리자만 여는
   화면이라 일반 사용자 경로의 번들에 들어가지 않는다.
4. **환각 위험은 D2 가 줄인다.** 라이브러리 API 를 컴포넌트 경계 안에 가두고 좌표 로직을 우리
   순수 함수로 빼면, 라이브러리가 바뀌어도 갈아 끼울 표면이 좁다.

## 기각한 대안

**`@dnd-kit` 으로 자체 캔버스** — 이미 설치돼 있어 신규 의존성이 0 이고, `KanbanBoard.tsx` 에
센서·접근성 announcements 실전 패턴이 있다.

기각 사유. `@dnd-kit` 은 **드래그 프리미티브**지 그래프 편집기가 아니다. 얻는 것은 드래그 하나뿐이고
간선 경로·재연결·팬·줌·미니맵·뷰포트 컬링은 전부 직접 만들어야 한다. 구현과 테스트 분량이 약 두 배로
늘고, 그 결과물은 우리가 유지보수해야 하는 미니 라이브러리다. 「의존성 0」의 값이 그 유지보수 비용보다
작다.

**mermaid 를 편집 가능하게 개조** — mermaid 는 텍스트 → SVG 단방향 렌더러다. 산출 SVG 에 이벤트를
붙여 편집을 흉내 낼 수는 있으나, 노드 위치를 우리가 정할 수 없어(레이아웃이 내부 위임) 드래그 배치가
성립하지 않는다. 기각.

## 영향

### 긍정

- Jira Cloud 다이어그램 모드와 같은 조작감을 얻는다.
- 좌표 로직이 순수 함수라 픽셀을 결정적으로 단위 테스트한다.
- mermaid 상세 화면과 e2e 4건이 무변경으로 살아남는다.

### 부정 / 위험

- **신규 의존성 1건.** 절대 규칙 17 대상이라 Maxi 승인을 선행했다. 버전은 고정하고 업그레이드는
  별도 판단으로 한다.
- **시각 회귀를 단위 테스트가 못 잡는다.** D2 로 좌표는 잡지만 렌더 자체는 Playwright 와 눈확인에
  의존한다. 절대 규칙 14 의 「ui 시각 변경은 red-first 면제, 대신 시각 검증 트랙」을 따르고
  라이트·다크 양쪽을 본다.
- **시각화 스택이 셋이 된다** — mermaid(읽기 전용 상태도·링크 그래프) · recharts(차트) ·
  xyflow(편집 캔버스) · 자체 SVG(Gantt). 각각의 담당 영역을 이 ADR 과 Gantt ADR 이 나눠 적는다.
  넷째를 들이려는 다음 사람은 이 표를 먼저 갱신해야 한다.

## 대안 채택 조건

- React Flow 가 React 다음 메이저에서 막히거나 라이선스가 바뀌면 → D2 의 순수 함수는 그대로 두고
  캔버스 컴포넌트만 교체한다. 그 교체 표면이 좁도록 설계하는 것이 D2 의 목적 중 하나다.
