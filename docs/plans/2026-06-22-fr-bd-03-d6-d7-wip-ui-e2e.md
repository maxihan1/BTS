### 백엔드 신호(실측, GET /api/v1/boards/{id} = BoardDetailResponse)

- `columns[].wipLimit: Int?`(null=무제한), `columns[].wipExceeded: Boolean`(카드수 > wipLimit, strictly greater)
- `swimlaneField: String`("NONE"/"ASSIGNEE"/"PRIORITY")
- 카드: `{ issueKey, summary, assigneeId: UUID?, version }` — **priority 없음**(BoardResponses.kt:139 NIT-1로 제외)
- 설정 쓰기(실측 경로): `PATCH /api/v1/boards/{id}`(body `{swimlaneField}` → BoardMetaResponse), `PATCH /api/v1/boards/{id}/columns/{columnId}`(body `{wipLimit}` → ColumnMetaResponse) — 둘 다 권한 IssuePermission.CREATE on Project
- 권한 사전 조회: GET `/api/v1/users/me/project-permissions?projectKey=` → `permissions.CREATE: boolean`(project-permissions.ts)

### 현재 프론트 미러 상태

- `boards.ts`의 Zod 스키마에 `wipLimit`·`wipExceeded`·`swimlaneField` **미반영**(백엔드 D4 신호 미러 필요). 카드에 priority 없음.

### 도메인 갭 3종 (spec서 Maxi 확인 — 갈림길)

1. **PRIORITY 스윔레인 priority 부재**: `BoardIssueView.priority`(BoardIssueLookupPort.kt:132)는 존재하나 `BoardCardResponse`가 NIT-1로 제외 → 카드 응답에 priority 없음. ADR 결정 2 근거("priority가 이미 노출")와 구현 모순(PR #13 learning 패턴). PRIORITY 스윔레인 그리려면 ⓐ 백엔드 view-layer patch로 priority 재노출(same-BC, PR #13 옵션C 선례) 또는 ⓑ PRIORITY 이연(enum은 백엔드 존재).
2. **ASSIGNEE displayName**: 카드엔 assigneeId(UUID)만 → 담당자 이름 표시에 users 조회 필요. ADR "기존 사용자 조회 패턴 재사용".
3. **설정 UI 범위**: product D6는 "헤더 경고 + 스윔레인 그룹" 표시만 명시. PATCH 2종(WIP 설정 + 스윔레인 선택) 설정 UI를 D6에 포함할지.
