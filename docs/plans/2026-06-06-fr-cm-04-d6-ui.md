## Brief

FR-CM-04(컴포넌트 리드 부재 시 프로젝트 리드 기본 담당자 폴백)의 D6 프론트엔드 단계.
프로젝트 설정 화면에 프로젝트 리드를 지정/해제하는 UI를 추가한다.

- 백엔드 변경(PATCH)은 PR #89(squash 5c9db97b)에 머지 완료.
  - `PATCH /api/v1/projects/{idOrKey}/lead` — body `{leadUserId: UUID|null}`, 2-state. 응답 `DataResponse<ProjectLeadResponse>{projectId, leadUserId}`.
  - 권한: ComponentPermission.UPDATE(=MANAGE_COMPONENTS, PROJECT_ADMIN 전용) 재사용.
- **이번 PR 범위**: 프론트 UI + 백엔드 조회 GET 1개(same-BC view layer). E2E(D7)는 후속 분리.

## 도메인 정리 (/bts-domain 산출)

### 결정 (게이트 전 Maxi 확정)

1. **현재 리드 조회 = 백엔드 `GET /api/v1/projects/{idOrKey}/lead` 신규 추가** (Maxi 결정).
   - 갭: 백엔드에 프로젝트 자체 조회 GET이 없어(서브리소스 컨트롤러만) "현재 리드"를 읽을 경로가 없었음. PATCH 응답만으로는 화면 진입 시 현재값 미표시.
   - same-BC(issue-tracking) view layer 추가 → learnings 2026-05-22 "옵션 C 패턴"(frontend가 요구하는 same BC view layer는 한 PR에서 처리). UI PR이지만 백엔드 GET 1개 포함.
2. **UI 위치 = 신규 설정 라우트 `projects/$projectKey/settings/project-lead`** (Maxi 결정).
   - 기존 `settings/{components,members,versions,workflow-scheme}`와 대칭. 리드 지정/해제 단독 화면.
3. **권한**: 변경(PATCH)만 MANAGE_COMPONENTS. 조회(GET)는 권한 게이트 없음 — 컴포넌트 READ와 동일(`ComponentApplicationService` L212 "READ 는 권한 게이트 없음 (Jira 동일 정책)"). 인증은 SecurityConfig가 401 보장.

### glossary / ADR

- 신규 도메인 용어 0건 (프로젝트 리드 개념은 FR-CM-04 PR #89 ADR `2026-06-06-project-lead-default-assignee-fallback.md`에 이미 정의).
- 신규 ADR 0건. GET 조회 엔드포인트 추가는 기존 모델의 view layer 확장이라 ADR 불요.

## 스펙 (/bts-spec 산출 — 경량 직접 기술 스펙)

### 사용자 시나리오

- US-1. PROJECT_ADMIN인 사용자가 프로젝트 설정 → "프로젝트 리드" 화면에 들어가면 **현재 리드(또는 "미지정")**가 보인다.
- US-2. 검색창에 이름을 입력해 사용자를 찾고, 선택하면 그 사용자가 프로젝트 리드로 지정된다(토스트 확인).
- US-3. "미지정" 버튼으로 리드를 해제할 수 있다.
- US-4. 권한이 없는 사용자는 화면에서 현재 리드는 보지만(조회 무권한), 변경 컨트롤은 disabled로 막힌다(fail-closed).

### FR (이번 D6 범위)

- FR-D6-1. `GET /api/v1/projects/{idOrKey}/lead` → 200 `{data:{projectId, leadUserId}}`. 프로젝트 미존재 404. 권한 게이트 없음(인증만).
- FR-D6-2. 프론트 api `fetchProjectLead(projectIdOrKey)` + `changeProjectLead(projectIdOrKey, leadUserId|null)`. Zod 스키마는 백엔드 DTO(projectId/leadUserId) 정합.
- FR-D6-3. `useProjectLead(projectKey)` 조회 훅 + `useChangeProjectLead(projectKey)` mutation 훅(성공 시 invalidate + 토스트).
- FR-D6-4. `ProjectLeadSelect` 순수 표현 컴포넌트(ComponentLeadSelect 동형) + i18n labels.
- FR-D6-5. 신규 라우트 `projects/$projectKey/settings/project-lead`(RouteAdapter+Page) + router.ts 등록.
- FR-D6-6. MSW project-lead-handlers(GET+PATCH, stateful store) + msw setup 등록 + 422(리드 미존재) 시나리오 플래그.

### 계약 (백엔드 정합 — frontend-zod-backend-dto-contract-gap 회피)

- 요청 PATCH body: `{ "leadUserId": "<uuid>" | null }`.
- 응답 GET/PATCH body: `{ "data": { "projectId": "<uuid>", "leadUserId": "<uuid>" | null } }`.
- 에러: ProblemDetail + `errorCode`(404 프로젝트 미존재 / 422 리드 사용자 미존재 / 403 권한). 프론트는 `extractComponentErrorCode` 동형 헬퍼로 추출.
- 주의: 응답엔 사용자 표시명이 없고 leadUserId(UUID)만. 화면 표시명은 `useUsersByIds([leadUserId])`로 별도 조회(컴포넌트 리드 동형).

### 에지 케이스

- EC1. 리드 미지정(leadUserId=null) → "미지정" 표시, 해제 버튼 숨김.
- EC2. 프로젝트 미존재(404) → ProjectNotFoundScreen 재사용(members 라우트 export).
- EC3. 변경 대상 사용자 미존재(422 PROJECT_LEAD_NOT_FOUND) → 토스트 에러, 현재값 유지.
- EC4. 권한 없음 → 컨트롤 disabled(로딩/에러/미인가 모두 fail-closed).
- EC5. mutation 후 refetch로 화면 갱신(msw-mutation-stateful-refetch — 핸들러 stateful 영속 필수, setQueryData 위 가짜그린 금지).
