**미결 결정 (bts-spec 에서 Maxi 확인).**

1. **모더레이션 정책** — 작성자 한정 (Worklog 대칭, `existing.authorId != actor` → 403)

2. 삭제 방식 — soft delete (`deleted_at`) 확정 여부와 목록 응답에서의 취급.
3. 수정 이력 표시 — `updated_at` 노출 / "수정됨" 표시 여부.

### 실측 결과 — 선례가 전이되지 않는다

메모리 `sibling-precedent-validation-placement-depends-on-producer-count` 의 판별식을 재적용했고,
**FR-CO-01 D7 에 이어 같은 축이 두 번째로 갈렸다.**

| 생산자 | Worklog | Comment |
|---|---|---|
| REST (사람) | `create` | `create` |
| Import | `createImported` | `createImported` |
| **automation** | **0건** (automation 모듈 전수 grep 에 worklog 언급 자체 없음) | **`AddCommentAction` 존재** |

자동화 댓글의 저작자 체인 (전 구간 실측, 추정 0).

```
ActionExecutor.kt:159   ExecutionEnv(rule.actorUserId, …)
ActionExecutor.kt:236   issueMutationPort.addComment(AddCommentCommand(env.actorId, …))
AutomationIssueMutationAdapter.kt:153   commentApplicationService.create(actor, key, body)
CommentApplicationService.kt:99         authorId = actor   ← create 가 강제 (FR-CO-01 D4)
```

→ 자동화 댓글은 **룰 소유자만** 삭제 가능해진다. Worklog 에는 이 생산자가 없어 문제 자체가 없었다.
**선례가 조용했던 이유는 답이 같아서가 아니라 질문이 없어서다.**

Worklog 선례 자체는 기록대로 정확 — `WorklogService:254`(update)·`:328`(delete) 작성자 한정,
관리자 우회 분기 **0건**.

### 실측 결과 — 새 권한 enum 불필요

마이그레이션 0 · 신규 resolver 분기 0.

### 스키마 — 마이그레이션 0건 확정

`V035__comments.sql` 실측. `deleted_at`(`:13`) · `updated_at`(`:12`) 존재,
부분 인덱스 `:22` `WHERE deleted_at IS NULL`, `CommentRepository.listByIssue:64` 가 이미
`DELETED_AT.isNull` 필터 적용 → **삭제분은 목록에서 자동 제외, 목록 API 계약 변경 0**.

### 🛑 Maxi 확정 — 모더레이션 정책 = **B안**

| 연산 | 게이트 |
|---|---|
| `PATCH` 수정 | `UPDATE` + `existing.authorId == actor` **필수** (PROJECT_ADMIN 도 403) |
| `DELETE` 삭제 | `UPDATE` + (`existing.authorId == actor` **또는** `SOFT_DELETE` 보유) |

근거 요약 — 실제 필요는 "지우기" 이고 "남의 글 고치기" 는 필요를 못 채우면서 기록 신뢰만 깎는다.
FR-CO-01 §D4(저작자 위조를 타입으로 차단)와 같은 방향. Jira 도 `Edit All Comments` /
`Delete All Comments` 를 분리한다.

### 자체 오류 1건 (기록)

ADR 초안 §함정 3 에 *"BTS 에 `PROJECT_ADMIN` 을 직접 검사하는 코드는 없다"* 라고 적었다가
**grep 으로 반증**했다 — `ProjectSecuritySchemeService.kt:170` 이 역할을 직접 검사한다(99 발생).
다만 그 KDoc `:39-43` 이 *"`ADMIN_PROJECT` 권한코드가 시드에 없어서"* 라는 우회 사유를 밝히므로
**선호 패턴이 아니다.** 댓글은 시드된 코드가 있어 권한 경로가 선호된다. ADR 에 정정 반영 완료.
교훈 — "BTS 에 X 가 없다" 류 전칭 단언은 grep 하고 쓸 것.
