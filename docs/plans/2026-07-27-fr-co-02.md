## Brief

**사용자 원문.** FR-CO-02 댓글 수정·삭제 기능 구현. FR-CO-01(#315)에서 분할된 후속.

**선행 컨텍스트.**

- FR-CO-01 은 PR #315 로 머지 완료 (커밋 `0de07e57c`, 2026-07-27). FR 카운트 129 → 131.
- ADR `docs/decisions/2026-07-27-fr-co-comment-feature.md` 에 Maxi 확정 8건 (D1~D8).
- D1 이 이 작업의 근거 — CO-01(작성+목록) / CO-02(수정+삭제) 2분할. 분할 사유는
  "누가 남의 댓글을 지우나" 권한 정책을 별도 리뷰 단위로 격리하기 위함.
- 댓글 백엔드의 출처는 `FR-IM-01` PR3(#224) 의 **부산물**이다 (learnings 2026-07-17).
  "파일 존재 ≠ 기능 존재" — 판정은 컨트롤러 HTTP 매핑을 세어서 한다.

**예상 변경 (bts-plan 에서 확정).**

- `Comment` 도메인 — 본문 변경 허용 (현재 전 필드 `val`)
- `CommentRepository` — `update` / `softDelete` 신설 (현재 `insert`·`listByIssue` 2개뿐)
- `CommentController` — `PATCH` / `DELETE /api/v1/issues/{key}/comments/{commentId}`
- 프론트 — 수정 / 삭제 UI
- E2E
- 마이그레이션 **0건 예상** (`deleted_at` 컬럼 기존)

**미결 결정 (bts-spec 에서 Maxi 확인).**

1. **모더레이션 정책** — 작성자 한정 (Worklog 대칭, `existing.authorId != actor` → 403)
   vs PROJECT_ADMIN 우회 허용. Worklog 선례는 관리자 우회를 두지 않았다.
2. 삭제 방식 — soft delete (`deleted_at`) 확정 여부와 목록 응답에서의 취급.
3. 수정 이력 표시 — `updated_at` 노출 / "수정됨" 표시 여부.
