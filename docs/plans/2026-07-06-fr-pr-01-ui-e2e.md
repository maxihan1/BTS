## Brief

FR-PR-01 사용자 프로필(이름/아바타/타임존/부서)의 D6(프론트 UI)·D7(E2E)를 진행한다.
백엔드 D1~D5는 PR #238(squash 338dec2d5)로 완료. 후속 UI PR.

**백엔드 API 계약 (identity-access, PR #238)**.
- `GET  /api/v1/users/me/profile` → `ProfileResponse { userId, username, email, displayName, avatarUrl, timezone, department }`
- `PATCH /api/v1/users/me/profile` (3-state) → 갱신 후 `ProfileResponse`. body `{ displayName?, timezone?, department? }`. displayName/timezone = 부재/값(2-state), department = 부재/null(삭제)/값(3-state).
- `POST /api/v1/users/me/profile/avatar` (multipart, part=`file`) → `AvatarUploadResponse { avatarUrl }`. MIME image 4종·5MB·nosniff.
- `GET  /api/v1/users/{userId}/avatar` → 이미지 바이너리 (인증 사용자면 동료 것도 조회).
- `DELETE /api/v1/users/me/profile/avatar` → 204 (멱등).
- 에러 봉투 `{ code, message }`. 400 PROFILE_VALIDATION_FAILED / AVATAR_VALIDATION_FAILED, 404 PROFILE_NOT_FOUND / AVATAR_NOT_FOUND, 401(PAT/무인증).

## 도메인 정리

- BC: personalization(논리) / identity-access(물리 모듈). 배치 결정은 ADR [2026-07-05-fr-pr-01-user-profile-placement](../decisions/2026-07-05-fr-pr-01-user-profile-placement.md).
- 영향 엔티티: 없음(신규 0). 프론트가 백엔드 D1~D5(PR #238)에서 확정한 `UserProfile` 계약을 view-layer에서 소비만 함.
- 새 용어: 없음. glossary에 프로필/아바타/타임존/부서 전용 용어 없음 — UI 라벨 수준이라 유비쿼터스 언어 추가 불필요.
- 기존 결정 충돌: 없음. `avatarUrl`은 저장이 아니라 `avatarObjectKey`에서 파생(백엔드 확정), 프론트는 응답의 `avatarUrl`을 그대로 `<img src>`에 사용.
- 관련 ADR: [2026-07-05-fr-pr-01-user-profile-placement](../decisions/2026-07-05-fr-pr-01-user-profile-placement.md) (기존, 백엔드 PR에서 생성). 이 UI PR은 신규 ADR 없음.
