## Brief

FR-SL-02 D6. 일반 사용자가 **본인 Slack 계정을 직접 연결/해제**하는 설정 페이지 + 그것을 노출하는 view-layer 엔드포인트.

- 이미 존재(재사용): `SlackUserMappingService`(link/unlink, `com.bts.slack.application`), `SlackUserMappingRepository`, `SlackUserMapping` 도메인, `user_slack_mapping(user_id, slack_user_id, team_id)` 테이블(V701)
- 신설: link/unlink를 노출하는 me-scope 엔드포인트 + 사용자용 매핑 페이지(apps/web)
- 미결: 연결 UX 스코프(Slack OAuth `identity` 스코프로 사용자 확인 vs Slack user ID 직접 입력) — /bts-spec 단계에서 옵션으로 결정
- 선례: FR-SL-01 D6(#247) 관리자 `/admin/slack` 페이지 + view-layer JSON 엔드포인트 2종. Bearer vs OAuth 전체페이지이동 충돌 해소 패턴 참조.

원문. FR-SL-02 D6 — 사용자 본인 Slack 계정 연결/해제 페이지와 엔드포인트. 백엔드 SlackUserMappingService(link/unlink)와 user_slack_mapping 테이블(V701)은 이미 존재. 신설: link/unlink를 노출하는 view-layer 엔드포인트 + 일반 사용자용 매핑 페이지. 연결 UX 스코프(Slack OAuth identity 스코프 vs 직접 입력)는 spec 단계에서 옵션으로 결정.

## 도메인 정리

- **BC**: slack-integration (`com.bts.slack`). classify의 `identity-access`는 "계정" 키워드 오분류 — 정정.
- **영향 엔티티**: `SlackUserMapping`(기존, `com.bts.slack.domain`). **신규 엔티티 없음**. `user_slack_mapping(user_id PK, slack_user_id, team_id, linked_at)` V701 재사용.
- **재사용 서비스 계약**: `SlackUserMappingService.link(userId, slackUserId, teamId)`(멱등 upsert) · `unlink(userId)`(하드삭제) · `resolveByUserId(userId)`. KDoc이 명시적으로 "D6 연결 플로우(웹 레이어)가 link/unlink 호출"로 이 PR을 예정.
- **용어 주의 (혼동 차단)**: glossary의 **"계정 연결(Account Linking, FR-AU-08)"** 은 로그인용 외부 신원(LDAP/SAML/OIDC) 연결이라 **이번 것과 다른 개념**. 이번은 "알림 수신 대상 Slack 사용자 매핑"이지 로그인 수단이 아님. 새 용어 후보 **"Slack 사용자 매핑 (Slack User Mapping)"** 으로 분리(Maxi 승인 후 glossary 추가). domain 노트 line 18 "SlackUser (Atlas user ↔ Slack user 매핑, FR-SL-02 예정)"의 실체.
- **기존 결정 충돌**: 없음. FR-SL-02 ADR line 60이 "D6 매핑 UI + D7 E2E = 후속 PR"로 이 작업을 예약(재논의 아님).
- **관련 ADR**: [[decisions/2026-07-10-fr-sl-02-slack-notification-delivery]](재사용) · [[decisions/2026-07-08-fr-sl-01-d6-slack-connect-page]](Bearer↔OAuth 전체페이지이동 충돌 해소 패턴 선례).

### ★ spec으로 넘길 핵심 결정 — 연결 UX (웹 레이어가 slackUserId+teamId를 얻는 방법)

`link()`가 raw `slackUserId`(`U…`)+`teamId`를 요구 → 사용자가 이걸 어떻게 얻나가 D6의 본질. 3안, 인프라 비용/보안 차이 큼.

- **A. Sign in with Slack (사용자 신원 OAuth)** — 사용자가 "연결" 클릭 → Slack OAuth(user `identity` 스코프) → 콜백이 인증된 slack_user_id+team_id 회수. **소유권 검증됨(오배송 0)**, domain 노트 line 26 의도 부합. 비용: 봇 install OAuth와 별개인 **신규 사용자 OAuth 흐름** 신설(콜백·서명 state·Bearer↔리다이렉트 충돌 #247 패턴).
- **B. Slack user ID 직접 입력** — 폼에 `U…` 입력 → 기존 `link()` 호출. **최소 비용**(폼+엔드포인트만). 단점: 소유권 미검증 → 오타 시 **타인에게 DM 오배송 위험**, UX 나쁨(사용자가 자기 `U…` 모름).
- **C. 이메일 자동 해석 (봇 `users.lookupByEmail`)** — "연결" 클릭 → 백엔드가 BTS 이메일로 Slack 사용자 조회 → slack_user_id 자동 매핑. UX 최상(원클릭)·이메일 일치로 검증. 비용: 봇 스코프 `users:read.email` 추가 → **워크스페이스 재설치 필요**, BTS 이메일==Slack 이메일 가정.

→ spec Phase A(office-hours/AskUserQuestion)에서 Maxi 결정.

- 재사용: `SlackUserMappingService`·`UserLookupPort.findEmailById`(이미 배선, 신규 cross-BC 포트 0)·`user_slack_mapping`(V701, 신규 마이그레이션 0)·SDK `users.lookupByEmail`(slack-api-client 1.45.4).

deviation. 봇 스코프 `users:read.email` 추가 → 기존 설치 1회 재연결 운영 의존(런북). 범위: D6+D7(E2E) 동시.
