**메타**.

- depends-on: []

**RED**:
- `StoredPasswordCredentialRepositoryTest` — (a) `save`로 `mustChangePassword=true` 저장 후 `findByUserId`가 true 반환; (b) **UPSERT 재호출**: 기존 행(must_change=true)에 `save(must_change=false)`로 덮어쓰면 `findByUserId`가 **false** 반환(★BLOCKER-2 핵심 — ON CONFLICT SET 검증). 컬럼 없어 실패.
- `StoredPasswordCredentialTest`(기존) — 필드 추가로 `5개 필드 노출`/`toString` 단언 갱신(CONCERN-2). must_change=true여도 `toString`에 password_hash 미노출 유지.
- `LocalCredentialServiceTest` — `store(userId, plain, mustChange=true)` 후 플래그 true; `rotate(...)` 성공 시 플래그 false(정상 변경은 강제플래그 자동 해제, 실 repo).

**GREEN**:
- V019 `ALTER TABLE local_credentials ADD COLUMN must_change_password BOOLEAN NOT NULL DEFAULT FALSE;`
- `StoredPasswordCredential`에 `mustChangePassword: Boolean = false` 필드(6번째).
- Repository `SQL_UPSERT` 3곳 모두 반영 — **INSERT 컬럼목록 + VALUES + `ON CONFLICT (user_id) DO UPDATE SET must_change_password = EXCLUDED.must_change_password`**(★자동 해제 핵심). `findByUserId` row 매핑에 컬럼 추가.
- `LocalCredentialService.store(userId, plain, mustChange: Boolean = false)`, `rotate`는 `mustChange=false`로 store → UPSERT SET이 플래그를 false로 덮어써 정상 변경 시 자동 해제. (명시 `clearMustChangePassword` 별도 메서드는 만들지 않음 — UPSERT SET 단일 경로로 결정, T5의 양다리 제거)

**REFACTOR**: 컬럼명 상수화 + KDoc(강제 변경 시맨틱 + UPSERT SET이 해제 경로임을 명시).
