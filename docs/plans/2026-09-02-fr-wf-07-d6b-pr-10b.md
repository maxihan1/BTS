## Brief

**FR-WF-07** D6b. 로드맵 PR 10b. 10a(#423, squash `53a7e466e`)가 편집기를 초안 기반으로 전환하고
발행 다이얼로그(이관이 필요 없는 경로)까지 냈다. 이 PR 은 **상태를 빼고 발행할 때 그 상태에 남은
이슈를 어디로 옮길지 묻는 마법사**와 이관 진행률 폴링을 얹어 **D6·D7 체크박스를 닫는다**.

`classify-task` 는 `type=backend / agent=backend-engineer` 로 떨어뜨렸으나 이는 **신호 0 → 기본값
fallback** 이다. 로드맵이 `[ui] apps/web` 으로 지정한 작업이고 범위 4조각이 전부 `apps/web` 이라
Maxi 확인 후 `ui / frontend-engineer` 로 교정했다. 티어도 classify 의 T1 이 아니라 **T2 선언**이다
(형제 PR 10a 가 실측 T2 · 46파일이었고, 마법사는 이슈 상태를 대량 이동시키는 비가역 조작을
트리거한다). 실측 티어는 머지 전 diff 로 다시 잰다.

### 범위 4조각 (로드맵 `cozy-hatching-otter.md:395` · plan `project-workflow.md` §2.7)

1. **상태 이관 마법사** — 발행 시 사라지는 상태에 이슈가 남아 있으면 도착지를 묻는 화면
2. **진행률 폴링** — `GET /api/v1/bulk-operations/{id}`
3. **한계 고지** — `board_columns` 경고는 **무조건부**(10a G3). 물을 API 가 없어 조건 판정을 흉내
   내면 그것이 거짓말이 된다
4. **D7 정본 E2E** — 「상태를 빼고 발행하면 마법사가 뜨고 이관 후 발행된다」

### 채택 판정 (화면 관점)

- **J2·J7 채택** — 마법사는 **빠지는 상태마다 도착지를 각각** 고르게 한다. 백엔드 커맨드가 이미
  상태별 매핑 목록을 받으므로(PR 7 이 J7 을 채택해 설계) 화면이 그 계약에 맞춘다.
- **J3 채택** — 상태별 잔여 건수를 마법사에 표시한다. 서버가 이미 응답에 싣는다(PR 6 이 J3 채택).
- **J6 채택** — 이관은 비동기이므로 화면이 **진행률을 폴링**한다.
  `GET /api/v1/bulk-operations/{id}`.
- **J8 채택 (표시 의무)** — 규칙 우회는 서버 동작이 이미 그러하다. 화면은 그 사실을 **고지**한다 —
  사용자가 「검증기가 막아 주겠지」로 오해하면 그 오해가 데이터에 남는다.
- **J9 기각 승계** → X1. 예외 매핑 UI 를 만들지 않는다.

### ★ spec 단계(`/bts-spec`)에서 추가 조회할 조작 1건

**「이관 진행 상황과 실패 항목을 Jira 는 화면에서 어떻게 보여주는가」** — J6 는 *API 레벨*
(location link 로 task 상태를 좇는다)만 답하고 **화면 표현**은 답하지 않는다. §1-0 은
「이번 변경이 새로 건드리는 조작만 추가 조회한다」이고 진행률·실패 목록 표시가 정확히 그 조작이다.
대응 화면이 없으면 §1-5 대로 「대응 없음 — ADS `<패턴>` 준용」과 사유를 남긴다.
**생략과 「조회했고 대응이 없었다」는 다른 기록이다.**
