- **영향 엔티티**: `Notification` (백엔드 #186에서 확장 완료, 신규 엔티티 없음). 프론트는 `InboxItem` 뷰 모델로 소비.
- **새 용어 (glossary 추가 후보, Maxi 승인 필요 — 머지 단계 동기화)**:

- **기존 결정 충돌**: 없음. ADR [docs/decisions/2026-06-25-fr-ux-03-inbox-data-model.md](../decisions/2026-06-25-fr-ux-03-inbox-data-model.md) (백엔드 #186 생성) 이미 채택됨. 본 D6/D7는 그 결정 위에서 프론트만 추가.

### 백엔드 API 계약 (#186, 프론트가 소비 — Explore 조사 확정)

baseURL `/api/v1/users/me/inbox`. 모두 본인 + IN_APP 채널 한정, 401/404 격리.

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| GET | `/` | 쿼리 `tab(ALL\|UNREAD\|ARCHIVED, 기본 ALL)`·`q`·`senderId(UUID)`·`issueKey`·`from(ISO)`·`to(ISO)`·`page`·`size(기본20, max100)` | `200` `Page<InboxItemResponse>` (Spring Page: content/totalElements/...) |
| GET | `/unread-count` | — | `200` `{ data: { count: number } }` |
| PATCH | `/{id}/read` | `{ read: boolean }` | `204` (본문 없음) |
| PATCH | `/{id}/archive` | `{ archived: boolean }` | `204` (본문 없음) |
| POST | `/read-all` | `{ ids?: UUID[] }` (null/빈배열=미읽음 전체) | `200` `{ data: { updated: number } }` |

**InboxItemResponse 필드** (정확히):
`id: UUID` · `eventType: string` · `issueKey: string|null` · `title: string` · `body: string|null` · `actorUserId: UUID|null` · `readAt: Instant|null` · `archivedAt: Instant|null` · `createdAt: Instant`

**탭 정의**: ALL = `archived_at IS NULL`(보관 안 된 전체, 읽음 무관) / UNREAD = `read_at IS NULL AND archived_at IS NULL` / ARCHIVED = `archived_at IS NOT NULL`. 정렬은 백엔드 `created_at DESC` 고정.

**멱등성**: read/archive는 COALESCE 시각 보존(이미 적용 시 최초 시각 유지). read-all은 0건도 200.

### spec에서 확정할 프론트 결정 (D6 설계 입력)

1. **진입점/카운트 뱃지 위치** — Header 종(🔔) 아이콘 + 미읽음 뱃지 + 별도 `/inbox` 라우트? (FR-UX-02 Header ⭐ 드롭다운 선례 참고)
2. **발신자 표시** — `actorUserId`(UUID) → 이름 해석 방법. 사용자 조회 API 사용 vs UUID/eventType 라벨만 (FR-UX-02는 targetId 라벨 그대로 사용 선례).
3. **그룹화 렌더** — 백엔드 InboxItemResponse에 그룹 메타 없음(issueKey 필드만). 프론트 자체 issueKey 묶음 vs 평면 목록.
4. **실시간 스트림 연동** — STOMP 새 알림 도착 시 미읽음 카운트/목록 invalidate 연동 여부.
