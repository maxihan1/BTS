## Brief

사용자 원문. "fr-mv-01 진행해줘"

FR-MV-01 — 프로젝트 간 이슈 이동 (필수, issue-tracking, SDD §6.1.1).
이슈를 한 프로젝트에서 다른 프로젝트로 옮긴다. 이슈 키 영속성(키 재사용 금지) +
IssueKeyRedirect 보존이 핵심 제약. (FR-MV-02 = 이동 시 히스토리 보존 + 링크 유지)

## 도메인 정리

- **BC**: issue-tracking (cross-BC 조회 = project-workflow 워크플로우 상태/스킴, resolver/port 경유)
- **영향 엔티티**: Issue(project_id/key 변경), IssueKeyRedirect(첫 실사용), IssueMoveOperation(신규 도메인 개념)
- **새 용어**: `IssueMoveOperation` — 한 번의 이동 행위(대상 프로젝트 + 매핑 묶음). glossary 추가 후보 (Maxi 승인 대기)
- **이동 = id 보존 + key만 변경** → FK 참조 데이터(히스토리·링크·워처·첨부·담당자) 자동 보존
- **핵심 결정 (Maxi 2026-06-16)**: **Jira식 매핑 마법사**. 비호환 항목만 사용자 매핑, 호환은 자동 유지
  - 종속 데이터(컴포넌트/버전/커스텀필드): 매핑 마법사(Jira식)
  - 워크플로우 상태: 매핑 마법사(Jira식) — 같은 state 있으면 유지, 없으면 사용자 선택(기본=초기상태)
  - 이슈 타입: 전역 → 유지
- **불변식**: ① id 보존 ② key_sequence advisory lock 발번 ③ redirect append-only ④ 옛 키 308 ⑤ 타입 전역 유지
- **API**: `POST /move/preview` (매핑 필요 항목 계산) + `POST /move` (매핑 적용, OCC) 2단계
- **기존 결정 충돌**: 없음 (이슈 키 영속성 ADR과 정합, 오히려 그 ADR §68이 본 기능을 지목)
- **관련 ADR**: [docs/adr/2026-06-16-issue-move-semantics.md](../adr/2026-06-16-issue-move-semantics.md) (생성됨), [issue-key-prefix-policy](../adr/2026-05-22-issue-key-prefix-policy.md)
- **범위 주의**: 마법사는 범위 큼 → 백엔드(D1~D5) 먼저, 프론트/E2E(D6/D7) 후속 PR 분할 가능성

## 스펙
