## Brief

FR-NT-03(수신자 정책 RecipientResolver)의 D6(프론트 UI)·D7(E2E) 마무리.
백엔드 D1~D5는 PR #159로 main 머지 완료. 본 작업은 **프론트 전용, 백엔드/마이그레이션 0**.

**범위(Maxi 확정 옵션 A)**.
1. **D6** — 관리자 정책 페이지(`/admin/notification-policies`)의 수신자 역할 드롭다운에
   각 역할이 "누구에게 알림이 가는지" 설명을 추가하고, **RULE_OWNER를 미지원으로 비활성 처리**해
   관리자가 선택해도 아무 알림이 안 가는 "조용한 막다른 길"을 차단한다.
2. **D7** — E2E로 5역할(WATCHER/COMPONENT_LEAD/PREVIOUS_ASSIGNEE/PROJECT_MEMBER/PROJECT_ADMIN)
   선택→정책 저장 영속 + RULE_OWNER 비활성 확인.

**핵심 통찰**. 수신자 역할 9종은 이미 FR-NT-01 D6 정책 폼(#124)에서 서버 카탈로그 기반으로 전부
선택 가능(`catalog.recipientRoles`, 한국어 라벨 존재). FR-NT-03은 enum을 추가하지 않았고 5역할의
백엔드 해석만 배선했다. 따라서 D6는 "새 UI"가 아니라 **기존 폼의 정보성/안전성 강화**(역할 설명 +
RULE_OWNER 비활성)가 본질. 백엔드가 RULE_OWNER를 skip하므로(automation BC 부재) 드롭다운에서
선택 가능하면 silent no-op이 발생 — 이것이 막아야 할 실제 UX 함정.

## 도메인 정리

- **BC**: notification (프론트 영역 = `apps/web/src/...` admin notification-policies). 백엔드 변경 0.
- **영향 컴포넌트(프론트)**: `NotificationPolicyForm`(수신자 select), `notification-policy-labels.ts`(라벨/설명 단일 출처), `api/notification-policies.ts`(RECIPIENT_ROLES 상수). E2E `notification-policy.spec.ts`(신규/확장).
- **새 용어**: 없음. 수신자 역할 9종 전부 기존 enum(`RecipientRole`)·프론트 라벨(`recipientRoleLabels`)에 존재. glossary엔 "워처=이슈 변경 알림 수신자"만 단독 등재, 나머지는 enum 라벨이 사실상 정의.
- **기존 결정 일관성 (핵심 확인)**:
  - RULE_OWNER skip = automation BC 부재로 백엔드 #159가 명시 skip + 디버그 로그. UI 비활성 처리는 이 결정과 **일관**(드롭다운 선택 가능 → silent no-op 함정 차단). 향후 FR-AT 시리즈에서 automation BC 결선 시 비활성 해제.
  - ADR `2026-06-11-notification-policy-bc-bootstrap.md §결정 3`이 **event_type** 차원에 동형 원칙 정립("발행원 없는 정책도 설정 데이터로 존재 가능") + **리스크**로 "동작하지 않는 설정 → 관리자 혼란" 명시. RULE_OWNER(수신자 역할)는 이 리스크의 recipient_role 차원 발현이며, 본 D6가 그 리스크를 UI에서 해소.
- **인접 갭(발견, 본 FR 범위 밖 → 별도 FR 노트)**: 같은 "발행원/해석기 없음 → 동작 안 함" 문제가 **event_type** 차원에도 존재 — `sprint.started`/`sprint.ended`(agile-planning BC 부재)·`automation.failed`(automation BC 부재). 이들도 폼에서 선택 가능하나 발행원이 없어 무동작. **FR-NT-03 범위(수신자 역할)가 아니라 FR-NT-01/FR-AT 영역**이므로 본 PR에서 처리하지 않음. 게이트 1에서 Maxi에 보고(원하면 별도 작업).
- **drift 주의**: RULE_OWNER 비활성은 백엔드 "skip" 사실의 프론트 인코딩 → drift 위험([[frontend-zod-backend-dto-contract-gap]]). 백엔드가 역할별 "지원 여부"를 카탈로그로 노출하지 않으므로(프론트 전용 범위 유지), 프론트 상수 1곳(예: `UNSUPPORTED_RECIPIENT_ROLES = ['RULE_OWNER']`)에 집중 + 기존 `recipientRoleLabels` 주석과 동일한 "enum/지원범위 변경 시 동반 갱신" 주석으로 단일 출처화. 백엔드 카탈로그 확장(지원여부 메타)은 향후 옵션으로 노트.
- **관련 ADR**: 신규 ADR 불요(enum/스키마/계약 변경 0). 참조 = `docs/decisions/2026-06-11-notification-policy-bc-bootstrap.md §결정 3`(동작 안 하는 설정 리스크).
