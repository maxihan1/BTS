## Brief

FR-NT-03(수신자 정책 RecipientResolver)의 D6(프론트 UI)·D7(E2E) 마무리.
백엔드 D1~D5는 PR #159로 main 머지 완료. 본 작업은 **프론트 전용, 백엔드/마이그레이션 0**.

**범위(Maxi 확정 옵션 A)**.
1. **D6** — 관리자 정책 페이지(`/admin/notification-policies`)의 수신자 역할 드롭다운에
   각 역할이 "누구에게 알림이 가는지" 설명을 추가하고, **RULE_OWNER를 미지원으로 비활성 처리**해
   관리자가 선택해도 아무 알림이 안 가는 "조용한 막다른 길"을 차단한다.
2. **D7** — E2E로 5역할(WATCHER/COMPONENT_LEAD/PREVIOUS_ASSIGNEE/PROJECT_MEMBER/PROJECT_ADMIN)
   선택→정책 저장 영속 + RULE_OWNER 비활성 확인.

**핵심 통찰**. 수신자 역할 9종은 이미 FR-NT-01 D6 정책 폼(#124)에서 서버 카탈로그 기반으로 전부
선택 가능(`catalog.recipientRoles`, 한국어 라벨 존재). FR-NT-03은 enum을 추가하지 않았고 5역할의
백엔드 해석만 배선했다. 따라서 D6는 "새 UI"가 아니라 **기존 폼의 정보성/안전성 강화**(역할 설명 +
RULE_OWNER 비활성)가 본질. 백엔드가 RULE_OWNER를 skip하므로(automation BC 부재) 드롭다운에서
선택 가능하면 silent no-op이 발생 — 이것이 막아야 할 실제 UX 함정.
