## Brief

PR #18 (FR-WF-02 backend D1~D5) 가 main 에 머지된 상태. backend REST 10 endpoint (Scheme CRUD 5 + Mapping 2 + Project assignment 2 + IssueType read 1 + RFC 7807 ExceptionHandler 11건) 의 frontend side 를 구현. 프로젝트 설정 화면에서 워크플로우 스킴 CRUD + 이슈 타입 별 워크플로우 매핑 + 프로젝트에 스킴 할당.

### 선례

- PR #10→#13 (FR-WF-01 backend→frontend) — workflows.$key 라우트 패턴
- PR #26 (FR-IS-01 D6 이슈 UI) — TanStack Router code-based + RouteAdapter + MSW + Zod + 낙관적 업데이트 + sonner 토스트
- PR #13/#16 (FR-WF-01 frontend) — mermaid stateDiagram-v2 다이어그램

### 핵심 함정 (learnings 인계)

- mermaid 사용 시 `vi.mock('mermaid', ...)` 필수 (jsdom getBBox 미구현)
- lint-staged race 재발 위험 (공유 파일 병렬 수정) → 공유 mock/i18n 은 단독 task 또는 명시 공유 task
- 서브에이전트 scoped typecheck 맹점 → wave 마지막 controller 가 전체 `pnpm typecheck` 필수
- vi.mock factory 시그니처는 `import type { ComponentProps }` 명시 (contract drift 본질 차단)
- §NFR silent 영구 보류 차단 — Deferred trigger blockquote 명시

- **D6 frontend 영역 신규 entity**: 없음 (backend 호출만)
- **신규 용어 후보 4건** (Maxi 승인 시 [[../../../Maxi_wiki/BTS/glossary]] 추가)
  1. **워크플로우 스킴** (Workflow Scheme) — 이슈 타입 별 워크플로우 매핑을 묶은 단위. 프로젝트에 할당하는 행정 단위
  2. **이슈 타입** (Issue Type) — Bug / Story / Task / Epic 등. PR #25 에서 shared-kernel 로 통일
  3. **스킴 할당** (Scheme Assignment) — 프로젝트 ↔ 워크플로우 스킴 binding
  4. **기본 매핑** (Default Mapping) — 스킴에서 명시 매핑이 없는 이슈 타입에 적용되는 기본 워크플로우
- **기존 결정 충돌**: 없음. workflow 관련 ADR 6건 모두 backend 영역 (transition identity policy / port result sealed / yaml vs db storage 등), D6 frontend UI 와 직접 충돌 없음
- **관련 ADR**: 신규 추가 후보 (UI 결정사항 — 일부 후속 plan/spec 단계에서 도출. 예. "Mapping 행 추가 UX 패턴" 또는 "기본 매핑 노출 방식")
- **domain/project-workflow.md 갱신 대기**: WorkflowScheme / SchemeIssueTypeMapping / ProjectWorkflowSchemeMap 3 entity + 4 신규 용어 (Maxi 승인 후 수동 갱신)
