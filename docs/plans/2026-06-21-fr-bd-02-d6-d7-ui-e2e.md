## Brief

FR-BD-02 "보드 필터 (담당자/라벨/컴포넌트)"의 D6(프론트 UI) + D7(E2E)을 구현한다.

- 백엔드 필터 API는 #168로 main 머지 완료: `GET /api/v1/boards/{id}?assignee=&label=&component=`
  - 필드내 OR + 필드간 AND, `assignee=unassigned` 센티널
  - assignee IN/IS NULL, label `&&` overlap, component EXISTS 서브쿼리
- 선행 FR-BD-01 보드 화면 UI는 #169로 완료 — `/projects/$projectKey/board?board=<id>`
- D6: 필터 칩 + 담당자/라벨/컴포넌트 다중 선택 UI
- D7: E2E (qa-engineer)
- 프론트 전용 작업 (백엔드 변경 0 예상)

classify 교정: E2E 키워드로 qa 오판정 → ui/frontend-engineer로 교정 (선례 FR-BD-01/FR-TT-02/FR-AC-01/FR-LK-01).

## 스펙

핵심 결정 (Maxi 확정).
- 필터 상태 = **URL search params** (`?board=&assignee=&label=&component=`, 반복 param, 새로고침/공유 보존)
- 라벨 = **자동완성 + 칩** (`LabelAutocompleteInput` 재사용), 담당자 = **검색형 다중선택 + 미배정**(`useUsers`), 컴포넌트 = **`ComponentMultiSelect` 재사용**
- ★queryKey **filter-aware** — `boardKeys.detail(boardId, filter)`를 `useBoard`·`useMoveCard`가 공유(드래그 낙관적 업데이트 정합)
- 프론트는 query param만 조립·전송, 필터는 백엔드 SQL 위임(클라 필터링 0). 백엔드 변경 0.

### Task 1. api/boards.ts — `fetchBoard` 필터 확장 + `BoardCardFilterParams` + query 조립

**메타**.
- agent: `frontend-engineer`
- files: [`apps/web/src/api/boards.ts`, `apps/web/src/api/boards.test.ts`]
- depends-on: []

**RED**: `boards.test.ts` — `fetchBoard(boardId, filter)`가 올바른 query string 생성 검증(fetch mock URL 단언).
- `{ assigneeIds:['a1'], includeUnassigned:true }` → `?assignee=a1&assignee=unassigned`
- `{ labels:['bug','urgent'] }` → `?label=bug&label=urgent`
- `{ componentIds:['c1'] }` → `?component=c1`
- 빈 필터 / filter 미전달 → query param 없음(`/api/v1/boards/{id}`).

**GREEN**: `BoardCardFilterParams = { assigneeIds: string[]; includeUnassigned: boolean; labels: string[]; componentIds: string[] }` export + `buildBoardFilterQuery(filter)` 헬퍼(URLSearchParams, unassigned 센티널 append, 빈 배열 생략) + `fetchBoard(boardId, filter?)` 2번째 인자. 응답 스키마 불변.

**REFACTOR**: query 조립 KDoc, 빈-필터 단축 경로.

**검증**: `pnpm --filter web test boards.test`

**REFACTOR**: filter 정규화 헬퍼 추출 + KDoc(기존 `useBoard(id)` 호출 호환 명시).
