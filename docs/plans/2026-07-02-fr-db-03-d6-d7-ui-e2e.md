## Brief

FR-DB-03 대시보드 공유 프론트 D6/D7 (PR2). 백엔드 PR1(#216, notification-dashboard BC)에서 공유 토큰 API + 익명 데이터 경로가 확정됨.

- 관리 API: `POST/GET/DELETE /api/v1/dashboards/{id}/shares` (소유자, MAX 20, 목록 token 미노출)
- 익명 데이터 경로: `GET /api/v1/public/dashboards/{token}` (permitAll GET 한정, 정적 가젯만, 404 열거차단)
- classify 정정: "E2E" 키워드로 qa 오분류 → Maxi 확정 ui/frontend-engineer (선례 #178/#185/#136/#41)

- **실제 머지된 백엔드 계약 (PR1 #216, grep 대조 — spec이 아니라 실제 DTO 기준)**:
  - 관리(인증·소유자): `POST /api/v1/dashboards/{id}/shares` → 201 `{ data: { id, token, createdAt, expiresAt? } }` (원문 token 1회 노출)
  - `GET /api/v1/dashboards/{id}/shares` → 200 `{ data: { items: [{ id, createdAt, expiresAt? }] } }` — **token/해시 미포함, `lastAccessedAt` 없음**(G1 MVP 미채택, spec S4 표기와 편차 — 프론트는 마지막 접근일 표시 금지)
  - `DELETE /api/v1/dashboards/{id}/shares/{shareId}` → 204
  - 익명(permitAll·GET): `GET /api/v1/public/dashboards/{token}` → 200 `{ data: { name, description?, layout } }` / 404(errorCode `NOTIF_DASHBOARD_NOT_FOUND`)
  - ⚠️ **익명 응답 `layout`은 JSON *문자열*** (`val layout: String`, 파싱된 객체 아님) — 프론트가 JSON.parse 후 렌더. 정화된 layout(데이터 가젯은 `{i,x,y,w,h,gadgetType,requiresAuth:true}`로 config 제거).
  - 응답은 모두 `DataResponse` = `{ data: ... }` 래핑.
  - `{id}`는 대시보드 UUID(키 아님).
- **프론트 기반 (기존 FR-DB-01/02 자산)**: `api/dashboards.ts`(확장 대상)·`hooks/use-dashboards.ts`·`components/dashboard/{DashboardGrid,DashboardTile,gadgets/}`(익명 뷰 렌더러 재사용)·`routes/dashboards.$dashboardId.tsx`(공유 버튼 진입점)·`mocks/dashboard-{handlers,fixtures}.ts`·`i18n/dashboard-labels.ts`.

### 프론트 슬라이스

- **진입점**: `routes/dashboards.$dashboardId.tsx` 상세 페이지에 "공유" 버튼. 게이팅 = 기존 `canEditDashboard(dashboard, currentUserId)`(= `ownerId===currentUserId`, 소유자 전용 = FR-8). visibility·ownerId는 `dashboardSchema`에 이미 노출됨.
- **공유 모달 (FR-6)** — 기존 `components/dashboard/GadgetCatalogModal.tsx` 패턴 재사용. 3 영역.
  - (a) **링크 생성**: "링크 생성" → `POST .../shares` → 응답의 원문 `token`으로 공개 URL(`{origin}/dashboards/shared/{token}`) 조립해 표시 + "복사"(기존 clipboard 유틸 `BackupCodesSection` 패턴). **PRIVATE/TEAM일 때 경고 배너**("링크가 있는 누구나 읽을 수 있습니다", G2/FR-6) — visibility !== "ORG" 조건.
  - (b) **임베드 코드**: 방금 생성된 토큰으로 `<iframe src="{origin}/dashboards/shared/{token}?embed=1" ...>` 스니펫 + 복사 (same-origin, O-1).
  - (c) **발급된 링크 목록**: `GET .../shares` → `{ id, createdAt, expiresAt? }` 표시 + "취소"(`DELETE`). ⚠️ **목록에는 복사 링크/임베드 없음** — 토큰은 해시만 저장돼 재조회 불가(원문 1회 노출). **`lastAccessedAt` 표시 안 함**(백엔드 DTO에 없음, G1 미채택).
- **핵심 UX 제약**: 복사 링크·임베드 스니펫은 **방금 발급한 토큰에 한해**(컴포넌트 state 보관) 제공. 목록 항목은 메타+취소만. 놓치면 취소 후 재발급. UI에 "이 링크는 지금만 복사할 수 있습니다" 안내.
- **익명 뷰 라우트 (FR-7)** `/dashboards/shared/{token}`:
  - **raw fetch**(apiFetch 금지 — 401 로그인 리다이렉트/인증헤더 회피, memory auth-pre-session-401-raw-fetch)로 `GET /api/v1/public/dashboards/{token}` 호출 → `{ data: { name, description?, layout } }` 언랩 → **layout은 JSON 문자열이라 `JSON.parse`**.
  - 렌더러는 **FR-DB-02 정화 렌더러 재사용**: 정적 가젯(text_widget/link_list)은 config로 렌더, 데이터 가젯(`requiresAuth:true`)은 "로그인이 필요한 가젯입니다" 플레이스홀더(useGadgetData 미호출).
  - **읽기 전용**: DashboardGrid를 드래그/편집 없는 static 모드로. 헤더·소유자정보·편집UI 미노출.
  - `?embed=1` → 크롬 최소화(헤더/여백 제거), 없어도 동작(EC-7).
  - **404 처리**: 무효/만료/삭제 토큰 → 404 → "공유된 대시보드를 찾을 수 없습니다"(로그인 리다이렉트 아님, EC-11).
  - **인증 가드 우회**: 이 라우트는 auth-required 레이아웃 밖에 등록(비로그인 접근 가능).
- **api/hooks**: `api/dashboards.ts` 확장(share CRUD + public get) — 기존 Zod `dataWrapper` 관례. `hooks/use-dashboards.ts`에 share mutation/query 훅(invalidate-only, `['dashboards', id, 'shares']` 키).
- **i18n**: `i18n/dashboard-labels.ts` 확장(콜론 종결 금지 — ktlint i18n 회귀가드).
- **MSW**: `mocks/dashboard-handlers.ts`에 share POST/GET/DELETE(stateful) + public GET 핸들러. public 핸들러는 정화 layout(데이터 가젯→requiresAuth 플레이스홀더) 반환. 계약 fidelity: DataResponse 래핑·layout JSON 문자열·목록 token 미노출.
- **E2E (qa-engineer task)**: 소유자 링크 발급→URL 복사→익명 뷰 열람(정적 가젯 렌더 + 데이터 가젯 플레이스홀더 + 편집UI 부재) / 취소→404 / (embed=1 크롬 최소화).

### 측정 가능한 완료 기준 (프론트)

1. 소유자가 공유 모달에서 링크 생성 → URL·임베드 복사 가능, PRIVATE/TEAM 경고 노출.
2. 익명 뷰에서 정적 가젯 렌더 + 데이터 가젯 플레이스홀더 + 편집/헤더 부재(E2E).
3. 무효/취소 토큰 접근 → 404 화면(로그인 리다이렉트 아님).
4. 기존 FR-DB-01/02 대시보드 테스트 전부 green(회귀 0).
5. vitest·typecheck·lint clean + E2E 신규 시나리오 pass.
