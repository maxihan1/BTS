## Brief

첨부 업로드 시 ClamAV(오픈소스 안티바이러스 엔진)로 악성코드를 검사하는 단계를 추가한다. FR-AC-01 D2(첨부 보안 게이트) 3항목 중 크기제한·업로드 MIME 화이트리스트(#149)·미리보기 MIME 화이트리스트(#147)는 닫혔고 ClamAV만 잔존. 이걸 끝내면 D2가 `[~]`→`[x]`.

**확정된 정책 (Maxi 결정, 2026-06-15)**.
- **장애 정책 = fail-closed**. ClamAV 데몬 미가용/타임아웃 시 업로드 거부(우회 틈 없음). 데몬 장애 동안 첨부 업로드 일시 중단(가용성 손해는 운영 복구로 해소). BTS 일관 기조(fail-open이 보안 갭을 가린 과거 사고 다수).
- **스캔 시점 = 저장 전 동기 스캔**. MinIO 저장 *전*에 ClamAV 통과. 감염 파일은 저장소에 아예 안 들어감. 기존 동기 업로드 흐름에 스캔 한 단계만 추가.

**작업 범위**.
- `infra/docker-compose`(dev)에 ClamAV 데몬 컨테이너 추가.
- 업로드 경로(권한 직후 · MinIO put 이전)에 ClamAV 스캔 연동.
- 감염 판정 시 거부 응답(에러코드 — #149의 `ISSUE_UNSUPPORTED_FILE_TYPE` 관례 참고, 바이러스 전용 코드 신설 검토).
- 데몬 미가용/타임아웃 시 fail-closed(거부).
- Testcontainers EICAR 테스트 파일 통합테스트.
- 완료 시 `docs/plan/product/issue-tracking.md` §4.2.1 D2를 `[~]`→`[x]`로 닫고 대시보드 재생성.

**관련 선행 PR**. #145(업로드 백엔드 MinIO) · #149(업로드 MIME 화이트리스트, 검증=권한직후·put이전 패턴).

**적용할 교훈**. Testcontainers companion object stale port 함정(learnings 2026-05-21) — ClamAV 컨테이너도 singleton `.apply { start() }` 패턴.
