## 도메인 정리

- **BC**: automation (뷰 레이어 확장 — 새 도메인 모델 없음)
- **성격**: 순수 프론트. 백엔드 도메인(액션·rule actor·dry-run·execution depth)은 FR-AT-02 D1~D5(PR #256)에서 ADR로 확정됨. 이번 작업은 그 확정 계약을 소비하는 UI.
- **새 용어**: 없음 (glossary "액션 = Action. 자동화 룰의 실행 결과" 이미 존재). rule actor·dry-run은 백엔드 내부 개념, UI 노출 문구는 스펙에서 확정.
- **기존 결정 충돌**: 없음. 관련 ADR: [docs/decisions/2026-07-11-fr-at-02-automation-actions.md](../decisions/2026-07-11-fr-at-02-automation-actions.md) (D1~D5, 소비만 함).

### 백엔드 계약 (정본 — 프론트 Zod가 invent 금지, 이 형태에 1:1 정합)

응답 `AutomationRuleResponse` (기존 프론트 Zod에 **누락됨 — D6에서 추가 필수**):
- `actions: ActionResponse[]` — `{ type: ActionType, config: object }` (config는 **객체**/Map)
- `actorUserId: UUID` (**non-null** 응답)

요청 `Create/PatchAutomationRuleRequest`:
- `actions: ActionRequest[]` — `{ type: string, config: JSON문자열 }` (config는 **JSON 문자열**)
- `actorUserId: UUID?` (생성 시 null=생성자 폴백, PATCH null=미변경)

**⚠️ config 비대칭**: 응답 config=객체, 요청 config=JSON 문자열. 읽기는 객체 파싱, 쓰기는 `JSON.stringify` 직렬화 (triggerConfig `serializeTriggerConfig` 선례 동형).

### 4종 액션 config 형식 (Action.kt / ActionConfig.kt 도메인 검증)

| 타입 | config 형식 | 도메인 제약 |
|---|---|---|
| SET_FIELD | `{field, value}` | field=비어있지 않은 문자열(**자유 입력, 실존 검증은 실행 시점 위임**), value=임의 JSON |
| ASSIGN | `{assigneeId}` | uuid 문자열 또는 **null(=담당자 해제)** |
| ADD_COMMENT | `{body}` | 비어있지 않은 문자열, `{{템플릿}}` 지원 |
| CALL_WEBHOOK | `{url, method?, headers?, body?}` | url=http(s):// prefix(템플릿 지원, 엄격 검증은 실행 시점), method 기본 POST, headers=문자열 맵 |

### 재사용 자산
- `apps/web/src/api/project-members.ts` + `use-project-members.ts` — actor/assignee 피커용 사용자 목록(`userId·displayName·username`)
- `AutomationRuleFormDialog.tsx` — 확장 대상 폼(react-hook-form·zodResolver·key 재마운트·409 폼닫기 처리 기존 완비)
- `serializeTriggerConfig` 선례 — actions 직렬화 헬퍼 동형 패턴

### 범위 확정
- dry-run/preview 엔드포인트 **미노출**(컨트롤러 POST/GET/PATCH/DELETE만) → D6에 dry-run UI **불포함**
- 스펙에서 확정할 UX 결정: **SET_FIELD field 입력 방식**(자유입력 vs 큐레이션 드롭다운)
