## 도메인 정리

- **BC**: personalization(논리) → identity-access(물리 모듈). FR-PR-01/02 계승.
- **영향 엔티티**: `OutOfOffice`(신규, User와 1:1). `user_ooo` 테이블(V029).
- **새 용어**: "부재중 (Out of Office)" — 사용자가 지정 기간 자리를 비움 + 대체 담당자 + 안내 메시지.
- **핵심 결정 (Maxi 확정)**:
  - D3 **자동 위임 스코프 = A안(단일 BC, 표시만)**. delegate 저장·표시만, 실제 assignee 자동 전환은 후속(issue-tracking 소유). "한 PR = 한 BC" 준수.
  - D4 자동 응답 = 표시용 안내 메시지(`user_ooo.message`), 이메일 자동회신 아님.
  - D5 활성 판정 = 조회 시 lazy 필터(`starts_at <= now < ends_at`), Clock 주입.
  - D6 whoami view-layer로 부재중 노출.
- **cross-BC 흐름**: 없음(delegate 실재 검증은 identity-access가 `users` 자체 SELECT). issue-tracking 무변경.
- **기존 결정 충돌**: 없음.
- **관련 ADR**: [docs/decisions/2026-07-07-fr-pr-03-ooo.md](../decisions/2026-07-07-fr-pr-03-ooo.md) (생성됨)

## 스펙

전체 스펙. [docs/specs/2026-07-07-fr-pr-03-ooo.md](../specs/2026-07-07-fr-pr-03-ooo.md)

핵심 시나리오 3줄 요약.
- 사용자가 부재 기간(시작/종료) + 대체 담당자(검색 선택) + 안내 메시지를 설정 → `PATCH /me/ooo`(원자적 교체), 해제는 `DELETE`
- 활성 판정은 `startsAt<=now<endsAt`(Clock 주입, lazy 필터). 미래예약 OOO 허용, 종료된 OOO는 GET에서 all-null
- whoami view-layer로 본인 부재중(`oooActive`/`oooUntil`) 노출 → Header 부재중 표시. 자동 assignee 전환은 후속(A안)

엔드포인트: `GET/PATCH/DELETE /api/v1/users/me/ooo`(product의 POST 표기 → 관례 수렴). 검증: 기간 필수·endsAt>startsAt·endsAt>now·delegate 존재+본인불가·message≤500.
