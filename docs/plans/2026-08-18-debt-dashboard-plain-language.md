→ 아래 Maxi 결정 ③.

**Maxi 결정이 필요한 것 — 게이트 1 에 싣는다.**

① **[5]·[6] 의 서브에이전트.** `bts-impl` 은 dispatch 가 기본이고 T2 는 리뷰 2종이다. 세션 지시문과
충돌하며 앞서 「상시 규칙화는 지금 정하지 않음」으로 남았다. **이번 PR 에서 확정한다.**

② **두 줄의 문체.** 「~합니다」체(비개발자 대상)인지 「~다」체(저장소 문서 기본)인지.
현재 `TODOS.md` 는 전부 「~다」체다. **기본값 「~다」체**로 잡았다 — 읽는 사람이 바뀐다고 파일 안에서
문체가 갈리면 그게 더 어색하다. 뒤집을 수 있다.

③ **PR 을 쪼갤 것인가.** 지금 범위는 세 덩어리다.
　　**(가) 내용** — 28건 두 줄 작성 + 등재 서식(W1·W8). 이게 Maxi 가 실제로 원한 것이다.
　　**(나) 코드** — 생성기 카테고리 렌더 + 판별식 + 파서 수정(W2~W5·W9).
　　**(다) 대이동** — `TODOS.md` 5,060줄 재배열(W7·W10).
　　**권고 — (가)+(나) 를 이 PR 로, (다) 를 후속 PR 로.** 이유 둘이다.
　　ㄱ. **(다)는 (가)·(나) 없이는 위험하다.** 재배열의 안전망이 「본문 해시 불변」인데, 그 판별식이
　　　(나)에서 나온다. 순서가 뒤집히면 맨손으로 5,000줄을 옮기는 것이다.
　　ㄴ. **(가)+(나)만으로 화면은 이미 카테고리별로 나온다.** 파일 안 순서는 사람이 `TODOS.md` 를
　　　직접 열 때만 보이는데, 그 용도는 대시보드가 대신하는 것이 이 작업의 목적이다.
　　**한 PR 로 가길 원하시면 그대로 진행한다** — 다만 리뷰가 이동/편집을 구분 못 하는 위험을 안는다.
