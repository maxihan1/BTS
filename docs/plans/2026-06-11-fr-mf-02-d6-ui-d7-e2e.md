### 백엔드 API 계약 (ground truth — #117 실측)

| 기능 | 엔드포인트 | 인증 | 요청 | 응답(200) | 에러 |
|---|---|---|---|---|---|
| 생성/재생성 | `POST /api/v1/auth/mfa/backup-codes` | JWT 전용 | body 없음 | `{ codes: string[10] }` (평문 `xxxxx-xxxxx`, 1회 노출) | 409 `totp_not_active` · 403 `session_management_requires_interactive_login`(PAT) · 401 |
| 남은 개수 | `GET /api/v1/auth/mfa/backup-codes` | JWT 전용 | — | `{ generated: bool, remaining: int }` | 403 PAT · 401 |
| 로그인 검증 | `POST /api/v1/auth/mfa/verify` | permitAll + CSRF skip (이미 등록) | `{ mfa_challenge_token, code, method:"backup_code" }` | `{ access_token, token_type, expires_in }` | 400 `invalid_method` · 401 `invalid_code` · 429 `too_many_attempts` |

- 재생성은 동일 엔드포인트(replaceAll, 사용/미사용 무관 전량 무효화).
- `/mfa/verify`의 `method` 기본값 `"totp"` (기존 클라이언트 호환). 백업코드는 `"backup_code"` 명시.
- rate-limit: `BackupCodeAttemptLimiter` 5회/5분 → 429 (TOTP와 별도 카운터).
- 에러 바디: `{ "error": "<code>" }` 일원화.

### spec에서 결정할 UX 포인트 (열린 질문)

1. 로그인 2단계에서 TOTP 입력 화면 ↔ 백업코드 입력 화면 **전환 방식** ("백업코드로 로그인" 링크 + 뒤로가기).
2. 설정 화면에서 백업코드 **생성 시점 평문 10개 1회 노출** UX (복사/다운로드, 닫기 후 재확인 불가 경고).
3. **남은 개수 부족 경고** 표시 기준(예: remaining ≤ 3).
4. 재생성 시 **기존 코드 전량 무효화 확인** 모달.

## 스펙

전체 스펙: [docs/specs/2026-06-11-fr-mf-02-d6-ui-d7-e2e.md](../specs/2026-06-11-fr-mf-02-d6-ui-d7-e2e.md)

핵심 시나리오.
- 설정 화면(TOTP 활성 시만): 백업코드 생성/재생성(확인 모달) + 평문 10개 1회 노출(복사/다운로드) + 잔여 개수(remaining≤3 경고).
- 로그인 2단계: "백업 코드로 로그인" 링크 토글 → 백업코드 입력 → `verify(method:"backup_code")` → 정식 세션.
- 평문은 메모리 비영속, verify는 raw fetch, 생성/재생성은 apiFetch+X-XSRF-TOKEN, mutation 후 invalidate-only.

Maxi UX 결정: (1) 복사+다운로드(.txt), (2) 링크 토글, (3) remaining≤3 경고, (4) 재생성 확인 모달.
