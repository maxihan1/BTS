primary_bc=issue-tracking. FR-BL-01 backlog-lexorank worktree/draft PR #179는 유지(별개).

## 도메인 정리

- **BC**: issue-tracking (물리 구현). 논리 FR 소속은 search-export-import 유지 (논리 ≠ 물리, ADR D1/D2).
- **영향 영역**: 프론트엔드 이슈 목록 화면 (apps/web). 백엔드 0 변경(이미 #180 완료).
- **새 용어**: 없음. 필터 4종(status/assignee/label/component)은 기존 개념. status=워크플로우 상태,
  assignee=담당자(unassigned 센티널 포함), label=라벨 이름, component=컴포넌트.
- **API 계약 (소비 대상, #180)**:
  - `GET /api/v1/issues?projectKey=&status=&assignee=&label=&component=&page=&size=`
  - 같은 파라미터 다중 값 = OR, 다른 파라미터 간 = AND (괄호/중첩 미지원 — 그건 FR-SR-02 AQL).
  - assignee: UUID 또는 `"unassigned"`(대소문자 구분 센티널). label: 이름 문자열. component: UUID.
  - 잘못된 UUID → 400 `ISSUE_FILTER_INVALID_UUID`.
  - 응답: `Page<IssueResponse>` (기존 목록 응답과 동일 스키마).
- **기존 결정 충돌**: 없음.
- **관련 ADR**: [docs/decisions/2026-06-23-fr-sr-01-issue-filter-bc.md](../decisions/2026-06-23-fr-sr-01-issue-filter-bc.md)
  (백엔드 PR #180에서 생성, D6/D7은 신규 ADR 불필요).
- **참고**: 보드 필터(FR-BD-02)가 동일 4필드 필터 UI를 이미 보유 가능 → 재사용/패턴 정렬 확인 필요(spec에서).

## 스펙

전체 스펙. [docs/specs/2026-06-23-fr-sr-01-d6-d7-ui-e2e.md](../specs/2026-06-23-fr-sr-01-d6-d7-ui-e2e.md)

핵심 결정 (Maxi 확정).
- **재사용 = 이슈 전용 신규 + 공유부품 재사용**. `IssueFilterBar` + `lib/issue-filter.ts` 신규, 보드 코드 0 변경.
  공유부품(`LabelAutocompleteInput`/`ComponentMultiSelect`/`useUsers`·`useLabels`·`useComponents`·`useDebounce`) 재사용.
- **status 옵션 = 전체 워크플로우 수집**. `GET /api/v1/workflows` states flatten + key dedupe, displayOrder 정렬. 신규 `useWorkflows`.
- **필터 상태 = URL search params** (`?status=&assignee=&label=&component=&page=`), 새로고침/공유 보존.
- **queryKey filter-aware** `['issues', projectKey, page, filter]`, bulk invalidate `['issues', projectKey]` prefix 정합.
- **클라 필터링 0** — 백엔드 SQL 위임. 필터 변경 시 page=0 리셋 + 일괄 선택 클리어(FR10).
