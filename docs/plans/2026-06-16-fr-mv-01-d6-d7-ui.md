## Brief

프로젝트 간 이슈 이동 다이얼로그(Jira "Move Issue Wizard"). 백엔드 #153(단건)+#154(서브태스크 동반, 노드별 매핑) 완료.
preview(POST /{key}/move/preview)+move(POST /{key}/move) 2단계 API 소비.
마법사: 대상 프로젝트 선택 → preview 노드별 비호환 매핑(컴포넌트/버전/커스텀필드/워크플로우 상태) 계산 →
사용자 매핑 확인 → move 실행. 단건 + 서브태스크(부모+직접 자식 노드별 subtasks 배열) 지원. 응답 movedSubtasks.
D7: 이동 + 옛 키 308 redirect E2E (FR-IS-01 D7에서 이관). 완료 시 FR-MV-01 전체 종료.

## 도메인 정리

- **BC**: issue-tracking (apps/web 프론트). 백엔드 도메인/API는 #153/#154에서 확정 — 프론트는 **소비측**.
- **새 도메인 모델/용어**: 없음 (기존 이동 의미론 그대로 — Jira Move Wizard, 노드별 매핑, redirect).
- **기존 결정 충돌**: 없음. ADR [docs/adr/2026-06-16-issue-move-semantics.md](../adr/2026-06-16-issue-move-semantics.md) 소비.
- **영향 (apps/web)**:
  - 이동 마법사 다이얼로그 컴포넌트 (신규) — 다단계(대상 프로젝트 선택 → 매핑 확인 → 실행)
  - 이슈 상세 페이지 "이동" 액션 진입점
  - `api/issues` 이동 함수(preview/move) + TanStack Query 훅
  - **Zod 스키마** — `MovePreview`(workflow/components/affectsVersions/fixVersions/customFields + **subtasks 노드별 섹션**), `MoveRequest`(평면 루트 + **subtasks 배열**, 자식 식별 `issueKey`), `MoveResponse`(issueKey/previousKey + **movedSubtasks**)
- **핵심 리스크 (메모리 교훈)**:
  - **Zod ↔ 백엔드 DTO 1:1 미러** — invent 금지, 백엔드 `MoveDtos.kt`/`MovePreviewService.kt`(머지됨)를 spec서 grep 검증 ([[frontend-zod-backend-dto-contract-gap]])
  - `@JsonInclude(NON_NULL)` ↔ Zod nullable/optional 정합 (백엔드 nullable 필드 실측)
  - 옛 키 308 redirect — SPA 라우팅에서 새 키로 이동 처리 (E2E 검증)
- **관련 ADR**: docs/adr/2026-06-16-issue-move-semantics.md (§후속 결정 = 서브태스크 동반)

- 단건+서브태스크 노드별 매핑(상태 select·컴포넌트/버전 매핑/제거·필수필드 입력), move 페이로드 노드별, 성공 시 새 키 이동+movedSubtasks 토스트
- Zod 백엔드 1:1 미러, 옛 키 308 redirect → 새 키 SPA navigate (D7 E2E)
