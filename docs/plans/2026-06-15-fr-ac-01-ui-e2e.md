## Brief

FR-AC-01 첨부 기능의 D6(프론트 UI) + D7(E2E)를 구현한다.
백엔드 D1~D5는 PR #145로 완료(MinIO 서버 경유 멀티파트 스트리밍).

**deviation 반영(#145, ADR 2026-06-15-fr-ac-01-attachment-storage)**:
- plan 표기 "react-dropzone + 직접 PUT"은 stale. 실제는 **서버 경유 multipart 업로드**.
- scope: 업로드 + 다운로드 + 목록 + 삭제 4종.
- 삭제 = 하드삭제. 권한 = IssuePermission.UPDATE(업로드/삭제) / VIEW(다운로드/목록).

### 백엔드 API 계약 (실측, IssueAttachmentController.kt)
- POST   /api/v1/issues/{key}/attachments  (multipart, part명 `file`) → 201 { data: AttachmentResponse } + Location
- GET    /api/v1/issues/{key}/attachments → 200 { data: AttachmentResponse[] }
- GET    /api/v1/issues/{key}/attachments/{attachmentId} → 200 바이트스트림 (Content-Disposition: attachment)
- DELETE /api/v1/issues/{key}/attachments/{attachmentId} → 204
- 에러: 401(미인증) / 403(권한) / 404(이슈·첨부 없음) / 413(크기 초과)
- AttachmentResponse = { id: UUID, filename, contentType, sizeBytes: Long, uploadedBy: UUID, createdAt: Instant }

### 프론트에 영향을 주는 ADR 결정
1. 업로드 = **서버 경유 멀티파트**(`POST` multipart `file` part). presigned 직접 PUT 아님 → react-dropzone는 파일 선택 UX만, 전송은 서버로.
2. 범위 = 업로드/다운로드/목록/삭제 4종.
3. 권한 = UPDATE(업로드/삭제) / VIEW(목록/다운로드). 프론트 권한 게이팅은 서버 403 처리 + (가능 시) 권한 요약 API.
4. 삭제 = **하드삭제**(복구 불가) → UI에서 삭제 확인 필요.
5. 다운로드 = `Content-Disposition: attachment`(브라우저 강제 다운로드, 인라인 렌더 X). 미리보기는 FR-AC-02로 분리.

## 스펙

전체 스펙. [docs/specs/2026-06-15-fr-ac-01-ui-e2e.md](../specs/2026-06-15-fr-ac-01-ui-e2e.md)

핵심 결정(Maxi 확정 2026-06-15).
- 파일 선택 = **네이티브 HTML5**(`<input type=file multiple>` + drag/drop). react-dropzone 등 신규 의존성 0.
- 업로드 진행 = **단순 로딩 상태**(fetch 기반, apiFetch 재사용).

핵심 시나리오.
- 이슈 상세 좌측 본문 하단 "첨부" 섹션 — 업로드(드롭존)/목록/다운로드/삭제 4동작.
- 업로드는 `apiFetch`에 FormData 지원 확장(JSON 직렬화·Content-Type 강제를 FormData면 건너뜀, 401 refresh 인프라 재사용).
- 다운로드는 `lib/download.ts` triggerBlobDownload 재사용. 삭제는 하드삭제라 확인 필수.
- 권한 게이팅은 기존 `issue-permissions` UPDATE 플래그 재사용(신규 권한 API 노출 불필요).
