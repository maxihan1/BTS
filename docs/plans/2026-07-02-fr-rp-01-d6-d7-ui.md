## Brief

FR-RP-01의 프론트엔드 마무리 (D6/D7). 백엔드 D1~D5는 **PR #219로 완료·머지**됨.

- **백엔드 API (완료)**. `GET /api/v1/sprints/{id}/burndown` — 스프린트 번다운/번업 시계열. 권한. 프로젝트 BROWSE + 이슈별 가시성 필터(뷰어 스코프). 에러. 401/403/404(SprintNotFound)/422(SPRINT_DATES_REQUIRED).
- **응답 형식 (BurndownResponse)**. `points: [{ date, remainingSeconds, idealSeconds, completedSeconds, scopeSeconds }]` — remainingSeconds/completedSeconds는 미래일 null 가능. 지표=잔여 추정시간(초). (정확한 필드는 D6 착수 시 백엔드 DTO grep으로 계약 확인 — frontend-zod-backend-dto-contract-gap)
- **D6**. recharts 라인 차트 컴포넌트 — 번다운(remaining) + ideal + scope, 번업(completed) 라인. 스프린트 화면/리포트 탭에 배치.
- **D7**. Playwright E2E — 차트 렌더 happy path.

**핵심 함정 (선행 인지)**.
- recharts는 jsdom에서 width 0 → 렌더 안 됨 → 단위테스트는 순수 데이터 변환 함수, 실제 렌더는 실브라우저 E2E (FR-TT-02 D6/D7 선례).
- 초(seconds) → 시간(h) 축 변환은 순수 함수로 분리·단위테스트.
- 백엔드 nullable(remaining/completed) → Zod `.nullish()` (@JsonInclude↔Zod 정합).
- MSW 계약 drift 주의(api ↔ MSW 핸들러 응답 형식 일치, 적대 리뷰서 표면화 선례).

## 도메인 정리

- **BC**. agile-planning (프론트는 `apps/web`에서 이 BC의 번다운 API 소비).
- **새 도메인 용어**. 없음 — 번다운/번업/ideal 라인/scope 라인/잔여 추정시간(초)은 백엔드 ADR에서 이미 정의. 프론트는 렌더링만.
- **영향 엔티티/read-model**. 신규 0. 기존 `BurndownResponse`/`BurndownPointResponse`(백엔드 #219) 소비.
- **기존 결정 충돌**. 없음.
- **관련 ADR**. [2026-07-02-fr-rp-01-burndown-burnup](../decisions/2026-07-02-fr-rp-01-burndown-burnup.md) (백엔드 #219에서 확정, 프론트는 그 계약 준수).
- **백엔드 응답 계약 (Zod 기준, DTO grep 확정)**.
  - `BurndownResponse`. `sprintId`(uuid), `projectKey`(string), `status`(SprintStatus enum), `startDate`/`endDate`(LocalDate→ISO "YYYY-MM-DD"), `totalScopeSeconds`(number), `points`(배열).
  - `BurndownPointResponse`. `date`(ISO date), `remainingSeconds`(**nullable**→`.nullish()`), `idealSeconds`(number), `completedSeconds`(**nullable**→`.nullish()`), `scopeSeconds`(number).
- **glossary 갱신 후보**. "번다운/번업" 미등재 — glossary는 Maxi 수동 영역이라 자동 추가 안 함 (필요 시 Maxi 확인).
- **grill-with-docs 생략 사유**. 도메인·ADR을 같은 세션 백엔드 PR #219에서 확정. 새로 모델링할 도메인 0 → 심층 그릴링 부적합(완료 FR office-hours 부적합 선례와 동일 판단). 경량 도메인 확인으로 대체.
