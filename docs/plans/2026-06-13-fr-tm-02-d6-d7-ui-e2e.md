## 리뷰 결과

### eng 집중 독립 리뷰 (2026-06-13) — frontend/ui (plan-design-review 대신)

classify=qa(fast-track) ↔ 실제 ui. UX는 Maxi 확정(옵션 A)이고 기존 다이얼로그 소규모 수정이라 대화형 plan-design-review는 과함(메모리 bts-review-plan-autoplan-overkill). 기술 리스크 집중 독립 리뷰로 대체.

- ✅ **RHF setValue→DOM 반영(G1 핵심)**: react-hook-form v7.76. registered 비제어 textarea에 `setValue('content', next)`는 field ref에 값을 써서 `el.value`가 갱신됨(LoginForm.tsx setValue 선례 존재). 따라서 **Approach A**(register 유지 + 삽입 시 `el.value`/`selection` 읽어 splice → setValue → caret 복원)가 현 코드 최소 변경으로 성립. T2 RED가 **실제 useForm harness로 el.value를 검증**하므로 가짜그린 없이 본질 확인.
- 🔁 **Contingency(B)**: 만약 T2 RED에서 setValue 후 `el.value` 미반영이 관측되면(shouldUnregister 등 예외), content를 controlled로 전환(LabelAutocompleteInput 동형 value/onChange) 후 caret useEffect 복원. 단 현 버전·선례상 A로 충분 예상.
- ⚠️ **caret 단위 테스트 취약성**: jsdom에서 `setSelectionRange`/`requestAnimationFrame` 타이밍은 flaky. **단위 테스트는 삽입 결과 value를 1차 검증**(splice 정확성 = insert-at-cursor 본질), caret/focus 복원은 느슨 검증 + E2E 위임. 커서 위치 픽셀 단언 금지.
- ✅ **create/edit 중복 제거(G2)**: T3가 두 branch를 `TemplateContentField`로 교체, 각 모드가 자기 register/setValue 주입 → 단일 구현 공유. 기존 다이얼로그 테스트 회귀 보존(T3 RED가 기존 케이스 유지).
- ✅ **토큰 drift(G3)**: T1 exact-token 테스트(`{{author}}`/`{{date}}`/`{{project}}`) + 백엔드 enum 출처 주석. Kotlin enum 자동 대조는 프론트 테스트 범위 밖 → 수동 미러가 현실적 한계, 수용(closed set 3종, 변동 드묾).
- ✅ **E2E(G4)**: 버튼 aria-label(`작성자 변수 삽입` 등)은 buttons-only 매칭이라 도움말 `<p>`·FR-TM-01 라벨과 비충돌. **라운드트립 검증**(create 토큰 삽입→저장→edit 재오픈 프리필에 토큰 잔존)이 토큰 전송을 end-to-end 입증 — 강력. 기존 issue-templates.spec.ts(FR-TM-01) 회귀 동반 실행.
- ⚠️ **변수 버튼 게이팅**: 다이얼로그 진입 자체가 MANAGE_TEMPLATES로 게이팅(추가/수정 버튼 disabled)되므로 다이얼로그 내부 변수 버튼은 별도 권한 게이팅 불요. `isPending`(저장 중) 시 비활성은 선택(경미).
