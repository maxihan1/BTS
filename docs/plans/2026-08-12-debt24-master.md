## 이 문서가 왜 있나

PR 묶음표가 **건수만 적고 어느 항목인지는 안 적으면** 두 목록(장부 24건 ↔ 묶음 11개)이
서로를 검사하지 못한다. 이 저장소의 지배적 결함 양식(`[[two-lists-never-check-each-other]]`)이
바로 그것이고, 처방은 **차집합 판별식**이다.

### ★키를 줄번호에서 제목으로 바꿨다 (2026-08-12 · PR #375)

초판은 `TODOS.md` **줄번호**를 키로 실었다. **그 키는 작성 시점부터 틀렸고, 그 뒤 더 벌어졌다.**

| 항목 | 초판이 적은 줄 | #365 머지 직후 실제 | #366 머지 후 실제 |
|---|---|---|---|
| OpenAPI required | `2023` | **2033** | **2098** |
| setupServer 59개 | `2285` | **2295** | **2360** |
| placeholder/aria-label | `3243` | **3429** | **3531** |

22건 중 **18건**이 어긋나 있었다. 원인은 둘이다.

1. **줄번호는 휘발성 키다.** 장부를 한 줄만 고쳐도 그 아래가 전부 밀린다 — PR #366 하나가
   110줄을 추가했다. 부채를 닫을 때마다 밀리므로 **매 PR 마다 깨지는 구조**다.
2. **대조가 자동화돼 있지 않았다.** 아래 스니펫이 문서 안에만 있었고 판별식이 아니었다.
   그래서 아무도 안 돌렸다 — 돌렸으면 즉시 걸렸다. **「가드는 있는데 배선이 없다」 양식.**

⇒ 키를 **항목 제목**으로 바꾸고, 대조를 `scripts/workflow/debt-ledger-mapping.test.ts` 로
승격했다. 제목도 바뀔 수 있지만 **바뀌면 판별식이 즉시 red** 다.
완벽한 키가 목표가 아니라 **조용히 깨지지 않는 것**이 목표다.

**대조 방법 (이제 CI 가 돌린다).**

```bash
node --experimental-strip-types --test scripts/workflow/debt-ledger-mapping.test.ts
```

키 정규화는 **제목 끝의 괄호 그룹 하나만** 떼는 것이다. 상태 표기(`미착수`·`착수`·`선재`·
`신규`)는 진행에 따라 바뀌지만 제목 본문은 안 바뀐다. ★「괄호 앞까지 자르기」는 안 된다 —
`apps/web(테스트 인프라) — …` 는 괄호가 **맨 앞**, `로딩 프레임 계약 — 임포트 페이지는
고정됨(2026-08-10), …` 은 **중간**에 있다.

## 묶음 기준 — 「종류」가 아니라 「충돌면」

`apps/web` 12개 파일을 두 PR 이 동시에 건드려 머지 충돌과 반쪽 봉합을 만든다.

## 판별식 뮤테이션 실측 (2026-08-12 · PR #375)

`scripts/workflow/debt-ledger-mapping.test.ts` 가 실제로 배선됐는지 5가지로 흔들었다.
기준선 pass 5 / fail 0.

| 뮤테이션 | 결과 | 잡은 케이스 |
|---|---|---|
| M1. 마스터 계획에서 한 행 삭제 (담당 PR 없는 부채) | **fail 1** | 장부→마스터 차집합 |
| M2. 항목 제목을 한 글자 변경 (키 drift) | **fail 2** | 양방향 차집합 둘 다 |
| M3. 장부의 한 항목을 ✅ 로 변경 (마스터가 못 따라감) | **fail 1** | 마스터→장부 차집합 |
| M4. 표의 상태 열을 통째 제거 (파서 무력화) | **fail 2** | **비-공허 짝** + 장부→마스터 |
| M5. 마스터 계획에 중복 행 추가 | **fail 1** | 중복 검사 |

**★M4 가 비-공허 짝의 값을 보여 준다.** 파서가 0건을 훑으면 차집합이 「빈 집합 == 빈 집합」으로
**공허 통과**한다. 실제로 판별식 최초 실행(RED)에서 마스터 계획이 옛 형식이었을 때
「마스터→장부 차집합 0」이 **통과**했고, 비-공허 짝이 그것을 잡았다.

**측정 자체가 두 번 틀렸다 (기록).** M4·M5 의 1차 시도는 `perl -CSD` 로 돌려 **뮤테이션이
적용조차 안 됐는데** 그대로 넘어갈 뻔했다. 원인은 `-CSD` 가 파일을 UTF-8 문자로 디코드하는데
스크립트 소스의 `⬜` 리터럴은 `use utf8` 없이 **바이트**로 남아 서로 안 맞은 것이다.
`[⬜✅]` 문자 클래스도 바이트 모드에서 쪼개져 깨진다 — `(?:⬜|✅)` 를 쓸 것.
**그래서 모든 뮤테이션 뒤에 `git diff --quiet` 로 「적용됐는가」를 먼저 확인한다.**
확인이 없으면 「생존」과 「미적용」이 구분되지 않는다.
