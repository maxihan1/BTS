## 도메인 정리

- **BC**: issue-tracking (물리 모듈) / 논리 BC 라벨 notification-dashboard 유지 (fr-index, 카운트 불변)
- **영향 엔티티/테이블 (활용, 신규 0)**: `issues`(created_at·deleted_at·current_state_key·type_id) +
  `issue_change_group`/`issue_change_item`(V018, field='status' 전이) + `WorkflowStateCatalog`(상태→카테고리 SPI)
- **새 용어**: **CFD** (Cumulative Flow Diagram, 누적 흐름 다이어그램), **CfdPoint** (VO, read-model)
- **Maxi 확정 결정 2건**:
  - D1. 누적 띠 = **카테고리 3띠** (TODO/IN_PROGRESS/DONE), 워크플로우 상태별 N띠 아님
  - D2. 시계열 = **on-the-fly 역산** (issue_change 이력), 스냅샷 테이블/스케줄러 0. V018 이전 이슈 한계 수용
- **설계 (선례 계승)**:
  - D3. 모듈 = issue-tracking (데이터 로컬, cross-BC 포트 불필요 — 번다운과 달리 스프린트 미참조)
  - D4. 보안 = 이슈별 가시성 필터 `filterVisibleIssueKeys`(buildActiveSecureWhere 재사용, 복제 금지) — 번다운 D6·벨로시티 동형
  - D5. 창 = from/to UTC 날짜 + 일 단위(utcDateField) + 상한, 잘못된 범위 422
- **상태 타임라인 역산 알고리즘**: 초기상태(첫 status 전이 from_value, 없으면 current_state_key) →
  전이들 created_at 오름차순 적용. day D 상태 = created_at::date ≤ D 마지막 전이 to_value(없으면 초기상태) → 카테고리 → 띠 +1.
  존재 판정 = created_at::date ≤ D AND (deleted_at NULL OR deleted_at::date > D).
- **기존 결정 충돌**: 없음
- **관련 ADR**: [docs/decisions/2026-07-03-fr-rp-03-cfd.md](../decisions/2026-07-03-fr-rp-03-cfd.md) (생성됨)

  - `SprintVelocityLookupAdapter.kt` — 가시성 필터 + IsolatedWorkflowStateLookup(REQUIRES_NEW) + 타입별 category 캐시 + WorkflowSchemeNoDefaultException 폴백 (전부 재사용)
  - `SprintBurndownQueryRepository.kt` — utcDateField(UTC 날짜 결정성) 패턴
