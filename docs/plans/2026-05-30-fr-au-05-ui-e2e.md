### 확정된 백엔드 계약 (PR #44 머지됨 — grep으로 실재 검증 필수)

- `POST /api/v1/users/me/password`, body `{ currentPassword, newPassword }`
- 성공 → 200 `{ changed: true }`
- 실패 → 400 `{ code: ... }`. 코드 3종(대소문자 정확히 확인 — frontend-zod-backend-dto-contract-gap, PR #41 errorCode 대소문자 BLOCKER 선례):

  - CURRENT_PASSWORD_MISMATCH — 현재 비밀번호 틀림
  - SAME_AS_CURRENT — 새 비밀번호가 기존과 동일
- 변경 성공 시 현재 세션 제외 다른 세션 무효화(백엔드 처리, 프론트는 성공 UX만)

### 백엔드 계약 ground-truth (grep 검증, PasswordController.kt / ChangePasswordRequest.kt / PasswordPolicy.kt)

- **요청**: `POST /api/v1/users/me/password`, body `{ currentPassword: string(NotBlank), newPassword: string(NotBlank) }`
- **성공**: `200` `{ "changed": true }`
- **실패(커스텀 400)**: `{ "code": "<UPPER_SNAKE>", "message": "<한글>", "violations"?: string[] }`
  - `POLICY_VIOLATION` — `violations` 배열 동반. 값은 `MIN_LENGTH` | `COMPLEXITY` 2종뿐 (PasswordPolicy.kt). MIN_LENGTH=12자, MIN_CHARACTER_CLASSES=3(대문자·소문자·숫자·특수 중 3종).
  - `CURRENT_PASSWORD_MISMATCH` — violations 없음. "현재 비밀번호가 일치하지 않습니다."
  - `SAME_AS_CURRENT` — violations 없음. "새 비밀번호가 현재 비밀번호와 같습니다."
- **빈 값(@NotBlank 실패)**: Spring 기본 검증 400 (커스텀 code 없음, 별도 shape) — 프론트가 클라이언트단 required로 사전 차단하면 도달 안 함.
- **미인증**: `401`(필터 체인) / CSRF 없음 시 `403`.
- ⚠️ **에러코드 대소문자**: 정본은 **대문자 스네이크**(enum.name). 프론트 비교/Zod도 대문자 (frontend-zod-backend-dto-contract-gap, PR #41 BLOCKER 선례).

### 프론트 배치 (기존 구조 grep)

- TanStack Router code-based. `routes/` 에 `settings.sessions.tsx`(세션 관리) 존재 → 비밀번호 변경 폼은 `settings.password` 라우트로 형제 배치가 자연스러움 (spec에서 확정).
- `components/auth/`, `auth/`(인증 상태), `hooks/`, `api/`, `mocks/`, `i18n/` 기존 인프라 재사용.

**RED** (`api/password.test.ts`):

- `sessions.ts`의 `readXsrfToken`을 `export`로 변경 후 재사용(중복 구현 금지, 신규 추상화 최소). sessions 동작/테스트 불변.

**REFACTOR**: 에러코드 enum 상수(`PasswordChangeErrorCode`) + 성공 스키마 KDoc.
