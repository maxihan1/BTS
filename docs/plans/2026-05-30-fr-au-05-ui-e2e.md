## Brief

사용자 원문: "fr-au-05 비밀번호 변경 프론트 폼 ui + e2e 진행해줘"

FR-AU-05(외부 협력사용 로컬 계정)의 PR-2. 백엔드 비밀번호 변경 API는 PR #44에서 머지 완료. 이번 PR은 그 프론트 폼 UI(D6) + Playwright E2E(D7).

### 확정된 백엔드 계약 (PR #44 머지됨 — grep으로 실재 검증 필수)

- `POST /api/v1/users/me/password`, body `{ currentPassword, newPassword }`
- 성공 → 200 `{ changed: true }`
- 실패 → 400 `{ code: ... }`. 코드 3종(대소문자 정확히 확인 — frontend-zod-backend-dto-contract-gap, PR #41 errorCode 대소문자 BLOCKER 선례):
  - POLICY_VIOLATION — 비밀번호 정책 위반 (최소 12자 + 영문 대소문자·숫자·특수 중 3종, SDD 19장)
  - CURRENT_PASSWORD_MISMATCH — 현재 비밀번호 틀림
  - SAME_AS_CURRENT — 새 비밀번호가 기존과 동일
- 변경 성공 시 현재 세션 제외 다른 세션 무효화(백엔드 처리, 프론트는 성공 UX만)

### 회귀 방지 메모 (이번 작업 직결)

- frontend-zod-backend-dto-contract-gap — Zod 스키마를 backend DTO와 분리 발명 금지. 백엔드 실제 응답/에러코드 대소문자 grep 검증.
- msw-mutation-stateful-refetch — POST mock은 결과를 stateful 영속.
- vitest-usertype-long-string-timeout — 비번 12자+ 타이핑 timeout 함정(delay:null + testTimeout).
- e2e-msw-serviceworker-block — serviceWorkers:'block' 금지, MSW 핸들러로.
- playwright-getbyrole-exact-strict-mode — 동일 텍스트 버튼 strict mode 주의.
- e2e-orphan-vite-after-worktree-remove — 머지 후 5173 orphan kill.
