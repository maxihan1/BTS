## Brief

FR-UX-02 즐겨찾기/Star D6/D7 프론트엔드. 백엔드 D1~D5는 PR #184에서 완료 (notification 모듈 favorite 패키지).

**소비할 백엔드 API** (계약).
- `POST /api/v1/favorites` — body `{ targetType, targetId }` → 멱등 (신규 201, 기존 200, created 플래그)
- `DELETE /api/v1/favorites?targetType=&targetId=` → 204 (대상 기준 멱등)
- `GET /api/v1/favorites?targetType=` → 본인 목록 (created_at DESC)
- `FavoriteTargetType` 4종 — ISSUE / FILTER / DASHBOARD / PROJECT (단, FILTER는 백엔드 정의만 — FR-SR-03 미구현이라 실대상 없음)
- 에러코드 접두사 `NOTIF_FAV_`

분류 정정. classifier가 "E2E" 키워드로 type=qa 오판 → Maxi 확인 후 type=ui/frontend-engineer로 정정 (D6/D7 선례 #181·#183 일치).

## 도메인 정리

- **BC**: notification-dashboard (논리), 물리 모듈 notification (`com.bts.notification.favorite`). 프론트는 `apps/web` view 레이어만.
- **영향 엔티티**: Favorite (신규 도메인 아님 — 백엔드 #184에서 확정). 프론트는 신규 도메인 개념 0.
- **유비쿼터스 언어**: 즐겨찾기(Favorite) — glossary.md L31에 이미 등재. Star = 즐겨찾기 등록/해제 토글 UI. 신규 용어 없음.
- **소비 API 계약** (백엔드 #184):
  - `POST /api/v1/favorites` body `{targetType, targetId}` → 멱등 (신규 201, 기존 200, `created` 플래그)
  - `DELETE /api/v1/favorites?targetType=&targetId=` → 204 (대상 기준 멱등)
  - `GET /api/v1/favorites?targetType=` → 본인 목록 created_at DESC
  - 에러코드 접두사 `NOTIF_FAV_`
- **ADR 함의** (docs/decisions/2026-06-24-fr-ux-02-favorites.md):
  - D3 — 대상 4종 중 **FILTER는 실사용 불가**(FR-SR-03 미구현). 프론트 Star 실대상 = **ISSUE / DASHBOARD / PROJECT 3종**. (어느 화면에 Star를 노출할지는 spec에서 확정)
  - D6 — **끊어진 참조(삭제/접근 불가 대상) graceful 렌더링이 프론트 책임**. 사이드바에서 깨진 즐겨찾기 graceful 처리 필요.
  - D5 — 해제=하드 삭제. 프론트는 toggle 후 목록 invalidate.
- **기존 결정 충돌**: 없음. FR-DB-01(대시보드)·FR-WT-01(워처) 프론트 패턴 계승 후보.
- **관련 ADR**: [docs/decisions/2026-06-24-fr-ux-02-favorites.md](../decisions/2026-06-24-fr-ux-02-favorites.md) (백엔드 작업에서 생성, 프론트 추가 ADR 불필요)
