## 도메인 정리

- **모듈**: agile-planning (엔드포인트 `GET /api/v1/sprints/{id}/burndown`, SprintController 이웃). fr-index 논리 BC 라벨(notification-dashboard)은 유지 — 물리 모듈 ≠ 논리 BC. FR 카운트 변동 없음(FR-TT 선례).
- **영향 엔티티/데이터**: Sprint·sprint_issues(agile-planning, 로컬) + issues.original_estimate_seconds·worklogs(issue-tracking, cross-BC 포트로 읽기 전용).
- **새 용어(read-model VO)**: BurndownPoint {date, remainingSeconds, idealSeconds}, BurnupPoint {date, completedSeconds, scopeSeconds}. 애그리거트/테이블 없음.
- **Y축 지표(Maxi 확정)**: 잔여 추정 시간(초). 스토리 포인트 미구현이라 대체. 총 스코프 = Σ original_estimate_seconds, 잔여(D) = 스코프 − Σ time_spent(started_at ≤ D).
- **데이터 소스(Maxi 확정)**: On-the-fly in-memory 계산. sprint_burndown_snapshot 테이블 + 스케줄러 미채택. 신규 스키마 0, 과거 스프린트 소급 가능.
- **cross-BC 포트**: shared-kernel에 SprintWorklog 조회 포트 신설(issue-tracking 어댑터 구현, agile-planning 소비). TimelineLookupPort 선례.
- **기존 결정 충돌**: SDD §13.5.1(스토리포인트)·§13.6(스냅샷)·§6.5와 deviation → 같은 PR에서 SDD 갱신 필수(ADR §SDD 동기화 대상).
- **관련 ADR**: [docs/decisions/2026-07-02-fr-rp-01-burndown-burnup.md](../decisions/2026-07-02-fr-rp-01-burndown-burnup.md)

## 스펙

전체 스펙. [docs/specs/2026-07-02-fr-rp-01.md](../specs/2026-07-02-fr-rp-01.md)

핵심 시나리오 3줄 요약.
- `GET /api/v1/sprints/{id}/burndown` — 번다운(Actual/Ideal) + 번업(Completed/Scope) 시계열을 단일 응답으로. 지표=추정시간(초).
- On-the-fly: 스코프=Σ original_estimate, day D 잔여=max(0, 스코프 − Σ worklog(started_at UTC ≤ D)). Ideal은 선형, Scope는 평탄.
- 권한=프로젝트 BROWSE(SprintController.get 미러). cross-BC 포트로 estimate/worklog 조회. 신규 스키마 0.

범위. 백엔드 D1~D5(도메인·계산·API·테스트·포트). 프론트 recharts(D6)+E2E(D7)는 후속 PR — FR-TL-01 선례. **게이트1에서 Maxi 확인.**
