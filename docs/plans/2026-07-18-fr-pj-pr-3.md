**Goal:** issue-tracking 에 프로젝트 목록/단건 조회(권한 필터링)와 설정(`name`) 변경 REST API를 추가한다.

**Architecture:** PR-2(FR-PJ-01) 가 세운 `com.bts.issue.project.*` 패턴을 따른다. 조회는 `Project`(3필드) 를 넘어서는 read 모델(`ProjectView`) + 신규 `ProjectQueryRepository`(jOOQ). 목록 접근필터는 shared-kernel `ProjectMembershipPort.projectKeysOf` **소비**(포트 수정 금지). 단건은 `IssuePermissionResolver.hasPermission(BROWSE, Project)`. 설정변경은 명시 호출 게이트 + 단일 컬럼 UPDATE(도메인 미경유, 리드/require_2fa 선례).

**Tech Stack:** Kotlin/Spring, jOOQ, Testcontainers(tembo pg16-pgmq), MockK, `:modules:app` 9-BC 조립 부팅.

실측으로 확정된 사실(조사 2건):
- `Project` 도메인 = `data class Project(id, key, name)` 3필드뿐(`project/domain/Project.kt:20-24`). 목록/조회에 `key_sequence·created_at` 등 노출하려면 **별도 read 모델** 필요(`ProjectResponse`·`ProjectView` 선례 0건).
- `projects` 컬럼 = `id, key, name, key_sequence, created_at, updated_at, deleted_at, lead_user_id, require_2fa`. **`archived_at` 없음**(마이그레이션 grep 0건) → **D1**.
- `ProjectLookup.resolve(projectIdOrKey): UUID?`(`project/ProjectLookup.kt:33-42`) = **다형 조회 정본**(UUID 파싱 분기→활성만). 재사용.
- 목록 접근필터 포트 `ProjectMembershipPort.projectKeysOf(userId): Set<String>`(shared-kernel, 어댑터 `ProjectMembershipAdapter.kt:54`, 술어 `:67-73`) — **소비만**, 수정 금지(실소비자 search-export-import `SavedFilterService`).
- 단건 BROWSE = `IssuePermissionResolver.hasPermission(actorId, IssuePermission.BROWSE, IssueScope.Project(key))`(shared-kernel 창구, 호출 선례 `SprintBurndownService.kt:111`·`BoardController.kt:159`). prod 어댑터가 멤버 게이트+매트릭스 판정, 관리자 우회 없음.
- **★치명적 함정** — `ProjectLeadExceptionHandler` 가 `@RestControllerAdvice(basePackages = ["com.bts.issue.project.web"])`(패키지 전역) + `Exception::class`→500 catch-all(`ProjectLeadExceptionHandler.kt:53,152-162`). **이 패키지에 새 컨트롤러를 두면 401/403/404 가 500 으로 변질**. PR-2 가 피한 방법 = `assignableTypes = [해당컨트롤러]` + `@Order(HIGHEST_PRECEDENCE)` + `ResponseStatusException` 재전파(`ProjectCreateExceptionHandler.kt:64-65,79-85`). **신규 컨트롤러도 동일 패턴 필수**.
- 응답 래퍼 `DataResponse<T>` → `{ "data": ... }`. 목록 = `DataResponse<List<X>>`(선례 `ComponentController.list:118-129`, name 정렬, 페이지네이션 없음).
- `CurrentActor.current(): ActorId`(`adapter/inbound/rest/CurrentActor.kt:39-50`) — 미인증/nil/형식오류 전부 `ResponseStatusException(401)`. **리소스 조회보다 먼저 호출**([[auth-extraction-before-resource-lookup]]).

### D1 — `archived_at` 컬럼 시점 (스펙 내부 순서 의존 모순)

PJ2-2(아카이브 기본 제외·`?archived=true`)·PJ3-2(아카이브 프로젝트 설정변경 409)가 `archived_at` 컬럼을 요구하나 **컬럼이 없다**. 스펙 §9.2 표는 PR-3 "마이그레이션 없음", `archived_at` 은 PR-4(issue V037) 예정.

| 안 | 내용 | trade-off | 전수동기화 |
|---|---|---|---|
| **(a) 추천** | 아카이브 필터/409/`?archived` 를 **PR-4로 이관**. PR-3 = 권한필터 목록 + 단건 + PATCH name | 마이그레이션 0 유지·PR-3 응집도↑(아카이브는 컬럼+쓰기+필터를 PR-4 한 묶음). PJ2-2·PJ3-2 를 PR-4 로 미루는 **deviation** | 스펙 §2.3 PJ2-2 · §2.4 PJ3-2 에 "PR-4 이관" 주석. fr-index 무변(FR-PJ-02/03 정의 자체는 유지) |
| (b) | `archived_at` 컬럼 마이그레이션만 PR-3 에 당김(NULL default·`POST archive` 쓰기는 PR-4). 필터·409 성립 | 스펙 "마이그레이션 없음"→"V037 있음"(PR-4 는 V038 로 밀림). 값이 전부 NULL 이라 필터는 무해하나, 컬럼 소유가 PR-4 도메인과 분리됨 | 스펙 §9.2 표 PR-3 "V037" · PR-4 "V038" 로 정정. `init_codegen.sql` 미러 영향 확인 |

**추천 (a)** — `archived_at` 에 **완전 의존**하는 PJ2-2/PJ3-2 를 컬럼 소유 PR(PR-4)과 묶는 게 응집도가 높고, 스펙 §9.2 의 "PR-3 마이그레이션 없음" 의도와 일치. PR-3 은 "권한 필터 목록 + 조회 + name 변경"으로 완결적. **아래 Plan 은 (a) 기준**이며, (b) 채택 시 추가 task(부록 §옵션(b) 전용)를 덧붙인다.

### D2 — PROJECT_ADMIN 판정 방법 (PATCH 설정변경 권한)

`IssuePermission` enum 에 관리자급 권한 없음(BROWSE/VIEW/CREATE/UPDATE/TRANSITION/SOFT_DELETE/SET_SECURITY/HARD_DELETE). 스펙 PJ3-1 은 "권한 = PROJECT_ADMIN, 명시 호출 게이트".

| 안 | 내용 | trade-off |
|---|---|---|
| (i) | **기존 프로젝트-설정 판정 재사용** — 리드변경은 `ComponentPermissionResolver.hasPermission(actorId, ComponentPermission.UPDATE, projectId)`(`ProjectLeadApplicationService.kt:136`). require_2fa 판정 방식도 실측 후 일관 선택 | BC 1개 유지·선례 일관. 단 "PROJECT_ADMIN" 과 `ComponentPermission.UPDATE` 의 의미 정합성 검토 필요 |
| (ii) | **새 `ProjectAdminPermissionResolver` 포트 신설**(shared-kernel + identity-access 어댑터가 `project_memberships` role=PROJECT_ADMIN 직접 확인, `SlackChannelMappingPermissionResolver` 선례) | 스펙 "PROJECT_ADMIN" 정확 부합. **cross-BC 확장 → BC 2개**(PR-3 이 issue-tracking 단일 전제를 깸) |

**확정 위치 = /bts-review-plan(plan-eng-review)** — `ProjectRequire2faController`/`ProjectLeadApplicationService` 의 실제 판정을 실측 대조 후 선택. 아래 T5 는 판정 호출을 `assertProjectAdmin(actorId, projectId)` **헬퍼 1점**으로 격리해, D2 결정이 그 헬퍼 본문만 바꾸도록 설계(task 골격 불변).
