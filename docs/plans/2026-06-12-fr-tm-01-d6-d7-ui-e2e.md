## 도메인 정리

- **BC**: issue-tracking (단일). 프론트는 기존 백엔드 API 소비 — 새 도메인 개념 없음.
- **확립된 도메인** (PR #125 + ADR `2026-06-12-issue-template-model-and-application`):
  - IssueTemplate — (project_id, issue_type_id) 조합당 1개, 활성 UNIQUE. 필드 `name` + `content`(Markdown).
  - 권한 `MANAGE_TEMPLATES` — CUD 게이트, READ/resolve 미게이트(프로젝트 조회 권한으로 충족).
  - 적용 방식 **옵션 C** — 프론트 프리필(타입 선택 시 resolve 조회 → 생성폼 description 프리필) + 서버 안전망.
- **기존 결정 충돌**: 없음. 이번 PR은 ADR 「적용 범위」의 "프론트 D6 + E2E D7 후속" 그대로 이행.
- **계약 정합 주의 (spec에서 grep 검증 필수)**: ADR 본문은 `body`로 표기됐으나 **실제 머지 DTO는 `name`+`content`**.
  프론트 Zod/API는 머지된 DTO에 맞출 것 — `CreateIssueTemplateRequest`(issueTypeId:Long, name:String, content:String),
  `UpdateIssueTemplateRequest`(name?/content?), `IssueTemplateResponse`. (메모리 frontend-zod-backend-dto-contract-gap)
- **D6 연기분 포함**: `MyProjectPermissionController.manageTemplates` 노출(백엔드 plan B2 연기) — 버튼 게이팅 전제.
- **glossary**: "이슈 템플릿/IssueTemplate"은 backend plan에서 등재 후보였으나 미등재(glossary는 Maxi 수동 영역).
  머지 시 Maxi 확인 후 추가 제안.
- **관련 ADR**: docs/adr/2026-06-12-issue-template-model-and-application.md (기존, 신규 ADR 불요)
