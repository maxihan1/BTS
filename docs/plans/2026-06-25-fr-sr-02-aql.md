## Brief

FR-SR-02 — AQL(Atlas Query Language) 텍스트 쿼리, JQL 99% 호환. 이번 PR은 **백엔드 코어 MVP**.

**Maxi 확정 결정 (게이트 전 사전 합의)**.
1. 파서 방식 — **손수 작성 재귀하강 파서 (zero-dep)**. ANTLR 4 미도입. SDD 10.1 "ANTLR 4로 구현" deviation → ADR 기록 필요.
2. PR 범위 — **백엔드 코어 MVP (D1~D5 일부)**. 핵심 키워드(`=`, `!=`, `IN`, `not in`, `~`, `AND`, `OR`, `NOT`, `ORDER BY`) + AST→jOOQ Condition 변환 + `POST /api/v1/search/aql` + visibility 보안 술어 AND 자동 결합 + 단위 50+. **후속 PR**. 함수(currentUser/now/상대날짜), is EMPTY/NOT EMPTY, pg_trgm, 프론트(D6/D7).
3. 모듈 위치 — **search-export-import 모듈 신설 (7번째 BC)**. cross-BC 이슈 조회 포트 필요.

## 도메인 정리 (← /bts-domain 채움)

- **BC**: search-export-import (신설, 7번째 BC) — AQL 언어 책임. issue-tracking — AQL→jOOQ 변환·실행 책임(BC 격리상 강제).
- **영향 엔티티/타입**:
  - 신규 — `AqlQuery`/`AqlNode`(AST: And/Or/Not/Comparison + Field/Operator/Value), AqlLexer/AqlParser(재귀하강), `IssueSearchPort`(shared-kernel 계약, 모양은 spec서 확정 — AST-as-contract 유력), IssueSearchAdapter(issue-tracking 구현).
  - 재사용 — `IssueRepository.buildSecurityCondition` + `IssueSecurityDirectory.accessibleLevels`(shared-kernel, visibility 보안 술어). jOOQ `Tables.ISSUES` 등(issue-tracking 내부 한정).
- **새 용어**: AQL/FTS는 glossary 기존 등재. 신규 후보 — "재귀하강 파서", "IssueSearchPort"(glossary 수동 영역 → Maxi 승인 후 반영 제안, 필수 아님).
- **기존 결정 관계**:

핵심 요약.
- `POST /api/v1/search/aql` `{projectKey, query, page, size}` → `Page<AqlSearchHit>`. 단일 프로젝트 스코프 필수.
- 문법(MVP) — `=`,`!=`,`~`,`IN`,`NOT IN`, `AND`/`OR`/`NOT`+괄호 중첩, `ORDER BY`. 키워드 대소문자 무시. 손수 재귀하강 파서.
- 지원 필드(MVP) — status, label, summary, priority. (assignee/reporter/component/project·함수·상대날짜·is EMPTY·pg_trgm은 후속.)
- AST→jOOQ는 issue-tracking 어댑터(IssueSearchPort 구현)가 수행 + visibility 보안 술어 항상 AND 결합(우회 불가). 데이터 모델 변경 없음.
