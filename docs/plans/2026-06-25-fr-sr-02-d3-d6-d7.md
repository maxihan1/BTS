## Brief

FR-SR-02(AQL 텍스트 쿼리, JQL 호환)의 백엔드 코어 MVP는 PR #189로 완료. 본 작업은 남은 D단계 마무리.

- **D3** — `pg_trgm` 확장 + GIN 인덱스 (issues.summary 등). AQL `~` 연산자(ILIKE `%term%`) 가속 (db-engineer)
- **D6** — AQL 입력창 + syntax highlight 프론트 UI (frontend-engineer)
- **D7** — E2E (qa-engineer)

classify 결과(type=qa)는 D7 "E2E" 키워드 오판 — 실제는 migration+ui+qa 복합. plan에서 task별 agent 지정.

백엔드 계약(이미 머지됨). `POST /api/v1/search/aql`, 지원 필드 status/label/summary/priority, 연산자 `=`/`!=`/`~`/`IN`/`NOT IN`/`AND`/`OR`/`NOT`/괄호/`ORDER BY`. DoS 가드(깊이50/토큰1000/2000자). 입력 오류 400 매핑.

## 도메인 정리

- **BC**: search-export-import (검색 UI 논리 소속) + issue-tracking (D3 인덱스 물리 위치). SR-01/SR-02 백엔드와 동일한 "논리≠물리" 구조 ([[fr-sr-01-issue-filter-done]]). 프론트(D6/D7)는 apps/web — BC 중립.
- **새 용어**: 없음. AQL(Atlas Query Language)은 glossary §검색/AQL에 이미 등재. trigram/pg_trgm·syntax highlight는 기술 용어(도메인 용어 아님) → glossary 추가 불필요.
- **새 엔티티**: 없음. 프론트는 기존 계약 소비. D3는 성능 인덱스(스키마 구조/도메인 로직 변경 없음).
- **기존 결정 충돌**: 없음. ADR `docs/decisions/2026-06-25-fr-sr-02-aql-parser-and-bc.md` 준수.

### 백엔드 계약 (PR #189 머지됨 — 프론트 정본)

- `POST /api/v1/search/aql`, body `{ projectKey: string, query: string, page?: int=0(min0), size?: int=50(1..100, 초과 시 400 거부=클램프 아님) }`. **인증 필수**(401 SEARCH_UNAUTHENTICATED), BROWSE 권한(403 SEARCH_ACCESS_DENIED).
- 응답: Spring `Page<AqlSearchHit>` raw(봉투 없음). `content[]` 항목: `key, summary, typeKey, currentStateKey, assigneeId(UUID|null), priority(int 1..5), priorityName, projectKey, updatedAt(ISO Instant)`. 메타: `totalElements, numberOfElements, first, last, empty, pageable{pageNumber,pageSize}`.
- 지원 필드: `status, label, summary, priority` (status/priority는 `~` 불가). 후속 예정 필드(assignee/reporter/component/project)는 400 `SEARCH_FIELD_NOT_YET_SUPPORTED`.
- 키워드(대소문자 무시): `AND OR NOT IN`, `ORDER BY`, `ASC DESC`. 연산자: `= != ~ IN "NOT IN"`. 리터럴: `"따옴표문자열"` · bare word · 정수.
- 에러: RFC 7807 ProblemDetail + `errorCode` + `detail` + `position`(0-base, 문법오류 시) + `timestamp`. 코드: `SEARCH_SYNTAX_ERROR`/`SEARCH_UNKNOWN_FIELD`/`SEARCH_FIELD_NOT_YET_SUPPORTED`/`SEARCH_VALIDATION_FAILED`(400), `SEARCH_UNAUTHENTICATED`(401), `SEARCH_ACCESS_DENIED`(403), `SEARCH_INTERNAL_ERROR`(500).
- DoS 가드: query 2000자 / 토큰 1000 / 중첩 깊이 50 초과 시 400.

### D3 인덱스 단서

- `~`(CONTAINS): `summary` → `summary ILIKE '%term%' ESCAPE '\'` (IssueRepository.kt:2292). `label` → `EXISTS(unnest(labels) ILIKE ...)` (IssueRepository.kt:2337).
- `summary` VARCHAR(255) → `pg_trgm` GIN 인덱스(`gin(summary gin_trgm_ops)`)로 ILIKE `%term%` 가속 가능.
- **결정 필요**: label `~`는 unnest 후 ILIKE라 trigram 인덱스 직접 적용 까다로움 → D3 범위에서 summary만 가속 vs label도 포함 결정(spec). 다음 마이그레이션 V번호 = issue-tracking **V031**(머지 직전 재확인 — [[migration-vnumber-concurrent-branch-collision]]).

### 결정 포인트 (→ spec 이월)

1. **syntax highlight 구현 방식**: 신규 라이브러리(CodeMirror/Monaco/Prism) vs 경량 자체 토크나이저. **신규 의존성은 Maxi 승인 필요**(DEVELOPMENT.md §외부 의존성). 새 라이브러리 채택 시 ADR 후보.
2. **D3 인덱스 대상 범위**: summary만 vs label 포함. pg_trgm 확장 설치(SDD §1.1에 이미 계획됨)는 인프라 영향 — 마이그레이션에 `CREATE EXTENSION IF NOT EXISTS pg_trgm` 포함.

- 관련 ADR: `docs/decisions/2026-06-25-fr-sr-02-aql-parser-and-bc.md` (기존, 준수). 신규 ADR은 syntax highlight 라이브러리 채택 시에만.
