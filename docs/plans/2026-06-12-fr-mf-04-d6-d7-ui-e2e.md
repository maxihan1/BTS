## Brief

FR-MF-04(MFA 강제 정책 — 관리자 + 민감 프로젝트)의 **D6 프론트 UI + D7 E2E** 후속 작업.
백엔드 D1~D5는 PR #123(`2002866b`)으로 완료.

- 백엔드 계약(이미 머지됨).
  - `GET /api/v1/users/me/whoami` 응답에 `mfaEnrollmentRequired: Boolean` 필드 노출
    (`WhoamiResponse.kt:30`, JWT 클레임 `mfa_enrollment_required`를 읽기만 — 단일 출처).
  - `MfaEnrollmentGateFilter` — 미등록 강제대상의 요청을 ALLOW_LIST 외 모든 경로에서 **403**
    `{"error":"mfa_enrollment_required"}`로 차단. ALLOW_LIST = `/api/v1/auth/mfa/**` ·
    `/api/v1/users/me/whoami` · `/api/v1/auth/logout` · `/api/v1/auth/refresh`.
- 프론트 목표(D6). whoami `mfaEnrollmentRequired === true`이면 MFA 등록(step-up) 화면으로 강제
  리다이렉트. `requirePasswordChanged`(routeGuard.ts:86, `mustChangePassword` 선례) 동형.
- E2E 목표(D7). 강제대상 미등록 → step-up 리다이렉트 / 등록 완료 후 해제 시나리오.

선례. FR-AU-05 `mustChangePassword`(routeGuard.requirePasswordChanged), FR-MF-01 #116 / FR-MF-02 #121
(MFA 프론트/E2E 분리 PR).
