## Brief

FR-MF-04(MFA 강제 정책 — 관리자 + 민감 프로젝트)의 **D6 프론트 UI + D7 E2E** 후속 작업.
백엔드 D1~D5는 PR #123(`2002866b`)으로 완료.

- 백엔드 계약(이미 머지됨).
  - `GET /api/v1/users/me/whoami` 응답에 `mfaEnrollmentRequired: Boolean` 필드 노출
    (`WhoamiResponse.kt:30`, JWT 클레임 `mfa_enrollment_required`를 읽기만 — 단일 출처).
  - `MfaEnrollmentGateFilter` — 미등록 강제대상의 요청을 ALLOW_LIST 외 모든 경로에서 **403**
    `{"error":"mfa_enrollment_required"}`로 차단. ALLOW_LIST = `/api/v1/auth/mfa/**` ·
    `/api/v1/users/me/whoami` · `/api/v1/auth/logout` · `/api/v1/auth/refresh`.
- 프론트 목표(D6). whoami `mfaEnrollmentRequired === true`이면 MFA 등록(step-up) 화면으로 강제
  리다이렉트. `requirePasswordChanged`(routeGuard.ts:86, `mustChangePassword` 선례) 동형.
- E2E 목표(D7). 강제대상 미등록 → step-up 리다이렉트 / 등록 완료 후 해제 시나리오.

선례. FR-AU-05 `mustChangePassword`(routeGuard.requirePasswordChanged), FR-MF-01 #116 / FR-MF-02 #121
(MFA 프론트/E2E 분리 PR).

## 도메인 정리

- **BC**. identity-access (프론트 게이팅은 apps/web, 백엔드 계약은 identity-access).
- **영향 엔티티**. 신규 0건. 기존 백엔드 계약(`whoami.mfaEnrollmentRequired`, `MfaEnrollmentGateFilter`)을 프론트가 소비할 뿐.
- **새 용어**. 0건. 기존 glossary "2FA" 재사용.
- **용어 정합 주의 (drift 차단)**. glossary "재인증 / step-up"(FR-AU-08)은 *민감 동작 직전 1회 재인증*(5분 윈도우)이다.
  product 문서가 D6를 "step-up 페이지"로 표기했으나 실제 개념은 *MFA 등록 자체를 강제하는 게이트*로 별개다.
  → 프론트 코드/스펙에서 이 개념을 **"MFA 등록 강제 게이트(MFA enrollment gate)"**로 명명하고
  "step-up"은 FR-AU-08 재인증 의미로 보존한다. (가드 함수명 후보: `requireMfaEnrolled`.)
- **기존 결정 충돌**. 없음. ADR `2026-06-12-mfa-enforcement-policy` D4가 "프론트 게이팅 UI + E2E는 D6/D7 후속"으로 명시.
- **관련 ADR**. [docs/decisions/2026-06-12-mfa-enforcement-policy.md](../decisions/2026-06-12-mfa-enforcement-policy.md) (기존, FR-MF-04 백엔드 시 생성). **신규 ADR 불요** — 프론트는 결정된 계약 소비.
- **선례 동형**. FR-AU-05 `mustChangePassword` → `requirePasswordChanged`(routeGuard.ts:86) 강제 리다이렉트 패턴.

## 스펙

전체 스펙. [docs/specs/2026-06-12-fr-mf-04-d6-d7-ui-e2e.md](../specs/2026-06-12-fr-mf-04-d6-d7-ui-e2e.md)

핵심 요구사항 요약.
- **FR-D6-1** whoami Zod에 `mfaEnrollmentRequired: z.boolean()` 추가 + 픽스처(makeWhoami/aliceUser/bobUser)·MSW·인라인 리터럴 전수 동기화.
- **FR-D6-2** `requireMfaEnrolled` 가드(routeGuard.ts, `requirePasswordChanged` 동형) → 강제대상 미등록을 `/settings/mfa`로 리다이렉트, 보호 라우트 체인 합성.
- **FR-D6-3** `/settings/mfa` 상단 강제 안내 배너(`mfaEnrollmentRequired===true`일 때만).
- **FR-D6-4 (정합성 필수)** enable 성공+강제모드 → 토큰 refresh + whoami 재조회 + setSession + /dashboard 이동(없으면 store stale로 영구 락).
- **D7** Playwright E2E 4종(강제 리다이렉트/게이트 고정/등록 후 해제/비강제 회귀) + 기존 회귀 0. 기존 `MFA_E2E_ENABLED_KEY` 토글 패턴 확장.

리다이렉트 대상 = 기존 `/settings/mfa` + 안내 배너 (Option A2, Maxi 확정 — 신규 라우트 0).
