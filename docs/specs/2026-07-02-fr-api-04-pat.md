# FR-API-04 — Personal Access Token 발급/관리 — 스펙

> slug: fr-api-04-pat · BC: identity-access · type: auth
> ADR: [2026-07-02-fr-api-04-pat-management](../decisions/2026-07-02-fr-api-04-pat-management.md)
> 선행 자산: FR-AU-09(#37) PAT 검증 인프라 완비 — 본 PR은 발급/관리/UI 신규.

## 1. 목표 · 사용자 시나리오

**목표.** 사용자가 CLI/스크립트에서 BTS API를 호출할 때 쓰는 개인 액세스 토큰(PAT)을 셀프서비스로 발급·조회·취소한다. PAT 검증(`PatAuthenticationFilter`)은 FR-AU-09에서 완성됐고, 본 PR은 그 앞단의 관리 계층(발급/목록/취소 + UI)을 완성한다.

**Given-When-Then.**
- Given 로그인 사용자가 `/settings/pats`에서, When 이름·scope·만료 기간을 선택해 발급하면, Then 서버가 `pat_` 접두 원본 토큰을 **응답에 1회만** 반환하고(이후 조회 불가), DB엔 SHA-256 해시만 저장한다.
- Given 발급된 PAT 목록에서, When 사용자가 특정 PAT를 취소하면, Then 즉시 `revoked_at`이 채워져 다음 API 호출부터 401.
- Given 만료 기간 미지정 또는 1년 초과로 발급 시도하면, Then 400(무기한/상한 위반 거부).

## 2. 기능 요구사항 (FR)

- **FR-1 발급.** `POST /api/v1/users/me/pats` — `name`(필수, 1..128), `scopes`(필수, 화이트리스트 검증), `expiresInDays`(필수, 1..365). raw `pat_<44자>` 토큰 1회 반환 + `id/name/scopes/expiresAt/createdAt`. token은 이후 어떤 응답에도 없음.
- **FR-2 목록.** `GET /api/v1/users/me/pats` — 본인 활성 PAT(취소되지 않은) 목록. `id/name/scopes/expiresAt/lastUsedAt/createdAt`. token/token_hash 미노출.
- **FR-3 취소.** `DELETE /api/v1/users/me/pats/{id}` — 본인 PAT revoke(멱등 204). 타 사용자 PAT는 404(IDOR 은닉). 이미 취소된 것도 204(멱등).
- **FR-4 scope 카탈로그.** 서버 상수로 지원 scope 정의. 발급 시 화이트리스트 검증(미지 scope 400). **실제 권한 강제는 본 PR 범위 밖**(hasScope 인프라 재사용, 후속). 제안 카탈로그(§7 확정): `read:issues`·`write:issues`·`read:projects`·`write:projects`·`*`(전체).
- **FR-5 TTL.** `expiresInDays` 필수(무기한 금지) + 1..365 상한. 위반 400. `expires_at = now + expiresInDays`.
- **FR-6 프론트 UI.** `/settings/pats`(requireAuth + requirePasswordChanged) — 발급 폼(name/scope 체크박스/만료 select) + 활성 목록 테이블(name/scope 배지/만료·마지막사용 시각/취소 버튼) + **발급 직후 토큰 1회 표시 모달**(복사 버튼, "다시 볼 수 없음" 경고, localStorage/sessionStorage 저장 금지 — 화면 상태만).

## 3. 비기능 요구사항 (NFR)

- **보안.** 토큰 원본은 발급 응답에만 존재(DEVELOPMENT §1.1 SHA-256 저장·§1.17 화면 1회·localStorage 금지). 목록/취소 응답에 token/hash 절대 미포함. PAT 관리 API는 **JWT 세션 전용** — PAT 자격증명으로 PAT 관리 호출 차단(ROLE_PAT는 403, session-management-pat-exclusion 선례).
- **CSRF.** POST/DELETE는 X-XSRF-TOKEN 필요(JWT 쿠키 세션). 발급/취소 mutation.
- **격리.** identity-access 단일 BC. 마이그레이션 0(V006 재사용). cross-BC 0.
- **감사(선택).** 발급/취소 시 기존 AuthEventType(PAT 관련 이벤트 존재 시) emit — FR-AU-10 인프라 재사용. 없으면 최소 로깅.

## 4. API 인터페이스 (REST)

```
POST /api/v1/users/me/pats
  req: { "name": "ci-deploy", "scopes": ["read:issues","write:issues"], "expiresInDays": 90 }
  res 201: { "id": "<uuid>", "name": "ci-deploy", "scopes": [...], "token": "pat_xxx…(1회)", "expiresAt": "<iso>", "createdAt": "<iso>" }
  err 400: name blank / scopes 빈배열 or 미지 scope / expiresInDays 누락·범위밖

GET /api/v1/users/me/pats
  res 200: [ { "id","name","scopes","expiresAt","lastUsedAt","createdAt" } ]   # token 없음

DELETE /api/v1/users/me/pats/{id}
  res 204: (멱등)
  err 404: 타 사용자 PAT / 미존재 (IDOR 은닉)
```

- 응답 시각은 Instant ISO-8601. nullable(`expiresAt` 항상 존재[FR-5], `lastUsedAt` nullable). `@JsonInclude(NON_NULL)` ↔ 프론트 Zod `.nullish()` 정합.

## 5. 데이터 모델

V006 `personal_access_tokens` **재사용, 마이그레이션 0**. 발급 시 `id/user_id/name/token_hash(SHA-256)/scopes(JSONB)/expires_at/created_at` INSERT, `revoked_at/last_used_at` NULL 시작. TTL은 애플리케이션 레벨 검증(스키마 `expires_at` nullable 유지 — 기존 무기한 PAT 데이터 호환).

## 6. 엣지 케이스

- **EC-1 무기한 거부.** `expiresInDays` 누락/null → 400(무기한 금지, ADR §3).
- **EC-2 상한 초과.** `expiresInDays > 365` 또는 `< 1` → 400.
- **EC-3 미지 scope.** 카탈로그 밖 scope → 400(전체 거부, 부분 무시 금지).
- **EC-4 빈 scope.** `scopes = []` → 400(최소 1개 필수. `*`로 전체 표현).
- **EC-5 발급 1회 노출.** token은 발급 201 응답에만. 목록/재조회 불가. 분실 시 재발급.
- **EC-6 취소 멱등.** 이미 취소·미존재(본인)여도 204. 타인 소유는 404.
- **EC-7 IDOR.** `DELETE {id}`가 타 사용자 PAT면 존재 여부 노출 없이 404.
- **EC-8 PAT로 PAT관리 차단.** ROLE_PAT 자격증명으로 `/users/me/pats` 호출 시 403(관리 API는 JWT 전용, session-management-pat-exclusion).
- **EC-9 name 중복 허용.** 같은 사용자가 동일 name PAT 다수 발급 가능(name은 라벨, 유니크 아님). token_hash만 UNIQUE.
- **EC-10 토큰 미저장.** 프론트가 발급 token을 localStorage/sessionStorage에 저장 금지(화면 상태만, 모달 닫으면 소멸).
- **EC-11 목록 정렬.** createdAt DESC(최신 발급 우선).
- **EC-12 만료된 PAT 표시.** 목록에 만료(expires_at < now)·활성 구분 표시(만료는 배지). 취소(revoked)는 목록에서 제외(활성만).

## 7. 제약 조건 / 확정 필요

- **scope 카탈로그 확정** — 제안: `read:issues`·`write:issues`·`read:projects`·`write:projects`·`*`. brainstorming/Maxi 확인 대상.
- 회전: 별도 API 없음(취소+재발급, ADR §2).
- scope 실제 권한 강제: 후속 트랙(ADR §1).
