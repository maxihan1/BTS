# FR-API-04 — Personal Access Token 발급/관리 — 스펙

> 선행 자산: FR-AU-09(#37) PAT 검증 인프라 완비 — 본 PR은 발급/관리/UI 신규.
> sanity check(2026-07-02) + Maxi 결정 4건 반영본.

## 1. 목표 · 사용자 시나리오

**목표.** 사용자가 CLI/스크립트에서 BTS API를 호출할 때 쓰는 개인 액세스 토큰(PAT)을 셀프서비스로 발급·조회·취소한다. PAT 검증(`PatAuthenticationFilter`)은 FR-AU-09에서 완성됐고, 본 PR은 그 앞단의 관리 계층(발급/목록/취소 + UI)을 완성한다.

**Given-When-Then.**
- Given 로그인 사용자가 `/settings/pats`에서, When 이름·scope·만료 기간을 선택해 발급하면, Then 서버가 `pat_` 접두 원본 토큰을 **응답에 1회만** 반환하고(이후 조회 불가), DB엔 SHA-256 해시만 저장한다.
- Given 발급된 PAT 목록에서, When 사용자가 특정 PAT를 취소하면, Then 즉시 `revoked_at`이 채워져 다음 API 호출부터 401(PAT는 verify 캐시 없음 — 즉시 반영).
- Given 만료 기간 미지정/1년 초과 또는 활성 PAT 20개 초과 발급 시도, Then 400.

## 2. 기능 요구사항 (FR)

- **FR-1 발급.** `POST /api/v1/users/me/pats` — `name`(필수, trim 후 1..128, blank 거부), `scopes`(필수, 최소 1개, 카탈로그 화이트리스트), `expiresInDays`(필수, 1..365). 서버가 **`SecureRandom`(CSPRNG) base62 48자** body 생성 → `pat_<48자>`(총 52자) 원본을 **응답에 1회만** 반환. DB엔 `SHA-256("pat_"+48body)` hex 64자만 저장(기존 `PersonalAccessToken` 도메인 상수 `TOKEN_BODY_LENGTH=48` 정합). 응답: `id/name/scopes/expiresAt/createdAt/token(1회)`.
- **FR-2 목록.** `GET /api/v1/users/me/pats` — 본인 PAT 중 **취소되지 않은(revoked_at IS NULL) 전부**(만료 포함 — EC-12 배지 표시). `id/name/scopes/expiresAt/lastUsedAt/createdAt`. token/token_hash 미노출. createdAt DESC. ※ 기존 `findActiveByUserId`(만료 제외)는 부적합 — **revoke만 제외하는 신규 repo 메서드** 필요.
- **FR-3 취소.** `DELETE /api/v1/users/me/pats/{id}` — **소유권 바인딩**(`revoke(id, userId)` 또는 `findByIdAndUserId` — 기존 `revoke(id)`는 user_id 미검사라 IDOR). 본인 PAT revoke(멱등 204, 이미 취소·활성 무관). 타 사용자/미존재는 404(IDOR 은닉).
- **FR-4 scope 카탈로그(확정).** 서버 상수 5종: `read:issues`·`write:issues`·`read:projects`·`write:projects`·`*`(전체). 발급 시 화이트리스트 검증(미지 scope → 전체 400, 부분 무시 금지). 대소문자 정확 일치 + 중복 제거 정규화. **실제 권한 강제는 본 PR 범위 밖**(hasScope 인프라 재사용, 후속).
- **FR-5 TTL.** `expiresInDays` 필수(무기한 금지) + 1..365. 위반 400. `expires_at = clock.now + expiresInDays`(Clock 주입).
- **FR-6 개수 상한.** 사용자당 **활성(미취소) PAT 20개** 상한. 발급 시 count 검사, 초과 400. 동시 발급 TOCTOU는 `pg_advisory_xact_lock(userId)` 또는 count 재검증으로 직렬화.
- **FR-7 감사.** 발급 시 `PAT_ISSUED`, 취소 시 `PAT_REVOKED` emit(신규 `AuthEventType` 2종 — 현재 22종→24종, `AuthEventEmitCoverageTest` 배선 강제 + enum 헤더 카운트 동기화). FR-AU-10 append-only 감사 인프라 재사용. metadata에 patId/name(token 원문·hash 미포함).
- **FR-8 프론트 UI.** `/settings/pats`(requireAuth + requirePasswordChanged) — 발급 폼(name/scope 체크박스/만료 select) + 활성 목록 테이블(name/scope 배지/만료·마지막사용/취소) + **발급 직후 토큰 1회 표시 모달**(복사 버튼·"다시 볼 수 없음" 경고·localStorage/sessionStorage 저장 금지). **scope 미강제 disclosure 경고**: 발급 화면에 "scope는 아직 강제되지 않으며 이 토큰은 계정 전체 권한을 가집니다" 명시.

## 3. 비기능 요구사항 (NFR)

- **보안.** 토큰 원본은 발급 응답에만 존재(DEVELOPMENT §1.1 SHA-256 저장·§1.17 화면 1회·localStorage 금지). raw token 로깅 금지(`toString()` hash 마스킹 기존 준수). 목록/취소 응답에 token/hash 절대 미포함. PAT 관리 API는 **JWT 세션 전용** — `@AuthenticationPrincipal Jwt?`가 null(=PAT 자격증명)이면 403(`session_management_requires_interactive_login`, `TrustedDeviceController` 선례). `jwt.subject`(UUID)로 userId 바인딩.
- **CSRF.** POST/DELETE는 X-XSRF-TOKEN 필요(JWT 쿠키 세션).
- **감사.** PAT_ISSUED/PAT_REVOKED append-only(FR-AU-10).
- **격리.** identity-access 단일 BC. 마이그레이션 0(V006 재사용). cross-BC 0.

## 4. API 인터페이스 (REST)

```
POST /api/v1/users/me/pats
  req: { "name": "ci-deploy", "scopes": ["read:issues","write:issues"], "expiresInDays": 90 }
  res 201: { "id","name","scopes","token":"pat_<48>(1회)","expiresAt","createdAt" }
  err 400: name blank / scopes 빈배열·미지 scope / expiresInDays 누락·1..365 밖 / 활성 20개 초과
  err 403: PAT 자격증명으로 호출(JWT 전용)

GET /api/v1/users/me/pats
  res 200: [ { "id","name","scopes","expiresAt","lastUsedAt","createdAt" } ]  # 미취소 전부(만료 포함), token 없음
  err 403: PAT 자격증명

DELETE /api/v1/users/me/pats/{id}
  res 204: (멱등, 소유권 바인딩)
  err 404: 타 사용자/미존재 (IDOR 은닉)
  err 403: PAT 자격증명
```

- 시각은 Instant ISO-8601. `@JsonInclude(NON_NULL)` ↔ 프론트 Zod `.nullish()`. `lastUsedAt` nullable + **레거시 무기한 PAT의 `expiresAt`도 nullable**(V006에 이미 있을 수 있는 `expires_at NULL` 행 — 프론트 required 파싱 금지, `.nullish()`).

## 5. 데이터 모델

V006 `personal_access_tokens` **재사용, 마이그레이션 0**. 발급 시 `id/user_id/name/token_hash(SHA-256)/scopes(JSONB)/expires_at/created_at` INSERT, `revoked_at/last_used_at` NULL 시작. TTL·개수 상한은 애플리케이션 레벨(스키마 `expires_at` nullable 유지 — 레거시 무기한 행 호환). 신규 repo 메서드 2종: 목록(revoke만 제외), 취소(소유권 바인딩).

## 6. 엣지 케이스

- **EC-1 무기한 거부.** `expiresInDays` 누락/null → 400.
- **EC-2 상한 초과.** `expiresInDays > 365` 또는 `< 1` → 400.
- **EC-3 미지 scope.** 카탈로그 밖 → 400(전체 거부).
- **EC-4 빈 scope.** `[]` → 400(최소 1개, `*`로 전체 표현).
- **EC-5 발급 1회 노출.** token은 발급 201 응답에만. 재조회 불가. 분실 시 재발급.
- **EC-6 취소 멱등.** 본인 PAT 이미 취소·미존재여도 204. 타인은 404.
- **EC-7 IDOR.** `revoke(id, userId)` 소유권 바인딩. 타 사용자 PAT는 404(존재 노출 없음).
- **EC-8 PAT로 PAT관리 차단.** ROLE_PAT/Jwt null → 403(관리 API JWT 전용).
- **EC-9 name 중복 허용.** 같은 name 다수 발급 가능(라벨, 유니크 아님). token_hash만 UNIQUE.
- **EC-10 토큰 미저장.** 프론트 localStorage/sessionStorage 금지(모달 닫으면 소멸).
- **EC-11 목록 정렬.** createdAt DESC.
- **EC-12 만료 PAT 표시.** 목록에 만료(expires_at < now)·활성 구분 배지. 취소(revoked)만 제외.
- **EC-13 개수 상한.** 활성 20개 초과 발급 400. 동시 발급 TOCTOU 직렬화(advisory lock/count 재검증).
- **EC-14 name trim.** 공백만("   ") → trim 후 blank → 400.
- **EC-15 scope 정규화.** 중복 제거, 대소문자 정확 일치(카탈로그와 exact match).
- **EC-16 감사 emit.** PAT_ISSUED/REVOKED 실패해도 발급/취소 자체는 성공(best-effort, web 레이어 try-catch — FR-AU-10 B-1 선례). token 원문·hash는 감사 metadata 미포함.
- **EC-17 발급 즉시 사용.** PAT는 verify 캐시 없음 → 발급 직후 즉시 API 유효(별도 처리 불요).

## 7. 제약 조건

- scope 카탈로그 5종 확정(§FR-4). 회전=별도 API 없음(취소+재발급, ADR §2). scope 실제 권한 강제=후속(ADR §1).
- 개수 상한 20(FR-6), TTL 1..365(FR-5), 감사 2종 추가(FR-7)는 Maxi 결정(2026-07-02).
