## 사용자 시나리오 (Given-When-Then)

- **S1 목록 조회**. Given 신뢰 디바이스 2건 보유, When `/settings/mfa` 진입, Then 신뢰 디바이스 섹션에 기기명·등록일·마지막 사용·만료일 2행 표시.
- **S2 단건 취소**. Given 목록 표시, When 한 기기의 "취소" → 인라인 확인 "확인", Then 204 후 목록에서 제거(refetch). 다른 기기 유지.
- **S3 전체 취소**. Given 목록 2건, When "모든 기기 신뢰 해제" → 확인, Then 204 후 빈 상태 안내.
- **S4 빈 상태**. Given 신뢰 디바이스 0건, When 섹션 렌더, Then "신뢰한 기기가 없습니다" 안내(취소 버튼 없음).
- **S5 로그인 시 신뢰 등록**. Given 로그인 2단계 MFA verify 화면, When "이 디바이스 신뢰(30일)" 체크 + 코드 입력 → 검증 성공, Then `trust_device=true` 전송 → 정식 로그인. 다음 로그인 시 MFA 생략(백엔드 우회).
- **S6 미체크(기본)**. Given MFA verify 화면, When 체크 안 함 + 코드 입력, Then `trust_device=false`(또는 미전송) → 기존 동작 그대로(회귀 0).
- **S7 보안키 신뢰 등록**. Given MFA verify 화면 + 보안키 지원, When 체크 + "보안 키로 인증" 성공, Then `trust_device=true` 전송.

## 기능 요구사항 (FR)

- **FR-1 (목록)**. `GET /api/v1/auth/mfa/trusted-devices` 호출 → `{devices:[{id,label,createdAt,lastUsedAt,expiresAt}]}` 표시. lastSeenAt 정렬은 백엔드 보장(없으면 표시 순서 그대로).
- **FR-2 (단건 취소)**. `DELETE /api/v1/auth/mfa/trusted-devices/{id}` (X-XSRF-TOKEN). 204 → refetch. 실수 방지 인라인 확인(모달 부재 — `BackupCodesSection` 재생성 확인 동형).
- **FR-3 (전체 취소)**. `DELETE /api/v1/auth/mfa/trusted-devices` (X-XSRF-TOKEN). 204(멱등) → 빈 상태. 인라인 확인.
- **FR-4 (신뢰 체크박스)**. 로그인 MFA verify 단계 공통 체크박스(opt-in, 기본 해제). TOTP·백업코드·보안키 **모든 수단** 적용(Maxi 확정). 체크 시 verify 요청 body에 `trust_device: true`.
- **FR-5 (섹션 위치)**. `MfaSettings`에 `TrustedDevicesSection` 추가, `WebauthnSection`처럼 **항상 노출**(TOTP 활성 여부 무관 — 어떤 MFA 수단으로든 신뢰 등록 가능).
- **FR-6 (PAT 방어)**. 목록/취소는 JWT 전용. 403 `session_management_requires_interactive_login` 수신 시 방어적 안내(정상 경로에선 미발생).

## 비기능 요구사항 (NFR)

- **NFR-1 (계약 정합)**. Zod 스키마를 백엔드 `TrustedDeviceResponse`와 1:1(`label` nullable, `lastUsedAt` nullable, 시각 ISO 문자열). `sessions.ts` 패턴 — `frontend-zod-backend-dto-contract-gap` 차단.
- **NFR-2 (CSRF)**. 상태 변경(DELETE)은 `readXsrfToken()` → `X-XSRF-TOKEN` 수동 주입(`sessions.ts`/`mfa.ts` 선례, `frontend-api-convention-per-bc`).
- **NFR-3 (verify는 raw fetch)**. `verifyMfa`는 이미 raw fetch(`auth-pre-session-401-raw-fetch`). `trust_device` 추가해도 raw fetch 유지, refreshCallCount=0 회귀 검증.
- **NFR-4 (i18n)**. 모든 라벨/안내/에러를 `i18n/ko.ts`로 추출(`mfaStrings` 확장 — 인라인 리터럴 금지).
- **NFR-5 (시각 표시)**. ISO Instant → 한국어 표시. InvalidDate 방어(`IssueChangelog` 선례).

## API 인터페이스 (소비 — 백엔드 기존)

| 용도 | 메서드·경로 | 응답 | 비고 |
|---|---|---|---|
| 목록 | `GET /api/v1/auth/mfa/trusted-devices` | 200 `{devices:[{id:UUID, label:string?, createdAt, lastUsedAt:string?, expiresAt}]}` | apiGet |
| 단건 취소 | `DELETE …/trusted-devices/{id}` | 204 / 404 `{error:"not_found"}` / 403 / 401 | X-XSRF-TOKEN |
| 전체 취소 | `DELETE …/trusted-devices` | 204(멱등) | X-XSRF-TOKEN |
| 신뢰 동의 | `POST /api/v1/auth/mfa/verify` body `+trust_device:boolean` | 기존 `TokenResponse`(쿠키만 추가) | raw fetch |

## 컴포넌트 설계

- **`api/trusted-devices.ts`** (신규, `sessions.ts` 동형). `listTrustedDevices()`·`revokeTrustedDevice(id)`·`revokeAllTrustedDevices()` + Zod 스키마(자체 정의).
- **`components/auth/TrustedDevicesSection.tsx`** (신규). useQuery 목록 + 단건/전체 취소 mutation(invalidate-only 플리커 회피 — `msw-mutation-stateful-refetch`/`mutation-setquerydata-partial-response-flicker`). 인라인 확인 state. 로딩/에러/빈 상태 분기.
- **`MfaSettings.tsx`** (수정). `<TrustedDevicesSection />`을 `<WebauthnSection />` 뒤에 추가.
- **`api/mfa.ts` `verifyMfa`** (수정). 4번째 인자 `trustDevice = false` → body `trust_device`. 하위호환(기존 호출 무변경).
- **`api/webauthn.ts` `authenticateWithSecurityKey`** (수정). `trustDevice = false` 인자 → verify body에 전달. 하위호환.
- **`LoginForm.tsx` `LoginMfaStep`** (수정). 공통 체크박스 state(부모 보관 — `MfaCodeInput` key 재마운트에도 보존). `MfaCodeInput`(verifyMfa)과 `handleWebauthnVerify` 양쪽에 trustDevice 전달.
- **`i18n/ko.ts`** (수정). `mfaStrings`에 신뢰 디바이스 라벨 추가.
- **MSW** — `trusted-devices-handlers.ts`(신규, stateful) + `mfa-handlers.ts` verify 분기에 `trust_device` 인식.
