## 사용자 시나리오 (Given-When-Then)

### S1. OOO 조회 (설정 없음 — 신규 사용자)
- **Given** 인증된 사용자 bob가 `user_ooo` row 없음
- **When** `GET /api/v1/users/me/ooo`
- **Then** 200 + `{ startsAt: null, endsAt: null, delegateUserId: null, delegateName: null, message: null, active: false }` (row 없어도 defaults, 강제 생성 안 함)

### S2. OOO 설정 (기간 + 대리자 + 메시지)
- **Given** alice, 현재 2026-07-07
- **When** `PATCH /api/v1/users/me/ooo` body `{ "startsAt": "2026-07-10T00:00:00Z", "endsAt": "2026-07-14T00:00:00Z", "delegateUserId": "<bob-uuid>", "message": "휴가 중입니다. 급한 건 bob에게." }`
- **Then** 200 + 저장값 반환(+`delegateName` 파생, +`active: false` — startsAt 미래). `user_ooo` row lazy upsert(통짜 교체)

### S3. 대리자·메시지 없이 기간만 설정
- **When** `PATCH` body `{ "startsAt": "2026-07-10T00:00:00Z", "endsAt": "2026-07-14T00:00:00Z" }`
- **Then** 200 + `{ ..., delegateUserId: null, delegateName: null, message: null }`. 대리자/메시지 없이도 OOO 성립(기간만 필수)

### S4. 활성 OOO 조회 (현재 부재중)
- **Given** alice의 OOO가 `startsAt=2026-07-05, endsAt=2026-07-14`(현재 2026-07-07 → 활성)
- **When** `GET /api/v1/users/me/ooo`
- **Then** 200 + 저장값 + `active: true`

### S5. OOO 해제
- **Given** alice가 OOO 보유
- **When** `DELETE /api/v1/users/me/ooo`
- **Then** 204(또는 200). row 삭제. 재조회 시 all-null(멱등 — 없어도 정상)

### S6. 종료된 OOO 조회 (lazy 필터)
- **Given** alice의 `ends_at`가 과거(`2026-07-01`, 현재 2026-07-07)
- **When** `GET /api/v1/users/me/ooo`
- **Then** 200 + all-null + `active: false`. 종료된 OOO는 응답에서 제외(스케줄러 없이 조회 시 필터). 행 물리 삭제는 best-effort(선택)

### S7. whoami에 활성 부재중 노출
- **Given** alice가 활성 OOO(`endsAt=2026-07-14`, 미종료) 보유
- **When** `GET /api/v1/users/me/whoami`
- **Then** 200 응답에 `oooActive: true`, `oooUntil: "2026-07-14T00:00:00Z"` 포함. 미설정/종료/미래예약(비활성)이면 `oooActive: false`, `oooUntil: null`. PAT 분기는 항상 false/null

### S8. Header 부재중 표시 (프론트)
- **Given** 로그인 사용자가 활성 OOO 보유
- **When** 앱 헤더 렌더
- **Then** 계정 아바타/메뉴에 "부재중" 표시(배지/라벨 + 복귀일 tooltip). 비활성이면 표시 없음

### S9. OOO 설정 모달 (프론트)
- **Given** 로그인 사용자가 계정 드롭다운의 "부재중 설정" 클릭
- **When** 모달에서 시작/종료일(date-time), 대리자(사용자 검색 선택), 안내 메시지 입력 후 저장
- **Then** 프론트가 로컬 기준 절대시각(ISO Instant)으로 PATCH. 성공 시 whoami 재조회 + authStore 갱신 → 헤더 부재중 표시 즉시 반영(FR-PR-01/02 D6 Header 연동 선례). "부재중 해제" 버튼은 DELETE 호출

## 기능 요구사항 (FR)

- **FR1** `GET /api/v1/users/me/ooo` — 현재 사용자의 OOO 반환(+`active` 계산, +`delegateName` 파생). 미설정/종료면 all-null. row 강제 생성 안 함.
- **FR2** `PATCH /api/v1/users/me/ooo` — OOO **원자적 교체(replace)**. `{ startsAt, endsAt, delegateUserId?, message? }`. startsAt·endsAt 필수. 검증 통과 시 upsert(통짜 교체, 3-state 병합 아님).
- **FR3** `DELETE /api/v1/users/me/ooo` — OOO 해제(row 삭제). 멱등(없어도 정상).
- **FR4** `OutOfOffice` 도메인 + `OutOfOfficeRepository`(**Spring `NamedParameterJdbcTemplate`** — identity-access 관례, FR-PR-01/02 선례. jOOQ 아님) — user_ooo upsert/delete/find. `Clock` 주입(활성 판정 결정성).
- **FR5** whoami 응답에 `oooActive`/`oooUntil` view-layer 추가(활성 필터 적용). identity-access same-BC view-layer 확장(FR-PR-01 displayName/avatarUrl, FR-PR-02 statusEmoji/statusText 선례).
- **FR6** (프론트) OOO 설정 모달(기간 + 대리자 검색 선택 + 메시지) + Header 부재중 표시 + api/mocks/i18n. 대리자 선택은 기존 `useUserSearch`/`useUsersByIds` 재사용.
- **FR7** (프론트) 저장/해제 성공 시 whoami 재조회 + authStore 갱신으로 헤더 즉시 반영.

## 비기능 요구사항 (NFR)

- **NFR1** OOO 조회 p95 < 100ms(product §NFR 프로필 조회 동급, 단일 PK 조회 + delegate 이름 JOIN).
- **NFR2** 모든 엔드포인트 인증 필수. me-scope는 JWT subject 식별(FR-PR-01 `currentUserId` 선례, PAT는 401).
- **NFR3** `message` 길이 상한 500자(안내문 수용, 남용 방지). 초과 400.
- **NFR4** WCAG 2.1 AA(모달 포커스 트랩·라벨, date 입력·대리자 검색 접근성, 부재중 표시 aria). axe 0 violations.
- **NFR5** startsAt·endsAt는 유효 ISO-8601 Instant. 파싱 실패 400. `endsAt > startsAt` 및 `endsAt > now`(이미 종료된 OOO 설정 무의미) 아니면 400. startsAt는 과거/미래 모두 허용(미래=예약).

## API 인터페이스 (REST)

### GET /api/v1/users/me/ooo → 200
```json
{ "startsAt": "2026-07-10T00:00:00Z", "endsAt": "2026-07-14T00:00:00Z",
  "delegateUserId": "3f...uuid", "delegateName": "Bob Kim",
  "message": "휴가 중입니다. 급한 건 bob에게.", "active": false }
```
- 미설정/종료 시 `{ startsAt: null, endsAt: null, delegateUserId: null, delegateName: null, message: null, active: false }`.
- `active` = `startsAt <= now < endsAt`(Clock 기준). `delegateName` = delegate의 `users.display_name` 파생(대리자 삭제/부재 시 null).

### PATCH /api/v1/users/me/ooo → 200 (설정 후 상태, GET과 동일 형태)
- `startsAt`: 필수, ISO Instant.
- `endsAt`: 필수, ISO Instant. `> startsAt` 및 `> now` 아니면 400.
- `delegateUserId`: nullable UUID. 존재하는 사용자여야(없으면 400), **본인 불가**(자기 위임 400).
- `message`: nullable. blank→null 정규화. ≤500자.

### DELETE /api/v1/users/me/ooo → 204
- 멱등. row 없어도 204.

### whoami (GET /api/v1/users/me/whoami) 응답 확장
```json
{ "...기존 필드...", "oooActive": true, "oooUntil": "2026-07-14T00:00:00Z" }
```
- 비활성(미설정/종료/미래예약)/PAT → `oooActive: false`, `oooUntil: null`.
- WhoamiController는 이미 `userProfileRepository`/`userStatusRepository`를 주입해 view-layer를 파생한다(선례). 동일하게 `OutOfOfficeRepository.findActiveByUserId`(활성 필터 SQL)를 주입.

## 데이터 모델 변경

신규 마이그레이션 `V029__user_ooo.sql` (identity-access):
```sql
CREATE TABLE user_ooo (
    user_id          UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    starts_at        TIMESTAMPTZ NOT NULL,
    ends_at          TIMESTAMPTZ NOT NULL,
    delegate_user_id UUID REFERENCES users(id) ON DELETE SET NULL,  -- 대체 담당자(없어도 성립)
    message          VARCHAR(500),                                   -- 안내 메시지(표시용)
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CHECK (ends_at > starts_at)
);
```
- user_statuses(V028)와 동일한 1:1 확장 테이블 + `user_id ON DELETE CASCADE`.
- `delegate_user_id ON DELETE SET NULL` — 대리자 계정 삭제 시 OOO는 유지, 대리자만 소멸.
- identity-access는 **jOOQ codegen 미사용** → init_codegen.sql 미러 대상 아님. Flyway V029만 추가.
- `updated_at`은 repository가 write마다 `NOW()` 세팅(identity-access 관례).
- **V029 번호는 머지 직전 재확인**(동시 브랜치 충돌 회귀 방지, memory: migration-vnumber-concurrent-branch-collision).

## 엣지 케이스

- **EC1** row 없는 사용자 GET → all-null(강제 생성 안 함). PATCH(설정)에서만 lazy upsert.
- **EC2** endsAt ≤ startsAt → 400(검증 먼저, upsert 안 함). DB `CHECK` 이중 방어.
- **EC3** endsAt ≤ now(이미 종료) → 400. 부분 적용 없음.
- **EC4** startsAt 미래 → 저장 OK, `active: false`(예약). whoami 비노출.
- **EC5** delegateUserId 미존재 UUID → 400(자기 위임도 400). delegate=본인 → 400.
- **EC6** message 501자 → 400. 공백만(`"   "`) → 정규화 blank→null.
- **EC7** 재설정(이미 OOO 있음) → upsert로 통짜 교체(이전 값 잔존 없음 — replace).
- **EC8** DELETE 후 재조회 → all-null(멱등). 없어도 204.
- **EC9** users 하드 삭제(본인) → ON DELETE CASCADE로 user_ooo 자동 정리. delegate 삭제 → SET NULL(OOO 유지, delegateName null).
- **EC10** whoami가 종료/미래예약 OOO를 노출하지 않음(활성만) — Header가 비활성 부재중을 표시하지 않도록 백엔드 필터.
- **EC11** PAT 인증으로 me/ooo 접근 → 401(JWT subject 전용). whoami PAT 분기는 oooActive false/oooUntil null.

## 제약 조건

- BC 격리: identity-access 내부에서만. 타 모듈 import 금지. **issue-tracking 무변경**(ADR D3 A안 — 자동 전환은 후속).
- @Transactional 메서드는 `@Service` 필수(ArchUnit `TransactionalServiceArchTest`).
- DB 접근 = Spring `NamedParameterJdbcTemplate`(identity-access 관례, jOOQ/init_codegen 아님).
- identity-access는 **전역 마이그레이션 카운트 가드가 아니라 테이블별 스키마 테스트** 패턴(`UserProfilesSchemaTest`·`UserStatusesSchemaTest` 등). V029는 전역 카운트를 깨지 않으므로 `UserOooSchemaTest`를 `UserStatusesSchemaTest` 미러로 신설(컬럼/제약/CASCADE/SET NULL 검증). 신설 전 전역 카운트 가드 부재 재확인.
- whoami DTO 확장 시 프론트 Zod mock fanout — 신규 필드 `.nullable().optional()` 방어(FR-PR-01/02 whoami 선례, memory: zod-schema-strengthen-inline-mock-fanout).
- MSW mutation은 stateful 오버라이드 영속(memory: msw-mutation-stateful-refetch). 파생동작은 시드 가능 공유 store.
- 프론트 시각: date-time 입력→ISO Instant는 로컬 기준. `<input type="datetime-local">` bare 값→Instant 변환 주의(memory: date-input-iso-instant-query-param — bare date/datetime을 Instant로 보내면 400, ISO 변환 필수. MSW lexical 비교 가짜그린 회귀가드).
- 대리자 선택기는 기존 `useUserSearch`(2자 미만 미조회 가드)/`useUsersByIds` 재사용 — 신규 사용자 검색 API/컴포넌트 만들지 않음.
- 완제품 품질(PoC/임시 코드 금지).
- product 문서 D4의 `POST /api/v1/users/me/ooo` 표기 → 실제 GET/PATCH/DELETE 관례로 수렴. **product `personalization.md §2.3` 및 관련 정본 endpoint 표기 동기화**(FR/범위 변경 전수 동기화 규칙, verify-master-plan은 카운트만 검사하나 문서 정합 위해 갱신).

## Brainstorming Check

✅ 통과 (1회 iteration, 코드 대조 + A안 스코프 재확인으로 발견 5건 기록. Maxi 결정 필요 gap 없음).

- **G1 (자기 표시 한정 — 의도된 A안 경계)**: 본 PR의 부재중 표시는 whoami 기반 **본인 자기 확인**(헤더 배지)뿐. 팀원이 타인의 부재중을 보는 것 + 이슈 assignee 자동 전환은 ADR D3 A안대로 후속(issue-tracking 소유). 재-litigate 아님. **후속 중간 옵션**: identity-access 소유 `GET /api/v1/users`(UserSummary)에 `oooActive` 얹으면 assignee 검색기 등에서 "(부재중)" 표시가 issue-tracking 백엔드 변경 없이 가능(프론트만) — 단일 BC 유지. 본 PR 범위 밖.
- **G2 (XSS — 메시지 평문 렌더)**: `message`는 마크다운/HTML 아닌 **평문**. 프론트는 React 기본 이스케이프(텍스트 노드)로 렌더, `dangerouslySetInnerHTML` 금지. 백엔드는 raw 저장. FR-MN-01 인라인HTML XSS 회귀와 무관(마크다운 파이프라인 미사용).
- **G3 (GET 필터 = ends_at > now)**: GET은 "아직 종료 안 됨(ends_at > now)"이면 저장 row 반환(미래예약 포함, `active`는 startsAt로 계산), 종료(ends_at ≤ now)면 all-null. 설정 폼이 예약 OOO를 보여주되 지난 OOO는 없는 것처럼 취급. whoami는 활성(startsAt≤now<endsAt)만.
- **G4 (product 문서 동기화 필요)**: (a) endpoint 표기 `POST` → `GET/PATCH/DELETE`, (b) 데이터모델 `user_ooo`에 `message`(+created/updated_at) 추가. `docs/plan/product/personalization.md §2.3` D3/D4 및 관련 정본 동기화 — 머지 전 전수 동기화 규칙(verify-master-plan은 카운트만 검사, 문서 정합은 수동).
- **G5 (타임존 표시 = 브라우저 로컬)**: OOO 날짜는 Instant 저장, 프론트는 브라우저 로컬(Intl)로 표시. 프로필 타임존(FR-PR-01) 연동은 MVP 제외. OCC(expectedVersion) 없음 — 개인 설정 last-write-wins(FR-PR-02 선례).
