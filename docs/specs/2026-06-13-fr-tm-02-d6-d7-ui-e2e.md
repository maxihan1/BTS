## 배경

FR-TM-02 백엔드(#132)는 이슈 생성 시 서버 안전망(`resolveDescription`)이 템플릿 content를 주입하는 분기에서만
`{{author}}`/`{{date}}`/`{{project}}` 토큰을 실제 값으로 치환한다. **정확히 일치하는 토큰만** 치환하며,
`{{ author }}`(공백)·`{{Author}}`(대문자)·오타는 치환하지 않고 리터럴로 남긴다(fail-safe).

따라서 관리자가 템플릿 본문을 손으로 작성하며 토큰을 직접 타이핑하면 오타로 치환이 조용히 실패할 위험이 있다.
D6은 **변수 삽입 버튼**으로 항상 정확한 토큰을 본문에 끼워 넣어 이 사고를 원천 차단한다(ADR `2026-06-13-issue-template-variable-substitution`의 "정확 토큰만 치환" 제약 보조).

## 범위

1. **변수 삽입 버튼** — `IssueTemplateFormDialog.tsx`의 본문(content) textarea에 `[+ 작성자][+ 일자][+ 프로젝트]` 버튼 3개. 클릭 시 textarea 커서 위치에 정확 토큰 삽입. **create/edit 두 모드 모두**.
2. **변수 도움말** — 본문 입력 영역 아래 "사용 가능 변수" 안내 문구(토큰 목록 + 생성 시 실제 값으로 치환된다는 설명).
3. **E2E** — 생성 다이얼로그에서 버튼으로 토큰 삽입 → 본문 반영 + 저장 시 전송.
4. **범위 외** — 백엔드 무변경(신규 엔드포인트/스키마/DTO 0). 이슈 생성폼 미리보기·`{{date}}` 실값 프리뷰는 범위 외(서버 안전망이 생성 시점에 치환).

## 사용자 시나리오 (Given-When-Then)

- **S1 작성자 삽입(빈 본문)**. Given 관리자 Alice가 "템플릿 추가" 다이얼로그를 열고 본문이 비어 있음. When 본문에 포커스 후 `[+ 작성자]` 클릭. Then 본문 = `{{author}}`.
- **S2 커서 위치 삽입**. Given 본문에 `보고자: ` 입력 후 커서가 끝에 있음. When `[+ 작성자]` 클릭. Then 본문 = `보고자: {{author}}`(커서 위치에 삽입, 커서는 토큰 뒤로 이동).
- **S3 3종 연속 삽입**. Given 빈 본문. When `[+ 작성자]` → 줄바꿈/텍스트 입력 → `[+ 일자]` → `[+ 프로젝트]` 순서로 클릭·입력. Then 각 토큰이 클릭 시점 커서 위치에 정확히 누적 삽입.
- **S4 선택 영역 대체**. Given 본문 `초안텍스트`에서 `초안` 부분을 드래그 선택. When `[+ 프로젝트]` 클릭. Then 선택 영역이 토큰으로 대체 → `{{project}}텍스트`.
- **S5 수정 모드 동일 동작**. Given 기존 템플릿의 "수정" 다이얼로그(본문 프리필됨). When 본문 끝에 커서 두고 `[+ 일자]` 클릭. Then 프리필 본문 끝에 `{{date}}` 삽입(create 모드와 동형).
- **S6 도움말 표시**. Given 생성/수정 다이얼로그. When 다이얼로그 표시. Then 본문 아래 "사용 가능 변수: {{author}} 작성자 · {{date}} 일자 · {{project}} 프로젝트 — 이슈 생성 시 실제 값으로 치환됩니다" 안내가 보인다.
- **S7 삽입 후 저장 반영**. Given 본문에 버튼으로 `{{author}}` 삽입. When 이름·타입 입력 후 저장. Then 전송 payload의 content에 `{{author}}`가 정확히 포함(RHF 값 동기화 확인). 빈 본문이 아니므로 "본문 필수" 검증 통과.

## 기능 요구사항 (FR)

- **FR-D6-1** 본문 라벨 행에 변수 삽입 버튼 3개 — `[+ 작성자]`→`{{author}}`, `[+ 일자]`→`{{date}}`, `[+ 프로젝트]`→`{{project}}`. 각 버튼 `type="button"`(폼 제출 트리거 금지) + aria-label.
- **FR-D6-2** 클릭 시 본문 textarea의 현재 선택 구간(`selectionStart`~`selectionEnd`)에 토큰 삽입. 선택 영역이 있으면 대체, 없으면 커서 위치 삽입. 삽입 후 커서를 **삽입 토큰 끝**으로 이동 + textarea 포커스 유지.
- **FR-D6-3** 삽입은 RHF(react-hook-form) `content` 필드 값을 갱신(`setValue('content', next, { shouldDirty: true, shouldValidate: true })`). 손 타이핑과 동일하게 검증·제출에 반영(별도 상태 분기 금지 — 단일 출처).
- **FR-D6-4** 본문 입력 영역 아래 변수 도움말 문구 — 토큰 3종 + "이슈 생성 시 실제 값으로 치환됩니다" 안내. i18n 라벨로 단일 출처.
- **FR-D6-5** create 모드·edit 모드 본문 textarea 모두 동일 버튼/도움말 적용. 두 모드가 같은 삽입 로직 공유(중복 구현 금지).
- **FR-D6-6** 토큰 형식 상수는 백엔드 `TemplateVariable` enum(`{{author}}`/`{{date}}`/`{{project}}`, 소문자·공백 없음)과 **정확히 일치**. 프론트는 Kotlin enum을 직접 import 불가하므로 상수로 미러하고, 출처 주석으로 drift 위험 명시(`frontend-zod-backend-dto-contract-gap` 정신).
- **FR-D7-1** E2E: 생성 다이얼로그에서 버튼 클릭 → 본문 textarea에 정확 토큰 반영(S1/S2 수준) + 저장 시 content 전송 확인.

## 비기능 요구사항 (NFR)

- 기존 다이얼로그(custom-fields/issue-templates)와 **시각·상호작용 일관**(DESIGN.md 토큰, shadcn/Radix, 기존 Button 컴포넌트 재사용). 버튼은 작은 보조 액션 — `variant="outline" size="sm"` 또는 그에 준하는 secondary 스타일.
- 신규 i18n 문자열은 `issue-template-labels.ts`에 추가(custom-field-labels 패턴, 단일 출처).
- 백엔드 무변경 — 신규 DTO/엔드포인트/스키마/마이그레이션 0. Zod 스키마 변경 0(content는 기존 string 그대로).
- RHF register와 textarea ref 공존 — register의 ref 콜백과 자체 ref를 병합(직접 DOM 접근은 selection 제어에 한정). 제어/비제어 혼선 금지.
- 접근성 — 버튼은 키보드 접근 가능(Tab/Enter), aria-label로 스크린리더 의미 전달. 도움말은 textarea와 `aria-describedby` 연결 권장(가능 시).

## 엣지 케이스

- **E1** textarea에 포커스가 없거나 selection 정보 없음 → 본문 **끝에 append**(fallback). 절대 토큰 유실 없음.
- **E2** 빈 본문에서 삽입 → 토큰만 삽입(S1).
- **E3** 선택 영역 존재 → 대체(S4).
- **E4** 연속 클릭 → 각 토큰이 직전 커서 위치 기준 누적(S3). 재치환·중복 삽입 없음.
- **E5** 한글 IME 조합 중 클릭 → 영문 토큰 삽입이라 조합과 무관. 조합 중인 글자 뒤/선택 위치에 삽입(브라우저 기본 동작).
- **E6** textarea resize/스크롤 상태 → 삽입 로직 무관(값+selection만 제어).
- **E7** 같은 토큰 중복 삽입(`{{author}}` 두 번) → 허용(백엔드가 전역 치환 — 시나리오 명세 "여러 번 등장 모두 치환").

## 제약 조건

- **BC 격리** — issue-tracking 프론트 view layer + E2E만. 백엔드/타 BC 무변경. 신규 cross-BC 호출 0.
- 토큰 문자열은 백엔드 정확 매칭(`{{author}}` 소문자, 공백 없음)과 일치해야 함 — 어긋나면 버튼이 치환 안 되는 토큰을 삽입(가짜 기능). 상수 미러 + 출처 주석으로 방지.
- 도움말 문구는 변수의 **의미**만 설명(작성자/일자/프로젝트). 실제 값 프리뷰(예: 오늘 날짜 표시)는 범위 외 — 생성 시점에 서버가 치환하므로 편집 시점 프리뷰는 오해 소지.
