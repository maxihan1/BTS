## 배경

백엔드 FR-LK-01(이슈 링크 4종 + parent-child)이 PR #135로 머지됨. 이슈 상세 화면에서 링크를 추가/제거하고 부모를 설정/해제하는 UI(D6) + E2E(D7)를 구현한다. 대상 이슈 선택은 **이슈 키 직접 입력**(Maxi 확정) — 백엔드에 텍스트 검색 API가 없고, POST가 존재/순환/자기참조를 검증해 인라인 에러로 피드백한다.

## 백엔드 API 계약 (소비, 박제)

베이스 `/api/v1/issues/{key}`. 응답은 모두 `DataResponse<T>` = `{ data: T }` 래퍼.

| 메서드 | 경로 | 요청 | 응답(data) | 상태 |
|---|---|---|---|---|
| POST | `/links` | `{ targetKey, linkType(소문자) }` | `IssueLinkResponse` | 201 |
| GET | `/links` | — | `{ outward: IssueLinkResponse[], inward: IssueLinkResponse[] }` | 200 |
| DELETE | `/links/{linkId}` | — | (없음) | 204 |
| PATCH | `/parent` | `{ parentKey: string \| null }` | `{ key, parent?: {key, summary} }` | 200 |

- **IssueLinkResponse** = `{ id: number, linkType: string(대문자 "BLOCKS"), direction: "OUTWARD"|"INWARD", label: string, otherIssue: { key, summary, statusKey } }`
- `linkType`은 **요청 소문자 / 응답 대문자** 비대칭. UI는 응답의 `label`을 그대로 표시(예: "blocks", "is blocked by"), 추가 시에는 소문자 코드 전송.
- parent 응답의 `parent`는 **null이면 JSON 키 자체 생략**(NON_NULL) → Zod `.nullish()` / `.optional()`.
- 에러 ProblemDetail `errorCode`: `ISSUE_NOT_FOUND`(404), `LINK_SELF_REFERENCE`(422), `DUPLICATE_LINK`(409), `LINK_CYCLE`(409), `LINK_NOT_FOUND`(404), `PARENT_SELF_REFERENCE`(422), `PARENT_CYCLE`(409), `INVALID_LINK_TYPE`(400), `VALIDATION_FAILED`(400).

### ⚠️ 버전 링크 패턴과의 차이 (복사 금지)
버전 링크(FR-VR-03)는 이슈 응답에 임베드된 배열을 PATCH로 통째 교체 + `expectedVersion` OCC. **이슈 링크는 자체 GET 쿼리 + 단건 POST/DELETE, OCC 없음**. mutation은 "전체 교체"가 아니라 "단건 add/remove" + `invalidateQueries(issueLinksKey)`.

## 사용자 시나리오 (Given-When-Then)

### S1. 링크 목록 조회
- **Given** alice가 BTS-1 이슈 상세를 연다.
- **When** 링크 패널이 렌더된다.
- **Then** `GET /links`로 받은 outward/inward 링크가 방향 라벨(예: "blocks BTS-2", "is blocked by BTS-3")과 상대 이슈 요약·상태로 표시된다. 링크가 없으면 "연결된 링크가 없습니다" 빈 상태.

### S2. 링크 추가 (happy path)
- **Given** alice가 BTS-1 상세에서 링크 패널을 본다.
- **When** 유형 드롭다운에서 "blocks"를 고르고, 대상 이슈 키 입력에 "BTS-2"를 타이핑 후 "추가"를 누른다.
- **Then** `POST /links {targetKey:"BTS-2", linkType:"blocks"}` 201 → 목록이 갱신되어 새 outward 링크가 보인다. 입력은 초기화된다. 성공 토스트.

### S3. 링크 추가 — 존재하지 않는 대상 (404)
- **Given** alice가 링크 추가 폼을 본다.
- **When** 대상 키에 "BTS-999"(없음)를 넣고 추가한다.
- **Then** 404 `ISSUE_NOT_FOUND` → 폼 인라인 에러 "존재하지 않는 이슈입니다.". 목록 변동 없음.

### S4. 링크 추가 — 자기 자신 (422)
- **When** BTS-1 상세에서 대상 키에 "BTS-1"을 넣고 추가한다.
- **Then** 422 `LINK_SELF_REFERENCE` → 인라인 에러 "자기 자신과는 링크할 수 없습니다.".

### S5. 링크 추가 — 중복 (409)
- **When** 이미 존재하는 (대상, 유형) 조합을 다시 추가한다.
- **Then** 409 `DUPLICATE_LINK` → 인라인 에러 "이미 연결된 링크입니다.".

### S6. 링크 추가 — blocks 순환 (409)
- **When** blocks 그래프에 순환을 만드는 링크를 추가한다(예: B blocks A 상태에서 A blocks B).
- **Then** 409 `LINK_CYCLE` → 인라인 에러 "순환 링크는 만들 수 없습니다.".

### S7. 링크 제거
- **Given** BTS-1에 outward 링크(linkId=10)가 있다.
- **When** 그 링크 행의 "제거"를 누른다(확인 인라인).
- **Then** `DELETE /links/10` 204 → 목록에서 사라진다. 성공 토스트.

### S8. 부모 설정 (happy path) + 새로고침 후에도 표시
- **Given** BTS-1에 부모가 없다.
- **When** parent 섹션에서 부모 키 "BTS-5"를 넣고 "부모 지정"을 누른다.
- **Then** `PATCH /parent {parentKey:"BTS-5"}` 200 → 이슈 쿼리 invalidate → "부모: BTS-5 (요약)" 표시. **페이지를 새로고침해도** `GET /issues/BTS-1` 응답의 `parent`로 현재 부모가 그대로 보인다(아래 백엔드 FR-B1).

### S9. 부모 설정 — 순환 (409) / 자기참조 (422) / 미존재 (404)
- **When** 조상 순환을 만들거나(BTS-5의 조상에 BTS-1), 자기 자신을, 없는 키를 부모로 지정한다.
- **Then** 각각 409 `PARENT_CYCLE` "순환 계층은 만들 수 없습니다." / 422 `PARENT_SELF_REFERENCE` "자기 자신을 부모로 지정할 수 없습니다." / 404 `ISSUE_NOT_FOUND` "존재하지 않는 이슈입니다." 인라인 에러.

### S10. 부모 해제
- **Given** BTS-1의 부모가 BTS-5다.
- **When** "부모 해제"를 누른다.
- **Then** `PATCH /parent {parentKey:null}` 200 → 부모 표시 사라지고 입력 폼으로 복귀.

## 기능 요구사항 (FR)

- **FR-1**. 이슈 상세에 `IssueLinksPanel`(전용 카드) 추가 — outward/inward 링크 목록 + 추가 폼 + parent-child 섹션.
- **FR-2**. 링크 목록은 `GET /links`를 자체 queryKey(`issueLinksKey(key)`)로 조회. 이슈 본문 쿼리와 분리.
- **FR-3**. 링크 추가 = 유형(4종 드롭다운) + 대상 키(텍스트) → `POST /links`(소문자 코드). 성공 시 목록 invalidate + 폼 리셋.
- **FR-4**. 링크 제거 = 행별 `DELETE /links/{linkId}` → invalidate.
- **FR-5**. parent 섹션 — **현재 부모를 이슈 본문 쿼리(`GET /issues/{key}`)의 `parent`에서 읽어 표시**(설정/해제 후 이슈 쿼리 invalidate로 갱신, 새로고침에도 유지), 설정/해제 `PATCH /parent`.
- **FR-B1 (백엔드, 같은 BC view-layer)**. `IssueResponse` DTO에 `parent: { key, summary }?`(nullable, `@JsonInclude(NON_NULL)`) 추가. **단건 조회 경로(`findByKey`)에만 self LEFT JOIN으로 채움**(부모 1:1, cartesian 무위험 — 메모리 cartesian-product-jooq-leftjoin-count). **목록 경로(`listIssues`)는 parent를 채우지 않음**(null/생략 — 목록은 parent 미표시, N+1/조인 비용 회피). Maxi 확정 옵션 1(PR #13 옵션 C — 프론트 PR이 동일 BC view layer 패치 허용). 기존 IssueResponse 매핑/테스트 회귀 0 보장.
- **FR-6**. 모든 도메인 에러(404/422/409/400)를 errorCode 기준으로 한국어 인라인 메시지에 매핑(토스트가 아니라 폼 근처 인라인 — 즉시 수정 유도). 토스트는 성공 알림에 사용.
- **FR-7**. i18n — 모든 신규 문자열은 `apps/web/src/i18n/ko.ts`에 키로 추가. 하드코딩 금지. 문장 콜론 종결 금지(ko.test 자동검증).
- **FR-8**. Zod 스키마는 `api/issue-links.ts`에 백엔드 DTO와 1:1 정의(invent 금지). linkType 응답 대문자, PATCH /parent 응답 nullish 정합. 추가로 `api/issues.ts` `issueResponseSchema`에 `parent: {key, summary}.nullish()` 필드 추가(FR-B1 노출 정합).

## UI 컴포넌트 스펙

- **위치**. 이슈 상세 본문 하단(변경이력 `IssueChangelog` 상단) 또는 메타패널 하단. 링크는 방향 라벨+상대 요약+상태로 폭이 필요 → 본문 하단 전용 카드 권장.
- **재사용**. `IssueMetaPanel`의 섹션 헤더 스타일, `IssueAssigneeSelect`(IssueMetaPanel.tsx:806~858)의 입력 패턴, DESIGN.md 토큰. 버튼/인풋은 기존 shadcn 컴포넌트.
- **구성**.
  1. 링크 섹션 — 그룹: 유형별 또는 outward/inward별 묶음. 각 행 = `label` + `otherIssue.key`(이슈 상세 링크) + summary + status 칩 + 제거 버튼.
  2. 추가 폼 — 유형 `<select>`(blocks/relates/duplicates/clones) + 대상 키 `<input>` + 추가 버튼 + 인라인 에러 영역.
  3. parent 섹션 — 현재 부모는 **이슈 본문 쿼리의 `parent`**에서 읽음. 부모 있으면 "부모: KEY (요약)" + 해제 버튼; 없으면 부모 키 입력 + 지정 버튼 + 인라인 에러.
- **상태**. 로딩(스켈레톤/spinner), 빈 상태, 에러(인라인), 진행 중(버튼 disabled).

## 엣지 케이스

- E1. 응답 `linkType` 대문자 vs 요청 소문자 비대칭 — 표시는 `label` 사용(코드 직접 노출 안 함), 전송은 드롭다운 value=소문자.
- E2. parent 응답 `parent` 키 생략(null) — Zod `.nullish()`, UI는 "부모 없음" 처리.
- E3. 같은 이슈가 outward이자 inward일 수 있음(다른 유형) — 두 그룹에 각각 표시 정상.
- E4. 소프트 삭제된 상대 이슈는 백엔드 listLinks가 제외 — 프론트는 받은 목록만 표시.
- E5. 키 입력 공백/대소문자 — 백엔드 `IssueKey`가 검증; 프론트는 trim 후 전송, 빈 값이면 추가 버튼 disabled.
- E6. 401(미인증) — `apiFetch`가 자동 refresh/redirect 처리(기존 패턴).

## E2E 시나리오 (D7, Playwright + MSW)

- E2E-1. 링크 추가 happy path(S2) — alice 로그인 → 이슈 상세 → blocks BTS-2 추가 → 목록에 표시.

- E2E-3. 링크 제거(S7) — 추가된 링크 제거 후 사라짐.
- E2E-4. 부모 설정(S8) + 해제(S10).
- E2E-5. (선택) blocks 순환(S6) 인라인 에러 — MSW가 순환 상태를 409로 응답.
- MSW — `issue-link-handlers.ts` 신규(또는 issue-handlers 확장). stateful store(메모리 msw-mutation-stateful-refetch / msw-derived-behavior-shared-store-e2e): POST가 store에 추가→GET이 반영, DELETE가 제거. 브라우저 시드 가능한 공유 store. 에러 시나리오는 localStorage 플래그/특정 키로 토글(메모리 e2e-msw-scenario-toggle-localstorage-flag).
- 회귀 — 기존 이슈 상세 E2E 함께 실행, loginAsAlice fixture 정합(메모리 e2e-fixture-whoami-userid-alignment).
