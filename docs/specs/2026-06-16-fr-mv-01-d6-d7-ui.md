# FR-MV-01 D6/D7 프론트 이동 마법사 UI + E2E — 스펙

## 사용자 시나리오 (Given-When-Then)

### S1. 단건 이동 (완전 호환)
- **Given** 이슈 상세 `ATLAS-12`(자식 없음), 사용자가 대상 `INFRA`에 CREATE 권한 보유
- **When** "이동" 액션 → 마법사 → 대상 `INFRA` 입력 → preview(매핑 불필요) → "이동" 확인
- **Then** move 성공 → 새 키 `INFRA-5`로 이동(상세 페이지 자동 이동), 토스트 "이동 완료"

### S2. 단건 이동 (비호환 매핑 필요)
- **Given** `ATLAS-12`(상태 `in_progress`, 컴포넌트 `Backend`, fix버전 `v1.0`), `INFRA`엔 `in_progress` 없음·동명 컴포넌트 없음·`v1.0` 있음
- **When** preview → 마법사가 "상태 선택 필요"(대상 상태 목록+제안), 컴포넌트 "매핑/제거", `v1.0` 자동매핑 제안 표시 → 사용자 선택 → 이동
- **Then** move에 매핑 페이로드 전달 → 성공

### S3. 서브태스크 동반 이동 (노드별 매핑)
- **Given** Story `ATLAS-12`가 서브태스크 `ATLAS-13`,`ATLAS-14` 보유
- **When** preview → 마법사가 **부모 + 각 자식 노드별 매핑 섹션**(`subtasks` 배열) 표시 → 노드별 확인 → 이동
- **Then** move에 `subtasks` 배열(자식별 매핑) 포함 → 성공 → `movedSubtasks` 토스트("3개 이슈 이동: INFRA-5/6/7")

### S4. 옛 키 redirect (D7 E2E)
- **Given** `ATLAS-12` → `INFRA-5` 이동 완료
- **When** 옛 키 URL `/issues/ATLAS-12` 접근
- **Then** 백엔드 308 → 새 키 `/issues/INFRA-5`로 이동(상세 정상 표시)

### S5. 오류 처리
- **Given** 이동 중 권한 없음(403)/OCC 충돌(409)/다단계 자식(422 `SUBTASK_HAS_OWN_SUBTASKS`)/비호환 상태 미선택(422 `INVALID_TARGET_STATE`)
- **When** move 호출
- **Then** 마법사가 해당 오류 메시지 표시(이동 안 됨, 마법사 유지)

| FR-8 | TanStack Query 훅 — `useMovePreview`(또는 단계 진입 시 호출), `useMoveIssue`(mutation) |
| FR-9 | **D7 E2E**: (a) 단건 이동 + 새 키 이동, (b) 서브태스크 동반 이동 + movedSubtasks, (c) **옛 키 308 redirect → 새 키 상세**. MSW로 preview/move/redirect 핸들러 |

## API 인터페이스 (소비 — 백엔드 1:1 미러)

### preview — `POST /api/v1/issues/{key}/move/preview`
요청 `{ targetProjectKey }`. 응답 `MovePreview` (**G1/G2 백엔드 보강 반영** — version·isDone 추가):
```jsonc
{
  "version": long,                              // (G1 신규) 루트 이슈 OCC version
  "workflow":        { "compatible": bool, "targetStates": [{key,name,isDone:bool}], "suggestedStateKey": string|null },  // (G2) isDone 추가
  "components":      { "current": [Component], "target": [Component], "autoMapping": { "<srcUuid>": "<targetUuid>|null" } },
  "affectsVersions": { /* VersionMappingSection 동형 */ },
  "fixVersions":     { /* 동형 */ },
  "customFields":    { "removed": [CustomFieldDefinition], "requiredMissing": [CustomFieldDefinition] },
  "subtasks": [ { "issueKey", "issueTypeKey": string|null, "version": long, "workflow", "components", "affectsVersions", "fixVersions", "customFields" } ]  // (G1) 자식 version 추가
}
```
- `Component`/`Version`/`CustomFieldDefinition`/`WorkflowStateView` 타입은 **기존 프론트 타입 재사용**(FR-CM/FR-VR/FR-IS-10). 백엔드 형식과 대조.
- **G1 version**: 프론트가 move의 루트·자식 `expectedVersion`(OCC)을 채우려면 preview가 각 노드 version을 줘야 함 → `MovePreview.version`·`SubtaskPreviewNode.version` 추가.
- **G2 isDone**: 선택한 상태가 DONE 카테고리인지 → `WorkflowStateView.isDone` 추가. 프론트가 선택 상태의 isDone으로 move의 `targetStateIsDone` 채움.

### move — `POST /api/v1/issues/{key}/move`
요청 `MoveRequest`:
```jsonc
{
  "targetProjectKey", "expectedVersion", "targetStateKey": string|null, "targetStateIsDone": bool,
  "componentMapping": {"<srcUuid>":"<targetUuid>|null"}, "affectsVersionMapping": {...}, "fixVersionMapping": {...},
  "customFieldValues": {"<key>": any},
  "subtasks": [ { "issueKey", "expectedVersion", "targetStateKey", "targetStateIsDone", "componentMapping", "affectsVersionMapping", "fixVersionMapping", "customFieldValues" } ]
}
```
응답 `MoveResponse`: `{ "issueKey", "previousKey", "movedSubtasks": [{ "previousKey", "issueKey" }] }`

### 옛 키 redirect (G3 처리 명확화)
- 백엔드 `GET /api/v1/issues/{oldKey}` → 308 + `Location`(새 키 경로).
- **프론트 처리**: 이슈 상세 fetch 시 308 응답을 감지 → `Location`(또는 응답 `response.url`/`redirected`)에서 새 키 추출 → SPA `navigate`로 새 키 라우트(`/issues/{newKey}`)로 교체(브라우저 URL도 갱신, 옛 키 페이지에 새 키 데이터 표시되는 불일치 방지). **구현 시 백엔드 308 실동작(fetch 자동 follow 여부·Location 형식) 확인** 후 방식 확정.
- D7 E2E로 검증(옛 키 접근 → 새 키 상세).

### 백엔드 view layer 보강 (BC 격리 예외 — Maxi 확정 2026-06-16)
프론트 move 구성에 필요한 데이터를 백엔드가 안 줘서, **이 프론트 PR에 same-BC view layer patch 포함**(메모리 선례: frontend PR의 same-BC view layer 변경). move 도메인 로직 불변.
- **issue-tracking** (`MovePreviewService.kt`): `MovePreview.version`(루트) + `SubtaskPreviewNode.version`(자식) 추가 — 조회한 issue.version 노출. 컨트롤러 DTO(`MoveDtos.kt`/preview 직렬화)도 반영.
- **shared-kernel** (`WorkflowStateView.kt`): `isDone: Boolean` 추가.
- **project-workflow** (`WorkflowStateCatalogImpl.kt`): `listStates`가 각 상태의 DONE 카테고리 여부로 `isDone` 채움.
- 영향 테스트(MovePreviewServiceTest 등) 동반 갱신. 백엔드 `--rerun-tasks` 재검증 필수.

| EC | 상황 | 처리 |
|---|---|---|

## 제약 조건

- 외부 라이브러리 추가 금지(절대규칙 #17). radix-ui Dialog + TanStack Query + Zod 기존.
- Zod 백엔드 1:1 미러(invent 금지). 백엔드 nullable → Zod `.nullable()`/`.optional()` 실측.
- 대상 프로젝트 = 키 직접 입력(목록 API 부재, FR-LK-01 선례). 향후 목록 API 생기면 드롭다운 교체.
- 토큰 localStorage 금지, CSRF 변이 헤더(X-XSRF-TOKEN) 기존 apiFetch 패턴.
- 백엔드 변경 없음(이미 #153/#154 머지). 순수 프론트 + E2E.
