# FR-PM-10 D6/D7 — 전역 권한 부여/회수 관리 화면 UI + E2E — 스펙

> slug: fr-pm-10-d6-d7-ui-e2e
> type: ui · BC: identity-access · 프론트 apps/web
> 백엔드 완료: #277 (`GlobalPermissionGrantController` grant/revoke/list)
> ADR: [2026-07-17-global-permission-grants](../decisions/2026-07-17-global-permission-grants.md)
> 선례: field-permissions UI (grant/revoke/list 동형)

## 개요

SYSTEM_ADMIN 이 사용자/그룹에게 전역 권한(`CREATE_PROJECT`)을 부여·회수하는 관리 화면과 E2E.
백엔드(D1~D5)는 완료. 이번은 순수 프론트 — 새 admin 라우트 `/admin/global-permissions` +
목록/부여/회수 UI + MSW + E2E.

**office-hours / design-shotgun 스킵.** 사유 — (1) 요구사항이 확정 ADR + 확정 API 계약으로 결정적이라
"만들 가치가 있나"는 이미 답이 나왔다([[bts-spec-office-hours-mismatch]] 선례). (2) 화면이 기존 admin
CRUD 패턴(audit-logs·field-permissions)과 동형이라, 디자인 변형 4종 발산은 "기존 admin 화면과의 일관성"
이라는 실제 요구와 역행한다(글로벌 CLAUDE.md §3 surgical). DESIGN.md 존재 → design-consultation 불요.

## 사용자 시나리오 (Given-When-Then)

### S1. 목록 조회
- **Given** SYSTEM_ADMIN 이 로그인한 상태에서
- **When** 관리 메뉴 > "전역 권한" 을 열면
- **Then** 부여된 전역 권한 grant 목록이 표(권한 · 대상 종류 · 대상 이름 · 부여자 · 부여 시각 · 회수)로 보인다.
  grantee/부여자 UUID 는 표시 이름으로 해소된다.

### S2. 그룹에 부여
- **Given** 관리 화면에서
- **When** "권한 부여" 를 눌러 권한=프로젝트 생성, 대상 종류=그룹, 대상=특정 그룹을 골라 제출하면
- **Then** 201 로 grant 가 생성되고 목록에 즉시 반영된다(재조회).

### S3. 사용자에 부여
- **Given** 관리 화면에서
- **When** "권한 부여" 에서 대상 종류=사용자, 대상=검색으로 특정 사용자를 골라 제출하면
- **Then** 201 로 grant 가 생성되고 목록에 반영된다.

### S4. 회수
- **Given** grant 가 하나 이상 있는 목록에서
- **When** 특정 행의 "회수" 를 누르고 확인하면
- **Then** 204 로 hard delete 되고 목록에서 사라진다.

### S5. 중복 부여 거부
- **Given** 이미 (권한=CREATE_PROJECT, 대상=그룹 G) grant 가 있는 상태에서
- **When** 동일 조합을 다시 부여하면
- **Then** 409 `grant_already_exists` 로 "이미 부여된 권한입니다" 오류가 폼에 표시되고 목록은 불변.

### S6. 비-관리자 차단
- **Given** SYSTEM_ADMIN 이 아닌 사용자가
- **When** `/admin/global-permissions` 로 직접 이동하면
- **Then** `requireSystemAdmin` 가드가 `/dashboard` 로 리다이렉트한다(메뉴에도 노출 안 됨).

### S7. 삭제된 사용자(orphan) grant 표시
- **Given** grantee 사용자가 삭제되어 grant 행만 남은 경우(ADR 잔여위험 1)
- **When** 목록을 보면
- **Then** 그 행이 **숨겨지지 않고** "삭제된 사용자" 로 표시된다(사후 발견 경로 보존). 회수 가능.

## 기능 요구사항 (FR)

| ID | 요구사항 |
|---|---|
| FR-1 | 새 라우트 `/admin/global-permissions` — `composeGuards(requireAuth, requireSystemAdmin, requirePasswordChanged, requireMfaEnrolled)` 가드. 페이지 h1 heading "전역 권한 관리". |
| FR-2 | 관리 메뉴(`Header.tsx` `ADMIN_LINKS`)에 `{ to:'/admin/global-permissions', label:'전역 권한' }` 추가. `isSystemAdmin` 게이팅은 기존 로직 재사용. |
| FR-3 | 목록: `GET /api/v1/admin/global-permissions` (bare 배열) → 표. 컬럼 = 권한(한글 라벨) · 대상 종류(사용자/그룹) · 대상 이름 · 부여자 · 부여 시각 · 회수 버튼. |
| FR-4 | UUID→이름 해소: USER grantee + 모든 grantedBy → `fetchUsersByIds`(배치 1회), GROUP grantee → `fetchGroups`(1회) 후 id find. 미존재 id 는 "삭제된 사용자"/"삭제된 그룹" 폴백. |
| FR-5 | 부여 다이얼로그: 권한 select(코드 화이트리스트 `['CREATE_PROJECT']`, 한글 라벨) + 대상 종류 토글(USER/GROUP) + 대상 선택기(USER=검색 typeahead `useUserSearch`, GROUP=`useGroups` 드롭다운). 제출 → `POST` (X-XSRF-TOKEN). |
| FR-6 | 회수: 행의 회수 버튼 → 확인 → `DELETE /{grantId}` (X-XSRF-TOKEN) → 204. |
| FR-7 | 성공 변이 후 grants 쿼리 `invalidateQueries`(setQueryData 부분갱신 플리커 회피, [[mutation-setquerydata-partial-response-flicker]]). |
| FR-8 | 에러 표면화: 폼에서 백엔드 `{ error: "<code>" }` 코드(`grant_already_exists`/`grantee_not_found`/`unknown_permission`) 를 한글 메시지로 매핑. 목록/네트워크 에러는 재시도 가능한 에러 상태. |
| FR-9 | 빈 목록: "부여된 전역 권한이 없습니다" empty state + "SYSTEM_ADMIN 은 모든 전역 권한을 자동 보유합니다" 안내. |
| FR-D7 | E2E: S1~S5 happy/error path Playwright 스펙 + MSW stateful 핸들러(grant/revoke 가 store 변이). |

## 비기능 요구사항 (NFR)

| ID | 요구사항 |
|---|---|
| NFR-1 | **에러 계약** — global-permissions 는 `{ error: code }`(snake_case, `errorCode` 아님). 추출기는 `body.error` 를 읽는다([[frontend-api-convention-per-bc]]). |
| NFR-2 | **CSRF** — POST/DELETE 는 `X-XSRF-TOKEN: readXsrfToken()` 필수. |
| NFR-3 | **응답 형태** — GET/POST 는 bare(배열/객체), `{ data }` 래퍼 없음(groups 선례, field-permissions 와 다름). |
| NFR-4 | **접근성** — 관리 메뉴 nav `aria-label="관리 메뉴"`(E2E 계약, [[frontend-nav-aria-label-e2e-contract]]) 유지. 회수 버튼은 대상 식별 aria-label. |
| NFR-5 | **타입 안전** — 응답 Zod 파싱(DTO invent 금지 [[frontend-zod-backend-dto-contract-gap]]). granteeType `z.enum(['USER','GROUP'])`, permission `z.string()`(백엔드가 화이트리스트 소유). |
| NFR-6 | **N+1 회피** — 이름 해소는 배치(users byIds 1회 + groups 1회). 행마다 개별 조회 금지. |
| NFR-7 | 토큰 sessionStorage(`bts.auth`), 401→refresh 자동 retry 는 기존 `apiFetch` 경로 사용. |

## API 인터페이스 (소비만 — 신규 백엔드 없음)

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| GET | `/api/v1/admin/global-permissions` | — | 200 `GrantResponse[]` (bare) |
| POST | `/api/v1/admin/global-permissions` | `{ permission, granteeType, granteeId }` | 201 `GrantResponse` / 400·409·404 `{error}` |
| DELETE | `/api/v1/admin/global-permissions/{grantId}` | — | 204 / 404 `{error}` |
| GET | `/api/v1/users?ids=<uuid,...>` | — | 200 `UserSummary[]` (기존 `fetchUsersByIds`) |
| GET | `/api/v1/users?query=` | — | 200 `UserSummary[]` (기존 `useUserSearch`) |
| GET | `/api/v1/groups` | — | 200 `GroupResponse[]` (기존 `fetchGroups`) |

`GrantResponse = { id: uuid, permission: string, granteeType: 'USER'|'GROUP', granteeId: uuid, grantedBy: uuid, createdAt: string }`

## 엣지 케이스

- **EC-1 orphan USER grant** — grantee 삭제 → `fetchUsersByIds` 결과에서 제외. 행 숨김 금지, "삭제된 사용자" 표시(S7). ADR 잔여위험 1의 "목록 API 사후 발견" 경로를 UI 가 실현.
- **EC-2 삭제된 그룹 grant** — `fetchGroups` 에 없음 → "삭제된 그룹" 폴백. (GROUP orphan 은 판정에서 자연 탈락하지만 grant 행은 남을 수 있음.)
- **EC-3 부여 대상이 로드~제출 사이 삭제** — 404 `grantee_not_found` → 폼 오류.
- **EC-4 권한 코드 단일** — 현재 `CREATE_PROJECT` 뿐. select 옵션 1개. 백엔드 CHECK 추가 시 프론트 상수만 확장(구조 불변).
- **EC-5 SYSTEM_ADMIN 은 목록에 없음** — 암묵 보유는 grant 행이 아니므로 목록 미표시. 빈 목록이 정상 초기 상태(FR-9 안내).
- **EC-6 자기 자신에게 부여** — 허용(무해, 부트스트랩). 별도 차단 없음.
- **EC-7 회수 확인 취소** — DELETE 미발사, 목록 불변.
- **EC-8 목록 로드 403/401** — 가드가 선차단하므로 정상 흐름에선 미발생. 방어적 에러 상태만.

## 제약 조건

- **한 PR = 한 BC** — 프론트 apps/web + identity-access view layer 소비만. 백엔드 무변경. BC 격리 유지.
- 기존 admin 라우트/네비/필드권한 UI 패턴을 따른다(신규 디자인 언어 금지, 글로벌 CLAUDE.md §3).
