## 0. 배경 / 범위

칸반 보드(`/projects/$projectKey/board?board=<id>`)에서 카드를 **담당자 / 라벨 / 컴포넌트**로 필터링하는 프론트 UI(D6) + E2E(D7).

- 백엔드 필터 API는 #168로 완성: `GET /api/v1/boards/{boardId}?assignee=&label=&component=`
  - 필드내 OR + 필드간 AND, `assignee=unassigned` 센티널
  - assignee/component = UUID(파싱 실패 시 400), label = 라벨 이름 문자열
  - 빈 필터 = 무필터 (`BoardCardFilter.EMPTY`)
- **프론트는 query param만 조립·전송하고 백엔드가 SQL로 필터링한다.** 클라이언트 사이드 필터링 없음 (보드 카드 DTO에 라벨/컴포넌트 정보가 없음 — `BoardCard = { issueKey, summary, assigneeId, version }`).
- 백엔드 변경 0 (프론트 전용).

## 2. 사용자 시나리오 (Given-When-Then)

- **S1 담당자 필터**. Given 보드에 여러 담당자의 카드, When 필터 바에서 담당자 Alice 선택, Then Alice가 담당인 카드만 각 컬럼에 표시.
- **S2 미배정 필터**. Given 미배정 카드 존재, When "미배정" 토글, Then 담당자 없는 카드만 표시 (`assignee=unassigned`).
- **S3 라벨 필터**. Given 카드에 라벨, When 라벨 입력창에 "bug" 자동완성 선택, Then 라벨 "bug"가 달린 카드만 표시. 선택 라벨은 칩으로.
- **S4 컴포넌트 필터**. Given 카드에 컴포넌트, When 컴포넌트 "Backend" 체크, Then 그 컴포넌트 카드만.
- **S5 복합 필터(AND)**. Given 담당자 Alice + 라벨 bug 동시 선택, Then Alice가 담당이면서 bug 라벨인 카드만 (필드간 AND, 백엔드 위임).
- **S6 같은 필드 OR**. Given 담당자 Alice + Bob 선택, Then Alice 또는 Bob 담당 카드 (필드내 OR).
- **S7 필터 초기화**. Given 필터 적용 상태, When "초기화" 클릭, Then 전체 카드 복원 + URL에서 필터 param 제거.
- **S8 칩 개별 제거**. Given 여러 필터 칩, When 한 칩의 ✕ 클릭, Then 그 조건만 해제.
- **S9 새로고침 보존**. Given 필터 적용 URL, When 새로고침, Then 필터 상태 그대로 복원 (URL search params).
- **S10 드래그 후 유지**. Given 필터 적용 + 카드 드래그 이동, When 이동 완료(invalidate), Then 필터 유지된 채 재조회.

## 3. 기능 요구사항 (FR)

- **FR-1** 담당자 다중 선택 필터 + "미배정" 옵션. 선택값은 `assignee` 반복 query param(UUID 또는 `unassigned`)으로 전송.
- **FR-2** 라벨 다중 선택 필터(자동완성). 선택값은 `label` 반복 query param(라벨 이름)으로 전송.
- **FR-3** 컴포넌트 다중 선택 필터. 선택값은 `component` 반복 query param(UUID)으로 전송.
- **FR-4** 필드내 OR + 필드간 AND는 **백엔드가 적용**. 프론트는 선택값을 그대로 param 배열로 전송만.
- **FR-5** 빈 필터(아무것도 선택 안 함) = 무필터. param 없이 `GET /api/v1/boards/{boardId}` 호출.
- **FR-6** 필터 상태 = URL search params. 필터 변경 → `navigate`로 URL 갱신 → `useSearch` 재읽기 → `useBoard` queryKey 변경 → 자동 재조회.
- **FR-7** 필터 초기화 버튼 — 모든 필터 param 제거(보드 선택 `board`는 유지).
- **FR-8** 선택된 필터를 칩으로 표시, 칩 개별 제거 가능.
- **FR-9** 필터 옵션 목록 조회 실패(useUsers/useLabels/useComponents 에러)는 best-effort — 보드 자체는 정상 표시, 해당 필터 옵션만 비어있음.
- **FR-10** 활성 필터 개수/요약 표시(선택) — 필터가 1개 이상 적용 중임을 시각적으로 인지.
- **FR-11** ★`useMoveCard`도 `boardKeys.detail(boardId, filter)` filter-aware queryKey 사용 — 드래그 낙관적 업데이트(cancelQueries/setQueryData/invalidate)가 현재 필터된 캐시를 갱신. BoardPage가 현재 filter를 KanbanBoard → useMoveCard로 전달.
- **FR-12** 필터 바 배치 — 보드 선택 드롭다운(보드 2+개) 아래, 경고 배너·KanbanBoard 위. 보드 상세(`boardDetail`)가 있을 때만 렌더(EC7).

## 4. API 인터페이스 (프론트 → 백엔드)

```
GET /api/v1/boards/{boardId}?assignee=<uuid|unassigned>&assignee=<uuid>&label=<name>&component=<uuid>
→ { data: BoardDetail }   # 기존 응답 형태 불변 (필터는 결과 카드 집합만 좁힘)
```

- 다중값 = 반복 query param (예: `?assignee=a1&assignee=b2&label=bug&label=urgent`)
- 빈 필터 = param 생략
- 응답 스키마 변경 없음 (`boardDetailSchema` 그대로). `truncated`/`unplacedCount`는 필터 적용된 결과 기준으로 백엔드가 계산.

### 4.1 프론트 계약 변경

- `fetchBoard(boardId, filter?: BoardCardFilterParams)` — 비파괴 확장. filter 없으면 기존 동작.
- `BoardCardFilterParams = { assigneeIds: string[]; includeUnassigned: boolean; labels: string[]; componentIds: string[] }`
- `useBoard(boardId, filter?)` — queryKey에 filter 직렬화 포함 → 필터 변경 시 자동 재조회.
- URL search 스키마: `{ board?: string; assignee?: string[]; label?: string[]; component?: string[] }` (TanStack Router `validateSearch`, 단일값도 배열로 정규화).
  - `assignee` 배열 안에 `"unassigned"` 문자열이 있으면 `includeUnassigned=true`로 매핑.
  - **빈 배열/빈 값은 URL에서 param 자체를 생략**(빈 `?assignee=` 잔존 금지) — navigate 시 빈 필터 키는 undefined로 설정.
- queryKey: `boardKeys.detail(boardId, filter?)` = filter 없으면 `['board', boardId]`(기존 호환), 있으면 `['board', boardId, <정규화된 filter>]`. 정규화는 정렬된 안정 직렬화(키 순서 무관 동일 캐시).

## 6. 엣지 케이스

- **EC1** 빈 필터 = 전체 보드 (param 생략).
- **EC2** 필터 결과 0건 → 모든 컬럼 카드 0개. 컬럼 구조는 유지, "조건에 맞는 카드가 없습니다" 빈 상태 안내.
- **EC3** 필터 옵션 로딩 실패 → 보드는 정상, 옵션 목록만 빈 채로(best-effort, FR-9). 콘솔 에러 금지(no-console 정책).
- **EC4** truncated 상호작용 — 필터로 카드 줄면 백엔드 `truncated` 완화. 배너는 백엔드 응답값 그대로 반영(프론트 재계산 금지).
- **EC5** URL에 잘못된 UUID 직접 입력 → 프론트는 그대로 전송 → 백엔드 400(`AGILE_BOARD_FILTER_INVALID_UUID`) → 보드 영역에 에러 안내(기존 ApiError 처리 경로). 필터 칩은 유지해 사용자가 정정 가능.
- **EC6** 드래그 이동 후 invalidate → 현재 필터 queryKey로 재조회(필터 유지).
- **EC7** 보드 0개/403 등 기존 상태에서는 필터 바 미표시(보드 상세가 있을 때만 필터 바 렌더).
- **EC8** `assignee=unassigned`와 특정 담당자 동시 선택 = "미배정 또는 그 담당자"(백엔드 OR).
- **EC9** 담당자 1000명 상한 — 전체 나열 대신 typeahead 검색(`useUsers(query)`). URL의 assignee UUID는 보드 카드 userMap/별도 조회로 칩 라벨 해석, 미해석 시 UUID 일부 표시(best-effort).

## 7. 비기능 요구사항 (NFR)

- **NFR-1** 필터 변경 시 즉시 재조회. 라벨 자동완성은 **선택 확정 시에만** 필터 적용(타이핑 중 매 키 입력마다 보드 재조회 금지).
- **NFR-2** 접근성 WCAG AA — 모든 필터 컨트롤에 label 연결, 칩 제거 버튼 aria-label, 키보드 조작 가능.
- **NFR-3** i18n — 모든 표시 문자열은 ko 번역 리소스 사용(하드코딩 금지, 콜론 종결 금지). 라벨/요약은 ko.test 자동검증 통과.
- **NFR-4** CSRF 불필요(agile-planning = identity-access 전역 SecurityConfig, Bearer 토큰). 필터는 GET이라 변이 아님.
- **NFR-5** no-console — 에러는 toast/UI로, console.* 금지(eslint).

## 8. 측정 가능한 완료 기준

- **단위 테스트**
  - `fetchBoard` 필터 query string 조립(반복 param, unassigned 센티널, 빈 필터 생략).
  - `useBoard` queryKey가 filter 변경 시 달라짐(재조회 트리거).
  - URL search ↔ `BoardCardFilterParams` 매핑(단일값→배열 정규화, unassigned→includeUnassigned).
  - 필터 바 컴포넌트: 담당자/라벨/컴포넌트 선택·해제·칩·초기화.
- **E2E (Playwright, MSW)**
  - S1 담당자 필터로 카드 감소, S2 미배정, S3 라벨, S4 컴포넌트, S5 복합 AND, S7 초기화, S9 새로고침 보존.
  - MSW 핸들러가 query param을 읽어 필터된 카드 집합 반환(stateful, 실제 필터 동작 검증 — vacuous 금지).
- **품질 게이트**: `pnpm typecheck && pnpm lint && pnpm test && pnpm build` 그린, verify-master-plan 123/123.
