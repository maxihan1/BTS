# FR-NT-03 D6/D7 — 알림 정책 페이지 프론트 확장 + E2E — 스펙

> 선행: FR-NT-01(#118 정책/평가, #124 관리자 정책 페이지) · FR-NT-03 백엔드 D1~D5(#159 RecipientResolver 5역할)
> 범위: 프론트 전용(apps/web). 백엔드/마이그레이션/계약 변경 0.

## 배경 한 줄

수신자 역할 enum 9종은 이미 FR-NT-01 정책 폼(#124)에서 서버 카탈로그 기반으로 전부 선택 가능하다(`catalog.recipientRoles`, 한국어 라벨 존재). FR-NT-03 백엔드(#159)는 그중 5역할(WATCHER/COMPONENT_LEAD/PREVIOUS_ASSIGNEE/PROJECT_MEMBER/PROJECT_ADMIN)을 **실제 사용자 집합으로 해석**하도록 배선했고, RULE_OWNER는 automation BC 부재로 **skip(무동작)** 유지한다. 따라서 본 D6는 "새 화면"이 아니라 **기존 폼의 정보성·안전성 강화**다.

## 사용자 시나리오 (Given-When-Then)

- **S1 역할 설명 노출**. Given SYSTEM_ADMIN이 정책 폼의 수신자 역할 드롭다운을 연다. When 옵션 목록이 보인다. Then 각 역할 이름 옆/아래에 "누구에게 알림이 가는지" 한 줄 설명이 함께 표시된다(예: "구독자 — 이 이슈를 지켜보는 사용자").
- **S2 5역할 정책 생성 영속**. Given 정책 폼. When 이벤트·수신자(WATCHER/COMPONENT_LEAD/PREVIOUS_ASSIGNEE/PROJECT_MEMBER/PROJECT_ADMIN 중 하나)·채널을 선택하고 "정책 추가"를 누른다. Then 목록에 새 행이 추가되고 새로고침/재진입 후에도 영속된다(MSW stateful store).
- **S3 RULE_OWNER 비활성**. Given 수신자 역할 드롭다운. When 목록을 본다. Then "규칙 소유자(RULE_OWNER)" 항목은 비활성(선택 불가)으로 렌더되고 "(미지원)" 표시 + 자동화 추후 안내가 보인다. 클릭해도 선택되지 않는다(조용한 무동작 막다른 길 차단).
- **S4 비활성 역할은 제출 불가**. Given 폼. When RULE_OWNER는 선택할 수 없으므로 수신자로 RULE_OWNER인 정책을 생성하는 경로가 UI에 존재하지 않는다. Then 관리자가 무동작 정책을 실수로 만들 수 없다.

## 기능 요구사항 (FR)

- **FR1** 수신자 역할 9종 각각에 한국어 설명 문구를 단일 출처(`notification-policy-labels.ts`)에 정의하고 드롭다운에 노출한다. 문구는 백엔드 #159 해석 규칙과 일치한다(PREVIOUS_ASSIGNEE=직전 1명, COMPONENT_LEAD=컴포넌트 lead, PROJECT_MEMBER=프로젝트 전체 멤버, PROJECT_ADMIN=PROJECT_ADMIN, WATCHER=지켜보는 사용자).
- **FR2** 백엔드가 해석하지 않는 역할(현재 RULE_OWNER)을 프론트 상수 단일 출처(`UNSUPPORTED_RECIPIENT_ROLES`)로 관리하고, 해당 옵션을 드롭다운에서 `disabled`로 렌더 + 라벨에 "(미지원)" 류 표시를 붙인다.
- **FR3** 설명/비활성 처리는 서버 카탈로그(`catalog.recipientRoles`)가 내려준 역할 목록 위에서 동작한다(프론트가 역할 목록을 독자 생성하지 않음 — drift 차단). 미지 역할(라벨/설명 미정의)은 기존 `labelFor` fallback대로 원문 표시 + 설명 생략 + 비활성 아님(전방호환).
- **FR4** 설명은 select **외부의 정적 범례**로 렌더해 옵션의 accessible name(역할 이름)과 트리거 표시를 변경하지 않는다(기존 E2E 옵션 셀렉터 보존). 인라인 채택 시엔 설명 span `aria-hidden`로 동일 목표 달성.

## 비기능 요구사항 (NFR)

- **NFR1** 백엔드 호출/계약/엔드포인트 변경 0. 기존 `GET /catalog` 응답 그대로 소비.
- **NFR2** i18n 문구는 콜론으로 문장 종결 금지(ko.test 자동 검증 대상, [[fr-mf-05-trusted-devices-done]] 교훈). 라벨/설명도 예외 아님.
- **NFR3** 기존 NotificationPolicyForm 단위 테스트(네이티브 select mock)와 기존 E2E(S1~S5, #124)가 회귀 없이 통과.
- **NFR4** drift 방지 주석: `UNSUPPORTED_RECIPIENT_ROLES`·`recipientRoleDescriptions`는 기존 `recipientRoleLabels` 주석과 동일하게 "백엔드 enum/지원범위 변경 시 동반 갱신" 명시.

## UI 설계 (plan 단계 확정 — design-review 재검토 대상)

- **설명 = 정적 범례(legend) [1차 채택]**. 수신자 역할 select 아래에 항상 보이는 muted 설명 목록을 `NotificationPolicyForm` 내부에 렌더(역할 라벨 → `recipientRoleDescriptions[role]`). 카탈로그 역할 9종 기준. 이유:
  - **테스트 가능성**: 폼 단위 테스트(네이티브 select mock)에서 범례는 일반 DOM이라 Radix 드롭다운 open 여부와 무관하게 직접 검증 가능. 인라인은 Radix가 jsdom에서 안 열려 실 컴포넌트 테스트가 까다로움.
  - **범위**: 공유 `ui/select.tsx` 변경 0(전역 blast radius 회피). 인라인은 공유 SelectItem 확장 필요.
  - **접근성/회귀**: 옵션 accessible name 무변경 → 기존 E2E `getByRole('option',{name,exact:true})` 그대로 보존(aria-hidden 트릭 불요, 스펙 §Brainstorming gap#1을 구조적으로 회피).
  - **항상 보임**: 드롭다운 열기 전에도 역할 의미 확인 가능(학습성).
  - 대안(인라인 per-item, Maxi 선택 옵션 목업 형태): 공유 SelectItem에 optional `description` prop(aria-hidden) 추가. 위치만 다르고 전달 정보 동일. **게이트 1에서 Maxi 확인 + design-review 재검토.**
- **비활성**. `buildRecipientRoleOptions`에서 role ∈ `UNSUPPORTED_RECIPIENT_ROLES`이면 `<SelectItem disabled>` + 라벨 `"${labelFor(...)} (미지원)"`. Radix가 `data-disabled`/`aria-disabled=true` 부여 → 선택 차단. (SelectItem은 radix passthrough라 `disabled` 이미 지원 — 공유 컴포넌트 변경 불요.) 범례의 해당 역할 줄에도 "(미지원·자동화 추후)" 명시.

## 엣지 케이스

- 미지 역할(서버가 라벨/설명 미정의 enum 추가): `labelFor` 원문 fallback + 설명 없음 + 활성 유지(전방호환). 비활성 목록에 없으면 선택 가능(보수적: 모르는 건 막지 않음 — 단, 알려진 무동작 RULE_OWNER만 명시 차단).
- RULE_OWNER가 서버 카탈로그에서 빠지는 경우(향후): 비활성 항목 자체가 안 보임 → 무해(추가 처리 불요).
- jsdom 단위 테스트: Radix Select가 네이티브 `<select>` mock으로 대체됨 → 인라인 description/`disabled`의 실제 렌더는 **E2E(실 Radix)가 권위 검증처**. 단위는 mock이 `disabled`/description를 option에 전달하도록 보강하거나, 실 `SelectItem` 전용 단위 테스트로 description/disabled 렌더 검증.
