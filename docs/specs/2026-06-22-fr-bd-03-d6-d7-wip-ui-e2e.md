## 배경 — 백엔드 신호(실측)

GET `/api/v1/boards/{id}` = `BoardDetailResponse`:
- `columns[].wipLimit: Int?` (null=무제한), `columns[].wipExceeded: Boolean` (카드수 > wipLimit, strictly greater)
- `swimlaneField: String` ("NONE"/"ASSIGNEE"/"PRIORITY")
- 카드: `{ issueKey, summary, assigneeId: UUID?, version }` — **priority는 이 작업에서 재노출**

설정 쓰기(권한 IssuePermission.CREATE on Project):
- `PATCH /api/v1/boards/{id}` body `{ swimlaneField: String }` → BoardMetaResponse
- `PATCH /api/v1/boards/{id}/columns/{columnId}` body `{ wipLimit: Int? }` → ColumnMetaResponse (이번 D6에선 미사용 — '편집' UI 이연)

권한 사전 조회: GET `/api/v1/users/me/project-permissions?projectKey=` → `permissions.CREATE: boolean`.

## 사용자 시나리오 (Given-When-Then)

### S1. WIP 초과 컬럼 헤더 경고
- **Given** "In Progress" 컬럼의 `wipLimit=2`이고 카드가 3개(`wipExceeded=true`)
- **When** 사용자가 보드를 연다
- **Then** 해당 컬럼 헤더에 시각 경고(카드수/제한 배지가 경고 색 + "WIP 초과" 의미의 aria-label)가 표시된다. **카드 이동은 차단되지 않는다**(ADR 결정 1).

### S2. WIP 제한 표시(초과 아님)
- **Given** 컬럼 `wipLimit=5`, 카드 2개(`wipExceeded=false`)
- **When** 보드를 연다
- **Then** 헤더에 "2/5" 형태의 일반(비경고) 표시. wipLimit이 null이면 기존처럼 카드 수만 표시.

### S3. 스윔레인 전환 — 담당자(ASSIGNEE)
- **Given** CREATE 권한 보유 사용자, 보드 `swimlaneField=NONE`
- **When** 보드 상단 스윔레인 셀렉터에서 "담당자"를 선택
- **Then** PATCH `/boards/{id}` `{swimlaneField:"ASSIGNEE"}` 호출 → 성공 시 보드가 담당자별 가로 레인으로 그룹화돼 표시된다. 각 레인 헤더에 담당자 이름(미배정 레인 포함). 새로고침/재진입 후에도 ASSIGNEE 유지(서버 저장).

### S4. 스윔레인 전환 — 우선순위(PRIORITY)
- **Given** CREATE 권한 사용자
- **When** 셀렉터에서 "우선순위"를 선택
- **Then** PATCH 성공 후 우선순위 값별 가로 레인으로 그룹화. 레인 헤더에 우선순위 라벨.

### S5. 스윔레인 없음(NONE)
- **When** 셀렉터에서 "없음"을 선택(또는 기본값)
- **Then** 기존 단일 카드 리스트(레인 분리 없음)로 표시.

### S6. 권한 없는 사용자
- **Given** CREATE 권한이 없는 사용자(`permissions.CREATE=false`)
- **Then** 스윔레인 셀렉터가 노출되지 않는다(또는 disabled). 단, 보드는 서버 저장된 `swimlaneField` 기준 그룹으로 **표시는 정상**(읽기는 BROWSE 권한).

### S7. 스윔레인 변경 실패(403/네트워크)
- **Given** 셀렉터 변경 시도 중 PATCH가 403/오류 반환
- **Then** 토스트로 안내하고 셀렉터 값을 이전 상태로 롤백한다(낙관적 표시 시 롤백). 보드 데이터는 변경되지 않는다.

## 기능 요구사항 (FR)

- **FR1**. 프론트 Zod 스키마(`apps/web/src/api/boards.ts`)를 백엔드 D4 신호에 맞춰 확장: `boardCardSchema`에 `priority: number`, `boardColumnSchema`에 `wipLimit: number|null`·`wipExceeded: boolean`, `boardDetailSchema`에 `swimlaneField: enum`.
- **FR2**. **백엔드 view-layer patch(same-BC)**: `BoardCardResponse`에 `priority: Int` 재노출(NIT-1 되돌림). `BoardIssueView.priority`를 매핑. PRIORITY 스윔레인 그룹화 근거.
- **FR3**. 컬럼 헤더 WIP 표시: `wipLimit !== null`이면 "카드수/제한" 표기. `wipExceeded`면 경고 스타일 + 접근성 라벨. null이면 기존(카드수만) 보존.
- **FR4**. 스윔레인 셀렉터(보드 상단): NONE/ASSIGNEE/PRIORITY. 변경 시 PATCH `/boards/{id}` 호출 + 보드 쿼리 invalidate. CREATE 권한자에게만 노출.
- **FR5**. 스윔레인 그룹 렌더 — **컬럼 내부 레인 그룹(세로)**(Maxi 결정 2026-06-22). 각 컬럼의 droppable column id를 그대로 유지하고, 컬럼 안에서 카드를 레인별 서브헤더로 묶는다(드래그 이동 회귀 0). 스윔레인 간 드래그로 담당자/우선순위 '변경'은 범위 아님.
  - NONE: 기존 컬럼별 단일 리스트(서브헤더 없음).
  - ASSIGNEE: 컬럼 안에서 담당자(assigneeId)별 서브그룹. 기존 `assigneeNames` Map 재사용으로 그룹 라벨. 미배정 그룹 포함. 그룹 순서 = 이름 가나다 + 미배정 마지막.
  - PRIORITY: 컬럼 안에서 priority 값별 서브그룹. 그룹 라벨 = 우선순위 표기. 그룹 순서 = priority asc(작을수록 높은 우선순위).
- **FR6**. WIP 제한 '편집' UI는 이번 범위에서 제외(후속 이연 — 스펙에 명시). 표시/경고만.
- **FR7**. E2E(Playwright): S1(WIP 경고 표시), S3/S4(스윔레인 전환+그룹), S6(권한 없는 사용자 셀렉터 미노출) 핵심 happy path. MSW 영속 핸들러로 PATCH 라운드트립 검증.

## 엣지 케이스

- **EC1**. `wipLimit=null` → 표시 변화 없음(카드 수만).
- **EC2**. `wipExceeded=true`인데 `wipLimit=null` → 불가(백엔드가 null이면 항상 false). 방어적으로 wipLimit null이면 경고 미표시.
- **EC3**. ASSIGNEE 스윔레인에서 담당자 이름 미해석(unknown) → "이름 미확인" 레인 또는 unknown 그룹. 미배정(null)과 구분.
- **EC4**. PRIORITY 스윔레인에서 카드 priority가 동일 → 단일 레인. 모든 우선순위 표시 순서는 priority 값 asc(작을수록 높은 우선순위, BoardIssueLookupPort.kt:124).
- **EC5**. 스윔레인 전환 PATCH 진행 중 빠른 재선택 → 마지막 선택 기준, invalidate 후 서버값으로 수렴.
- **EC6**. 드래그 이동(FR-BD-01) 회귀 0 — 컬럼 내부 레인 그룹이므로 droppable column id는 컬럼당 1개 그대로 유지. 카드는 서브그룹으로 묶어 표시만 하고, useDraggable id(issueKey)/useDroppable id(columnId)는 불변.
- **EC7**. 빈 보드/필터 결과 0건 — 기존 빈 상태 보존, 스윔레인 그룹 미적용.
