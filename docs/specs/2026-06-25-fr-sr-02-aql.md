# FR-SR-02 — AQL 텍스트 쿼리 (JQL 호환) 백엔드 코어 MVP — 스펙

> 관련 ADR. [docs/decisions/2026-06-25-fr-sr-02-aql-parser-and-bc.md](../decisions/2026-06-25-fr-sr-02-aql-parser-and-bc.md)
> SDD. 10.1 (AQL). FR-SR-01 ADR. [2026-06-23-fr-sr-01-issue-filter-bc.md](../decisions/2026-06-23-fr-sr-01-issue-filter-bc.md)

## 0. 한 줄 요약

사용자가 `summary ~ "로그인" AND status = open AND (label = bug OR label = urgent)` 같은 텍스트 쿼리를 보내면, 손수 작성한 파서가 AST로 변환하고 issue-tracking이 그 AST를 visibility 보안 술어와 결합해 jOOQ로 실행, 접근 가능한 이슈만 페이지로 돌려준다.

## 1. 사용자 시나리오 (Given-When-Then)

- **S1 단순 검색.** Given 사용자가 PROJ 프로젝트에 접근 가능. When `POST /api/v1/search/aql` 에 `{"query": "status = open"}` 전송. Then open 상태이며 사용자가 볼 수 있는 이슈 페이지 반환.
- **S2 불리언 조합.** Given. When `summary ~ "버그" AND (label = urgent OR priority = 1)`. Then 제목에 "버그" 포함 AND (라벨 urgent 또는 우선순위 1)인 이슈 반환.
- **S3 정렬.** Given. When `status = open ORDER BY priority DESC`. Then 우선순위 내림차순 정렬된 결과.
- **S4 권한 차단.** Given 사용자가 볼 수 없는 보안 등급 이슈가 조건에 부합. When 검색. Then 그 이슈는 결과에서 제외(visibility 술어 AND 결합, 우회 불가).
- **S5 문법 오류.** Given. When `status = = open`(문법 오류). Then 400 + 오류 위치(컬럼)와 메시지 반환. 결과 없음.
- **S6 알 수 없는 필드.** Given. When `foobar = 1`(미지원 필드). Then 400 + "지원하지 않는 필드: foobar".

## 2. 기능 요구사항 (FR)

### FR-1. AQL 문법 (MVP)

손수 작성 렉서 + 재귀하강 파서. 지원 문법(EBNF 근사).

```
query        := orExpr (ORDER BY sortList)?
orExpr       := andExpr (OR andExpr)*
andExpr      := notExpr (AND notExpr)*
notExpr      := NOT notExpr | primary
primary      := '(' orExpr ')' | comparison
comparison   := field operator value
             |  field ('IN' | 'NOT' 'IN') '(' valueList ')'
field        := IDENT
operator     := '=' | '!=' | '~'
value        := QUOTED_STRING | BARE_WORD | NUMBER
valueList    := value (',' value)*
sortList     := field ('ASC'|'DESC')? (',' field ('ASC'|'DESC')?)*
```

- 키워드(AND/OR/NOT/IN/ORDER/BY/ASC/DESC)는 **대소문자 무시**.
- 문자열 리터럴은 큰따옴표 `"..."`. 공백/특수문자 없는 값은 따옴표 생략 가능(bare word).
- `~`(contains) 연산자는 부분 문자열 일치(MVP는 대소문자 무시 `ILIKE %v%`. pg_trgm 유사도는 후속).

**MVP 제외(후속 PR 명시).** 함수(`currentUser()`/`now()`/`startOfDay()`), 상대 날짜(`-7d`/`+1w`), `is EMPTY`/`is NOT EMPTY`, `>`/`>=`/`<`/`<=` 범위 비교, pg_trgm 유사도, 한글 형태소(FR-SR-04).

### FR-2. 지원 필드 (MVP) — ⚠️ Maxi 확인 항목

값이 텍스트/키/숫자로 직관적이어서 사용자가 따옴표 텍스트로 입력 가능한 필드만 MVP에 포함한다.

| AQL 필드 | 매핑 | 연산자 | 값 형식 |
|---|---|---|---|
| `status` | current_state_key | `=` `!=` `IN` `NOT IN` | 워크플로우 상태 키(예 open) |
| `label` | 라벨 | `=` `!=` `IN` `NOT IN` `~` | 문자열 |
| `summary` | 제목 | `~` `=` | 문자열(주 용도 `~`) |
| `priority` | 우선순위 | `=` `!=` `IN` `NOT IN` | 정수 |

(`project`는 AQL 본문 미지원 — 요청 파라미터 projectKey로 단일 스코프 지정. FR-4 참조. cross-project AQL `project` 필드는 후속.)

**후속 분리.** `assignee`/`reporter`/`component`는 사용자·컴포넌트 **식별자 해석**(username→UUID, 이름→ID)이 필요해 `currentUser()` 함수와 함께 후속 PR로 분리한다. MVP에서 이들 필드 사용 시 400("후속 지원 예정 필드").

### FR-3. AST → jOOQ 변환 + visibility (issue-tracking)

- search 모듈이 만든 AST를 `IssueSearchPort`로 issue-tracking에 전달. issue-tracking 어댑터가 AST를 재귀 순회하며 jOOQ `Condition`으로 변환.
- visibility 보안 술어(`buildSecurityCondition` + `IssueSecurityDirectory.accessibleLevels`)를 **항상 AND로 최상위 결합**. 사용자 AST는 보안 술어 위에만 얹힌다(우회 불가). soft-deleted 제외.
- 미지원 필드/연산자 조합은 변환 단계에서 거부(400). 단, 가능하면 파싱/검증 단계에서 조기 거부.

### FR-4. API

```
POST /api/v1/search/aql
Body: { "projectKey": "PROJ", "query": "<AQL 텍스트>", "page": 0, "size": 50 }
200: Page<AqlSearchHit>   (Spring Page 형식, 기존 GET /issues와 동형)
400: ProblemDetail { code, detail, errorCode, position? }  (문법/필드 오류)
401: 미인증
```

- 인증 필수(기존 인증 필터 체인). actor를 SecurityContext에서 추출(위조 차단). **actor 추출은 리소스/검증 이전에 수행**(교훈 auth-extraction-before-resource-lookup).
- **projectKey 필수(단일 프로젝트 스코프).** MVP는 SR-01 GET /issues?projectKey= 와 일관되게 한 프로젝트 안에서만 검색한다. visibility 보안(`accessibleLevels(actor, projectKey)`)이 프로젝트 단위이므로 단일 스코프가 가장 단순·안전하다. cross-project 검색(`project IN (...)` 전역)은 후속 PR. 따라서 MVP의 AQL 본문에서 `project` 필드는 미지원(요청 파라미터 projectKey로 대체) — 후속에 AQL `project` 필드 추가.
- `AqlSearchHit`(search 모듈 응답 DTO)는 shared-kernel 중립 View(`IssueSearchHit`)에서 직렬화. 필드(MVP) — key, summary, currentStateKey, assigneeId(nullable), priority, projectKey.
- 페이지네이션. page(0-base)/size. size 기본 50, 최대 100(초과 시 100 클램프 또는 400 — spec 확정값. **클램프 채택**).
- 정렬. ORDER BY 파싱 결과 적용. 미지정 시 기본 `created_at DESC`. 정렬 필드도 FR-2 화이트리스트 한정.

### FR-5. 신규 포트 (shared-kernel)

```kotlin
interface IssueSearchPort {
    fun search(
        projectKey: String,      // 단일 프로젝트 스코프(필수, FR-4)
        ast: AqlNode,            // 또는 중립 criteria — plan서 확정(AST-as-contract 유력)
        sort: List<AqlSort>,
        viewerUserId: UUID,
        page: Int,
        size: Int,
    ): IssueSearchPage
}
```

AST/AqlNode/AqlSort의 정의 위치(shared-kernel vs search 모듈)는 plan에서 확정. shared-kernel 경계 가드(`SharedKernelBoundaryArchTest`) 통과 필수.

## 3. 비기능 요구사항 (NFR)

- **NFR-1 성능.** product 임계 — AQL 100만건 검색 p95 < 1s. MVP는 인덱스 활용(기존 status/assignee 부분 인덱스 V029) + LIMIT/OFFSET. pg_trgm 가속은 후속.
- **NFR-2 보안.** visibility 우회 불가(FR-3). SQL injection 불가(jOOQ 바인딩, 문자열 직접 조립 금지). 입력 길이 상한(쿼리 문자열 max 2000자, 토큰 수 상한으로 DoS 방지).
- **NFR-3 BC 격리.** search 모듈은 issue-tracking 내부/ jOOQ 직접 접근 금지(ArchUnit). 포트 경유만.
- **NFR-4 에러 명확성.** 문법 오류는 위치(컬럼 인덱스)와 사람이 읽을 메시지 제공.
- **NFR-5 예외 핸들러 격리.** 신규 search BC 컨트롤러는 형제 BC의 `@RestControllerAdvice`가 적용되지 않으므로 **자체 예외 핸들러**(`@RestControllerAdvice(assignableTypes=[SearchController::class])` 또는 basePackages 한정)를 둔다. AQL 문법/필드 예외(400)·미인증(401)을 명시 매핑해 catch-all에 의한 500 변질을 차단(교훈 catch-all-exceptionhandler-swallows-responsestatusexception · domain-exception-http-handler-basepackage-scope). errorCode를 응답에 명시.

## 4. 엣지 케이스

- 빈 쿼리(`""` 또는 공백) → 400("빈 쿼리").
- 괄호 불균형 `(status = open` → 400 + 위치.
- 닫히지 않은 따옴표 `summary ~ "abc` → 400 + 위치.
- 중복 ORDER BY / ORDER BY 뒤 표현식 → 400.
- IN 빈 목록 `status IN ()` → 400.
- 매우 깊은 중첩(괄호 폭탄) → 깊이 상한(예 50)으로 거부(DoS).
- project 필드와 전체 검색 — project 미지정 시 viewer가 접근 가능한 모든 프로젝트 대상(visibility 술어가 자연 제한).
- 결과 0건 → 빈 페이지(정상 200).

## 5. 데이터 모델 변경

- **없음(MVP).** 신규 테이블/컬럼/마이그레이션 없음. 기존 issues 및 V029 인덱스 활용. pg_trgm 확장/인덱스는 후속 PR.

## 6. 측정 가능한 완료 기준

- 파서 단위 테스트 50+ (JQL 호환 케이스 — 비교/IN/불리언/괄호/정렬/오류 위치). ADR §1.1 "단위 50개" 충족.
- AST→jOOQ 변환 단위 테스트(각 연산자/필드, 보안 술어 AND 결합 확인).
- 통합 테스트(Testcontainers) — 실제 이슈 시드 후 visibility 차단(S4)·문법오류 400(S5)·미지원 필드 400(FR-2 후속필드 포함) end-to-end.
- ArchUnit — search BC 격리 룰 + shared-kernel 경계 통과.
- 기존 issue-tracking 테스트 회귀 0(SR-01 GET /issues 무변경).
