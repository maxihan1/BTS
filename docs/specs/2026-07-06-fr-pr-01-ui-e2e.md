> BC: personalization(논리) / identity-access(물리)
> 백엔드 D1~D5 완료(PR #238). 이 문서는 D6(프론트 UI)·D7(E2E) 범위.

## 범위 결정 (Maxi 확정 2026-07-06)

- **타임존 입력**. 네이티브 `<select>` + `Intl.supportedValuesOf('timeZone')` 전체 IANA 목록. 신규 combobox 컴포넌트 없음.
- **Header 연동 포함**. whoami 응답에 `displayName`+`avatarUrl` 추가(identity-access same-BC 백엔드 view-layer 패치, learnings PR #13 선례) + Header가 아바타/표시이름 렌더. → 이 PR은 UI + 동일 BC 백엔드 혼합, BC 격리 유지(타 BC import 0).

## 사용자 시나리오 (Given-When-Then)

- **S1 프로필 조회**. Given 로그인한 사용자가 `/settings/profile` 진입, When 페이지 로드, Then GET `/me/profile` 결과로 username·email(읽기 전용) + displayName·timezone·department(편집 가능) + 현재 아바타(또는 이니셜 폴백)를 표시한다.
- **S2 표시이름/타임존/부서 저장**. Given 폼에서 displayName="김맥시", timezone="Asia/Seoul", department="플랫폼팀" 입력, When "저장" 클릭, Then PATCH `/me/profile` 1회 호출 후 성공 메시지 + 폼이 갱신값 반영.
- **S3 부서 비우기(3-state)**. Given department에 값이 있던 사용자가 필드를 비우고 저장, When PATCH, Then department=명시 null로 전송돼 부서가 삭제된다(빈 문자열이 아니라 null).
- **S4 아바타 업로드**. Given 사용자가 파일 선택(이미지, ≤5MB), When 선택 즉시 POST `/me/profile/avatar` (multipart part=`file`), Then 성공 시 새 아바타가 미리보기·Header에 반영.
- **S5 아바타 삭제**. Given 아바타가 설정된 사용자, When "아바타 삭제" 클릭, Then DELETE `/me/profile/avatar` 후 이니셜 폴백으로 되돌아감(멱등, 없어도 성공).
- **S6 검증 실패 표시**. Given displayName을 빈 값으로 저장 시도, When PATCH가 400 PROFILE_VALIDATION_FAILED 반환, Then 폼에 한글 에러 메시지(`role=alert aria-live`)를 표시하고 화면은 유지.
- **S7 아바타 크기/형식 위반**. Given 6MB 파일 또는 비이미지 선택, When POST가 400 AVATAR_VALIDATION_FAILED, Then "아바타 파일이 너무 큽니다/지원하지 않는 형식" 계열 한글 메시지 표시.
- **S8 미인증 가드**. Given 미인증 상태로 `/settings/profile` 접근, When beforeLoad requireAuth, Then `/login`으로 리다이렉트(기존 settings 페이지 관례).
- **S9 Header 표시**. Given displayName·avatarUrl이 있는 사용자, When 앱 로드(whoami), Then Header 계정 버튼이 아바타 이미지 + displayName을 표시(avatarUrl null이면 이니셜, displayName null이면 username 폴백).

## 기능 요구사항 (FR)

### 프론트 — 프로필 페이지
- **F1**. `/settings/profile` 라우트(code-based, `Page`+`RouteAdapter`, `requireAuth` 가드). Header 계정 드롭다운에 "프로필" 링크 추가.
- **F2**. GET `/me/profile`을 TanStack Query로 조회. 로딩/에러 상태 표시.
- **F3**. 편집 폼 — displayName(text, required), timezone(native select, IANA 전체, required), department(text, 비우기 허용). username·email은 읽기 전용 표시. "저장" 클릭 시 PATCH 1회.
- **F4**. 3-state 매핑 — 폼이 서버 값 대비 변경된 필드만 PATCH body에 실어 보낸다. department는 빈 문자열 입력 시 명시 `null`로 전송(삭제), 미변경 시 키 생략(부재). displayName/timezone은 값이 있으면 그대로 전송.
- **F5**. 아바타 — 현재 아바타 또는 displayName 이니셜 폴백을 표시하는 `Avatar` 컴포넌트. 파일 선택 시 즉시 업로드(POST), "삭제" 버튼으로 DELETE. 아바타 뮤테이션은 profile 쿼리 invalidate + whoami 쿼리 invalidate.
- **F5-1 (인증 이미지 fetch, ★ Phase B 발견)**. 메인 API는 STATELESS + JWT Bearer(Authorization 헤더 주입, `useAuthStore`)이고 아바타 GET은 `@PreAuthorize("isAuthenticated()")`다. `<img>` 태그는 Authorization 헤더를 실을 수 없어 **직접 `<img src={avatarUrl}>`는 401로 깨진다**(MSW E2E는 가짜 그린으로 은폐). 따라서 `Avatar`는 `apiFetch(avatarUrl)` → `res.blob()` → `URL.createObjectURL` → `<img src={objectUrl}>`로 표시하고 언마운트/교체 시 `revokeObjectURL`한다 — `AttachmentPreviewModal.tsx`의 인증 이미지 표시 선례를 재사용. `avatarUrl`(whoami/profile 응답)은 (a) 아바타 존재 여부 판정 + (b) fetch 경로로만 쓰고, src로 직접 넣지 않는다.
- **F6**. 클라이언트 검증 최소화 — displayName 빈 값은 버튼 비활성 또는 제출 차단, 나머지 정책(길이/형식)은 서버 위임(drift 차단, ChangePasswordForm 선례). 아바타 크기/MIME는 서버가 최종 판정하되 UX용 `accept="image/*"` 힌트만.
- **F7**. 에러 매핑 — 백엔드 `{code,message}`의 code(UPPER_SNAKE)를 프론트 상수 테이블로 한글 매핑(백엔드 message 무시). PROFILE_VALIDATION_FAILED / AVATAR_VALIDATION_FAILED / PROFILE_NOT_FOUND / AVATAR_NOT_FOUND / 401.
- **F8**. 제출 중(isPending) 버튼 비활성 + 중복 제출 차단.

### 프론트 — Header 연동
- **F9**. `WhoamiResponseSchema`에 `displayName: z.string().nullable()`, `avatarUrl: z.string().nullable()` 추가.
- **F10**. Header 계정 트리거가 `Avatar`(avatarUrl→이미지, null→이니셜) + displayName(null→username 폴백)을 렌더. `aria-label`도 displayName 우선.

### 백엔드 — whoami view-layer (identity-access same-BC)
- **F11**. `WhoamiResponse` DTO에 `displayName: String?`, `avatarUrl: String?` 추가.
- **F12**. `WhoamiController` JWT 분기 — `displayName = user.displayName`, `avatarUrl = UserProfileRepository.findByUserId(userId)?.avatarObjectKey?.let { "/api/v1/users/$userId/avatar" }`. PAT 분기는 봇 컨텍스트라 둘 다 null(기존 username="" 관례와 동일).

### D7 — E2E
- **F13**. `profile.spec.ts` — S1(조회)·S2(저장)·S4(아바타 업로드)·S5(삭제)·S6(검증실패) happy/edge 시나리오. MSW stateful 핸들러로 조회↔수정 반영 검증. i18n 라벨 정본 import(hardcoded 금지).
- **F14**. UI 추가가 기존 settings E2E(password-change 등)의 셀렉터를 깨지 않는지 함께 실행(ui-pr-defer-e2e-regression-latent 회귀 방지).

## 비기능 요구사항 (NFR)
- **N1 a11y**. 폼 라벨(`htmlFor`), 에러 `role=alert aria-live=polite`, 성공 `role=status`, 아바타 이미지 `alt`. 아바타 파일 input에 접근 가능한 라벨.
- **N2 계약 정합**. Zod 스키마는 백엔드 DTO와 1:1(ProfileResponse/AvatarUploadResponse/WhoamiResponse). backend DTO invent 금지(frontend-zod-backend-dto-contract-gap).
- **N3 E2E 견고성**. 텍스트 중복 버튼("저장" 등)은 컨테이너 한정 또는 접근 가능한 이름으로 유일화(strict mode violation 방지).
- **N4 보안**. 뮤테이션(PATCH/POST/DELETE)에 X-XSRF-TOKEN 헤더(readXsrfToken, double-submit cookie). 인증은 apiFetch 기본(JWT Bearer). 아바타 GET은 apiFetch blob fetch(F5-1) — 직접 `<img src>` 금지(STATELESS JWT라 401).

## API 인터페이스 (소비 계약)
백엔드 PR #238 확정 — 이 PR에서 백엔드 신규 없음(whoami DTO +2 필드 제외).
- `GET  /api/v1/users/me/profile` → `{ userId, username, email|null, displayName, avatarUrl|null, timezone, department|null }`
- `PATCH /api/v1/users/me/profile` (body 3-state `{ displayName?, timezone?, department? }`) → 갱신 후 ProfileResponse. 400 PROFILE_VALIDATION_FAILED.
- `POST /api/v1/users/me/profile/avatar` (multipart part=`file`) → `{ avatarUrl }`. 400 AVATAR_VALIDATION_FAILED(5MB/MIME).
- `GET  /api/v1/users/{userId}/avatar` → 이미지 바이너리(nosniff·inline).
- `DELETE /api/v1/users/me/profile/avatar` → 204(멱등).
- `GET  /api/v1/users/me/whoami` → 기존 + `displayName|null`, `avatarUrl|null` (이 PR에서 추가).

## 엣지 케이스
- **EC1**. 프로필 행 lazy — 아바타/타임존 한 번도 설정 안 한 사용자는 timezone="UTC"(컬럼 기본), department=null, avatarUrl=null로 정상 응답(백엔드 처리). 프론트는 그대로 표시.
- **EC2**. department 빈 문자열 vs null — 폼에서 공백만 입력 후 저장 시 trim하여 빈 값이면 null 전송(삭제 의미). 3-state 매핑 명확화.
- **EC3**. timezone 목록에 서버가 준 현재 값이 없을 가능성 — `Intl.supportedValuesOf`는 런타임 전체 목록이라 서버 저장값이 목록에 없을 수 없음(둘 다 IANA). 그래도 방어적으로 현재 값이 옵션에 없으면 그 값을 옵션으로 추가.
- **EC4**. 아바타 업로드 중 연속 클릭 — isPending 동안 input/버튼 비활성.
- **EC5**. 아바타 삭제 멱등 — 아바타 없는 사용자가 삭제해도 204(백엔드), 프론트는 성공 처리.
- **EC6**. whoami PAT 분기 — displayName/avatarUrl null. Header는 username 폴백(PAT 세션은 대화형 UI 대상 아님, 방어만).
- **EC7**. 아바타 갱신 — blob fetch 방식이라 업로드/삭제 후 profile+whoami 쿼리 invalidate → 재fetch로 새 blob objectURL 생성 → 즉시 반영(브라우저 URL 캐시 우회, 캐시버스터 불필요).
- **EC8**. 아바타 fetch 404 — avatarUrl이 있었으나 사이 삭제돼 GET이 AVATAR_NOT_FOUND(404)면 이니셜 폴백으로 조용히 처리(에러 배너 금지). blob fetch 실패는 폴백.
- **EC9**. 파일 input 재선택 — 업로드 후 input.value 초기화해 같은 파일 재선택이 change 이벤트를 다시 발화하게 함.
