## 사용자 시나리오 (Given-When-Then)

**S1. 담당자 이름 표시 (G1 해소).**
- Given. ATLAS 프로젝트 백로그에 담당자가 김앨리스인 이슈가 있다
- When. 사용자가 백로그 화면을 연다
- Then. 그 카드에 **`김` 이니셜 아바타**가 보이고 접근성 이름이 `담당자: 김앨리스` 다

**S2. 스프린트 칸도 동일.**
- Given. 스프린트 1 에 담당자가 있는 이슈가 있다
- When. 백로그 화면을 연다
- Then. 스프린트 칸 카드도 이니셜 아바타를 표시한다 (백로그 칸과 같은 Map 을 공유)

**S3. 미배정은 그대로.**
- Given. `assigneeId = null` 인 이슈가 있다
- When. 백로그 화면을 연다
- Then. `미배정` 텍스트가 보인다 (`?` 아바타 아님 — 기존 3상태 유지)

**S4. 이름을 못 찾은 담당자.**
- Given. 이슈의 `assigneeId` 가 사용자 조회 결과에 없다 (삭제·비활성 사용자)
- When. 백로그 화면을 연다
- Then. `?` 아바타 + `이름 미확인` 툴팁 (기존 동작 보존 — 이 상태는 **정당한 상태**다)

**S5. 담당자 50명 초과 (M1 의 판정식).**
- Given. 백로그 전체에 서로 다른 담당자가 60명 있다
- When. 백로그 화면을 연다
- Then. **60명 전원**의 이름이 채워진다 (요청은 50 + 10 으로 나뉜다)

**S6. 조회 실패 → 에러 + 재시도 (G2 해소).**
- Given. 백로그 조회 API 가 500 을 돌려준다
- When. 사용자가 백로그 화면을 연다
- Then. `role="alert"` 안내와 `다시 시도` 버튼이 보인다. 빈 화면이 아니다

**S7. 재시도 성공.**
- Given. S6 상태에서 서버가 회복됐다
- When. 사용자가 `다시 시도` 를 누른다
- Then. 백로그가 정상 렌더된다 (`refetch` 경유. 새로고침 불필요)

**S8. 담당자 조회만 실패해도 보드는 산다.**
- Given. 백로그 조회는 성공, 사용자 조회만 실패한다
- When. 백로그 화면을 연다
- Then. 카드는 정상 렌더되고 담당자만 `?` 로 떨어진다. **전체 에러 화면으로 가지 않는다**
  (담당자 이름은 보조 정보다 — 이것 때문에 백로그를 통째로 막으면 안 된다)
