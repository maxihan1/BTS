## 범위

1. **템플릿 관리 페이지** — 프로젝트 설정 하위 `/projects/{projectKey}/settings/issue-templates`. 목록 + 생성/수정 다이얼로그 + 삭제. **커스텀 필드 관리(FR-IS-10) 동형 미러**.
2. **권한 노출(B2 연기분)** — 백엔드 `MyProjectPermissionController`에 `MANAGE_TEMPLATES` 추가 + 프론트 `project-permissions` 반영. 버튼 게이팅 전제.
3. **E2E** — 관리 페이지 CRUD + 권한 게이팅 시나리오.
4. **범위 외**(분리) — 이슈 생성폼 타입선택/프리필 UI. 서버 안전망이 자동적용 담당.

## 사용자 시나리오 (Given-When-Then)

- **S1 목록**. Given 프로젝트 관리자 Alice가 설정 진입. When `issue-templates` 탭 열기. Then (project,type)별 활성 템플릿 목록(이름·타입·수정시각)이 보인다. 없으면 빈 상태 안내.
- **S2 생성**. Given 관리자. When "템플릿 추가" → 이슈 타입 선택 + 이름 + 본문(Markdown) 입력 후 저장. Then 201 → 목록에 추가, 다이얼로그 닫힘.
- **S3 중복**. Given (project,type) 템플릿이 이미 존재. When 같은 타입으로 생성. Then 409 → 다이얼로그 내 인라인 에러("이미 해당 타입의 템플릿이 있습니다").
- **S4 수정**. Given 기존 템플릿. When 행의 "수정" → 이름/본문 변경 저장. Then 200 → 목록 갱신. (타입은 불변, 수정 폼에서 비활성.)
- **S5 빈값 거부**. Given 수정 다이얼로그. When 이름 또는 본문을 공백으로 저장. Then 클라이언트 Zod 차단(서버 도달 시 422 인라인).
- **S6 삭제**. Given 기존 템플릿. When "삭제"(확인 후). Then 204 → 목록에서 사라짐(소프트 삭제).
- **S7 권한 없음**. Given 비관리자(MANAGE_TEMPLATES 없음). When 페이지 진입. Then "추가/수정/삭제" 버튼 비활성 + 안내 title. (목록 조회는 가능 — READ 미게이트.)

## 기능 요구사항 (FR)

- **FR-D6-1** 프로젝트별 템플릿 목록 조회·표시(활성만, 타입명 해석).
- **FR-D6-2** 템플릿 생성 — 타입 선택(useIssueTypes) + 이름(≤100, 필수) + 본문(필수). 중복(409)·권한(403) 인라인 처리.
- **FR-D6-3** 템플릿 수정 — 이름/본문(부분 수정, null=무변경). 타입 불변. 422 인라인.
- **FR-D6-4** 템플릿 삭제 — 확인 후 소프트 삭제(204).
- **FR-D6-5** MANAGE_TEMPLATES 권한 게이팅 — fail-closed(로딩/에러/미인가→비활성). 목록 READ는 항상 허용.
- **FR-D6-6** (백엔드) `MyProjectPermissionController` managePermissions에 `MANAGE_TEMPLATES`(TemplatePermission.CREATE resolver) 추가 + null-projectKey false 분기. 마이그레이션 불요.
- **FR-D7-1** E2E: S1·S2·S3·S6·S7 시나리오 + (가능 시) S4.

## 비기능 요구사항 (NFR)

- 기존 settings 페이지(custom-fields/components/versions)와 **시각·상호작용 일관**(DESIGN.md 토큰, shadcn/Radix).
- Zod 스키마는 **실제 머지 DTO와 정확 일치**(invent 금지 — `frontend-zod-backend-dto-contract-gap`).
- 변이 요청에 `X-XSRF-TOKEN` 수동 주입(custom-fields.ts 관례).
- MSW stateful store(생성/수정/삭제 영속) + refetch 검증(`msw-mutation-stateful-refetch`).
- 신규 i18n 문자열은 `i18n/ko` 패턴.

## API 인터페이스 (REST) — 실제 머지 계약 (변경 없음, 소비만)

베이스 `/api/v1/projects/{projectIdOrKey}/issue-templates`.

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| GET | `` | — | 200 `{data: IssueTemplateResponse[]}` |
| GET | `/{templateId}` | — | 200 `{data: IssueTemplateResponse}` (404 미존재) |
| GET | `/resolve?issueTypeId={Long}` | — | 200 `{content:string}` 또는 204 |
| POST | `` | `{issueTypeId:Long>0, name:string(≤100,비공백), content:string(비공백)}` | 201 `{data}` / 409 중복 / 403 / 404 타입미존재 |
| PATCH | `/{templateId}` | `{name?:string≤100, content?:string}` (null=무변경) | 200 `{data}` / 422 blank / 404 / 403 |
| DELETE | `/{templateId}` | — | 204 / 404 / 403 |

**IssueTemplateResponse** `{ id:UUID, projectId:UUID, issueTypeId:Long, name:string, content:string, createdAt:Instant(ISO), updatedAt:Instant(ISO) }`.
**에러바디** RFC7807 ProblemDetail + `errorCode`(실제 wire 값 — `IssueTemplateErrorCodes`):
`ISSUE_TEMPLATE_PROJECT_NOT_FOUND`(404) / `ISSUE_TEMPLATE_NOT_FOUND`(404) / `ISSUE_TEMPLATE_ISSUE_TYPE_NOT_FOUND`(404) /
`ISSUE_TEMPLATE_DUPLICATE`(409) / `ISSUE_TEMPLATE_ACCESS_DENIED`(403) / `ISSUE_TEMPLATE_INVALID`(422) / `VALIDATION_FAILED`(400).
**주의**. 상수명(TEMPLATE_DUPLICATE)≠wire값("ISSUE_TEMPLATE_DUPLICATE"). 프론트는 wire 문자열 매칭(에러키 drift 함정).

권한 노출. `GET /api/v1/users/me/project-permissions?projectKey=` → managePermissions에 `MANAGE_TEMPLATES:boolean` 추가(FR-D6-6).

## 엣지 케이스

- **E1** 타입 목록 비어있음/로딩 중 — 생성 다이얼로그 타입 셀렉트 비활성 + 안내.
- **E2** 이미 모든 타입에 템플릿 존재 — 생성 시 남은 타입 없음 안내(또는 409로 자연 차단).
- **E3** projectKey 미존재(404 PROJECT_NOT_FOUND) — 페이지 레벨 role="alert".
- **E4** Markdown 본문 장문 — textarea 스크롤, 미리보기는 범위 외(리터럴 텍스트).
- **E5** 수정 중 타입 변경 시도 — UI에서 타입 셀렉트 비활성(불변).
- **E6** 권한 토글(E2E) — localStorage 플래그로 403 시나리오.
