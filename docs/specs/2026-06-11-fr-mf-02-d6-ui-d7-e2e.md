# FR-MF-02 D6/D7 — 백업코드(Recovery Codes) 프론트엔드 UI + E2E 스펙

> 작성: 2026-06-11 · BC: identity-access · 백엔드: #117 완료 · 형제: FR-MF-01 TOTP 프론트(#116)

## 배경 / 제약

- 백엔드 D1~D5는 #117로 완료. 이 작업은 **D6(프론트 UI) + D7(E2E)** 만 다룬다. 도메인/API 계약 변경 없음.
- **핵심 제약**: 백엔드는 백업코드 생성·조회에 **TOTP ACTIVE를 선행 조건**으로 요구한다(`409 totp_not_active`). 따라서 백업코드 UI는 `MfaSettings.tsx`의 **TOTP 활성(isEnabled) 분기 안에서만** 노출한다.
- 동형 패턴: `MfaSettings.tsx`(설정) · `api/mfa.ts`(verify=raw fetch) · `schemas.ts`(Zod) · `LoginForm.tsx` LoginMfaStep(로그인 2단계) · `mfa-handlers.ts`+mfaStore(MSW stateful) · `i18n/ko.ts` · E2E `mfa-settings.spec.ts`/`mfa-login.spec.ts`.

## Maxi 결정 (2026-06-11)

1. 평문 노출 액션 = **복사 + 다운로드(.txt)**.
2. 로그인 전환 = **"백업코드로 로그인" 링크 토글**(같은 화면, 뒤로가기 링크 포함).
3. 잔여 경고 = **remaining ≤ 3**.
4. 재생성 = **확인 모달**(전량 무효화 경고).

## 사용자 시나리오 (Given-When-Then)

### S1 — 백업코드 최초 생성
- **Given** TOTP 활성 사용자가 `/settings/mfa` 진입, 백업코드 미생성(generated=false)
- **When** "백업 코드 생성" 버튼 클릭
- **Then** 평문 10개 표시 + [복사] [다운로드(.txt)] 버튼 + "지금 저장하세요. 이 화면을 닫으면 다시 볼 수 없습니다" 경고
- **And** 상태가 generated=true, remaining=10으로 갱신(invalidateQueries)

### S2 — 잔여 개수 조회 + 부족 경고
- **Given** 백업코드 생성됨(remaining=2)
- **When** `/settings/mfa` 진입
- **Then** "남은 백업 코드: 2개" 표시 + remaining≤3 경고 배너("백업 코드가 얼마 남지 않았습니다. 재생성을 권장합니다")

### S3 — 재생성 (확인 모달)
- **Given** 백업코드 생성됨
- **When** "백업 코드 재생성" 클릭 → 확인 모달("기존 백업 코드가 모두 무효화됩니다") → 확인
- **Then** 새 평문 10개 표시(S1과 동일 UI), 기존 코드 전량 무효화

### S4 — 로그인 백업코드 인증
- **Given** TOTP 활성 사용자가 로그인 1단계 통과 → `mfa_required` 응답(MFA 코드 입력 화면)
- **When** "백업 코드로 로그인" 링크 클릭 → 입력 필드가 백업코드 입력으로 전환 → 유효 백업코드 입력 → 확인
- **Then** `POST /mfa/verify {method:"backup_code"}` → 정식 세션 발급 → 대시보드 이동

### S5 — 로그인 백업코드 오답
- **Given** 백업코드 입력 화면
- **When** 잘못된/이미 사용된 코드 입력
- **Then** 인라인 에러("백업 코드가 올바르지 않습니다") + 화면 유지
- **주의(EC-12)**: 백엔드는 오답이어도 챌린지 토큰을 1회 소진하므로, 재시도 시 동일 토큰은 만료. 메시지로 재로그인 유도.

### S6 — TOTP 미활성 사용자
- **Given** TOTP 미활성 사용자가 `/settings/mfa` 진입
- **Then** 백업코드 섹션 **미노출**(TOTP를 먼저 활성화하라는 기존 흐름만).

## 기능 요구사항 (FR)

- **FR-1** 설정 화면 백업코드 섹션(TOTP 활성 시만): 상태(generated/remaining) 조회 + 생성/재생성 + 평문 노출.
- **FR-2** 평문 노출: 복사 버튼 + .txt 다운로드 버튼 + "다시 볼 수 없음" 경고. 닫기 시 평문 폐기.
- **FR-3** remaining≤3 경고 배너(remaining=0은 강조).
- **FR-4** 재생성 확인 모달(전량 무효화 명시) 후에만 재생성 호출.
- **FR-5** 로그인 2단계 "백업 코드로 로그인" 링크 토글 → 백업코드 입력 → `verify(method:"backup_code")`. "TOTP로 돌아가기" 링크 포함.
- **FR-6** 에러 메시지 한국어화: `totp_not_active`/`invalid_code`/`invalid_method`/`too_many_attempts`.

## 비기능 요구사항 (NFR)

- **NFR-1** 평문 코드는 React state 메모리에만 보관. localStorage/sessionStorage/authStore 영속 **금지**. 페이지 이탈/새로고침 시 소멸(서버 재조회 불가).
- **NFR-2** 백엔드 snake_case 필드명 그대로 Zod 스키마(`codes`, `generated`, `remaining`).
- **NFR-3** 로그인 `verify`는 raw `fetch`(apiFetch 금지 — 401 자동 refresh 회피, learning `auth-pre-session-401-raw-fetch`). `method` 파라미터 추가 시 기본값 `"totp"`로 하위호환 보장(기존 TOTP 호출 무변경).
- **NFR-4** 생성/재생성은 `apiFetch` + 수동 `X-XSRF-TOKEN`(readXsrfToken 재사용). 조회는 apiGet.
- **NFR-5** mutation 후 `invalidateQueries(['mfa','backup-codes'])`로만 상태 갱신(setQueryData 부분응답 플리커 금지, learning `mutation-setquerydata-partial-response-flicker`).
- **NFR-6** 접근성: 에러 `role="alert"`, 경고 배너 적절한 라벨, 버튼 명확한 텍스트.

## 엣지 케이스

- **EC-1** 생성 중 `totp_not_active`(다른 탭에서 TOTP 비활성화 레이스) → 에러 메시지 + 상태 재조회로 섹션 숨김.
- **EC-2** 평문 노출 화면에서 새로고침 → 평문 소실(재조회 불가). 잔여 개수만 표시.
- **EC-3** 로그인 백업코드 오답 → 챌린지 토큰 소진 → 재시도 시 `invalid_code`(만료) → "다시 로그인" 유도(S5).
- **EC-4** `too_many_attempts`(429) → "잠시 후 다시 시도해 주세요".
- **EC-5** 다운로드 .txt: 파일명 `bts-backup-codes.txt`, 한 줄당 코드 1개(+ 안내 헤더).
- **EC-6** 클립보드 API 미지원/거부 → 에러 처리(복사 실패 안내). 다운로드는 항상 가능.
- **EC-7** remaining=0 → "남은 백업 코드가 없습니다" 강조 + 재생성 유도.
- **EC-8** `invalid_method`(400) — 정상 흐름에선 발생 안 함(프론트가 항상 유효 method 전송). 방어적 일반 에러.
- **EC-9** 백업코드 입력 형식 — 프론트는 trim + 대소문자 정규화 정도만(빈 값 가드). `xxxxx-xxxxx` 형식 강제 검증은 하지 않고 유효성은 백엔드에 위임(TOTP `maxLength=6`과 달리 하이픈 포함 가변 입력 허용).
