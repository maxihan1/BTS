# FR-IS-08 — 이슈 인쇄 + PDF 출력 — 스펙

> slug: fr-is-08-pdf · BC: issue-tracking · type: backend

> 구현 완료: PR #71

## 개요

이슈 단건을 서버에서 PDF로 렌더하여 다운로드한다. 기존 `MarkdownRenderer.renderSafe()`가
생성하는 sanitized HTML(본문)을 재사용해 서식(굵게/목록/코드블록/링크)을 보존하고,
메타데이터(상태·타입·우선순위·담당자·라벨·영향도·resolution·일시)를 표로 함께 출력한다.

## 사용자 시나리오 (Given-When-Then)

**S1 — 정상 PDF 출력**
- Given 조회 가능한 이슈 `ATLAS-42`가 존재하고 본문(Markdown)이 있다.
- When `GET /api/v1/issues/ATLAS-42/pdf` 호출.
- Then 200 OK, `Content-Type: application/pdf`,
  `Content-Disposition: attachment; filename="ATLAS-42.pdf"`, 본문은 유효한 PDF 바이너리(`%PDF-` 시그니처로 시작).

**S2 — 본문 없는 이슈**
- Given 본문(description)이 null인 이슈.
- When PDF 호출.
- Then 200 OK + 메타데이터 표만 있는 PDF(본문 영역 비움 또는 "(설명 없음)" placeholder). 예외 없음.

**S3 — 한글 본문/제목**
- Given 제목·본문에 한글이 포함된 이슈.
- When PDF 호출.
- Then 한글 글리프가 깨지지 않고 렌더(임베딩된 한글 폰트). tofu(□) 없음.

**S4 — 존재하지 않는 이슈**
- Given 없거나 소프트 삭제된 이슈 키.
- When PDF 호출.
- Then 404 (기존 `GET /api/v1/issues/{key}`와 동일한 `IssueNotFoundException` 경로).

**S5 — 잘못된 키 형식**
- Given `not-a-key` 같은 형식 위반 키.
- When PDF 호출.
- Then 기존 단건 조회와 동일한 검증 경로(400 또는 404)를 따른다.

## 기능 요구사항 (FR)

- **FR1** `GET /api/v1/issues/{key}/pdf` 신규 엔드포인트. 단건 조회와 동일한 actor/조회 경로 재사용.
- **FR2** 응답은 `application/pdf` + `Content-Disposition: attachment; filename="{key}.pdf"`.
- **FR3** PDF 본문 = 기존 `descriptionHtml`(sanitized) 재사용. 새 sanitize 정책 만들지 않음.
- **FR4** 메타데이터 표 포함(리치): 키, 제목, 프로젝트, 상태(currentStateKey), 타입(typeName),
  우선순위(priorityName), 담당자(assigneeId — UUID 표기), 라벨, 영향도(impactName), resolution(name), 생성/수정 일시.
- **FR5** 페이지 헤더(이슈 키 + 제목) + 페이지 푸터(페이지 번호 `n / m` + 생성 시각).
- **FR6** 한글 폰트 임베딩으로 한글 렌더 보장.

## 비기능 요구사항 (NFR)

- **NFR1 보안** PDF 입력 HTML은 반드시 `MarkdownRenderer.renderSafe()` 출력만 사용. raw description을
  HTML로 직접 주입 금지(XSS·SSRF·외부 리소스 로드 차단). openhtmltopdf의 외부 리소스 로딩(이미지 URL 등)은
  비활성/차단(allowlist된 태그엔 `<img>` 없음 → 자연 차단되나, 명시적으로 외부 fetch 금지 확인).
- **NFR2 결정성** 동일 이슈 입력 → 구조적으로 동일한 PDF(타임스탬프 푸터 제외). 테스트 가능.
- **NFR3 성능** 단건 동기 렌더. 1K 사용자 규모에서 빈도 낮음 → 별도 비동기/캐시 불필요.
- **NFR4 BC 격리** issue-tracking 단일 모듈 내 완결. 다른 BC import 금지.

## API 인터페이스 (REST)

```
GET /api/v1/issues/{key}/pdf
  → 200 OK
     Content-Type: application/pdf
     Content-Disposition: attachment; filename="ATLAS-42.pdf"
     body: <PDF bytes>
  → 404 (IssueNotFoundException — 기존 핸들러 재사용)
```

- 컨트롤러 반환 타입: `ResponseEntity<ByteArray>` (DataResponse 래핑 안 함 — 바이너리).
- `produces = MediaType.APPLICATION_PDF_VALUE`.

## 기술 설계 (구현 결과 반영)

### 의존성 (Maxi 승인됨)
issue-tracking `build.gradle.kts`에 인라인 버전으로 추가(버전 카탈로그 없음).
- `com.openhtmltopdf:openhtmltopdf-pdfbox:1.0.10` **한 줄** (core + PDFBox 2.0.24 전이로 자동 포함).

### XHTML 호환성 (도메인 정리 쟁점 2 해소)
- openhtmltopdf는 **well-formed XHTML** 요구. OWASP HtmlSanitizer 출력은 이미 well-formed
  XML(`<br />` 자기종결, `<p>…</p>` 균형)이라 **jsoup 등 추가 파서 불필요**.
- 전략: sanitized 본문 HTML을 XHTML 문서 골격(`<?xml?>` + XHTML 1.0 Strict DOCTYPE +
  `<html xmlns><head><style>…</style></head><body>…</body></html>`)에 삽입.
- 검증: `IssuePdfTemplateTest`가 실제 `renderSafe()` 출력(한글+코드블록+중첩리스트+mailto)을
  `DocumentBuilder.parse`로 well-formed 확인(C2 가드).

### 한글 폰트
- OFL 라이선스 `NanumGothic-Regular.ttf`(약 2MB) 단일 weight를 `src/main/resources/fonts/`에 번들.
  OFL.txt 라이선스 동봉. openhtmltopdf `useFont`로 등록, CSS `font-family: 'NanumGothic'`.
- 폰트 바이트는 `IssuePdfRenderer` companion에 1회 캐싱(렌더마다 재읽기 방지).

### 렌더러 구조
- `IssuePdfTemplate` (com.bts.issue.pdf) — IssueResponse → XHTML 문자열(메타 표 + 본문 + @page 헤더/푸터 CSS).
- `IssuePdfRenderer` (com.bts.issue.pdf, @Component) — XHTML → ByteArray via openhtmltopdf.
- 컨트롤러는 `service.findByKey`로 IssueResponse(descriptionHtml 포함) 획득 → 렌더러 호출 → 바이트 반환.

## 엣지 케이스 (Phase B 새너티 체크 — 인라인)

1. **본문 null** → 메타만, placeholder. (S2)
2. **본문 빈 문자열** → null과 동일 처리.
3. **descriptionHtml이 null인 경로** — `findByKey→withSingleDetail`이 항상 채움(renderHtml 경로). PDF는 findByKey만 사용.
4. **매우 긴 본문** → 다중 페이지 자동 분할(openhtmltopdf 페이지네이션). 푸터 페이지 번호 `n/m` 정확.
5. **한글/이모지/특수문자** → 폰트 글리프 미존재 시 tofu. 한글은 폰트 임베딩으로 보장. 이모지는 범위 외(미보장, 명시).
6. **resolution/assignee/impact가 null** → 표에서 "-" 표기. NPE 금지.
7. **존재하지 않음/소프트 삭제** → 404 (S4).
8. **filename 인젝션** — key는 이슈 키 형식(검증됨)이라 `"`/개행 불가하나, Content-Disposition filename은 안전 인코딩.
9. **XSS 잔존** — sanitized HTML만 입력. raw description 직접 주입 절대 금지(NFR1).
10. **외부 리소스 로드** — sanitized allowlist에 `<img>`/`<link>` 없음 → 외부 fetch 자연 차단. baseUri=null로 명시 비활성.
11. **대용량 동시 요청** — 동기 렌더, 빈도 낮음. 메모리는 ByteArrayOutputStream 단건. 별도 제한 불필요(NFR3).
