# FR-UX-09 F3 — 보드/백로그/스프린트 이슈 생성 진입점 스펙

> **FR**. FR-UX-09 (이슈 생성 흐름 — 모달 · 진입점) §4.7 · **PR** #333
> **선행**. #328(B1 백엔드 필드) · #331(F2 `CreateIssueDialog`)
> **ADR**. [2026-08-03-fr-ux-09-f3-create-issue-entry-points](../decisions/2026-08-03-fr-ux-09-f3-create-issue-entry-points.md) D-1~D-5
> **범위**. `apps/web` 프론트 전용 — 백엔드 0줄 · 마이그레이션 0 · 신규 API 0 · 신규 의존성 0

## 1. 배경 — 무엇이 없어서 문제인가

지금 이슈를 만드는 길은 **상단바 「만들기」와 딥링크 `/issues/new` 둘뿐**이다(F2, #331).
보드나 백로그를 보다가 이슈를 만들려면 화면 위쪽 끝까지 가야 하고, 만들고 나면
**어느 스프린트에 넣을지는 다시 드래그**해야 한다.

F2 가 `CreateIssueDialog` 를 **라우터 훅 import 0** 으로 만들어 둔 덕에, 이 스펙의 진입점은
URL 을 바꾸지 않고 제자리에서 모달을 연다.

## 3. 사용자 시나리오 (Given-When-Then)

**S1 — 백로그 칸에서 만든다.**
Given 백로그 화면에 있고 CREATE 권한이 있다
When 백로그 칸 헤더의 「+」를 누르고 제목을 넣어 만든다
Then 모달이 닫히고 **백로그 칸에 새 이슈가 나타난다** · URL 은 바뀌지 않는다

**S2 — 스프린트 칸에서 만들면 그 스프린트에 들어간다.**
Given 백로그 화면에 스프린트 「2026-W31」이 있다
When 그 칸의 「+」로 이슈를 만든다
Then **그 스프린트 칸에** 새 이슈가 나타난다 (백로그 칸이 아니다)

**S3 — 스프린트 배정만 실패한다.**
Given S2 와 같고, 배정 요청이 실패한다
When 생성은 성공하고 배정이 실패한다
Then **「이슈는 만들어졌고 백로그에 있다」는 사실을 이슈 키와 함께 알린다** ·
모달은 닫힌다 · **생성을 되돌리지 않는다** · 사용자가 다시 만들도록 유도하지 않는다

**S4 — 보드에서 만든다.**
Given 보드 화면에 있다
When **보드 헤더**의 「이슈 만들기」로 이슈를 만든다
Then 제자리에 머물고 토스트로 알린다 · 토스트의 「보기」로 상세로 갈 수 있다

**S5 — 권한이 없으면 못 누른다.**
Given CREATE 권한이 없다 (또는 권한 조회가 로딩·에러다)
When 세 화면을 본다
Then 진입점이 **비활성**이고 눌러도 모달이 열리지 않는다 (fail-closed)

**S6 — 프로젝트가 미리 채워져 있다.**
Given `/projects/INFRA/backlog` 에 있다
When 진입점으로 모달을 연다
Then 프로젝트 칸이 **INFRA** 로 채워져 있다

**S7 — 완료된 스프린트에는 못 만든다.**
Given 스프린트 상태가 `COMPLETED` 다
When 그 칸을 본다
Then **진입점이 없다** (드롭이 막혀 있는 것과 같은 이유)

## 8. 이 스펙이 확정하는 설계 결정

**D-A. 프로젝트 프리필은 명시 전달로 바꾼다 (ADR D-4 가 열어 둔 결정).**
ADR 은 「기존 활성 프로젝트 경로로도 동작한다」까지만 확정하고 명시화 여부를 이 단계에 넘겼다.
**명시 전달을 채택한다** — 근거 3가지.

1. **페이지는 `projectKey` 를 직접 갖고 있다.** 전역 스토어를 한 바퀴 도는 것은 우회다.
2. **기록 가드에 구멍이 있다.** `useTrackActiveProject` 는 `isKnownProject`(프로젝트 목록 대조)가
   통과해야 기록한다. 목록이 아직 안 왔으면 활성 프로젝트는 **직전 값 또는 없음**이다 —
   그 순간 모달을 열면 **다른 프로젝트가 채워진 채로 열린다**.
3. 선례가 있다 — `SprintColumn` 이 이미 `projectKey` 를 prop 으로 받는다.

**대가.** `CreateIssueDialog` 와 `IssueCreateForm` 에 `initialProjectKey` prop 이 하나 늘어난다.
**기존 소비처 2곳(상단바·딥링크)은 넘기지 않으므로 동작 무변경**이고, 미전달 시 기존
활성 프로젝트 기본값 경로가 그대로 산다.

**D-B. 진입점 시각 형태는 칸 헤더의 아이콘 버튼, 보드는 텍스트 버튼.**
칸 헤더는 폭이 288px 로 좁고 이미 제목·개수·상태 배지가 있다 → **아이콘(`Plus`) + `sr-only` 이름**.
보드 헤더는 폭 여유가 있고 화면당 1개뿐이라 **아이콘 + 텍스트**(상단바 「만들기」와 같은 형태).
근거 — FR-UX-08 PR-B 의 선례 「아이콘만 + sr-only 는 단일 링크 관례」와 반대 방향으로 보이지만,
여기서는 **이름에 칸 이름이 들어가 서로 구분되므로**(FR-10) 그 관례의 취지(구분 불가 방지)를 만족한다.

**D-C. 부분 성공은 토스트로 알리고 `error` 톤을 쓰지 않는다.**
이슈는 **만들어졌다**. 빨간 실패 토스트는 「안 만들어졌다」로 읽혀 재시도 → 중복 이슈를 부른다.
경고 톤 + 이슈 키 + 「보기」 액션으로 낸다.

**D-D. MSW 목 확장을 스펙 요구사항으로 승격한다 (FR-13). ★Phase B 발견.**

**실측.** `mocks/issue-handlers.ts:426 createIssueHandler` 는 만든 이슈를 이슈 저장소에만 넣고
`backlogStore` 에는 넣지 않는다. 그리고 `mocks/backlog-handlers.ts:230` 의
`assignToSprintHandler` 는 **`backlogStore` 에서 못 찾은 키를 201 로 멱등 처리**하고 아무것도 안 한다.

**결과 — 두 방향으로 다 틀린다.**

- **가짜 그린.** 「`POST /sprints/{id}/issues` 가 1회 호출됐다」만 보는 테스트는 **항상 통과**한다.
  목이 201 을 주기 때문이다. 배정이 실제로 반영됐는지는 검증되지 않는다.
- **거짓 실패.** 「스프린트 칸에 나타난다」를 보는 테스트는 **구현이 옳아도 실패**한다.
  만든 이슈가 애초에 `backlogStore` 에 없기 때문이다. 이 실패를 만난 구현자가
  단언을 「호출됐다」로 약화시키면 위의 가짜 그린으로 착지한다.

**처방.** `createIssueHandler` 가 생성된 이슈를 해당 프로젝트의 `backlogStore` **백로그 칸에
추가**하도록 확장한다. 그러면 S1 은 그 자체로, S2 는 기존 stateful 이동 로직으로 참·거짓이 갈린다.
**F2 의 FR-14(MSW 핸들러가 신규 필드를 무시해 가짜 그린) 와 같은 계열의 처방이다.**

**D-E. 접근 가능한 이름 충돌은 눈이 아니라 판별식으로 막는다 (FR-14). ★Phase B 발견.**

**실측 — 이미 깨질 조합이 존재한다.**

| 기존 이름 | 출처 | 새 이름이 이것을 포함하면 |
|---|---|---|
| `만들기` | `nav-labels.ts:71` 상단바 — **모든 페이지에 있다** | e2e `issue-create-dialog.spec.ts:18` 의 `name: '만들기'` 가 2개에 매칭 |
| `이슈 생성` | `ko.ts:736` 모달 제출 버튼 | 같은 파일 `:19` 의 `name: '이슈 생성'` 이 모달 열린 순간 2개에 매칭 (E-10) |
| `스프린트 생성` | `backlog-labels.ts:66` | 단위 테스트 `BacklogBoard.test.tsx:242` 의 `/스프린트 생성/i` 가 2개에 매칭 |

Playwright 의 `getByRole(name)` 과 Testing Library 의 정규식 매칭은 **둘 다 기본이 부분 일치**다.
따라서 「이슈 만들기」·「백로그에 이슈 생성」 같은 자연스러운 이름이 **기존 테스트를 깬다**.

**처방 2단.**
1. 새 이름은 위 3개를 부분 문자열로 **포함하지 않는다**.
2. **전수 판별식**을 둔다 — 같은 화면에 동시에 존재할 수 있는 버튼 이름 집합을 모아
   서로 부분 문자열 관계인 쌍이 **0** 임을 단언한다. 손으로 3개만 나열하지 않는다.
   **FR-UX-08 PR-B 의 `admin`('관리') ⊂ `adminNav`('관리 메뉴') 와 같은 결함 양식**이고,
   그때 전수 판별식이 손나열이 놓친 것을 첫 실행에서 잡았다.
