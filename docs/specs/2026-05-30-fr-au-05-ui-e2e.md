# FR-AU-05 비밀번호 변경 프론트 폼 UI + E2E (PR-2) — 스펙

## 배경 · 스코프

FR-AU-05의 PR-2 = **인증된 사용자가 자기 비밀번호를 바꾸는 프론트 화면 + E2E**. 백엔드 API는 PR #44 머지 완료. 본 PR은 그 화면(D6) + Playwright E2E(D7).

**본 PR 포함**: `/settings/password` 라우트 + 비밀번호 변경 폼 컴포넌트 + API 클라이언트(`changePassword`) + TanStack Query mutation 훅 + MSW 핸들러 + 단위/컴포넌트 테스트 + Playwright E2E.

**본 PR 제외**: 가입/임시비번/리셋(후속, 권한·이메일 인프라 선행). 비밀번호 강도 미터 같은 부가 UX(범위 외). 진입 내비게이션 링크 메뉴 정비(기존 settings 내비 패턴 따름, 별도 메뉴 작업 아님).

## 사용자 시나리오 (Given-When-Then)

- **S1 정상 변경**. Given 로그인된 사용자가 `/settings/password` 진입, When 현재 비번 + 정책 만족 새 비번 + 확인 비번(일치) 입력 후 제출, Then 200 → 인라인 성공 메시지("비밀번호가 변경되었습니다") + 입력 필드 초기화 + 제출 버튼 재활성화.
- **S2 현재 비번 불일치**. When 백엔드 400 `CURRENT_PASSWORD_MISMATCH`, Then "현재 비밀번호가 일치하지 않습니다." 인라인 에러, 필드 값 유지(재시도 가능), 폼 잠기지 않음.
- **S3 정책 위반(길이)**. When 백엔드 400 `POLICY_VIOLATION` violations=[MIN_LENGTH], Then "비밀번호는 최소 12자 이상이어야 합니다." 표시.
- **S4 정책 위반(복잡도)**. When 400 `POLICY_VIOLATION` violations=[COMPLEXITY], Then "영문 대문자·소문자·숫자·특수문자 중 3종 이상을 포함해야 합니다." 표시. (두 violations 동시면 둘 다 나열)
- **S5 동일 비번**. When 400 `SAME_AS_CURRENT`, Then "새 비밀번호가 현재 비밀번호와 같습니다." 표시.
- **S6 새 비번 ≠ 확인 비번**. Given 새 비번과 확인 비번 불일치, When 제출, Then **클라이언트단에서 차단**(API 미호출) + "새 비밀번호가 일치하지 않습니다." 표시.
- **S7 미인증 접근**. Given 비로그인 사용자가 `/settings/password` 직접 접근, Then `beforeLoad: requireAuth`로 `/login` 리다이렉트(기존 settings 라우트 패턴).
- **S8 세션 무효화 안내**. 변경 성공 후 성공 메시지에 "다른 기기의 세션은 로그아웃되었습니다" 보조 안내 1줄(백엔드 FR-6 동작 사용자 고지). 현재 세션은 유지.

## 기능 요구사항 (FR)

- **FR-1 (라우트)**. `/settings/password` code-based 라우트 등록. `staticData: { requireAuth: true }` + `beforeLoad: requireAuth` (settings.sessions 패턴 동일). Page + RouteAdapter export.
- **FR-2 (폼)**. 3개 입력 — `현재 비밀번호` / `새 비밀번호` / `새 비밀번호 확인`. 모두 `type="password"`. 제출 버튼.
- **FR-3 (API 클라이언트)**. `api/password.ts`의 `changePassword({ currentPassword, newPassword })`. `apiFetch` POST + **`X-XSRF-TOKEN` 헤더**(sessions.ts `readXsrfToken` 패턴 재사용/공유). 성공 응답 Zod 검증(`{ changed: z.literal(true) }`). 비-2xx면 `ApiError(status, body)` throw.
- **FR-4 (mutation 훅)**. TanStack Query `useMutation` 래퍼(`useChangePassword`). onSuccess/onError 상태를 컴포넌트가 구독.
- **FR-5 (에러 매핑)**. `ApiError.body.code`(대문자 스네이크)를 한글 메시지로 매핑. `POLICY_VIOLATION`은 `body.violations`(MIN_LENGTH|COMPLEXITY)별 메시지. 미지의 code/네트워크 오류는 "비밀번호 변경에 실패했습니다. 잠시 후 다시 시도해 주세요." 폴백.
- **FR-6 (클라이언트 검증 — D1 확정: 정적 안내 + 서버 권위)**. 클라이언트는 **3필드 required(빈 값 제출 차단) + 새 비번==확인 비번(S6)만** 검증. 정책(12자/복잡도)은 **입력란 아래 고정 안내문**("12자 이상, 영문 대문자·소문자·숫자·특수문자 중 3종 이상")으로만 표시하고 실제 판정은 **서버에 위임**(POLICY_VIOLATION 응답 → FR-5 매핑). 프론트에 12자/복잡도 검증 로직 구현 금지(drift 차단, frontend-zod-backend-dto-contract-gap).
- **FR-7 (제출 상태)**. 제출 중 버튼 비활성 + 로딩 표시. 중복 제출 차단.

## 비기능 요구사항 (NFR)

- **NFR-1 (계약 정합)**. Zod 스키마/에러코드 비교는 백엔드 ground-truth(대문자 스네이크)와 1:1. 프론트에서 형식 재발명 금지(frontend-zod-backend-dto-contract-gap, PR #41 BLOCKER 선례).
- **NFR-2 (보안 UX)**. 비밀번호 평문을 로그/콘솔/URL/쿼리에 노출 금지. 입력은 마스킹(`type=password`). 에러 메시지에 입력 평문 미반영.
- **NFR-3 (접근성)**. 각 입력에 `<label>` 연결, 에러는 `aria-live`/role로 스크린리더 전달, 제출 버튼 키보드 접근. DESIGN.md 폼 토큰 준수.
- **NFR-4 (디자인)**. settings.sessions 셸(`mx-auto max-w-2xl px-4 py-8` + 제목/설명) 패턴 + DESIGN.md 폼/버튼 컴포넌트 재사용.

## API 인터페이스 (프론트 소비)

```
POST /api/v1/users/me/password   (apiFetch, credentials:include, Authorization 자동, X-XSRF-TOKEN 수동)
Request:  { "currentPassword": string, "newPassword": string }
Responses:
  200 { "changed": true }
  400 { "code": "POLICY_VIOLATION", "violations": ["MIN_LENGTH"|"COMPLEXITY", ...], "message": string }
  400 { "code": "CURRENT_PASSWORD_MISMATCH", "message": string }
  400 { "code": "SAME_AS_CURRENT", "message": string }
  401 (필터) → apiFetch 자동 refresh 1회 retry → 실패 시 clearSession
  403 (CSRF 누락) → X-XSRF-TOKEN 헤더로 사전 방지
```

## 제약 조건

- **절대 규칙(DEVELOPMENT.md §1)**. TypeScript strict, 보안(평문 미노출), 입력 검증, 테스트.
- **BC 격리**. identity-access 프론트 단독. cross-BC 없음.
- **기존 패턴 보존**. apiFetch/ApiError/readXsrfToken/router code-based/settings 셸 재사용. 신규 추상화 최소.
- **TDD 강제**. api → 훅 → 폼 컴포넌트 → 라우트 배선 → E2E 순 RED→GREEN→REFACTOR.
- **MSW 함정**. POST 핸들러 stateful, serviceWorkers:'block' 금지(E2E), getByRole exact, 긴 비번 타이핑 delay:null+testTimeout.

## 측정 가능한 완료 기준

1. `/settings/password` 라우트가 미인증 시 `/login` 리다이렉트, 인증 시 폼 렌더(컴포넌트/라우트 테스트).
2. S1~S8 시나리오 컴포넌트 테스트 통과(MSW stateful mock 위, 에러코드 대문자 정합).
3. `changePassword` API 단위 테스트 — 성공 Zod 파싱 + 각 400 code → ApiError, X-XSRF-TOKEN 헤더 포함 검증.
4. Playwright E2E — 정상 변경(S1) + 현재 비번 불일치(S2) + 정책 위반(S3/S4) + 확인 불일치(S6) happy/sad path.
5. `pnpm lint typecheck test build` 전부 통과 + E2E 그린(기존 회귀 0).
6. 평문 비밀번호가 네트워크 탭 외 어디에도(콘솔/로그/URL) 노출 안 됨(코드 리뷰 + NFR-2).
