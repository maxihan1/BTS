# FR-IS-10 D6·D7 — 커스텀 필드 프론트 UI + E2E — 스펙

## 범위

- **D6-a 커스텀 필드 관리 페이지** — 프로젝트 설정에 정의 CRUD UI (`settings.components` 동형)
- **D6-b 이슈 폼 동적 렌더링** — FieldType 10종별 입력 위젯, 이슈 생성 폼 + 이슈 상세 메타패널
- **D7 E2E** — 정의 CRUD + 이슈 값 입력/검증 시나리오 (qa-engineer)

비범위. FR-PM-07(필드 수준 권한)은 별도 PR(#97). 본 작업은 MANAGE_CUSTOM_FIELDS(정의 관리)만 게이팅, 값 입력은 이슈 CREATE/UPDATE 권한 전제. **이슈 목록(테이블) 화면의 커스텀 필드 컬럼 표시는 비범위**(백엔드는 목록 응답에 customFields를 노출하나, 컬럼/필터 UI는 후속). 본 작업은 이슈 생성 폼 + 이슈 상세에서의 입력·조회·편집만 다룬다.

## 사용자 시나리오 (Given-When-Then)

**S1. 필드 정의 생성 (관리자)**
- Given 프로젝트 관리자가 `/projects/{key}/settings/custom-fields`에 진입
- When "필드 추가" → key/name/fieldType 입력, 선택형이면 옵션 추가 → 저장
- Then 목록에 displayOrder 순으로 표시. key 중복이면 409 → "이미 같은 키의 필드가 있습니다" 토스트, Dialog 유지

**S2. 필드 정의 수정 (관리자)**
- Given 기존 필드의 수정 Dialog
- When name/description/required/displayOrder/options 변경 → 저장
- Then 갱신 반영. fieldType·key는 읽기 전용으로 표시(불변, 시도 시 백엔드 422 방어). 옵션 변경은 전체 교체

**S3. 필드 정의 삭제 (관리자)**
- Given 행별 삭제 액션
- When 확인 → DELETE
- Then 목록에서 제거(소프트 삭제). 기존 이슈의 값은 백엔드에서 보존(프론트는 재조회만)

**S4. 권한 없는 사용자**
- Given MANAGE_CUSTOM_FIELDS 권한 없는 멤버
- When 관리 페이지 진입
- Then 추가/수정/삭제 버튼 disabled + tooltip(fail-closed). 목록 조회는 가능

**S5. 이슈 생성 시 값 입력**
- Given 이슈 생성 폼에서 projectKey 입력 후
- When 프로젝트의 활성 커스텀 필드가 타입별 위젯으로 렌더 → 값 입력 → 생성
- Then customFields가 요청에 포함. required 누락/형식 오류면 백엔드 422 → 필드별/일반 에러 표시

**S6. 이슈 상세에서 값 조회·편집**
- Given 이슈 상세 메타패널
- When 커스텀 필드 섹션에서 값 확인/편집 → 저장
- Then PATCH customFields(낙관락 expectedVersion). 409 버전충돌 시 재조회+토스트(기존 메타 패턴)

### FieldType 10종 → 입력 위젯 매핑 (FR-6)

| FieldType | 위젯 | 값 형식(JSON) | 비고 |
|---|---|---|---|
| SHORT_TEXT | `<input type=text>` (Input) | string | ≤255 |
| LONG_TEXT | `<textarea>` (네이티브) | string | ≤32768 |
| NUMBER | `<input type=number>` | number | 유한값 |
| DATE | `<input type=date>` | "YYYY-MM-DD" | 네이티브 값 그대로 |
| DATETIME | `<input type=datetime-local>` | ISO8601 offset | local→ISO 변환(엣지 E-1) |
| SINGLE_SELECT | `<Select>` (shadcn) | string(option value) | |
| MULTI_SELECT | 체크박스 목록(네이티브) | string[] | |
| CHECKBOX | 단일 `<input type=checkbox>` | boolean | |
| RADIO | 라디오 그룹(네이티브) | string(option value) | |
| URL | `<input type=url>` | string | `^https?://.+` |

> checkbox/radio/textarea/datepicker는 ui/ 에 없음 → 네이티브 input + Label로 구현(shadcn 신규 도입 안 함, 의존성 0).

## 비기능 요구사항 (NFR)

- NFR-1 계약 정합 — Zod 스키마/타입은 백엔드 DTO를 invent 없이 미러(`frontend-zod-backend-dto-contract-gap`). customFields 값은 `Record<string, unknown>`로 표현(임의 JSON)
- NFR-2 검증 ground-truth는 백엔드 — 프론트는 required/형식 클라 검증을 보조로 하되 최종 판정은 422 응답 표시
- NFR-3 mutation은 invalidate-only(`mutation-setquerydata-partial-response-flicker`)
- NFR-4 TypeScript strict — `any` 금지, customFields 값은 unknown narrowing
- NFR-5 i18n 하드코딩 금지 — 모든 라벨 상수화

## 엣지 케이스

- **E-1 DATETIME 타임존** — `datetime-local`은 타임존 없는 로컬 시각. 백엔드는 ISO8601 offset(`Z`/`+09:00`) 요구 → 저장 시 로컬→ISO(offset 부여) 변환, 표시 시 ISO→로컬 역변환
- **E-2 미정의 키 잔존** — 필드 삭제 후에도 기존 이슈 custom_fields에 값 보존됨. 이슈 상세 표시 시 활성 정의에 없는 키는 "비활성 필드"로 표시 or 숨김(정의 목록과 join). 본 작업: 활성 정의 기준으로만 입력 위젯 렌더, 정의 없는 잔존 값은 표시 생략
- **E-3 required 빈 값** — 생성/수정 시 required 필드 미입력 → 클라 1차 경고 + 백엔드 422 최종
- **E-4 선택형 옵션 0건** — 생성 Dialog에서 선택형인데 옵션 미추가 → 저장 버튼 disabled(클라) + 백엔드 422(CUSTOM_FIELD_INVALID_DEFINITION) 방어
- **E-5 MULTI_SELECT 빈 배열 vs 미입력** — 선택 안 함 = `[]` 또는 키 생략. required면 빈 배열은 누락 취급
- **E-6 이슈 수정 값 삭제** — 특정 필드 값을 비우면 PATCH에서 키를 null로 전송(백엔드 키 단위 삭제 규칙)
- **E-7 projectKey 미입력 이슈 생성** — 커스텀 필드 섹션 disabled(컴포넌트 셀렉터 패턴 동일)
- **E-8 key 중복** — 409 → Dialog 유지 + 필드별 에러
