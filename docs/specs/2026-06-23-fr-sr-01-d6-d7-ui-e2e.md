# FR-SR-01 D6/D7 — 이슈 필터(다중 필드 조합) 프론트 UI + E2E 스펙

- 날짜: 2026-06-23
- FR: FR-SR-01 (논리 소속 search-export-import, 물리 구현 issue-tracking)
- 선행: 백엔드 D1~D5 완료 (#180). `GET /api/v1/issues`에 status/assignee/label/component 필터 파라미터 추가됨.
- 유형: 프론트엔드 전용 (백엔드 변경 0 예상). 보드 필터(FR-BD-02) D6/D7과 동형 + status 추가.

## 배경 / 재사용 자산

이슈 목록 화면(`/issues`)은 현재 `projectKey`(ATLAS 하드코딩) + `page`만으로 조회한다. 필터 UI가 없다.
백엔드는 이미 `status`(워크플로우 상태 키, OR) / `assignee`(UUID + `unassigned` 센티널, OR) /
`label`(이름, OR) / `component`(UUID, OR) 파라미터를 지원한다. 같은 필드 OR, 다른 필드 AND.
잘못된 UUID는 400 `ISSUE_FILTER_INVALID_UUID`.

보드 필터(FR-BD-02, #168/#171)가 담당자·라벨·컴포넌트 필터를 이미 구현했으나 **status가 없다**(보드는 컬럼=상태).
이슈 필터는 status를 더한다.

## 핵심 설계 결정 (Maxi 확정)

- **D1. 재사용 전략 = 이슈 전용 신규 + 공유부품 재사용.**
  `IssueFilterBar.tsx` + `lib/issue-filter.ts`를 신규 작성한다. 보드 코드(`BoardFilterBar`/`board-filter.ts`/
  `BoardCardFilterParams`)는 **0 변경**(보드 회귀 위험 차단 — 공유 VO 확장 시 소비처 회귀 교훈).
  공유 부품(`LabelAutocompleteInput`, `ComponentMultiSelect`, `useUsers`/`useUsersByIds`/`useLabels`/
  `useComponents`/`useDebounce` 훅)은 그대로 재사용한다.
- **D2. status 옵션 소스 = 전체 워크플로우에서 수집.**
  `GET /api/v1/workflows`(전체 워크플로우 목록, `fetchWorkflows`)의 `states`를 flatten + `key` 기준 중복 제거해
  status 옵션 목록을 만든다. 정렬은 `displayOrder`. 신규 `useWorkflows` 훅 + 옵션 추출 헬퍼.
  단일 프로젝트(ATLAS) 환경 적합. 백엔드 추가 0.
- **D3. 필터 상태 = URL search params** (`?status=&assignee=&label=&component=&page=`, 반복 param).
  새로고침/공유 시 보존. 보드 필터 패턴 동일(`filterToSearch`/`searchToFilter`).
- **D4. 클라이언트 필터링 0.** 프론트는 query string만 조립·전송, 필터 술어는 백엔드 SQL 위임.
- **D5. queryKey filter-aware.** 이슈 목록 queryKey를 `['issues', projectKey, page, filter]`로 확장.
  일괄 작업(bulk edit/transition) invalidate `['issues', projectKey]`는 prefix 매칭이라 모든 page/filter 캐시를
  무효화(정합 유지). 이슈 목록은 setQueryData 낙관적 업데이트가 없어(invalidate-only) 보드 드래그만큼 위험하지 않으나,
  filter 변경 시 재조회를 위해 queryKey에 filter를 포함한다.

## 사용자 시나리오 (Given-When-Then)

- **S1. status 필터.** Given 이슈 목록, When 사용자가 status="open" 선택, Then current_state_key=open 이슈만 표시 + URL `?status=open`.
- **S2. 담당자 필터.** When alice 선택, Then alice 담당 이슈만 + URL `?assignee=<alice-uuid>`.
- **S3. 미배정 필터.** When "미배정" 체크, Then 담당자 없는 이슈만 + URL `?assignee=unassigned`.
- **S4. 라벨 필터.** When "bug" 라벨 선택, Then bug 라벨 이슈만 + URL `?label=bug`.
- **S5. 컴포넌트 필터.** When 컴포넌트A 선택, Then 컴포넌트A 이슈만 + URL `?component=<uuid>`.
- **S6. 복합 AND.** When status=open + assignee=alice, Then 둘 다 만족(AND) 이슈만.
- **S7. 같은 필드 OR.** When status=open + status=in_progress, Then open 또는 in_progress(OR) 이슈.
- **S8. 초기화.** When "초기화" 클릭, Then 모든 필터 제거 + URL param 제거 + 전체 목록.
- **S9. 새로고침 보존.** Given URL `?status=open&assignee=...`, When 새로고침, Then 필터 상태 복원 + 동일 결과.
- **S10. 필터 변경 시 페이지 리셋.** Given page=2, When 필터 변경, Then page=0으로 리셋(다른 결과셋).

## 기능 요구사항 (FR)

- FR1. status/assignee/label/component 4종 필터를 다중 선택할 수 있다(각 필드 다중 값 = OR).
- FR2. 서로 다른 필드는 AND로 결합된다.
- FR3. 담당자 필터는 "미배정(unassigned)" 옵션을 포함한다.
- FR4. 활성 필터를 칩으로 표시하고 개별 ✕로 제거할 수 있다.
- FR5. "초기화" 버튼으로 모든 필터를 한 번에 제거한다.
- FR6. 필터 상태는 URL search params에 반영되어 새로고침/공유 시 보존된다.
- FR7. 필터 변경 시 이슈 목록이 자동 재조회된다(filter-aware queryKey).
- FR8. status 옵션은 전체 워크플로우의 상태(`displayOrder` 정렬, key 중복 제거)에서 채운다.
- FR9. 필터 결과 0건이면 빈 상태 안내 + "필터 초기화" 회복 CTA를 표시한다.
- FR10. 필터 변경 시 일괄 선택 상태(useIssueSelection)를 클리어한다(결과셋 전환 → 보이지 않는 선택 잔존 혼란 차단). 단순 페이지 이동은 기존대로 선택 누적 유지.

## 비기능 요구사항 (NFR)

- NFR1. 접근성 WCAG AA — 각 필터 컨트롤 label 연결, 칩 제거 버튼 aria-label, 키보드 조작 가능, 터치 타깃 44px+.
- NFR2. 반응형 — 컨테이너 `flex flex-wrap`로 모바일 세로 적층, 칩 영역 wrap.
- NFR3. 담당자 typeahead는 debounce(250ms)로 과다 호출 방지(보드 패턴 동일).
- NFR4. 클라이언트 필터링 0(백엔드 SQL 위임), DTO 오염 0.

## API 인터페이스 (소비 — 변경 없음)

- `GET /api/v1/issues?projectKey=ATLAS&status=&assignee=&label=&component=&page=&size=` → `Page<IssueResponse>`
- `GET /api/v1/workflows` → `{ data: WorkflowView[] }` (status 옵션 소스, states 포함)
- `GET /api/v1/labels?q=` / `GET /api/v1/projects/{key}/components` / `GET /api/v1/users?query=` (기존 옵션 훅)

## 엣지 케이스

- EC1. 필터 0건 결과 → 빈 상태 + "필터 초기화" CTA(회복 경로).
- EC2. 빈 필터 → URL param 키 완전 생략(`?status=` 잔존 금지).
- EC3. 새로고침/직접 URL 진입 → 필터 복원.
- EC4. `unassigned` 센티널(대소문자 구분) → includeUnassigned 매핑.
- EC5. 단일 문자열 vs 배열 — TanStack Router가 단일/배열 양쪽을 주므로 항상 배열 정규화(`toArray`).
- EC6. 필터 변경 시 page=0 리셋.
- EC7. status 옵션 로딩 중/에러 → status 섹션 비활성 또는 빈 목록(fail-safe, 다른 필터는 동작).
- EC8. filter-aware queryKey ↔ bulk invalidate prefix 정합(회귀 가드).
- EC9. 잘못된 UUID는 프론트가 정상 옵션에서만 선택하므로 발생 어려움. 단, 직접 URL 조작 시 백엔드 400 → 에러 표시.
