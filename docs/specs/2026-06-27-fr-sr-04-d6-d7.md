# FR-SR-04 D6/D7 — AQL 검색창 `text` 가상 필드 강조 + E2E — 스펙

> slug: fr-sr-04-d6-d7 · type: ui · 생성: 2026-06-27
> 선행: FR-SR-04 D1~D5 백엔드 #195(완료), FR-SR-02 AQL UI(토크나이저/하이라이터)
> ADR: [2026-06-26-fr-sr-04-korean-fts.md](../decisions/2026-06-26-fr-sr-04-korean-fts.md) D4 이행

## 배경 (한 줄)

백엔드가 #195에서 AQL `text` 가상 FTS 필드(`~` 전용, summary+description 전문 검색)를
추가했으나, 프론트 검색창 syntax highlighter는 이를 모른다. 사용자가 `text ~ "검색어"`를
입력하면 `text`가 일반 단어(PLAIN)로 처리돼 색칠되지 않는다. 이 계약 drift를 해소한다.

## 사용자 시나리오 (Given-When-Then)

- **S1 강조**: Given 검색 페이지, When `text ~ "로그인"` 입력, Then `text`가 다른 필드명
  (status/label 등)과 동일한 FIELD 색으로 강조된다.
- **S2 검색 실행**: Given `text ~ "검색어"` 입력, When Cmd/Ctrl+Enter, Then 백엔드 FTS
  검색이 실행되고 매칭 이슈 목록이 표시된다.
- **S3 대소문자**: Given `TEXT ~ "x"` 입력, When 토큰화, Then `TEXT`도 FIELD로 강조된다
  (백엔드 `classify("TEXT")==SUPPORTED`와 정합, 토크나이저 기존 `toLowerCase()` 경로).

## 기능 요구사항 (FR)

- **FR-1**: `aql-tokenizer.ts`의 `AQL_FIELDS` 화이트리스트에 `'text'`를 추가한다.
  백엔드 정본 `com.bts.shared.search.AqlFields.MVP_FIELDS`(`{status, label, summary,
  priority, text}`)와 일치시킨다. 토크나이저 타입 주석(line 7-8)도 갱신.
- **FR-2**: `text` 토큰은 기존 `FIELD` 토큰 타입으로 분류되어 `AqlHighlighter`의
  `text-syntax-field` 색을 재사용한다(신규 토큰 타입·색 추가 없음).
- **FR-3 (선택, 발견성)**: 검색창 placeholder(`search.tsx`)에 `text ~ "키워드"` 전문
  검색 예시를 추가해 사용자가 신규 필드를 발견하게 한다. 기존 placeholder 참조 테스트
  영향 grep 후 적용.

## 비기능 요구사항 (NFR)

- **NFR-1 단일 진실출처**: 프론트 `AQL_FIELDS`는 백엔드 `AqlFields.MVP_FIELDS`의 미러다.
  drift 방지를 위해 주석에 백엔드 정본 경로를 명시(기존 패턴 유지).
- **NFR-2 best-effort**: 토크나이저는 강조 best-effort이며 판정 정본은 백엔드 파서다
  (기존 KDoc 불변). 연산자 제약(`text =` 금지 등)은 백엔드가 400으로 판정하며 프론트는
  강조만 한다 — 기존 필드(priority ~ 등)와 동일 정책.

## 데이터 모델 변경

없음. 순수 프론트엔드 상수 + 테스트.

## 엣지 케이스 (self sanity-check 완료)

- **EC1 부분 식별자**: `textfield` → bare word 통째로 읽혀 `FIELD_SET.has("textfield")`
  false → PLAIN. 오강조 없음. ✅(기존 구조)
- **EC2 문자열 내부**: `summary ~ "text"` → 따옴표 안은 STRING 토큰 → `text` 미강조. ✅
- **EC3 대소문자**: `Text`/`TEXT` → `toLowerCase()` 후 매칭 → FIELD 강조. ✅
- **EC4 잘못된 연산자**: `text = "x"` → 프론트는 `text` FIELD 강조(best-effort),
  백엔드가 400 SEARCH 에러 반환 → 입력창 하단 alert 표시(기존 경로). ✅
- **EC5 ORDER BY text**: `... order by text` → 프론트 `order`/`by` KEYWORD + `text`
  FIELD 강조(best-effort), 백엔드 400 거부. 강조는 무해. ✅

→ 모든 엣지 케이스가 기존 토크나이저 구조로 자연 처리됨. 추가 분기 로직 불필요.

## 측정 가능한 완료 기준

1. `tokenizeAql('text ~ "x"')`의 첫 토큰이 `{type: 'FIELD', value: 'text'}`. (단위)
2. `AqlHighlighter`가 `text`를 `text-syntax-field` className span으로 렌더. (단위)
3. 프론트 `AQL_FIELDS` === 백엔드 `MVP_FIELDS` 정합(주석 명시 + 테스트로 5개 필드 확인).
4. E2E: `text ~ "키워드"` 입력 → FIELD 강조 + 검색 결과 표시(MSW). (D7)
5. `pnpm verify`(lint+typecheck+test+build) 통과.
