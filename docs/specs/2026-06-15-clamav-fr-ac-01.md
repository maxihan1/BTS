# ClamAV 첨부 바이러스 스캔 (FR-AC-01 D2) — 스펙

> BC: issue-tracking · slug: clamav-fr-ac-01 · 2026-06-15
> 관련 ADR: [docs/adr/2026-06-15-clamav-attachment-virus-scan.md](../adr/2026-06-15-clamav-attachment-virus-scan.md)
> 확정 결정: ①fail-closed ②저장 전 동기 스캔 ③raw clamd INSTREAM(의존성0) ④임시파일 버퍼링 ⑤StreamMaxLength≥100MB

## 사용자 시나리오 (Given-When-Then)

**S1. 정상(clean) 파일 업로드**
- Given: UPDATE 권한 보유 사용자가 정상 PDF(MIME 허용·100MB 이내)를 업로드
- When: `POST /api/v1/issues/{key}/attachments` (multipart)
- Then: clamd가 `stream: OK` 반환 → MinIO 저장 → 201 Created (기존 동작 유지)

**S2. 감염 파일 업로드**
- Given: UPDATE 권한 보유 사용자가 악성코드(또는 EICAR 테스트 시그니처) 포함 파일 업로드
- When: 업로드 요청
- Then: clamd가 `stream: <sig> FOUND` 반환 → **MinIO 저장·DB insert 모두 미수행** → 422 + `ISSUE_ATTACHMENT_INFECTED`(시그니처명 비노출 일반 메시지)

**S3. ClamAV 데몬 미가용 (fail-closed)**
- Given: clamd가 다운/응답 없음/타임아웃/연결 거부
- When: 업로드 요청
- Then: **업로드 거부**(저장 안 함) → 503 + 재시도 안내. 권한·MIME·감염과 구분되는 일시 거부

**S4. 권한/MIME 거부는 스캔 이전에 차단(불필요 스캔 회피)**
- Given: VIEW만 있거나(UPDATE 없음) 비허용 MIME
- When: 업로드 요청
- Then: 기존대로 403 / 415 — clamd 스캔 도달 전 차단

## 기능 요구사항 (FR)

- **FR-1**. 업로드 시 MinIO 저장 *이전*에 clamd로 파일 전체를 동기 스캔한다.
- **FR-2**. 스캔 결과가 정확히 `stream: OK`일 때만 저장을 진행한다. `FOUND`·미상 응답·빈 응답·프로토콜 오류는 모두 차단(fail-closed).
- **FR-3**. clamd 미가용/타임아웃/연결오류는 차단(저장 안 함)하고 503으로 응답한다.
- **FR-4**. 감염 차단은 422 + `ISSUE_ATTACHMENT_INFECTED`. 응답 message는 시그니처·내부정보를 노출하지 않는 일반 문구.
- **FR-5**. clamd 연동은 raw INSTREAM 프로토콜 직접 구현(신규 외부 의존성 0).
- **FR-6**. 스캔 입력은 디스크 임시 파일 버퍼링 경유(메모리 전체 적재 금지). 임시 파일은 성공/실패/예외 모든 경로에서 정리(try/finally).
- **FR-7**. dev/test 인프라에 clamd 제공. `StreamMaxLength`/`MaxFileSize`/`MaxScanSize`를 첨부 한도(100MB) 이상으로 설정.

## 비기능 요구사항 (NFR)

- **NFR-1 (보안)**. 스캔 우회 경로 0. 모든 비-OK 결말은 거부. 데몬 응답 신뢰 전 검증(정확한 `OK` 매칭).
- **NFR-2 (성능)**. 100MB 스캔이 업로드 응답 시간에 추가됨(사내 도구라 허용). 연결/read 타임아웃 명시(예 connect 5s, read 60s — plan에서 확정).
- **NFR-3 (리소스)**. 100MB를 힙에 적재하지 않음(디스크 임시파일). DB 커넥션은 기존대로 MinIO I/O 구간에서 비점유(트랜잭션 밖).
- **NFR-4 (설정)**. clamd host/port는 `bts.clamav.*`(`BTS_CLAMAV_HOST`/`BTS_CLAMAV_PORT`) — MinIO 설정 패턴 미러. **설정(host) 빈값 = 부팅 fail-fast**(MinIO endpoint와 동일, 스캔 불가 서비스 기동 금지). **런타임 데몬 다운/타임아웃 = 503 fail-closed**. 설정 오류와 일시 장애를 분리.
- **NFR-5 (테스트)**. EICAR 표준 테스트 시그니처로 감염 경로 검증. 데몬 다운 경로 결정적 검증.

## API 인터페이스 (REST)

신규 엔드포인트·권한·요청형식 **변경 없음**. 기존 `POST /api/v1/issues/{key}/attachments`(multipart) 내부에 스캔 게이트만 삽입. 응답 측 추가.

| 결과 | HTTP | errorCode | 비고 |
|---|---|---|---|
| clean | 201 Created | — | 기존 동작 |
| infected | 422 Unprocessable Content | `ISSUE_ATTACHMENT_INFECTED` | 일반 메시지(시그니처 비노출) |
| daemon 미가용/타임아웃 | 503 Service Unavailable | `ISSUE_ATTACHMENT_SCAN_UNAVAILABLE` | 재시도 가능 신호 |

(422 채택 근거: 형식은 정상이나 내용상 거부 → Unprocessable Content. 415는 MIME 전용(#149), 400보다 의미 정확.)

## 데이터 모델 변경

**없음.** `issue_attachments` 스키마 무변경, 신규 마이그레이션 없음. 스캔은 게이트일 뿐 영속 상태를 만들지 않음(저장 전 차단이므로 감염 파일 row 자체가 없음).

## 업로드 흐름 (변경 후)

```
checkPermission(UPDATE)
  → AttachmentTypePolicy.isAllowed (MIME, #149)
  → resolveIssueId (404 fail-fast — 비싼 스캔 이전, 권한 이미 통과라 존재 probe 무관)
  → [신규] 임시파일 버퍼링 → VirusScanPort.scan(tempStream)
        · OK     → 진행
        · FOUND  → ISSUE_ATTACHMENT_INFECTED (422)
        · 미가용  → ISSUE_ATTACHMENT_SCAN_UNAVAILABLE (503)
  → storagePort.put(tempStream, ...)
  → repository.insert (실패 시 보상 삭제)
  → finally: 임시파일 삭제
```

**스트림 재읽기 (gap 해소)**. 업로드 `input: InputStream`은 1회 read라 스캔+저장 양쪽에 못 씀. **서비스가 inbound 스트림을 내부 임시파일로 1회 복사**한 뒤, 임시파일을 ① 스캔 ② MinIO put에 각각 재오픈한다. 기존 `upload(input: InputStream, ...)` 계약·컨트롤러 무변경. (MultipartFile.getInputStream() 재읽기 의존은 컨테이너 동작 결합이라 기각 — 견고성 우선.)

신규 컴포넌트.
- `VirusScanPort`(application port) — `scan(input: InputStream): ScanVerdict {CLEAN, INFECTED}` (미가용은 예외로 표현 → fail-closed).
- `ClamdInstreamScanner`(adapter) — raw TCP INSTREAM 구현 + 타임아웃 + 응답 파싱.
- `ClamavConfig` — `bts.clamav.*` 바인딩(MinioStorageConfig 패턴 미러).
- 신규 예외 2종 — `AttachmentInfectedException`(422), `AttachmentScanUnavailableException`(503) + AttachmentExceptionHandler 매핑.

## 엣지 케이스

- **빈 파일(0바이트)**. clamd INSTREAM 0바이트 → OK. 허용(MIME 검증이 타입 책임). 특수처리 없음.
- **정확히 100MB**. multipart 한도와 동일. clamd `StreamMaxLength`를 100MB+여유(예 110M)로 설정해 경계 파일이 size limit으로 거부되지 않도록.
- **clamd StreamMaxLength 초과 응답**(`INSTREAM size limit exceeded`). 정상이면 발생 안 하나, 발생 시 비-OK → 차단(fail-closed). 설정으로 예방.
- **타임아웃**(connect/read). 차단(503). 데몬 응답 지연을 통과로 해석 금지.
- **연결 거부/데몬 다운**. 차단(503).
- **미상/빈 응답**. 차단(fail-closed). 정확한 `stream: OK`만 통과.
- **임시파일 정리**. 스캔 실패·MinIO 실패·예외 전 경로에서 finally 삭제(디스크 누수 0).
- **기존(스캔 이전 업로드) 파일**. 소급 스캔 비대상(스코프 외 — #145 이후 dev 데이터만, 운영 전). 다운로드 시 재스캔 안 함.

## 제약 조건

- 신규 외부 의존성 금지(raw 구현). 절대 규칙 §외부 의존성.
- BC 격리 유지(issue-tracking 내부, cross-BC 호출 없음).
- 기존 첨부 테스트(#145/#149) 회귀 0.
- Testcontainers ClamAV는 기동이 무거움(시그니처 DB 포함 이미지라도 수십초+) → singleton `.apply { start() }`(learnings 2026-05-21 stale port 회피) + ready 대기 전략(clamd PING/PONG 또는 ready 로그). `CLAMAV_NO_FRESHCLAMD=true` + 번들 DB로 freshclam 네트워크 의존·기동지연 완화(EICAR 탐지엔 번들 DB로 충분).
- 백엔드 CI 부재(로컬 게이트, learnings) → 무거운 ClamAV 컨테이너는 로컬 테스트에만 영향. 동시 Testcontainers suite flaky 위험(memory) → 통합테스트 단독 재실행 가능하게.
- prod(Naver Cloud 단일 호스트)도 clamd 실행 + `BTS_CLAMAV_*` 설정 필요(미설정 시 부팅 fail-fast). prod compose는 레포 외부라 본 PR은 dev/test 인프라 + 설정 키만 추가, prod 기동 가이드는 결과에 기록.
