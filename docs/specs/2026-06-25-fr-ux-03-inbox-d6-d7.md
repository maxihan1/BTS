백엔드 API 계약이 #186에서 확정된 **완료 FR의 후속 프론트 작업**이라, office-hours builder mode(기능 가치 검증)는 부적합 → 직접 기술 스펙 작성(learnings "bts-spec office-hours mismatch"). 프론트 설계 결정 4건은 Maxi 확정(2026-06-25, 아래 §제약 조건).

## 사용자 시나리오 (Given-When-Then)

### S1. 미읽음 뱃지 확인
- **Given** 인증된 사용자가 미읽은 인앱 알림 N건을 보유
- **When** 어느 페이지든 Header를 본다
- **Then** Header 우측 🔔 종 아이콘에 미읽음 개수 뱃지(N)가 표시된다. N=0이면 뱃지 숨김. N>99면 "99+".

### S2. Inbox 페이지 진입
- **Given** 사용자가 Header 🔔 아이콘을 본다
- **When** 종 아이콘을 클릭한다
- **Then** `/inbox` 페이지로 이동하고, 기본 탭(전체)의 알림 목록이 최신순(created_at DESC)으로 표시된다.

### S3. 탭 전환
- **Given** /inbox 페이지
- **When** "전체 / 안읽음 / 보관함" 탭을 전환한다
- **Then** 해당 탭 기준으로 목록이 다시 조회된다. (전체=미보관 전체, 안읽음=미읽음+미보관, 보관함=보관됨)

### S4. 읽음 토글
- **Given** 안읽음 알림 항목
- **When** 항목의 읽음 처리 버튼을 누른다
- **Then** 해당 항목이 읽음으로 표시되고, 미읽음 뱃지 카운트가 1 감소한다. (멱등 — 이미 읽음이면 변화 없음)

### S5. 보관 토글
- **Given** 알림 항목
- **When** 보관 버튼을 누른다
- **Then** 항목이 현재 탭(전체/안읽음)에서 사라지고 보관함 탭으로 이동한다. 보관함에서는 보관 해제 가능.

### S6. 일괄 읽음
- **Given** 미읽음 알림 여러 건
- **When** "전체 읽음" 버튼을 누른다
- **Then** 미읽음 알림이 모두 읽음 처리되고 뱃지 카운트가 0이 된다. (0건이어도 정상)

### S7. 검색/필터
- **Given** /inbox 페이지
- **When** 텍스트 검색어(q)·발신자·기간(from/to)을 입력한다
- **Then** 해당 조건으로 필터된 목록이 표시된다. (백엔드 푸시다운, 탭과 조합)

### S8. 이슈로 이동
- **Given** issueKey가 있는 알림 항목
- **When** issueKey 링크를 클릭한다
- **Then** SPA 라우팅으로 `/issues/{issueKey}` 이슈 상세로 이동한다.

### S9. 발신자 이름 표시
- **Given** actorUserId가 있는 알림
- **When** 목록을 본다
- **Then** UUID가 아니라 발신자 displayName(없으면 username)이 표시된다. actorUserId=null이면 "시스템".

### S10. 실시간 갱신
- **Given** /inbox 페이지 또는 Header가 열린 상태에서 STOMP 스트림 연결됨
- **When** 새 인앱 알림이 STOMP로 도착한다
- **Then** 미읽음 카운트와 (활성 탭이 영향받으면) 목록이 자동 갱신된다(invalidate).

## 기능 요구사항 (FR — 프론트)

| ID | 요구사항 |
|---|---|
| FR-F1 | Header에 🔔 종 아이콘 + 미읽음 카운트 뱃지(unread-count 소비). N=0 숨김, >99 "99+". |
| FR-F2 | `/inbox` 라우트 페이지 신규 (TanStack Router code-based, adapter 패턴). |
| FR-F3 | 탭 3종(ALL/UNREAD/ARCHIVED) 전환 → tab 쿼리 파라미터. |
| FR-F4 | 검색 필터: 텍스트(q)·발신자(senderId)·기간(from/to). 탭과 조합. 발신자는 사용자 검색 자동완성(fetchUsers query)으로 선택 → senderId(UUID) 설정(UUID 직접 입력 불가). |
| FR-F5 | 단건 읽음/안읽음 토글 (PATCH /{id}/read). |
| FR-F6 | 단건 보관/보관해제 토글 (PATCH /{id}/archive). |
| FR-F7 | 일괄 읽음 "전체 읽음" (POST /read-all, ids 생략=미읽음 전체). |
| FR-F8 | 발신자 이름 해석: actorUserId 배치 수집 → fetchUsersByIds → displayName/username. null→"시스템". |
| FR-F9 | 페이지네이션 (Spring Page: page/size, totalElements 기반 페이지 이동). |
| FR-F10 | issueKey 항목 → `/issues/{key}` SPA Link 이동. |
| FR-F11 | STOMP 스트림(useNotificationStream) 새 알림 시 unread-count + inbox 목록 invalidate. |

## 비기능 요구사항 (NFR)

- TypeScript strict, Zod 스키마는 백엔드 InboxItemResponse와 1:1(invent 금지).
- mutation은 invalidate-only(setQueryData 금지 — 부분응답 플리커 회피, PR #46 교훈).
- i18n 문자열은 ko.ts 정본(콜론 종결 금지). E2E 셀렉터는 i18n 정본 import.
- 접근성: 종 아이콘 aria-label, 탭 role, 뱃지 스크린리더 텍스트.
- Inbox 100건 페이지네이션 p95 300ms(백엔드 §NFR, 프론트는 페이지 size≤100 강제 준수).

## API 인터페이스 (백엔드 #186 확정 — 소비만)

baseURL `/api/v1/users/me/inbox`. 본인 + IN_APP 한정. 401/404 격리.

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| GET | `/` | `tab`·`q`·`senderId`·`issueKey`·`from`·`to`·`page`·`size(max100)` | `200` `Page<InboxItemResponse>` |
| GET | `/unread-count` | — | `200` `{ data: { count: number } }` |
| PATCH | `/{id}/read` | `{ read: boolean }` | `204` |
| PATCH | `/{id}/archive` | `{ archived: boolean }` | `204` |
| POST | `/read-all` | `{ ids?: string[] }` | `200` `{ data: { updated: number } }` |

추가 소비: `GET /api/v1/users?ids=<uuid>,...` (fetchUsersByIds, 발신자 이름 해석).

**InboxItemResponse**: `id` · `eventType` · `issueKey?` · `title` · `body?` · `actorUserId?` · `readAt?` · `archivedAt?` · `createdAt`. (Instant 필드는 ISO-8601 문자열로 직렬화 → Zod `z.string().datetime()`).

**Spring Page 응답 형태**: `{ content: InboxItemResponse[], totalElements, totalPages, number, size, ... }`. favorites와 달리 DataResponse 래퍼 없음(Page 직접).

## 제약 조건 (Maxi 확정 2026-06-25)

1. **진입점**: Header 🔔 아이콘 + 미읽음 뱃지 → 별도 `/inbox` 페이지(탭/검색/페이지네이션 풀기능). 드롭다운 미리보기 아님.
2. **발신자 표시**: fetchUsersByIds로 이름 해석(기존 API 재사용). null→"시스템".
3. **그룹화**: **평면 목록 채택**(created_at DESC). SDD 9.2 "issueKey 그룹화 묶음렌더"는 **미채택** — issueKey는 검색 필터로만 제공. (백엔드 응답에도 그룹 메타 없음 → 일관). **deviation: product §5.2 D3 그룹화 표기 동기화 필요**.
4. **스트림 연동**: STOMP 새 알림 도착 시 unread-count + inbox 목록 invalidate.

추가 제약:
- BC 격리: notification BC 프론트. favorites.ts api 관례 계승.
- apiFetch from @/api/client. CSRF는 GET/PATCH/POST 백엔드 정책 따름(favorites 선례: apiFetch가 처리).
