# FR-SL-02 D6/D7 — 사용자 Slack 계정 연결/해제 — 스펙

> BC: slack-integration (`com.bts.slack`)
> 연결 UX 결정(Maxi): **C. 이메일 자동해석** (`users.lookupByEmail`)
> 재사용: `SlackUserMappingService`(link/unlink/resolveByUserId)·`user_slack_mapping`(V701)·`UserLookupPort.findEmailById`(이미 배선)·`SlackMessageClient` SDK 패턴
> 범위: D6(엔드포인트+페이지) + D7(E2E) 동시 (FR-SL-01 D6/D7 #247 선례)

## 개요

FR-SL-02 백엔드(#252)가 이슈 멘션/할당을 Slack DM으로 발송하지만, `user_slack_mapping`에 행이 없으면 수신 대상 해석이 skip돼 **실제로 아무도 못 받는다**. D6은 사용자가 본인 Slack 계정을 연결해 이 알림을 **활성화**하는 자가 서비스(self-service) 진입점이다.

연결 방식은 **이메일 자동해석**. 사용자가 "Slack 연결"을 클릭하면 백엔드가 그 사용자의 BTS 이메일로 워크스페이스 봇 토큰을 써서 `users.lookupByEmail`을 호출, 매칭된 `slack_user_id`+`team_id`를 자동으로 매핑한다. 사용자는 자기 Slack ID를 몰라도 되고, 이메일 일치로 소유권이 검증돼 **오배송이 0**이다.

## 사용자 시나리오 (Given-When-Then)

- **S1 연결(happy)**: Given 로그인 사용자·미연결·워크스페이스 봇 설치됨·BTS 이메일==Slack 이메일, When "Slack 연결" 클릭, Then 백엔드가 이메일로 조회→매핑 upsert, 카드가 "연결됨 · {워크스페이스명}"으로 갱신, 이후 멘션/할당 시 Slack DM 수신.
- **S2 해제**: Given 연결됨, When "연결 해제" 클릭, Then 매핑 행 제거, 카드 "미연결"로, 이후 DM 미수신(graceful skip).
- **S3 재연결(멱등)**: Given 이미 연결됨, When "Slack 연결" 재클릭, Then 이메일 재조회→같은 행 upsert(최신 slack_user_id/team_id), 200.
- **S4 이메일 불일치**: Given Slack 이메일이 BTS 이메일과 다른 사용자, When 연결 클릭, Then "Slack에서 이 이메일로 계정을 찾을 수 없습니다" 안내(연결 안 됨). (수동 입력 폴백은 후속.)
- **S5 워크스페이스 미설치**: Given 관리자가 아직 Slack 앱 미설치, When 연결 클릭, Then "먼저 관리자가 워크스페이스에 Slack을 연결해야 합니다" 안내.
- **S6 봇 스코프 부족**: Given 봇에 `users:read.email` 미부여(구 설치), When 연결 클릭, Then "관리자가 Slack 앱을 다시 연결해야 합니다" 안내.

## 기능 요구사항 (FR)

- **FR1** me-scope 엔드포인트 3종(GET 상태 / POST 연결 / DELETE 해제), JWT subject로 본인만. **PAT → 401**(profile/status/preferences me-scope 선례).
- **FR2** POST 연결 = `UserLookupPort.findEmailById(userId)` → 워크스페이스 봇 토큰으로 `users.lookupByEmail(email)` → `SlackUserMappingService.link(userId, slackUserId, teamId)`.
- **FR3** GET 상태 = `resolveByUserId(userId)` → `{ connected, workspaceName, linkedAt }`. workspaceName은 `slack_installs.team_name`을 team_id로 조회.
- **FR4** DELETE 해제 = `unlink(userId)`(하드삭제), 미연결 상태에서도 멱등 200.
- **FR5** 봇 스코프 `users:read.email`를 `DEFAULT_SLACK_SCOPES`에 추가(deviation). 기존 설치는 1회 재연결 필요(운영 노트·런북).
- **FR6** 프론트 `/settings/slack` 사용자 페이지 — 연결 상태 카드 + 연결/해제 버튼 + 결과 배너. **OAuth 리다이렉트 없음**(평범한 apiFetch JSON POST/DELETE, Bearer).

## API 인터페이스 (REST)

| 메서드 | 경로 | 인증 | 응답 |
|---|---|---|---|
| GET | `/api/v1/slack/me/connection` | JWT me | 200 `{ connected: bool, workspaceName: string?, linkedAt: iso? }` |
| POST | `/api/v1/slack/me/connection` | JWT me | 200 상태 / 오류(아래) |
| DELETE | `/api/v1/slack/me/connection` | JWT me | 200 `{ connected: false }` |

POST 오류 매핑(로컬 `@ExceptionHandler`, 컨트롤러 패키지 한정 — 교훈 domain-exception-http-handler-basepackage-scope).
- 이메일 없음(BTS 사용자 email null) → **422** `EMAIL_UNAVAILABLE`
- 워크스페이스 미설치 → **409** `WORKSPACE_NOT_INSTALLED`
- 봇 스코프 부족(`missing_scope`) → **409** `SLACK_SCOPE_MISSING`
- Slack에서 이메일 미발견(`users_not_found`) → **404** `SLACK_USER_NOT_FOUND`
- Slack 일시 오류(429/5xx/네트워크) → **503** `SLACK_TEMPORARILY_UNAVAILABLE`

응답은 `slack_user_id`·이메일·봇 토큰을 **절대 노출 안 함**(FR-SL-01 3중 미노출 관례). 상태는 connected/workspaceName/linkedAt만.

## 신규 코드(윤곽)

- `SlackUserLookupClient`(신규) — `methods.usersLookupByEmail` 래퍼. sealed 결과(Found(id, teamId)/NotFound/MissingScope/Transient). 봇 토큰 미노출. `MethodsClient` 주입(SlackMessageClient 동일 부팅 안전 패턴).
- `SlackUserConnectionService`(신규 오케스트레이터) — email 조회 → 봇 토큰 해석(설치 조회+복호화) → lookup → `SlackUserMappingService.link`. **외부 HTTP는 @Transactional 밖**(I/O tx밖, SlackInstallService CONCERN-1 교훈). link() upsert만 트랜잭션.
- `SlackConnectionController`(신규) — me-scope 3 엔드포인트. `SlackActorExtractor.extract()` 재사용.
- `SlackConnectionExceptionHandler`(신규 or 기존 확장) — 위 오류 매핑, 컨트롤러 패키지 한정.
- 프론트: `settingsSlackRoute` `/settings/slack` · `SlackUserConnectionCard` · `api/slack.ts` 확장(getMyConnection/connect/disconnect + Zod) · MSW `slack-user-connection-handlers`(시드가능 stateful + 오류 시나리오 토글) · E2E.

- **보안**: 봇 토큰 3중 미노출. 이메일·slack_user_id 응답 미노출. me-scope(타인 매핑 불가·JWT subject 고정).

## 엣지 케이스

- EC1 재연결 멱등(upsert). EC2 email null→422. EC3 미설치→409. EC4 scope 부족→409. EC5 이메일 미발견→404. EC6 다중 설치(멀티워크스페이스): 각 설치 봇 토큰으로 순차 lookup, 첫 매칭 사용(사내 단일 워크스페이스 가정, 다중도 best-effort 동작). EC7 429→503(사용자 재시도). EC8 미연결 해제 멱등 200. EC9 동시 연결=같은 user 행 upsert 직렬화.

## 제약 조건

- 봇 스코프 `users:read.email` 추가 → **기존 설치 1회 재연결** 운영 의존(런북 명시). 미재연결 시 EC4로 명확 안내.
- BTS 이메일 == Slack 이메일 가정(사내 단일 워크스페이스). 불일치 사용자는 수동 입력 폴백(후속, BLOCKER 아님).
