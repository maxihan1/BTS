## 범위 (Maxi 확정 2026-07-05)

MVP = 전역 네비게이션 5종 + 도움말 모달. 커스텀 훅(의존성 0). `j/k/e/m/s`(컨텍스트 의존)는 후속 FR로 제외.
`cmd+k`(Command Palette)는 FR-UX-04에서 이미 구현 — 도움말에 표기만.

| 단축키 | 동작 | 구현 |
|---|---|---|
| `?` (Shift+/) | 단축키 도움말 모달 토글 | 모달 열기/닫기 |
| `c` | 새 이슈 생성 | navigate `/issues/new` |
| `/` | 검색 | navigate `/search` |
| `g` → `i` | 내 이슈 | navigate `/issues` |
| `g` → `d` | 대시보드 | navigate `/dashboards` |

라우트는 FR-UX-04 `commands.ts`의 QUICK_LINKS와 동일(router.ts 실재 확인). 지어낸 경로 없음.

## 사용자 시나리오 (Given-When-Then)

### S1. 새 이슈 단축키 (`c`)
- Given 로그인한 사용자가 아무 페이지에서 텍스트 입력에 포커스가 없을 때
- When `c` 키를 누르면
- Then `/issues/new`(새 이슈 폼)으로 이동한다.

### S2. 검색 단축키 (`/`)
- Given 로그인 사용자, 입력 포커스 없음
- When `/` 키를 누르면
- Then `/search`(검색 페이지)로 이동한다. 브라우저 기본 동작(빠른 찾기)은 preventDefault로 막는다.

### S3. leader-key 시퀀스 (`g i`, `g d`)
- Given 로그인 사용자, 입력 포커스 없음
- When `g`를 누른 뒤 1초 이내에 `i`를 누르면 → `/issues`(내 이슈)로 이동
- When `g`를 누른 뒤 1초 이내에 `d`를 누르면 → `/dashboards`(대시보드)로 이동
- When `g` 뒤 1초가 지나거나 `i`/`d`가 아닌 키를 누르면 → 시퀀스 리셋, 아무 이동 없음

### S4. 도움말 모달 (`?`)
- Given 로그인 사용자, 입력 포커스 없음
- When `?`(Shift+/)를 누르면 → 단축키 목록 모달이 열린다
- When 모달이 열린 상태에서 `?` 또는 `Esc`를 누르면 → 모달이 닫힌다(토글)
- Then 모달은 구현된 단축키(5종 + `Cmd+K`)를 그룹/설명과 함께 보여준다

### S5. 입력 포커스 가드
- Given 사용자가 `input`/`textarea`/`select`/`contentEditable`에 포커스를 두고 타이핑 중
- When `c`, `/`, `g`, `?` 등 단축키 문자를 입력하면
- Then 단축키가 발화하지 않고 해당 문자가 정상 입력된다(네비게이션/모달 없음).

### S6. 비로그인 가드
- Given 로그인하지 않은 사용자(로그인 화면 등)
- When 단축키를 누르면
- Then 아무 반응 없음(keydown 리스너 미등록 — FR-UX-04 E5 패턴).

### S7. 명령 팔레트와 공존
- Given `Cmd+K` 명령 팔레트가 열려 있음(팔레트 입력창 포커스)
- When `c`/`/` 등 단축키 문자를 팔레트에서 타이핑하면
- Then 전역 단축키가 발화하지 않는다(팔레트 입력창은 입력 포커스 가드에 해당).

## 기능 요구사항 (FR)

- **FR1** 커스텀 훅 `useKeyboardShortcuts`는 native `document` keydown 리스너로 5종 단축키를 처리한다.
- **FR2** `c`/`/`는 단일키 즉시 네비게이션, `g i`/`g d`는 leader-key 시퀀스(타임아웃 1초) 네비게이션.
- **FR3** `?`(Shift+/)는 도움말 모달을 토글한다(열림↔닫힘).
- **FR4** 입력 포커스 가드 — 이벤트 target이 `input`/`textarea`/`select`/`contentEditable`이면 단축키 무시.
- **FR5** IME 조합 가드 — `e.isComposing`(한글 등 조합 입력 중)이면 단축키 무시.
- **FR6** 수정자 가드 — `meta`/`ctrl`/`alt`가 눌린 조합은 무시(단, `?`의 Shift는 허용). `Cmd+K`(팔레트)·브라우저 단축키를 삼키지 않음.
- **FR7** `enabled`(인증) 가드 — 비로그인 시 리스너 미등록 + pending 시퀀스 상태 초기화(FR-UX-04 `useCommandPalette` 선례).
- **FR8** 도움말 모달은 접근성 다이얼로그(role=dialog, 포커스 트랩, Esc 닫기, 포커스 복원). 구현된 단축키(5종 + `Cmd+K`)만 목록화(비구현 `j/k/e/m/s` 미표시).
- **FR9** 네비게이션 단축키는 기본 브라우저 동작을 preventDefault로 막은 뒤 라우터 이동.
- **FR10** 훅/모달은 인증 시에만 렌더(`__root.tsx`에서 `useNotificationStream`/`useCommandPalette`와 동일 패턴).

## 비기능 요구사항 (NFR)

- **NFR1** 단축키 동작률 100% (E2E 전수 — §NFR 측정표 "단축키 동작률").
- **NFR2** 도움말 모달 WCAG 2.1 AA — 포커스 트랩/복원, Esc, aria 속성.
- **NFR3** 단축키 반응 keydown→네비게이션 즉시(<100ms 체감, 서버 왕복 0).
- **NFR4** 메모리 누수 0 — 언마운트/`enabled` 변경 시 리스너·타이머 cleanup.

## 엣지 케이스

- **E1** `g` 단독 후 타임아웃(1초 경과) → 시퀀스 리셋, 이동 없음.
- **E2** `g` 후 `x`(무효 키) → 시퀀스 리셋 + `x`는 정상 처리(무동작).
- **E3** `g g` 연타 → 두 번째 `g`가 pending 재시작(리셋 후 재대기).
- **E4** 입력창에서 `c` 타이핑 → 네비게이션 안 됨, 문자 정상 입력(S5).
- **E5** 한글 조합 중 `ㅊ`(c 위치) 입력 → `isComposing` 가드로 무시(E4와 별개 경로).
- **E6** 팔레트 열림 중 단축키 → 무시(S7, 팔레트 입력 포커스 가드).
- **E7** 도움말 모달 열림 중 `c`/`/` → 모달 내부(다이얼로그)라 전역 단축키 억제, Esc/`?`만 반응.
- **E8** 비로그인 → 리스너 미등록(S6).
- **E9** `?` 반복 → 토글(열림↔닫힘)이 stale 없이 동작(react-usestate-stale-key-prop / FR-UX-04 controlled Dialog 토글닫기 선례 주의).
- **E10** 같은 라우트로 재이동(예 이미 `/issues`에서 `g i`) → 라우터 idempotent, 무해.

- **E11** 도움말 모달 열림 중 `Cmd+K` → 팔레트가 도움말 위에 스택(두 Radix 다이얼로그 공존). 허용(비차단).

## 설계 명확화 (Brainstorming Phase B 반영)

- **키 매칭은 `e.key`** — `?`와 `/`는 같은 물리 키(Shift 차이)라 `e.key`(`'/'` vs `'?'`)로 구분한다. `e.code`/`keyCode` 사용 금지.
- **단일 진실 출처** — 단축키 정의를 코드 상수 레지스트리(`SHORTCUTS`) 한 곳에 두고, 훅 dispatch와 도움말 모달 목록이 **같은 상수를 구동**한다(fixture drift 선례 차단, learnings zod-schema-strengthen-inline-mock-fanout 정신).
- **가드 순서** — (1) `enabled` (2) `isComposing` (3) 입력 포커스 (4) 수정자 순으로 검사하고, 실패 시 `preventDefault` **이전에** early return(입력창에서 `/`가 정상 타이핑되도록).
- **네비게이션은 TanStack Router `useNavigate`** — 훅이 `__root.tsx`(RouterProvider 내부)에서 호출되므로 `useNavigate()` 사용 가능.
- **파일 배치** — `command-palette/` 미러 구조. `keyboard-shortcuts/{shortcuts.ts, useKeyboardShortcuts.ts, ShortcutsHelpDialog.tsx}`.

### Non-goals
- leader-key pending 시각 표시(Linear식 "g" 힌트) — 미구현.
- 컨텍스트 의존 단축키(`j/k/e/m/s`), 커스텀 키맵(FR-PF-03) — 범위 밖.

## 제약 조건

- react-hotkeys-hook 등 신규 의존성 도입 금지(ADR D2). native keydown만.
- 단일키(`c`/`/`/`?`)는 반드시 입력 포커스·IME·수정자 가드 통과 시에만 발화.
- 컨텍스트 의존 단축키(`j/k/e/m/s`) 구현 금지(범위 밖, 후속 FR).
- 도움말 모달에 비구현 단축키를 "동작하는 것처럼" 표기 금지.
