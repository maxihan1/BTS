## 배경 / 범위

FR-UX-02 즐겨찾기/Star의 프론트엔드 D6(UI)·D7(E2E). 백엔드 D1~D5(#184)가 제공하는 favorites API를 소비해 (1) 화면에서 대상을 Star(즐겨찾기 등록/해제)하는 토글 버튼, (2) Header의 즐겨찾기 목록 드롭다운을 구현한다.

**Maxi 확정 결정 (2026-06-24)**.
- D-1. Star 노출 대상 = **ISSUE / DASHBOARD / PROJECT 3종 모두**. FILTER는 FR-SR-03(필터 저장) 미구현이라 실대상이 없어 제외.
- D-2. 즐겨찾기 목록 = **Header의 ⭐ 아이콘 드롭다운**(타입별 그룹). 현재 좌측 사이드바 인프라가 없고, 기존 계정 드롭다운 패턴 재사용이 가장 가볍다.
- D-3. 드롭다운 항목 라벨 = **targetId 그대로 + 타입 아이콘**. 백엔드가 제목을 주지 않으므로 추가 fetch 없이 targetId(이슈 키·프로젝트 키·대시보드 UUID)를 표시.

## 소비 API 계약 (백엔드 #184, 변경 없음)

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | `/api/v1/favorites` | `{ targetType, targetId }` | 201(신규) / 200(멱등 기존) `{ data: { id, targetType, targetId, createdAt } }` |
| DELETE | `/api/v1/favorites?targetType=&targetId=` | (쿼리) | 204 (대상 기준 멱등) |
| GET | `/api/v1/favorites[?targetType=]` | (쿼리) | 200 `{ data: { items: [{ id, targetType, targetId, createdAt }] } }` (created_at DESC) |

- 에러: 400 `{ errorCode: "NOTIF_FAV_INVALID" }` (잘못된 targetType / 빈 targetId / malformed JSON), 401(미인증).
- `targetType` enum 문자열: `ISSUE` / `DASHBOARD` / `PROJECT` (`FILTER`는 백엔드 정의만, 프론트 미사용).
- `targetId`: 이슈=이슈 키(`PROJ-123`), 프로젝트=프로젝트 키(`PROJ`), 대시보드=대시보드 UUID 문자열.

## 사용자 시나리오 (Given-When-Then)

### S1. 이슈 즐겨찾기 등록/해제
- Given 사용자가 이슈 상세(`/issues/PROJ-123`)를 보고 있고, 해당 이슈는 즐겨찾기 안 된 상태
- When Star 버튼을 클릭
- Then POST `/api/v1/favorites {targetType:"ISSUE", targetId:"PROJ-123"}` 호출 → 버튼이 채워진 별(★, 즐겨찾기됨) 상태로 전환, Header 드롭다운 목록에 추가됨
- When 다시 Star 버튼을 클릭
- Then DELETE `/api/v1/favorites?targetType=ISSUE&targetId=PROJ-123` → 빈 별(☆) 상태로 전환, 드롭다운 목록에서 사라짐

### S2. 대시보드 / 프로젝트 즐겨찾기
- Given 사용자가 대시보드 상세(`/dashboards/{uuid}`) 또는 프로젝트 보드(`/projects/{key}/board`)를 보고 있음
- When 화면의 Star 버튼 클릭
- Then 해당 타입(DASHBOARD/PROJECT)·targetId(대시보드 UUID / 프로젝트 키)로 POST/DELETE 토글

### S3. 즐겨찾기 드롭다운 조회·이동
- Given 사용자가 이슈 2개·대시보드 1개를 즐겨찾기함
- When Header의 ⭐ 아이콘을 클릭
- Then 즐겨찾기 목록이 타입별 그룹(이슈/대시보드/프로젝트 순)으로 표시됨. created_at DESC 순(백엔드 정렬 유지)
- When 목록 항목을 클릭
- Then 해당 라우트로 이동(이슈→`/issues/{key}`, 대시보드→`/dashboards/{id}`, 프로젝트→`/projects/{key}/board`), 드롭다운 닫힘

### S4. 빈 상태
- Given 즐겨찾기가 하나도 없음
- When ⭐ 아이콘 클릭
- Then "즐겨찾기한 항목이 없습니다" 빈 상태 메시지 표시

### S5. 깨진 참조 graceful (ADR D6)
- Given 즐겨찾기한 대상이 삭제/접근 불가가 됨 (백엔드는 끊어진 참조도 그대로 목록에 반환 — 형식만 검증)
- When 드롭다운에서 해당 항목 클릭
- Then 라우트 이동 후 대상 화면이 404/403을 graceful 표시(기존 라우트의 에러 처리에 위임). 드롭다운 자체는 항목을 정상 렌더(targetId 표시) — 목록 깨짐 없음

## 기능 요구사항 (FR)

- **FR-1.** `api/favorites.ts` — Zod 스키마(`{data}` 언랩), `fetchFavorites(targetType?)`, `addFavorite(targetType, targetId)`, `removeFavorite(targetType, targetId)`, React Query 훅(`useFavorites`, `useAddFavorite`, `useRemoveFavorite`), 에러코드 상수(`NOTIF_FAV_*`)·추출기. issue-watchers.ts 패턴 1:1 계승.
- **FR-2.** `FavoriteButton` 공유 컴포넌트 — `targetType`·`targetId` props. 현재 즐겨찾기 여부에 따라 ★/☆ 토글. 클릭 시 add/remove mutation. `aria-pressed`·접근 가능 라벨. 로딩 중 토글 비활성(중복 클릭 가드).
- **FR-3.** 즐겨찾기 상태 판정 — Star 버튼과 드롭다운이 **같은 `useFavorites()`(필터 없음, 전체 목록) 단일 쿼리를 공유**한다(N개 버튼이 각자 조회하는 낭비 차단, queryKey 동일). 목록에서 `(targetType, targetId)` 일치 항목 존재 여부로 isFavorited 도출. add/remove mutation의 `onSettled`는 즐겨찾기 목록 쿼리를 invalidate.
- **FR-4.** Star 버튼 배치 — (a) 이슈 상세 액션 영역, (b) 대시보드 상세 액션 영역, (c) 프로젝트 보드(또는 프로젝트 헤더) 액션 영역. 각 화면의 라우트 파라미터에서 targetId 도출.
- **FR-5.** `FavoritesMenu` — Header의 ⭐ 아이콘 드롭다운. `useFavorites()` 목록을 타입별 그룹으로 렌더, 각 항목은 타입 아이콘 + targetId 라벨 + 라우트 링크. 빈 상태 메시지. 인증 사용자에게만 노출(Header가 이미 isAuthenticated 게이팅).
- **FR-6.** 쿼리 키 — `favoritesKey(targetType?)` 독립 키. 토글 mutation이 목록 쿼리를 invalidate해 Star 버튼 상태와 드롭다운이 동기화.
- **FR-7.** MSW — `favorite-handlers.ts`(POST/DELETE/GET) + `handlers.ts` 등록. **stateful 공유 store**(브라우저 시드 가능)로 토글 후 목록이 실제로 갱신되어야 함(가짜 그린 회피, 메모리 msw-mutation-stateful-refetch).

## 비기능 요구사항 (NFR)

- **NFR-1.** TypeScript strict — `any` 금지, Zod 스키마는 백엔드 DTO 1:1 미러(field invent 금지).
- **NFR-2.** API 관례 — `apiFetch`(`@/api/client`) 사용, issue-watchers.ts와 동일한 `{data}` 언랩·에러 throw 패턴. CSRF는 apiFetch가 처리(POST/DELETE).
- **NFR-3.** 단위 테스트 — api/favorites.ts(스키마·fetch·훅), FavoriteButton(토글·로딩·aria), FavoritesMenu(그룹·빈상태·링크). vitest.
- **NFR-4.** E2E — Playwright. 이슈 Star 토글 라운드트립 + 드롭다운에서 항목 확인 + 클릭 이동. MSW stateful store로 실제 등록/해제 반영(건수 단언으로 vacuous 차단).
- **NFR-5.** lint/typecheck clean — pnpm lint, pnpm typecheck(tsconfig.app.json, 메모리 ci-typecheck-tsconfig-app-vs-local).
- **NFR-6.** i18n — 즐겨찾기 버튼 라벨·드롭다운 제목·빈 상태·에러 메시지는 i18n(ko) 키로 작성. 한국어 문장은 콜론으로 끝내지 않음(메모리 i18n 콜론종결 ko.test 검증).

## 엣지 케이스

- **EC-1.** 중복 클릭(연타) — 토글 mutation isPending 동안 버튼 비활성. 멱등 API라 서버 측은 안전하나 UI 플리커 방지.
- **EC-2.** 즐겨찾기 등록 실패(네트워크/4xx) — 토스트/인라인 에러, 버튼 상태는 서버 진실로 복원(낙관적 업데이트 안 함 → 플리커 회피, 메모리 mutation-setquerydata-partial-response-flicker / setQueryData 금지).
- **EC-3.** 깨진 참조(S5) — 드롭다운은 targetId만 렌더하므로 항상 정상. 이동 후 대상 화면이 404/403 처리. 드롭다운에서 직접 "삭제된 대상" 표시는 추가 fetch 필요 → 본 PR scope 외(D-3).
- **EC-4.** 미인증 — Header 자체가 isAuthenticated일 때만 렌더되므로 ⭐ 메뉴도 미노출. API 401은 apiFetch refresh 흐름에 위임.
- **EC-5.** 대시보드 targetId=UUID 표시 — D-3 확정대로 UUID 그대로 노출(라벨 해석 안 함). 타입 아이콘으로 종류 구분.
- **EC-6.** 목록 항목 일부 displayName 부재 — 해당 없음(백엔드가 displayName 미반환, targetId만 사용).

## 제약 조건

- BC 격리 — 본 PR은 `apps/web` 프론트만. 백엔드 변경 없음(#184 계약 그대로 소비). favorites API 외 다른 BC 호출 없음.
- 신규 라우트 불필요 — 드롭다운은 Header 인라인 렌더(별도 /favorites 페이지 안 만듦, D-2).
- targetId 라벨 — 제목 해석 N+1 fetch 금지(D-3).

2. Header ⭐ 드롭다운이 즐겨찾기 목록을 타입별 그룹으로 표시, 항목 클릭 시 올바른 라우트로 이동.
3. 빈 상태 메시지 표시.
4. 단위 테스트(api/favorites + FavoriteButton + FavoritesMenu) + E2E(Star 라운드트립 + 드롭다운 이동) 통과.
