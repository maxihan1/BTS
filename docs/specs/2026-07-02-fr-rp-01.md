# FR-RP-01 번다운 / 번업 차트 — 스펙

> 모듈: agile-planning | 엔드포인트: `GET /api/v1/sprints/{id}/burndown`
> 지표: 잔여 추정 시간(초) | 데이터 소스: on-the-fly in-memory
> 관련: ADR 2026-07-02-fr-rp-01-burndown-burnup, SDD §13.5.1/§13.6/§6.5
> 범위: 백엔드 D1~D5 (프론트 recharts D6 + E2E D7은 후속 PR — FR-TL-01 선례)

## 사용자 시나리오 (Given-When-Then)

**S1. ACTIVE 스프린트 번다운 조회 (해피 패스)**
- Given: BROWSE 권한 보유자가 start_date~end_date가 설정된 ACTIVE 스프린트에 이슈 3개(추정 각 8h/4h/4h = 16h)가 할당됨. 2일차까지 worklog 6h 기록.
- When: `GET /api/v1/sprints/{id}/burndown`.
- Then: 200. burndown Actual Line이 1일차 16h→2일차 10h로 감소, Ideal Line은 16h→0으로 선형. burnup Completed Line은 누적 6h, Scope Line은 16h 평탄.

**S2. COMPLETED 스프린트 회고**
- Given: 종료된 COMPLETED 스프린트.
- When: 동일 요청.
- Then: 200. start_date~end_date 전 구간의 Actual/Ideal/Completed/Scope 시계열 반환 (과거 데이터 on-the-fly 재구성).

**S3. 기간 미설정 스프린트**
- Given: start_date 또는 end_date가 NULL인 스프린트.
- When: 동일 요청.
- Then: 422 (code=SPRINT_DATES_REQUIRED). 시간축 정박점이 없어 계산 불가.

**S4. 권한 없음 / 미인증 / 미존재**
- 미인증 → 401. BROWSE 권한 미충족 → 403. 미존재/소프트삭제 스프린트 → 404. (SprintController.get 미러 — actor 추출을 리소스 조회보다 먼저)

**S5. 빈 스프린트**
- Given: 이슈 0개(또는 전부 추정치 NULL).
- Then: 200. Scope=0, 전 구간 remaining=0, ideal 0→0 평탄선. (에러 아님)

## 기능 요구사항 (FR)

- **FR1**. `GET /api/v1/sprints/{id}/burndown`가 번다운(Actual/Ideal) + 번업(Completed/Scope) 시계열을 단일 응답으로 반환한다.
- **FR2**. 지표는 **초 단위 추정 시간**. 총 스코프 = Σ `issues.original_estimate_seconds`(스프린트 소속·미삭제 이슈, NULL=0).
- **FR3**. day D 누적 완료 = Σ `worklogs.time_spent_seconds` (스프린트 이슈·미삭제 worklog 중 `started_at`의 **UTC 날짜** ≤ D). day D 잔여 = max(0, 총 스코프 − 누적 완료).
- **FR4**. Ideal Line = start_date의 총 스코프 → end_date의 0으로 일자별 선형 보간.
- **FR5**. 시계열 일자 축 = [start_date, end_date] 각 캘린더 일(inclusive). Actual/Completed는 [start_date, min(end_date, today)]까지만 산출(미래 일자는 데이터 없음). Ideal/Scope는 전 구간. today는 주입된 `Clock`의 UTC 날짜(시각 의존 로직 Clock 주입 — learnings AuthController time-bomb).
- **FR6**. 권한: 스프린트 소속 projectKey에 대한 `IssuePermission.BROWSE` (SprintController.get·list와 동일). cross-BC `IssuePermissionResolver`로 판정.

## 비기능 요구사항 (NFR)

- **NFR1 (BC 격리)**. agile-planning은 issue-tracking 내부를 직접 import하지 않는다. estimate/worklog 조회는 shared-kernel 신규 포트만 사용(TimelineLookupPort 선례).
- **NFR2 (결정성)**. 시계열은 일자 오름차순 결정적 정렬. 동일 입력 → 동일 출력(테스트 가능).
- **NFR3 (성능)**. 1K 사용자·스프린트당 수백 worklog 규모 → 포트는 이슈키 집합으로 estimate 합 + worklog 목록을 **최소 쿼리(2회 이하)**로 반환. N+1 금지.
- **NFR4 (fail-closed)**. 신규 포트의 default 구현은 fail-safe(빈 데이터). prod 어댑터 미주입 시 부팅 실패(non-null 주입) 또는 non-prod stub — 기존 포트 관례 준수.
- **NFR5 (보안 그레인 — 2단 필터, Maxi 게이트2 확정)**. (1) 스프린트 projectKey에 대한 **프로젝트 BROWSE 1회**(SprintController.get·list 미러) + (2) **이슈별 가시성 필터 적용** — 집계 전 이슈 키를 뷰어 가시 집합으로 좁힌다(`IssueRepository.filterVisibleIssueKeys`가 정본 보안 술어 `buildActiveSecureWhere` **재사용**, TimelineLookupAdapter 선례). 뷰어가 볼 수 없는 이슈(security_level 차단)의 estimate/worklog는 집계에서 제외되어 집계 시간값을 통한 간접 추론이 차단된다. **트레이드오프(수용)**. 차트는 뷰어 스코프라 이슈별 기밀이 걸린 프로젝트에서 뷰어별 부분값이 될 수 있다. 뷰어 스코프 부분값을 응답에 고지(partial 플래그)하는 것은 후속 프론트(D6)에서 검토.
- **미사용 필드 명시**. `remaining_estimate_seconds`는 사용하지 않는다(현재 스냅샷 단일값이라 시계열 재구성 불가). 스코프=`original_estimate_seconds`, 소진=worklog 누적으로만 계산.

## API 인터페이스 (REST)

```
GET /api/v1/sprints/{id}/burndown
  path: id (UUID)
  200 OK:
  {
    "data": {
      "sprintId": "uuid",
      "projectKey": "ATLAS",
      "status": "ACTIVE",
      "startDate": "2026-07-01",
      "endDate": "2026-07-14",
      "totalScopeSeconds": 57600,
      "points": [
        {
          "date": "2026-07-01",
          "remainingSeconds": 57600,   // Actual (미래일=null)
          "idealSeconds": 57600,        // Ideal (전 구간)
          "completedSeconds": 0,        // Burnup 누적 (미래일=null)
          "scopeSeconds": 57600         // Burnup 총 스코프 (전 구간, 평탄)
        }
      ]
    }
  }
  401 미인증 / 403 BROWSE 미충족 / 404 미존재·삭제 / 422 기간 미설정(SPRINT_DATES_REQUIRED)
```

- 응답은 기존 `DataResponse<T>` 래핑. 날짜는 ISO(`LocalDate` → "yyyy-MM-dd"), 초는 정수.
- 미래 일자(> today, ACTIVE 스프린트)의 `remainingSeconds`/`completedSeconds`는 **null**(아직 미도래). `idealSeconds`/`scopeSeconds`는 전 구간 non-null.
- 예외는 SprintExceptionHandler 계열이 ProblemDetail로 처리(신규 422 코드 추가).

**없음.** 기존 재사용 — `sprints`, `sprint_issues`, `worklogs`, `issues.original_estimate_seconds`. 신규 마이그레이션/스냅샷 테이블/스케줄러 없음(ADR D3).

## cross-BC 포트 (신규, shared-kernel)

`SprintBurndownLookupPort` (가칭, plan에서 확정) — issue-tracking 어댑터 구현, agile-planning 소비.

```kotlin
interface SprintBurndownLookupPort {
    /** 이슈 키 집합의 번다운 원천 데이터. 미삭제 이슈/worklog만. */
    fun fetchBurndownSource(issueKeys: Set<String>): BurndownSource
    // default: BurndownSource(0, emptyList())  — fail-safe
}
data class BurndownSource(
    val totalOriginalEstimateSeconds: Long,          // Σ original_estimate (NULL=0)
    val worklogEntries: List<WorklogContribution>,   // 미삭제 worklog
)
data class WorklogContribution(
    val startedOnUtcDate: LocalDate,   // worklogs.started_at AT TIME ZONE UTC 의 날짜
    val timeSpentSeconds: Long,
)
```

- 어댑터는 issue_key → issues.id → worklogs 조인 + estimate 합을 2쿼리 이하로. `started_at`은 TIMESTAMPTZ → UTC 날짜 버킷(FR-TT-02 date_trunc AT TIME ZONE UTC 선례).
- 배선: prod 어댑터(issue-tracking) + agile-planning 전체-컨텍스트 통합테스트용 stub 빈 등록(learnings: cross-BC SPI 부팅함정 — 신규 포트 미주입 시 82 fail). BoardIssueLookupPort/TimelineLookupPort 배선 선례.

## 계산 알고리즘 (D2 핵심)

```
입력: sprint(start, end, projectKey), issueKeys, BurndownSource(scope, worklogs), today(=Clock UTC date)
1. scope = source.totalOriginalEstimateSeconds
2. 일자별 완료량 map: day -> Σ timeSpent (worklog.startedOnUtcDate 로 그룹)
3. cumulative = 0; asOf = min(end, today)
4. for d in [start..end]:
     ideal(d)  = scope * (end - d) / (end - start)   // 선형, end==start면 d==start=scope, 그 외 0
     scopeLine(d) = scope
     if d <= asOf:
        cumulative += 완료량[d] (없으면 0)
        completed(d) = cumulative
        remaining(d) = max(0, scope - cumulative)
     else:
        completed(d) = null; remaining(d) = null
```

- **주의**: worklog.startedOnUtcDate < start 인 기여는 d==start 루프에서 cumulative에 선반영(스프린트 이전 로그 = 이미 소진). ≤ 비교로 자연 처리하려면 알고리즘 2에서 start 이전 기여를 start 버킷에 합산.
- end==start(1일 스프린트): ideal은 start=scope 단일점. 0 나눗셈 방지 분기.

## 엣지 케이스

1. start 또는 end NULL → 422 SPRINT_DATES_REQUIRED.
2. 이슈 0개 / 전부 추정 NULL → scope 0, 평탄 0 라인 200.
3. 로그 > 추정 → remaining max(0,·) 클램프(음수 없음). completed는 클램프 없음(scope 초과 가능 — 문서화된 한계).
4. worklog가 start 이전/이후 일자 → start 이전은 start 버킷 합산, end 이후는 범위 밖 무시.
5. today < start (아직 시작 안 한 미래 스프린트) → asOf < start → Actual/Completed 전부 null, Ideal/Scope만. (계획 열람은 허용)
6. today > end (지난 스프린트, status 무관) → 전 구간 Actual 산출.
7. 소프트삭제 이슈/worklog 제외. sprint_issues의 issue_key가 삭제된 이슈 가리키면 estimate/worklog 0 기여.
8. PLANNED 상태라도 기간 있으면 계산 허용(에러 아님) — status로 막지 않음. 기간 유무로만 판정.

## 제약 조건

- 스코프 변경 이력 미재구성 → Scope Line 평탄(SDD §13.5.2 "스코프 변경 가시화" v1 미지원, ADR D4 명시).
- 완료 판정 = 시간 로그 기반(worklog). 이슈 상태 전환(DONE)와 무연동 — 추정/로그 미입력 팀은 번다운 무의미(ADR D2 한계, product D2 명시).
- BC 격리: sprint_issues(agile-planning) ↔ estimate/worklog(issue-tracking)는 포트로만.
