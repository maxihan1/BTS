> Maxi 결정(2026-06-25): ① syntax highlight = 자체 경량 토크나이저(textarea+overlay) ② UI = 별도 라우트 `/search` ③ D3 = summary만 GIN trgm

## 배경

FR-SR-02(AQL = Atlas Query Language, JQL 호환 텍스트 검색)의 백엔드 코어 MVP는 PR #189로 완료. 본 작업은 남은 3개 D단계.
- **D3** — `pg_trgm` 확장 + GIN 인덱스로 `~`(부분일치) 검색 가속
- **D6** — `/search` AQL 입력창 + syntax highlight + 결과 목록 프론트 UI
- **D7** — E2E

백엔드 계약(불변, 프론트 정본)은 plan `## 도메인 정리 §백엔드 계약` 참조. 요지.
- `POST /api/v1/search/aql` body `{ projectKey, query, page=0, size=50(1..100) }`
- 응답 `Page<AqlSearchHit>` raw — `content[]{key,summary,typeKey,currentStateKey,assigneeId,priority,priorityName,projectKey,updatedAt}` + `totalElements/totalPages/first/last/empty/number`
- 에러 RFC 7807 ProblemDetail + `errorCode`/`detail`/`position`/`timestamp`

## 사용자 시나리오 (Given-When-Then)

**S1 — 정상 검색.**
- Given. 로그인 + 프로젝트 BROWSE 권한 보유, `/search` 진입
- When. 입력창에 `status = open AND priority IN (1, 2)` 입력 후 검색
- Then. 매칭 이슈가 목록으로 표시(key/summary/상태/우선순위), 페이지네이션 동작, 입력 중 키워드(`AND`)·필드(`status`)·연산자(`=`,`IN`)·문자열·숫자가 색상 구분됨

**S2 — 문법 오류.**
- Given. 입력창에 잘못된 쿼리 `status = ` (값 누락)
- When. 검색
- Then. 백엔드 400 `SEARCH_SYNTAX_ERROR` + `detail` 메시지를 입력창 하단에 표시, `position`이 있으면 해당 위치를 시각적으로 안내. 결과 목록은 갱신 안 함(이전 상태 유지 또는 초기)

**S3 — 미지원 필드.**
- Given. `assignee = me` 입력(후속 PR 예정 필드)
- When. 검색
- Then. 400 `SEARCH_FIELD_NOT_YET_SUPPORTED` → "아직 지원하지 않는 필드입니다" 안내(`detail` 노출)

**S4 — 0건.**
- Given. 매칭 없는 쿼리
- When. 검색
- Then. "조건에 맞는 이슈가 없습니다" 빈 상태

**S5 — 권한/인증.**
- 미인증(401 `SEARCH_UNAUTHENTICATED`) → 로그인 안내. BROWSE 없음(403 `SEARCH_ACCESS_DENIED`) → "검색 권한이 없습니다"(프로젝트 존재 여부 미노출)

**S6 — 결과에서 이슈 진입.**
- 결과 항목 클릭 → `/issues/{key}` 상세로 이동

## 기능 요구사항 (FR)

- **FR-1 (D6)** `/search` 라우트 신규. AQL 입력창(textarea 기반) + 검색 버튼 + 결과 목록 + 페이지네이션. TanStack Router code-based 패턴(Page 컴포넌트 + RouteAdapter), URL search params에 `q`/`projectKey`/`page` 동기화(공유 가능 링크). **projectKey(G1)** — 기존 `issues.index` 선례를 따라 `DEFAULT_PROJECT_KEY='ATLAS'` 기본값 + URL `projectKey` override 허용(현 프론트는 멀티 프로젝트 스위처 미성숙 — 단일 기본 프로젝트가 일관적). 프로젝트 선택 드롭다운은 후속.
- **FR-2 (D6)** syntax highlight — 자체 토크나이저(`lib/aql-tokenizer.ts`)가 입력 문자열을 토큰(KEYWORD/FIELD/OPERATOR/STRING/NUMBER/PAREN/COMMA/PLAIN)으로 분해. `AqlHighlighter`가 textarea 위 overlay(`<pre aria-hidden>`)로 색상 렌더. **색상은 DESIGN.md 신규 syntax 토큰(design B1 — 임의 색 금지)**, 폰트는 `--font-mono` 토큰(design B2 — 정렬 정본). **IME(design B3)** — 한글 조합 중 `isComposingRef`로 overlay 갱신 보류(use-mention-autocomplete 패턴). 백엔드 토큰셋과 정합(키워드 `AND OR NOT IN`+`ORDER BY ASC DESC`, 연산자 `= != ~`, 필드 `status label summary priority`). **ORDER BY(G2)** — `ORDER`/`BY`를 각각 KEYWORD 토큰(백엔드 AqlToken과 동일). 키워드 매칭 대소문자 무시. **하이라이트는 best-effort 표시용, 판정 정본은 백엔드** — 토큰셋 상수는 회귀 스냅샷 + 백엔드 정본 file:line 주석으로 가드(TS↔Kotlin import 불가라 "백엔드 동일 단언"은 vacuous — eng B3).
- **FR-3 (D6)** API 클라이언트 `api/search.ts` — `searchAql({projectKey, query, page, size})`. 같은 BC 선례 없으면 issue-tracking 관례(apiFetch) 따름. POST + 인증 → CSRF 토큰 동반(impl에서 BC 관례 grep 확정).
- **FR-4 (D6)** Zod 스키마 — `AqlSearchHit` + `Page` 형태를 백엔드 DTO와 1:1 정합(추측 필드 invent 금지). `assigneeId` nullable, `updatedAt` ISO Instant.
- **FR-5 (D6)** 에러 표시 — ProblemDetail의 `errorCode`별 사용자 메시지 매핑 + `detail` 노출 + `position`(문법오류) 위치 안내. 200/400/401/403/500 분기.
- **FR-6 (D6)** 입력 제약 — textarea `maxLength=2000`(백엔드 MAX_QUERY_LENGTH 미러), 빈/공백 쿼리 시 검색 버튼 비활성(백엔드 NotBlank 사전 차단). **page size=20 고정**(issues.index 일관성), `page` 0-base. **검색 트리거(G2)** — 검색 버튼 클릭 + `Cmd/Ctrl+Enter`(textarea라 단순 Enter는 줄바꿈 보존). placeholder에 예시 쿼리(`status = open AND priority = 1`) 노출.
- **FR-7 (D6)** 헤더 네비에 `/search` 진입점 추가(검색 아이콘/링크).
- **FR-8 (D3)** Flyway 마이그레이션(issue-tracking, V031) — `CREATE EXTENSION IF NOT EXISTS pg_trgm` + `CREATE INDEX idx_issues_summary_trgm ON issues USING gin (lower(summary) gin_trgm_ops)`. **표현식 인덱스 `lower(summary)`** — 백엔드 `~`가 jOOQ `likeIgnoreCase`(`lower(summary) LIKE lower(?)`)라 bare 컬럼 인덱스는 미사용(eng B1). **`init_codegen.sql` 미러 필수**(확장→인덱스 순서, codegen 부트스트랩 컨벤션 — eng B2). EXPLAIN 인덱스 사용 통합테스트로 실효 검증. label `~`는 범위 제외(후속).
- **FR-9 (D7)** E2E — S1(정상)/S2(문법오류)/S4(0건) 최소 happy+error path. MSW 핸들러(`POST /api/v1/search/aql`) 신규.

## 비기능 요구사항 (NFR)

- **NFR-1** AQL 단순 쿼리 p95 < 500ms, 100만건 < 1s(product §NFR). D3 인덱스가 summary `~` 검색을 seq scan → trgm GIN으로 전환. (측정은 후속 — 인덱스 존재 검증까지가 본 PR 범위)
- **NFR-2** DoS — 클라 maxLength 2000 + 백엔드 토큰1000/깊이50 가드 의존. 클라가 백엔드 가드를 대체하지 않음(방어 중복).
- **NFR-3** 접근성 — 입력창 label, 에러 `role="alert"`, 결과 목록 `aria-label`. overlay는 `aria-hidden`(스크린리더는 textarea만 읽음).
- **NFR-4** syntax highlight overlay와 textarea의 스크롤/폰트/패딩 완전 정렬(텍스트 어긋남 0). 폰트는 mono.

## API 인터페이스

백엔드 #189 확정 계약 사용(신규 백엔드 변경 없음). 프론트는 소비만.
- 요청 `POST /api/v1/search/aql` `{ projectKey: string, query: string, page?: number, size?: number }`
- 응답 200 `Page<AqlSearchHit>`. 에러 400/401/403/500 ProblemDetail.

## 데이터 모델 변경 (D3)

- issue-tracking V031 — `pg_trgm` 확장 설치 + `issues.summary` trigram GIN 인덱스. **구조 변경 없음**(성능 인덱스). 소프트삭제/이슈키 영속성 무관(읽기 가속만).

## 엣지 케이스

- EC1. 빈/공백 쿼리 → 검색 버튼 disable(클라) + 백엔드 NotBlank 400 안전망
- EC2. 2000자 초과 → maxLength로 입력 차단 + 백엔드 400(SEARCH_VALIDATION_FAILED) 대비
- EC3. 문법오류 position 0-base → UI는 1-base 또는 캐럿 위치 안내(혼선 방지 명시)
- EC4. 미지원 필드/알 수 없는 필드 → errorCode별 구분 메시지
- EC5. 결과 0건 vs 에러 구분(빈 상태 ≠ 에러 alert)
- EC6. 페이지 이동 중 쿼리 변경 → page=0 리셋(filter-aware queryKey, [[fr-sr-01-d6-d7-done]] 미러)
- EC7. URL `q`에 특수문자/한글 → 인코딩 round-trip 정합
- EC8. 401 자동 refresh 함정 — 로그인된 검색은 apiFetch 정상. 단 검색 자체는 pre-session 아님(인증 후 기능)이라 [[auth-pre-session-401-raw-fetch]] 비해당
