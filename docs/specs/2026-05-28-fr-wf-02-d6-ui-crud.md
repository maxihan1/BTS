# FR-WF-02 D6 — 워크플로우 스킴 관리 admin UI — 스펙

> slug: fr-wf-02-d6-ui-crud · type: ui · BC: project-workflow · 2026-05-28
> 범위 결정 (Maxi). 전체 4 화면 (목록 + 상세+매핑 + 생성 + 프로젝트 할당). 디자인. 시안 1 (Multi-pane admin console, PR #26 사이드 메타패널 taste 계승).

## 사용자 시나리오 (Given-When-Then)

- **S1 스킴 목록 조회.** Given admin 권한 사용자, When `/admin/workflow-schemes` 접근, Then 좌 사이드바에 표준 4 + 커스텀 N 스킴 트리 표시. 각 스킴의 매핑 수 + 사용 프로젝트 수 카운트.
- **S2 스킴 상세 진입.** Given 스킴 목록, When 좌 네비 항목 클릭, Then `/admin/workflow-schemes/{schemeKey}` 라우트, 중앙 패널에 매핑 테이블 + 우 메타패널에 표준 여부/사용 프로젝트/생성·수정/액션 표시.
- **S3 스킴 생성.** Given 좌 네비 하단 「＋ 새 스킴 생성」 클릭, When `/admin/workflow-schemes/new` 라우트, key/name/description 입력 후 저장, Then 201 응답 의 새 스킴 상세로 이동. 좌 네비 자동 재조회.
- **S4 매핑 추가 (낙관적).** Given 스킴 상세, When 「＋ 매핑 추가」 버튼 → 이슈 타입 select + 워크플로우 select 인라인 행 append + 저장, Then `POST /workflow-schemes/{key}/mappings`. UI 즉시 반영 + 성공 시 매핑 list 갱신. 409 MAPPING_DUPLICATE 시 낙관적 변경 롤백 + 토스트.
- **S5 매핑 삭제.** Given 스킴 상세 매핑 행, When 행 액션 ⋯ → 「삭제」, Then `DELETE /workflow-schemes/{key}/mappings/{mappingId}` 204 후 행 제거 + 토스트.
- **S6 default mapping 설정/변경.** Given 스킴 상세, When 매핑 추가 시 이슈 타입 = "기본 (모든 타입)" 선택, Then `POST /mappings` body `{ issueTypeKey: null, workflowKey: "..." }`. partial UNIQUE 중복 시 409 MAPPING_DEFAULT_DUPLICATE 토스트 + 기존 default mapping 변경 안내. **G2 보강 — shadcn Select 의 value 는 string only, NULL 직접 표현 불가**. frontend 가 sentinel `"__default__"` 사용 → POST 직렬화 시점에 null 로 변환 (`@/api/workflow-schemes.ts` 의 sentinel 처리 utility 함수).
- **S7 표준 스킴 보호.** Given 표준 스킴 상세 (is_default = true), When 우 메타패널 「삭제 불가」 버튼 보임 (disabled, tooltip "표준 스킴은 삭제 불가"). key/is_default 필드는 읽기 전용. name/description은 편집 가능. mapping 변경 자유 (D11 결정).
- **S8 사용 중 스킴 삭제 차단.** Given 커스텀 스킴 사용 중 (project_workflow_scheme_assignments 1+), When 「삭제」 클릭, Then 409 SCHEME_IN_USE + body `{ usedByProjects: ["ATLAS", ...] }` 모달 표시 (프로젝트 link 클릭 → 프로젝트 스킴 할당 화면).
- **S9 프로젝트 스킴 할당.** Given project ATLAS settings, When `/projects/ATLAS/settings/workflow-scheme` 접근, Then 현재 적용 스킴 + 변경 select (전체 스킴 list) + 「적용」 primary 버튼. `PUT /projects/ATLAS/workflow-scheme` body `{ schemeKey: "team-a-scheme" }` UPSERT.
- **S10 자동 할당 (EC-1) 인지 표시.** Given project 가 assignment 행 없음 (첫 transition 전), When 프로젝트 스킴 할당 화면 진입, Then "현재 스킴 없음. 첫 이슈 전이 시 software-scheme 자동 할당" 안내 카드 표시.

## 기능 요구사항 (FR)

- **FR1.** `/admin/workflow-schemes` 라우트 — 좌 사이드바 스킴 트리 (표준 4 + 커스텀 N + 「＋ 새 스킴」). 각 항목 카운트 (사용 프로젝트 수). 시안 1 layout.
- **FR2.** `/admin/workflow-schemes/$schemeKey` 라우트 — 중앙 매핑 테이블 + 우 메타패널. 라우트 패턴 `workflows.$key.tsx` 선례 (PR #13, code-based RouteAdapter).
- **FR3.** `/admin/workflow-schemes/new` 라우트 — 스킴 생성 폼 (key/name/description). Zod 검증 (key REGEX, name 1~255자). 201 후 상세로 navigate.
- **FR4.** 매핑 CRUD (인라인) — 「＋ 매핑 추가」 버튼 → 행 append 모드 (이슈 타입 select + 워크플로우 select + 저장/취소). 행별 ⋯ 액션 (삭제). useMutation `onMutate` 캐시 선반영 + `onError` 롤백 + `onSettled` invalidate. **G1 보강 — 이슈 타입 select 옵션에서 이미 매핑된 타입은 제외** (서버 round-trip 절약, 더 명확한 UX). 5 표준 IssueType 중 미매핑만 노출 + "기본 (모든 타입)" 옵션 (default mapping 가 비어있을 때만 활성).
- **FR5.** 표준 스킴 보호 UI — `is_default === true` 시 (a) key/is_default 필드 read-only + (b) 「삭제」 버튼 disabled + tooltip "표준 스킴은 삭제 불가" + (c) name/description/mapping 편집 가능 (D11 결정 반영).
- **FR6.** 사용 중 스킴 삭제 차단 모달 — 409 SCHEME_IN_USE 응답 시 modal `usedByProjects` list 표시. 각 프로젝트 link → 그 프로젝트의 스킴 할당 화면으로 navigate (변경 후 재시도 동선).
- **FR7.** `/projects/$projectKey/settings/workflow-scheme` 라우트 — 현재 스킴 표시 + 변경 select + 적용 CTA. `GET /projects/{projectKey}/workflow-scheme` + `PUT` UPSERT.
- **FR8.** 자동 할당 안내 (EC-1) — assignment 행 부재 시 404 응답 → "첫 이슈 전이 시 software-scheme 자동 할당" 안내 카드.
- **FR9.** 에러 처리 — errorCode 10종 → 한국어 사용자 메시지 매핑. 409 토스트 + 자동 재조회 (MAPPING_DUPLICATE / MAPPING_DEFAULT_DUPLICATE / SCHEME_IN_USE / VERSION_CONFLICT). 403 toast (SCHEME_STANDARD_NOT_DELETABLE / TYPE_STANDARD_NOT_DELETABLE). 404 폴백 role=alert (SCHEME_NOT_FOUND / WORKFLOW_NOT_FOUND / ISSUE_TYPE_NOT_FOUND). 500 일반 토스트 (WORKFLOW_SCHEME_NO_DEFAULT).
- **FR10.** 디자인 — 시안 1 (Multi-pane admin console). 3-컬럼 (좌 240px 사이드바 + 중앙 1fr + 우 280px 메타패널). DESIGN.md OKLCH 토큰 고정. shadcn/ui 컴포넌트.
- **FR11.** Navigation 링크 — dashboard / header 에 「관리 → 워크플로우 스킴」 link 1개 추가 (G4 보강). admin 권한 분기는 FR-PM-04 후속 (모든 사용자에게 노출).
- **FR12 (후속 후보).** 좌 네비 가상 스크롤 (커스텀 스킴 100+ 시). 본 PR scope 외.

### backend (BC 격리 예외 — PR #13 D2 옵션 C 패턴)

- **FR-B1.** `WorkflowSchemeResponse` 에 `mappingsCount: Int` + `usedByProjectsCount: Int` 추가 (list/get/create/update 응답 공통).
- **FR-B2.** 단건 조회 응답에 `mappings: List<MappingResponse>` 동봉 — PR #18 controller 주석 line 35 약속 이행.

- **FR-B5.** ArchUnit BC 격리 예외 ADR — `docs/adr/2026-05-28-workflow-scheme-frontend-view-layer-cross-bc-lookup.md` 신규.

## 비기능 요구사항 (NFR)

- **낙관적 업데이트 패턴.** PR #26 일관 — `onMutate`(cancelQueries + snapshot + 캐시 선반영) → `onError`(snapshot 롤백 + toast) → `onSettled`(invalidateQueries). 매핑 추가/삭제, default mapping 변경, 스킴 할당 모두 적용.
- **응답 래퍼.** Scheme 단건/생성 = `{ data: WorkflowSchemeResponse }`, Scheme 목록 = `Page<WorkflowSchemeResponse>` (Spring Page). Mapping = nested in scheme detail. IssueType list = `IssueTypeResponse[]` (래퍼 0, 5개 표준 고정).
- **타입 안전.** TS strict. Zod 응답 파싱. 백엔드 정본 필드명 (`schemeKey`, `mappings`, `isDefault`, `issueTypeKey`, `workflowKey`). PR #13 learnings 의 spec §6 정본 표기 패턴 적용 (plan §의 축약 표기 사용 금지).
- **접근성.** WCAG AA. 좌 네비 키보드 탐색 (방향키 + Enter), 우 메타패널 disabled 버튼 tooltip aria-describedby, 모달 focus trap, 토스트 role=status.
- **테스트.** Vitest + RTL 단위 + MSW API mock. `vi.mock` 좁은 범위 (learnings 2026-05-26). MSW handlers 통합 (mocks/handlers.ts 에 schemeHandlers spread + dev/test 양쪽 동작). PR #26 의 C1 learning 회귀 방지.
- **로깅.** eslint no-console 준수 (PR #12 ADR).
- **D7 E2E 준비.** Playwright 시나리오 — S1~S9 happy path UI 완주 가능 (백엔드 기동 시). D7 PR 에서 정식 시나리오 작성.

## API 인터페이스 (정본 — backend PR #18 변경 없음)

base `/api/v1`. 모든 endpoint 권한 검증 — `WorkflowSchemePermission.MANAGE_SCHEME` (4.1, 4.2, 4.4) / `ASSIGN_SCHEME` (4.3). AlwaysAllow stub `@Profile("!prod")` (FR-PM-04 후속 정식 RBAC).

### 4.1 Scheme CRUD (5 endpoint)
| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | `/workflow-schemes` | `{ key, name, description }` | 201 `{ data: SchemeResponse }` |
| GET | `/workflow-schemes` | `?page=&size=` | 200 `Page<SchemeResponse>` |
| GET | `/workflow-schemes/{schemeKey}` | — | 200 `{ data: SchemeDetailResponse }` (mappings 동봉) |
| PUT | `/workflow-schemes/{schemeKey}` | `{ name?, description? }` (key/is_default 변경 불가) | 200 `{ data: SchemeResponse }` |
| DELETE | `/workflow-schemes/{schemeKey}` | — | 204 (S7 차단 / S8 차단) |

### 4.2 Mapping CRUD (2 endpoint)
| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | `/workflow-schemes/{schemeKey}/mappings` | `{ issueTypeKey: string \| null, workflowKey: string }` | 200 `{ data: MappingResponse }` |
| DELETE | `/workflow-schemes/{schemeKey}/mappings/{mappingId}` | — | 204 |

### 4.3 Project assignment (2 endpoint)
| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| PUT | `/projects/{projectKey}/workflow-scheme` | `{ schemeKey }` | 200 `{ data: AssignmentResponse }` (UPSERT) |
| GET | `/projects/{projectKey}/workflow-scheme` | — | 200 `{ data: AssignmentResponse }` 또는 404 (EC-1 안내) |

### 4.4 IssueType (read-only, 1 endpoint)
| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| GET | `/issue-types` | — | 200 `IssueTypeResponse[]` (5 표준, `is_standard = true`) |

**TypeScript types** (frontend 정본 — Zod schema). backend FR-B1~B3 의 view layer patch 가 반영된 후 정합.
```ts
type SchemeResponse = { id: number; key: string; name: string; description: string | null; isDefault: boolean; createdAt: string; updatedAt: string; mappingsCount: number; usedByProjectsCount: number };
type SchemeDetailResponse = SchemeResponse & { mappings: MappingResponse[]; usedByProjects: string[] };
type MappingResponse = { id: number; schemeId: number; issueTypeId: number | null; issueTypeKey: string | null; issueTypeName: string | null; workflowId: string; workflowKey: string; workflowName: string; createdAt: string };
type AssignmentResponse = { projectId: number; workflowSchemeId: number; assignedAt: string; assignedBy: string };  // backend 정본
type IssueTypeResponse = { id: number; key: string; name: string; description: string | null; iconName: string | null; isStandard: boolean };
```

**errorCode (RFC 7807 ProblemDetail)** — `SCHEME_KEY_INVALID` (400) · `SCHEME_NOT_FOUND` (404) · `SCHEME_STANDARD_NOT_DELETABLE` (403) · `SCHEME_STANDARD_FIELD_LOCKED` (403, key/is_default 변경 시도) · `SCHEME_IN_USE` (409, body `{ usedByProjects }`) · `MAPPING_DUPLICATE` (409) · `MAPPING_DEFAULT_DUPLICATE` (409) · `WORKFLOW_NOT_FOUND` (404) · `ISSUE_TYPE_NOT_FOUND` (404) · `TYPE_STANDARD_NOT_DELETABLE` (403) · `WORKFLOW_SCHEME_NO_DEFAULT` (500).

## 데이터 모델 변경

**DB 스키마 변경 0.** 그러나 **backend DTO view layer patch 동반** (Maxi 게이트 1 옵션 (A) 채택).

- `WorkflowSchemeResponse` 에 `mappingsCount`, `usedByProjectsCount` 추가 (list/get/create/update 응답).
- 단건 조회 응답에 `mappings: List<MappingResponse>` 동봉.
- `MappingResponse` 에 `issueTypeKey/issueTypeName/workflowKey/workflowName` 추가.
- `IssueTypeLookupPort` outbound port 신설 (cross-BC IssueType lookup).

→ DB 컬럼 / 마이그레이션 변경 0. DTO mapper + application service + 신규 port + adapter 만.

## 엣지 케이스

1. **빈 커스텀 스킴 list** → 좌 네비 "커스텀 (0)" 아래 「＋ 새 스킴 생성」만 표시.
2. **404 스킴 (잘못된 schemeKey)** → 중앙 패널 role=alert "스킴을 찾을 수 없습니다" + 좌 네비 트리만 사용 가능.
3. **409 MAPPING_DUPLICATE** (같은 이슈 타입 매핑 추가 시도) → 인라인 추가 행 토스트 "이미 매핑된 이슈 타입입니다" + 행 강조 (기존 매핑).
4. **409 MAPPING_DEFAULT_DUPLICATE** (default mapping 중복) → 토스트 "기본 매핑은 스킴당 1개만 가능합니다. 기존 기본 매핑을 변경하세요" + 기존 default 행 강조.
5. **409 SCHEME_IN_USE** (사용 중 스킴 삭제 시도) → 모달 with `usedByProjects` list (각 프로젝트 link → 프로젝트 스킴 할당 화면, 변경 후 재시도 동선).
6. **403 SCHEME_STANDARD_NOT_DELETABLE** (표준 스킴 삭제 시도, UI 에서 disabled 였으나 race) → 토스트 "표준 스킴은 삭제할 수 없습니다".
7. **403 SCHEME_STANDARD_FIELD_LOCKED** (표준 스킴 key/is_default 변경 시도, UI 에서 read-only 였으나 race) → 토스트 "표준 스킴의 key 와 표준 여부는 변경할 수 없습니다".
8. **매우 긴 description (1000+ 자)** → 중앙 패널 carriage return 보존 + 우 메타패널 truncate (... 보임).
9. **매핑 추가 시 워크플로우 list 비어있음** (workflows 미시드) → select disabled + 안내 "사용 가능한 워크플로우가 없습니다. /admin/workflows 에서 먼저 생성하세요".
10. **프로젝트 자동 할당 (EC-1) — assignment 없는 프로젝트** → `GET /projects/{key}/workflow-scheme` 404 시 안내 카드 "현재 적용된 스킴 없음. 첫 이슈 전이 시 software-scheme 자동 할당" + 변경 select 는 그대로 사용 가능.
11. **권한 없는 사용자** (FR-PM-04 후속 정식 RBAC 도입 시) — AlwaysAllow stub 단계라 본 PR 에서 영향 없음. 후속 PR 에서 401/403 분기 추가.
12. **매우 많은 커스텀 스킴 (100+)** — 좌 네비 가상 스크롤 도입 가능 (본 PR 스코프 외, FR12 후속 후보).

## 제약 조건

- **BC 격리 (예외 적용).** project-workflow frontend + same BC backend view layer patch (DTO/ApplicationService/Port). PR #13 D2 옵션 C 패턴 적용 — learnings 2026-05-22 의 BC 격리 예외 사유 "frontend 가 spec 의 새 필드를 요구 → backend 가 그 필드를 응답 형태에 추가" 정확 일치. cross-BC IssueType lookup port 는 issue-tracking adapter 구현, ArchUnit 룰 예외 처리 + ADR 동반.
- **라우팅.** TanStack Router code-based + RouteAdapter 패턴 (`workflows.$key.tsx` 선례 PR #13, `issues.$key.tsx` 선례 PR #26). 새 라우트 4개 — `admin/workflow-schemes.tsx`, `admin/workflow-schemes.$schemeKey.tsx`, `admin/workflow-schemes.new.tsx`, `projects/$projectKey.settings.workflow-scheme.tsx`.
- **API 모듈.** `@/api/workflow-schemes.ts` 신규 — `@/api/client.ts` 의 `apiFetch` + Zod 스키마.
- **공유 mocks 갱신.** `mocks/handlers.ts` 에 `schemeHandlers` spread 추가 (PR #26 C1 learning — dev 동작 보장). 별도 task 로 단독 작성 (lint-staged race 회피, learnings PR #20).
- **백엔드 미가용.** D6 단위 테스트는 MSW 충분. D7 E2E 는 백엔드 기동 + 시드 필요 (D7 후속 PR scope).
- **표준 스킴 protection.** D11 결정 (mapping 변경 자유, key/name/description/is_default lock) 반영. UI 에서 read-only + tooltip + disabled 일관.
- **시안 1 (Multi-pane admin console)** — 3-컬럼 layout. 우 메타패널 PR #26 사이드 메타패널 taste 직접 계승. shadcn `Card` + `Table` + `Select` + `DropdownMenu` 컴포넌트 우선.
