## Maxi 결정 (spec 게이트)

1. **진입점** — 프로젝트 설정 전용 페이지 `/projects/$projectKey/settings/import`. RouteAdapter + Page 패턴(components/versions 형제). 프로젝트 설정은 중앙 nav 부재 관례 → router.ts 등록 + 직접 URL 접근(설정 허브 신설은 범위 밖 별도 FR).
2. **dry-run** — 2-step: [검증만 실행] → 검증 결과 확인 → [이 파일로 실제 Import]. 마이그레이션 안전 우선.
3. **첨부 zip** — v1 포함. optional 두 번째 파일 입력(`attachmentsZip`).

## 사용자 시나리오 (Given-When-Then)

- **S1 검증 먼저**. Given 프로젝트 관리자가 import 설정 페이지 진입, When CSV 파일 선택 후 [검증만 실행] 클릭, Then dry-run 잡 접수 → 진행률 폴링 → "검증 완료: 성공 예상 N / 실패 M" + (실패 있으면) 에러 로그 다운로드 + [이 파일로 실제 Import] 버튼.
- **S2 실제 Import**. Given 검증 결과 확인 후, When [이 파일로 실제 Import] 클릭(같은 파일 재사용), Then dryRun=false 잡 접수 → 폴링 → "Import 완료: 성공 N / 실패 M" + 에러 로그 다운로드.
- **S3 바로 실행**. Given 폼, When [Import 시작] 직접 클릭, Then dryRun=false 잡 → 폴링 → 완료.
- **S4 실패**. Given 잡이 FAILED(파싱 실패/행 초과 등), When 폴링이 FAILED 감지, Then errorCode 한국어 메시지 + (errorLogReady면) 에러 로그 + [다시 시도].
- **S5 접수 거부**. Given 권한 없음/파일 초과/미지원 형식, When [Import 시작]/[검증만 실행], Then submit 에러(403/413/400) 인라인 표시, 폼 유지.

## 기능 요구사항 (FR)

- **FR-1**. `/projects/$projectKey/settings/import` 라우트. `ProjectImportSettingsRouteAdapter`(useParams) + `ProjectImportSettingsPage`(props projectKey) — 라우터 비의존 단위 테스트 가능(components 설정 선례). router.ts 등록.
- **FR-2**. 폼 단계 — format 라디오(CSV/JSON) + 매니페스트 파일 입력(필수, `accept=".csv,.json"`) + 첨부 zip 입력(선택, `accept=".zip"`). **첨부 zip 입력은 format=JSON일 때만 노출**(FR-2a).
- **FR-2a**. ★brainstorming gap — 백엔드는 **CSV import 시 attachmentsZip을 조용히 무시**한다(하위호환, `ImportJobService.kt:57` 확정). UI가 CSV+zip을 허용하면 첨부가 반영된 줄 오인 → 마이그레이션에서 첨부 유실 혼란. 방지. format=CSV면 첨부 zip 입력을 렌더하지 않는다(또는 disabled + "첨부 zip은 JSON에서만 지원" 안내). format=JSON 전환 시에만 노출. format을 CSV로 되돌리면 선택된 zip을 state에서 초기화(무시되는 파일이 남지 않게).
- **FR-3**. [검증만 실행] → `submitImportJob({dryRun:true})` → tracking. done(dryRun COMPLETED)에서 성공/실패 예상 수 + 에러 로그 + [이 파일로 실제 Import](state의 file 재사용) + [처음으로].
- **FR-4**. [Import 시작] → `submitImportJob({dryRun:false})` → tracking. done(real COMPLETED)에서 최종 성공/실패 수 + 에러 로그 + [처음으로].
- **FR-5**. 진행률 폴링 `use-import-job-polling.ts` — `GET /api/v1/imports/{jobId}` 1500ms 간격, 종단 COMPLETED/FAILED 중단, `query.state.status==='error'` 중단(react-query v5 `refetchInterval:(query)=>`). export hook 1:1 미러.
- **FR-6**. `errorLogReady===true`일 때만 [에러 로그 다운로드] → `GET /api/v1/imports/{jobId}/errors` blob → `triggerBlobDownload`.
- **FR-7**. 실패 표시 — HTTP 에러(submit) + 잡 errorCode(poll FAILED) 모두 `IMPORT_ERROR_CODES` 한국어 매핑. FAILED done에서 [다시 시도] → form(jobId=null).
- **FR-8**. `api/imports.ts` — `submitImportJob`(multipart FormData, apiFetch FormData 지원), `fetchImportJobStatus`, `downloadImportErrorLog`, `importJobStatusSchema`(Zod), `IMPORT_ERROR_CODES`, `IMPORT_POLL_INTERVAL_MS=1500`.

## 상태머신 (ImportForm 내부)

```
phase: 'form' | 'tracking' | 'done'
state: format, file(File|null), attachmentsZip(File|null), jobId, lastDryRun(bool), submitError

form ──[검증만 실행]──▶ submit(dryRun=true)  ──onSuccess──▶ tracking (lastDryRun=true)
form ──[Import 시작]───▶ submit(dryRun=false) ──onSuccess──▶ tracking (lastDryRun=false)
form ──[submit 에러]───▶ form (submitError, role=alert)
tracking ──[폴링 COMPLETED/FAILED]──▶ done
tracking ──[폴링 error]──────────────▶ (에러 UI: 닫기/다시 시도→form)
done(COMPLETED, lastDryRun) ──[이 파일로 실제 Import]──▶ submit(dryRun=false, 같은 file) ──▶ tracking
done(COMPLETED) ──[처음으로]──▶ form (성공적 real이면 file 초기화)
done(FAILED) ──[다시 시도]──▶ form (jobId=null)
```

file/attachmentsZip은 phase 전환에도 state 보존(“이 파일로 실제 Import” 재사용). submitError 소유는 ImportForm(dialog-submiterror-ownership-dead-path 교훈) — done 단계에서도 다운로드 실패 렌더.

## API 인터페이스 (REST — 백엔드 확정, 소비만)

- `POST /api/v1/imports` (multipart, 202) — file·attachmentsZip?·projectKey·format·dryRun → `ImportJobResponse`.
- `GET /api/v1/imports/{jobId}` (200) — `ImportJobResponse`.
- `GET /api/v1/imports/{jobId}/errors` (200, text/csv, attachment) — 실패행 에러 로그.
- `ImportJobResponse`(@JsonInclude NON_NULL) = jobId·status(PENDING/RUNNING/COMPLETED/FAILED)·progress(0~100)·totalRows(nullable)·succeededRows·failedRows·errorCode(nullable)·errorLogReady·dryRun.
- Zod `importJobStatusSchema` — totalRows/errorCode `.nullish()`(NON_NULL이라 키 부재), 나머지 required.
- errorCode 한국어 매핑. IMPORT_ACCESS_DENIED·IMPORT_FILE_TOO_LARGE·IMPORT_UNSUPPORTED_FORMAT·IMPORT_VALIDATION_FAILED·IMPORT_ROW_LIMIT_EXCEEDED·IMPORT_PARSE_FAILED·IMPORT_INTERNAL_ERROR.

## 엣지 케이스

- 파일 미선택 → [검증만 실행]/[Import 시작] disabled.
- submit 중 → 버튼 disabled + "접수 중...".
- dry-run 완료 후 "실제 Import" → 같은 file 재사용(state 보존).
- 다운로드 실패 → done 단계 submitError 렌더(dead-path 방지).
- FAILED + errorLogReady=false → 에러 로그 버튼 미표시.
- 폴링 error(403/404/재시도 소진) → tracking 에러 UI + 다시 시도.
- 잘못된 형식(zip을 매니페스트로) → 백엔드 400 IMPORT_UNSUPPORTED_FORMAT submit 에러.
