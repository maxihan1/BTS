# FR-MV-01 프로젝트 간 이슈 이동 — 스펙

> slug: fr-mv-01 · BC: issue-tracking (cross-BC: project-workflow) · type: backend
> 도메인/결정: [docs/plans/2026-06-16-fr-mv-01.md](../plans/2026-06-16-fr-mv-01.md), [ADR issue-move-semantics](../adr/2026-06-16-issue-move-semantics.md)
> 핵심: Jira "Move Issue Wizard" — preview(매핑 필요 항목 계산) + move(매핑 적용) 2단계 + **서브태스크 동반 이동**

## 사용자 시나리오 (Given-When-Then)

### S1. 완전 호환 이동 (매핑 불필요)
- **Given** `ATLAS-12`(상태 `open`, 컴포넌트/버전 없음, 자식 없음), 대상 `INFRA` 워크플로우에 `open` 존재
- **When** 사용자가 `INFRA`로 이동
- **Then** 새 키 `INFRA-5`, `open` 유지, `issue_key_redirects(ATLAS-12 → INFRA-5)`, 히스토리·링크·워처·첨부 보존

### S2. 워크플로우 상태 비호환 (상태 매핑)
- **Given** `ATLAS-12`(상태 `in_progress`)를 `INFRA`로 이동하려는데 `INFRA`엔 `in_progress` 없음
- **When** preview 요청
- **Then** "상태 매핑 필요" + 대상 워크플로우 상태 목록 + 제안값(초기 상태) → 사용자가 대상 상태 선택 → move 적용

### S3. 컴포넌트/버전 매핑
- **Given** `ATLAS-12`가 컴포넌트 `Backend`, fix 버전 `v1.0`. `INFRA`엔 같은 이름 컴포넌트 없음, 버전 `v1.0` 있음
- **When** preview → **Then** 컴포넌트는 "매핑 또는 제거"(자동 제안 없음), `v1.0`은 이름 일치 자동 제안 → 사용자가 매핑/제거 선택

### S4. 옛 키 영구 redirect
- **Given** `ATLAS-12` → `INFRA-5` 이동 완료
- **When** `GET /api/v1/issues/ATLAS-12` (Slack/이메일 옛 링크)
- **Then** `308 Permanent Redirect` + `Location: /api/v1/issues/INFRA-5`

### S5. 체인 이동
- **Given** `ATLAS-12` → `INFRA-5` → `WIKI-3` 두 번 이동
- **When** `GET .../ATLAS-12` → **Then** redirect 체인 순회해 최종 `WIKI-3`로 308

### S6. 필수 커스텀 필드 보충
- **Given** `INFRA`에 필수 필드 `severity` 정의, `ATLAS-12`엔 값 없음
- **When** preview → **Then** "필수 필드 누락" → 사용자가 move 시 `severity` 값 입력

### S7. 서브태스크 동반 이동 (Jira 정석)
- **Given** Story `ATLAS-12`가 서브태스크 `ATLAS-13`, `ATLAS-14`를 가짐(parent_id=ATLAS-12.id), 그리고 `ATLAS-12`의 부모 Epic `ATLAS-5`가 있음
- **When** `ATLAS-12`를 `INFRA`로 이동
- **Then** 서브트리(`ATLAS-12`+`ATLAS-13`+`ATLAS-14`) 전부 `INFRA`로 함께 이동 — 각각 새 키 발번(`INFRA-5/6/7`) + redirect. 내부 parent_id 관계는 새 id로 보존(이동해도 id 불변이므로 자동 보존). `ATLAS-12`의 부모(Epic `ATLAS-5`)와의 관계는 **끊김(parent_id=null, 최상위화)** — Epic은 원본에 잔류

## 기능 요구사항 (FR)

| ID | 요구사항 |
|---|---|
| FR-MV-01-1 | `POST /api/v1/issues/{key}/move/preview` — 대상 프로젝트 기준 필요 매핑 항목(상태/컴포넌트/affects·fix 버전/커스텀필드)을 **이동 대상 서브트리 전체**에 대해 계산. 자동 매핑 제안 포함 |
| FR-MV-01-2 | `POST /api/v1/issues/{key}/move` — 매핑 검증 후 **단일 트랜잭션**으로 서브트리 전체 이동. 각 노드 id 보존, 새 키 발번, redirect, 종속데이터 정리, 히스토리 기록 |
| FR-MV-01-3 | 새 키 발번은 대상 `key_sequence`를 `pg_advisory_xact_lock`으로 보호하며 노드 수만큼 증가 (이슈 생성 `incrementKeySequence` 재사용) |
| FR-MV-01-4 | 옛 키 → 새 키 매핑을 `issue_key_redirects`에 노드별 append-only INSERT (UPDATE/DELETE 트리거 차단) |
| FR-MV-01-5 | 옛 키로 단건 조회 시 `308 Permanent Redirect` + `Location`(새 키 경로). 체인 순회. 308 분기는 `findByKey` 404 던지기 전에 redirect 조회 |
| FR-MV-01-6 | 워크플로우 상태: 현재 상태가 대상 워크플로우에 있으면 유지, 없으면 사용자 선택. 결정은 `WorkflowKeyResolver` + **신규 상태목록 조회 SPI** |
| FR-MV-01-7 | 종속데이터(컴포넌트/버전): 사용자 매핑값 대체, 미매핑 제거. 커스텀필드: 대상 정의에 있는 key만 유지, 없는 key 제거, 대상 필수는 값 강제 |
| FR-MV-01-8 | 이슈 타입 전역 유지. 대상 워크플로우 결정 시 `issueTypeKey`로 조회(매칭 없으면 default mapping) |
| FR-MV-01-9 | 권한: 원본 프로젝트 이슈 수정 권한 + 대상 프로젝트 이슈 생성 권한 둘 다 필요 (`IssuePermissionResolver`). preview도 동일 권한 게이트 |
| FR-MV-01-10 | 이동은 OCC(`expectedVersion`)로 보호 — 루트 이슈 버전 불일치 시 409. advisory lock으로 동시 이동 직렬화 |
| FR-MV-01-11 | **서브태스크 동반 이동**: 이동 이슈의 하위 서브트리(parent_id 재귀) 전부 동반. 내부 부모-자식 관계는 id 보존으로 자동 유지. 이동 이슈가 다른 이슈의 자식이면 그 관계는 끊고 최상위화(parent_id=null) |
| FR-MV-01-12 | 상태/프로젝트/키 변경은 이슈 히스토리(`issue_change_group`/`item`)에 "이동" 변경으로 기록. 제거된 컴포넌트/버전/필드도 이력 기록(추적성) |

### 서브태스크 매핑 설계 제안 (게이트1 Maxi 확인)
- **제안**: 사용자는 **루트 이슈**의 매핑만 입력. 서브태스크(자식)는 **자동 규칙** — 상태=각 타입의 대상 워크플로우 초기 상태(resolveStart), 컴포넌트/버전=이름 일치 자동 매핑(없으면 제거), 커스텀필드=대상에 있는 key만 유지. 서브태스크의 필수필드 누락은 이동 허용 + 이력 기록(이동 후 보충)
- **대안**: preview가 서브트리 각 노드의 매핑 항목을 반환, move 페이로드가 노드별 매핑 맵(정확하나 UI/페이로드 복잡)

## 비기능 요구사항 (NFR)

- 이동 트랜잭션 p95 < 1s (product §NFR 측정표) — 서브트리 N노드 포함
- redirect 조회 308 (이슈 키 영속성, product §NFR)
- 이동 전체 단일 트랜잭션 — 서브트리 전 노드의 이슈 UPDATE + redirect INSERT + 종속데이터 정리 + 히스토리 (일부 실패 시 전체 롤백)
- cross-BC 호출 SPI/resolver 경유, project-workflow 직접 import 금지 (CLAUDE.md §BC 격리). 신규 SPI는 shared-kernel 정의, project-workflow 구현
- 이동 이벤트/알림(워처 통지): **이번 범위 deferred** — notification BC 연동은 FR-MV-02/후속. 히스토리 기록만 본 범위

```jsonc
    "currentStateKey": "in_progress",
    "compatible": false,

  "components": {
    "current": [{"id": "...", "name": "Backend"}],
    "targetOptions": [{"id": "...", "name": "Platform"}],
    "autoMapping": {"<srcId>": null}            // 이름 일치 시 대상 id, 없으면 null
  },
  "affectsVersions": { /* 동형 */ },
```

요청.

## 데이터 모델 변경

- **마이그레이션 신규 없음.** `issue_key_redirects`(V001, D3 완료), `issues.project_id`/`key`/`current_state_key`/`custom_fields`/`labels`·조인테이블은 기존 컬럼 UPDATE
- 신규 repository. `IssueKeyRedirectRepository` — append-only INSERT + old_key 단건 조회 + 체인 순회(+ max-hop 가드)
- UPDATE 시 노드별 `key`/`project_id`/`current_state_key`/조인(컴포넌트·버전)/`custom_fields` 갱신, `id`/parent_id(내부)·FK 참조 데이터 불변, `version` OCC bump

## 엣지 케이스

| EC | 상황 | 응답 |
|---|---|---|
| EC1 | 대상 == 원본 프로젝트 | 422 `MOVE_SAME_PROJECT` |
| EC2 | 대상 프로젝트 없음/소프트삭제 | 404 / 422 `TARGET_PROJECT_NOT_FOUND` |
| EC3 | 원본 이슈 없음/소프트삭제 | 404 |
| EC4 | 원본 수정 권한 또는 대상 생성 권한 없음 | 403 |
| EC5 | OCC 충돌(루트 expectedVersion) | 409 |
| EC6 | 대상 워크플로우 미설정(resolveExisting null) | 422 `WORKFLOW_NOT_CONFIGURED` |
| EC7 | targetStateKey 비호환인데 미지정/대상에 없음 | 422 `INVALID_TARGET_STATE` |
| EC8 | 매핑 대상 id가 대상 프로젝트에 없음 | 422 `INVALID_TARGET_MAPPING` |
| EC9 | 대상 필수 커스텀필드 값 누락(루트) | 422 `REQUIRED_FIELD_MISSING` |
| EC10 | 옛 키 조회 | 308 + Location(체인 최종 키) |
| EC11 | 동시 이동(같은 서브트리) | advisory lock 직렬화 → 한쪽 409 |
| EC12 | redirect 체인 순회 가드 | 키 재사용 불가로 순환 구조적 불가 + 방어적 max-hop |
| EC13 | 서브태스크가 자기 자식을 또 가짐(다단 트리) | 재귀 수집, 트리 전체 동반. cycle 가드 |
| EC14 | cross-project 링크(이동 후 링크 상대가 다른 프로젝트) | 허용(Jira 동일). 링크는 id 참조라 보존 |
| EC15 | **(이번 PR 한정)** 이동 이슈에 자식(서브태스크) 있음 | 422 `ISSUE_HAS_SUBTASKS` — 서브태스크 동반 이동은 후속 PR. 부모만 있는 경우는 끊고 이동 허용 |

## 제약 조건

- 이슈 키 재사용 절대 금지(DATA.md §1.1). 옛 키 영구 보존 + redirect
- redirect append-only — 수정/삭제 불가(트리거)
- id 보존으로 FK 참조 데이터(히스토리·링크·워처·첨부·내부 parent_id) 자동 보존 (FR-MV-02 구조적 충족)
- cross-BC project-workflow 직접 import 금지, SPI 경유
- 미매핑 종속데이터 제거는 이력 기록(추적성)
- bulk 이동(여러 루트 동시)은 본 FR 범위 밖(FR-IS-05 bulk와 별개)

- [ ] move가 단일 트랜잭션으로 서브트리 전 노드 id 보존 + 새 키 발번 + redirect 기록
