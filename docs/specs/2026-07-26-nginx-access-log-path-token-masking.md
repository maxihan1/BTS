## 배경 — 실증된 결함

```
Dockerfile.web:6                 FROM nginx:1.27-alpine
이미지 기본 nginx.conf (실측)      log_format main '... "$request" ...'
                                 access_log /var/log/nginx/access.log main;
                                 error_log  /var/log/nginx/error.log notice;
                                 include /etc/nginx/conf.d/*.conf;
컨테이너 (실측)                    access.log -> /dev/stdout · error.log -> /dev/stderr
infra/prod/nginx.conf (54줄)      access_log · log_format 재정의 0건 → 상속
```

`$request` = 요청 첫 줄 통째(쿼리 포함) ⇒ **매 요청 표준출력 평문 → `docker logs` → 중앙 로그 수집기.**
불투명 토큰은 **소지가 곧 인증**이므로(glossary), 로그에 남은 원문은 그대로 유효한 자격증명이다.

## ★설계를 가르는 사실 — 토큰 길이 분포

전 토큰이 **32바이트 CSPRNG** 이고, 인코딩만 다르다(실측).

| 경로 | 토큰 인코딩 | **길이** | 출처 |
|---|---|---|---|
| `/api/v1/public/dashboards/{token}` | base64url no-pad | **43자** | `ShareTokenMinter.kt:59-60,91` |
| `/dashboards/shared/{token}` (SPA) | 위와 동일 토큰 | **43자** | `router.ts:586` |
| `/ical/feed/{token}.ics` | 소문자 hex | **64자** | `CalendarFeedToken.kt:27,49` |
| `/api/v1/webhooks/git/{token}` | base64url no-pad | **43자** | `GitWebhookRegistrationService.kt:197-199,211` |
| `/api/v1/automation/webhooks/{token}` | base64url no-pad | **43자** | `AutomationRuleService.kt:773-775` |

**대조군 — 마스킹하면 안 되는 경로 세그먼트.**

| 종류 | 길이 | 마스킹 대상? |
|---|---|---|
| UUID (`8-4-4-4-12`) | **36자** | ❌ 유지 (디버깅 상관용) |
| 이슈 키 (`ATLAS-4`) | ~7자 | ❌ 유지 |
| 프로젝트 키 (`ATLAS`) | ~5자 | ❌ 유지 |

**⇒ 최소 토큰(43자) > 최대 정상 식별자(36자). 길이만으로 완전 분리된다.**
따라서 **경로 목록 없이 구조적 판별식으로 마스킹할 수 있다.** 이것이 본 스펙의 핵심 결정이다.

## 사용자 시나리오 (Given-When-Then)

**S1 — 캘린더 구독 (정상 경로, 가장 흔한 유출)**
- Given. 사용자가 캘린더 피드 토큰을 발급받아 Google Calendar 에 구독을 등록했다
- When. Google 이 주기적으로 `GET /ical/feed/<64자hex>.ics` 를 폴링한다
- Then(현재). 폴링마다 원문 토큰이 접속 로그에 평문으로 적재된다
- Then(요구). 로그에는 `GET /ical/feed/***.ics 200` 이 남고 **원문 토큰은 어디에도 없다**

**S2 — 대시보드 공유 링크를 브라우저로 열기 (트래픽 최다)**
- Given. 공유 토큰이 담긴 링크를 비로그인 사용자가 받았다
- When. 브라우저로 `/dashboards/shared/<43자>` 를 연다 (SPA 폴백 + 이어지는 API 호출)
- Then(요구). SPA 라우트와 API 호출 **양쪽 모두** 마스킹된다

**S3 — SSO 로그인 콜백 (쿼리 비밀값)**
- Given. 사용자가 OIDC 로 로그인한다
- When. IdP 가 `GET /login/oauth2/code/{regId}?code=…&state=…` 로 리다이렉트한다
- Then(요구). 로그에 `code`·`state` **값이 남지 않는다**

**S4 — 운영자가 장애를 조사한다 (관측성 보존)**
- Given. 캘린더 피드가 느리다는 신고가 들어왔다
- When. 운영자가 접속 로그를 본다
- Then(요구). **메서드·경로 모양·상태코드·응답시간·업스트림시간·바이트수·클라이언트IP·User-Agent 가 전부 남아 있어**
  조사가 가능하다. 마스킹은 비밀값만 가린다

**S5 — 새 토큰 경로가 추가된다 (회귀 방지)**
- Given. 6개월 뒤 누군가 경로에 토큰을 싣는 새 엔드포인트를 추가한다
- When. 그 사람이 nginx 설정을 전혀 건드리지 않는다
- Then(요구). **구조적 규칙이 자동으로 마스킹**한다. 목록 갱신을 잊어서 새는 일이 없다

**S6 — 누군가 토큰을 짧게 바꾼다 (판별식 무효화)**
- Given. 개발자가 토큰 바이트 수를 32 → 16 으로 줄인다 (base64url 22자)
- When. 22자 < 판별 임계값이라 구조적 규칙이 더는 잡지 못한다
- Then(요구). **봉인 검사가 실패**해 머지가 막힌다

## 요구사항

### 기능 요구 (구현 대상)

**RQ-1. 경로 세그먼트 마스킹 — 구조적 판별식.**
경로에서 `[A-Za-z0-9_-]` 로 이루어진 **연속 40자 이상** 세그먼트를 `***` 로 치환해 로깅한다.
임계값 40 은 최소 토큰 43 과 최대 정상 식별자 36 **사이**에서 양쪽에 여유를 둔 값이다.
경로 목록을 하드코딩하지 않는다.

**RQ-2. 쿼리 문자열 값 미로깅 — 일반 규칙.**
접속 로그에 쿼리 문자열 **값**을 남기지 않는다. 목록 없이 전량 적용한다
(`$uri` 는 쿼리를 포함하지 않는 nginx 내장 변수이므로 `$request`/`$request_uri` 를 쓰지 않으면 자동 충족).
쿼리 유무 자체는 남겨도 되나 값은 남기지 않는다.

**RQ-3. 관측성 보존.**
다음 필드는 반드시 남는다 — 시각 · 클라이언트IP · 요청메서드 · 마스킹된 경로 · 프로토콜 ·
상태코드 · 응답바이트 · Referer · User-Agent · X-Forwarded-For · **요청처리시간** · **업스트림응답시간**.
(현행 `main` 포맷보다 처리시간·업스트림시간이 **추가**된다 — 마스킹으로 잃는 것 이상을 돌려준다.)

**RQ-4. Referer 헤더도 마스킹 대상이다.**
`$http_referer` 에는 **직전 페이지 URL** 이 실린다. S2 에서 공유 뷰(`/dashboards/shared/<토큰>`) 를 거쳐
API 를 호출하면 Referer 에 토큰이 담긴다. 경로와 **동일한 판별식**을 Referer 에도 적용한다.
⚠️ 이 항목은 초기 조사에서 누락됐던 것으로, 경로만 가리면 반쪽 봉합이 된다.

**RQ-5. 봉인 — 판별식 기반 회귀 검사. 3축 전부 필요(Phase B G2·G3 반영).**
"경로/쿼리에 비밀값을 싣는 지점"을 **코드에서 파생 열거**하고 다음 **세 축을 모두** 검사한다.
하드코딩 경로 목록으로 검사하지 않는다.

| 축 | 단언 | 이 축이 없으면 |
|---|---|---|
| **A. 길이** | 각 토큰의 발급 길이 > RQ-1 임계값 | 누가 토큰을 짧게 줄이면 조용히 샌다 (S6) |
| **B. 알파벳** | 각 토큰의 인코딩 문자군 ⊆ `[A-Za-z0-9_-]` | **표준 base64(`+`·`/`)·JWT(`.`) 토큰은 세그먼트가 쪼개져 마스킹을 빠져나가는데 길이 검사는 통과한다** |
| **C. 설정 실효** | `infra/prod/nginx.conf` 가 실제로 마스킹한다 | **`map` 블록을 지워도 A·B 는 그대로 통과한다** — 봉인이 봉인하는 대상을 안 본다 |

- **미분류(파생은 됐으나 세 축 중 하나라도 판정 불가한 항목)는 실패로 처리**한다
- 파생 개수의 **하한**을 단언한다 (현재 5) — 파생기가 고장나 0건이 되면 vacuous 통과를 막는다
- **다중 비밀값 라우트 부재**를 단언한다 (E3 대체 조건)
- 세 축 각각에 **일부러 위반을 주입해 실패하는 것을 확인**한 뒤 통과시킨다
  (메모리 `archunit-vacuous-rule-silent-pass` — 위반을 넣어보지 않은 룰은 통과가 무의미하다)

**RQ-6. nginx 설정 문법 검증.**
변경된 `nginx.conf` 가 실제 nginx 로 파싱되는지 검증한다(`nginx -t` 동형).
이 프로젝트에 인프라 설정 검증 선례가 없으므로 **수단을 새로 만든다**.

**RQ-7. 마스킹 실효 검증 — 실제 요청 통과.**
설정 문법만이 아니라 **실제로 토큰이 로그에 안 남는지**를 요청을 흘려서 확인한다.
판별자는 **로그 출력 문자열에 원문 토큰이 포함되지 않을 것** — 상태코드나 마스킹 기호 존재가 아니다
(메모리 `negative-guard-needs-body-discriminator`).

### 비기능 요구

**NFR-1. 성능.** `map` 은 nginx 기동 시 컴파일되고 요청당 정규식 1회 평가다. 정규식은 앵커를 붙여
백트래킹을 억제한다. 요청당 추가 비용은 마이크로초 수준이어야 한다.

**NFR-2. 가용성.** 설정 오류로 nginx 가 기동 실패하면 **프론트 전체가 죽는다**(현행 `nginx.conf` 는
백엔드 다운과 무관하게 서빙하도록 설계돼 있다 — L18-20). 문법 검증(RQ-6)은 선택이 아니라 필수다.

**NFR-3. 되돌리기.** 변경은 단일 파일이며 되돌리기는 그 파일 revert 로 끝나야 한다.

## 엣지 케이스

| # | 케이스 | 요구 동작 |
|---|---|---|
| E1 | 퍼센트 인코딩된 토큰 (`%2F` 등 포함) | `$uri` 는 **디코딩된** 경로다. 디코딩 후 판별식이 적용되므로 우회 불가 |
| E2 | `.ics` 접미사가 붙은 토큰 | 세그먼트가 `<64자hex>.ics` 다. `.` 는 판별 문자군 밖이라 hex 부분만 매칭 → `***.ics` 로 남아 **경로 모양이 보존**된다 |
| E3 | 경로에 토큰이 2개 이상 | **요구를 하향 조정했다(Phase B G1).** nginx `map` 은 전역 치환을 못 한다 — 정규식 1회 매치 + 캡처 재조립이라 다중 세그먼트 치환이 구조적으로 불가능하다. 따라서 "모두 치환" 을 요구하지 않고, **봉인이 "비밀값 2개를 경로에 싣는 라우트가 존재하지 않음" 을 단언**한다. 그런 라우트가 생기면 봉인이 실패해 설계를 다시 보게 된다 |
| E4 | 정상 40자 이상 세그먼트 (오탐) | 현재 코드베이스에 없음(최장 = UUID 36자). 오탐 시 로그 가독성만 손해이고 **보안 손실은 없다** — fail-safe 방향 |
| E5 | 쿼리에만 토큰 (`?code=…`) | RQ-2 로 값 전체 미로깅. 판별식 불필요 |
| E6 | **`error_log` 채널** | 아래 §제약 참조 — 별도 취급 |
| E7 | 마스킹 규칙이 적용 안 된 location | `access_log` 는 http 레벨 상속이므로 **모든 location 에 일괄 적용**된다. SPA 폴백 포함 |
| E8 | WebSocket 업그레이드 (`/ws`) | 토큰 없음. 규칙 적용되나 무해 |

## 제약 조건

**C1. ★`error_log` 는 포맷을 바꿀 수 없다 (nginx 구조적 한계).**
이미지 기본이 `error_log … notice` 이고 `/dev/stderr` 로 나간다(실측). nginx 는 `log_format` 을
**access_log 에만** 적용하며 **error_log 포맷은 커스터마이즈 불가**다. 오류 항목에는
`request: "GET /path HTTP/1.1"` 형태로 URI 가 실린다.
⇒ 접속 로그(상시·전요청)와 달리 **오류 시에만** 발생하지만 **본 PR 로 완전 봉합되지 않는다.**
가능한 완화는 로그 레벨 상향뿐이며, 이는 **장애 조사 능력과 정면 상충**한다.
**이 결정은 게이트 1 에서 Maxi 판단을 받는다** (아래 §미결 결정 D1).

**C2. 검증 파이프라인 부재.** Gradle 도 vitest 도 이 파일을 읽지 않는다. 이 프로젝트 **최초의 인프라 전용 PR**
이라 RQ-5·RQ-6·RQ-7 의 실행 수단 자체를 새로 만들어야 한다. 수단 선택은 plan 단계 결정.

**C3. prod 전용.** `infra/prod/nginx.conf` 는 프로덕션 이미지 전용이다. 개발 환경은 Vite dev server 라
이 경로를 타지 않는다 → **개발 중에는 결함이 보이지 않는다**(그래서 3주 넘게 잠복했다).

**C4. `map` 은 http 컨텍스트가 필요하다.** `conf.d/*.conf` 는 http 블록 안에서 include 되므로 동작한다.
같은 파일 L3 의 `map $http_upgrade $connection_upgrade` 가 선례다.

## 미결 결정 (게이트 1 에서 Maxi 확정)

**D1 — `error_log`(C1) 를 이번 PR 에서 어떻게 다룰 것인가.**
- (A) 범위 밖으로 명시 등재하고 접속 로그만 봉합 — 관측성 온전, 오류 시 유출 잔존
- (B) `error_log` 레벨을 `notice` → `warn`/`crit` 상향 — 유출 표면 축소, 장애 조사 정보 손실
- (C) 오류 로그를 별도 수집 경로로 분리해 접근 통제 — 범위 큼, 인프라 변경 확대

**D2 — RQ-4(Referer 마스킹) 포함 여부.** 포함이 기본안. 제외하면 S2 에서 반쪽 봉합이 된다.

## 측정 가능한 완료 기준

1. `infra/prod/nginx.conf` 에 `access_log` + 커스텀 `log_format` 이 명시돼 이미지 기본 상속이 끊긴다
2. 실제 nginx 로 설정이 파싱된다 (RQ-6)
3. 실제 요청을 흘렸을 때 **출력 로그 전문에 원문 토큰 문자열이 0회** 등장한다 —
   **5개 라우트 × 2개 인코딩(base64url 43자 · hex 64자) 전부**, 그리고 **경로·Referer 양쪽**에서 (RQ-4·RQ-7)
4. 동일 검사에서 **메서드·상태코드·응답시간이 모두 남아 있음**을 확인한다 (RQ-3 역방향 단언)
5. 봉인 검사가 코드에서 비밀값 경로를 파생하고, **길이 임계 위반을 실제로 실패시킨다**(일부러 위반 주입해 확인) (RQ-5)
6. 봉인 검사의 파생 개수 하한 단언이 존재한다 (현재 5)
7. `verify-master-plan.sh` 통과 · **FR 카운트 129 불변**

### 발견된 gap 5건 — 전부 스펙에 반영 완료

**G1 (중대) — E3 요구가 `map` 으로 구현 불가능하다.**
nginx `map` 은 정규식 **1회 매치 + 캡처 재조립**이라 한 문자열의 여러 부분을 전역 치환할 수 없다.
"경로의 모든 토큰 세그먼트를 치환" 은 `njs` 모듈 없이는 불가능하고, `nginx:1.27-alpine` 에 njs 는 없다.
→ **E3 을 "모두 치환" 요구에서 "다중 비밀값 라우트 부재를 봉인이 단언" 으로 대체.**
요구를 조용히 낮춘 게 아니라 **불가능한 요구를 검사 가능한 불변식으로 바꿨다.**

**G2 (중대) — 봉인이 봉인 대상을 보지 않았다.**
원안 RQ-5 는 "토큰 발급 길이" 만 검사했다. 그러면 **누가 `map` 블록을 통째로 지워도 봉인이 통과한다.**
검사하는 축과 보호하려는 대상이 어긋나 있었다. → **RQ-5 에 축 C(설정 실효) 추가.**

**G3 (중대) — 알파벳 가정이 검사되지 않았다.**
판별식은 토큰이 `[A-Za-z0-9_-]` 로만 이루어진다고 **가정**하는데, 원안 봉인은 이를 검사하지 않았다.
표준 base64(`+`·`/`) 나 JWT(`xxx.yyy.zzz`) 형식 토큰이 새로 들어오면 **`/` 나 `.` 가 세그먼트를 쪼개
40자 미만 조각으로 만들어 마스킹을 빠져나가는데, 길이 검사는 44자라서 통과한다.**
가장 조용한 실패 경로였다. → **RQ-5 에 축 B(알파벳) 추가.**

**G4 (중) — 검증 수단의 실행 주체가 미정이다.**
RQ-6·RQ-7 은 "무엇을 확인할지" 만 정하고 "언제 자동으로 도는지" 를 정하지 않았다.
C2 대로 이 프로젝트엔 인프라 검증 파이프라인이 없어, 자동화되지 않으면 **1회성 확인으로 끝나고 썩는다.**
→ **plan 단계에서 실행 주체를 반드시 확정**하고, 자동화 불가 시 그 사실을 ADR 잔여 위험에 명시한다.
(선행 #310 ADR 이 "범위 밖" 으로 적어둔 항목이 3주 잠복한 전례가 바로 이 실패 양식이다.)

**G5 (경) — 완료 기준 3 의 "5개 토큰 형식" 이 부정확했다.**
5개는 **라우트** 수이고 인코딩 **형식**은 2개(base64url 43 · hex 64)다. 형식 기준으로 세면 검증 표본이
2개로 줄어 커버리지가 과소평가된다. → 완료 기준 3 을 "5 라우트 × 2 인코딩 × 경로·Referer 양축" 으로 정정.

### 반증했으나 gap 이 아니었던 것

- **UUID 오탐 우려.** UUID 는 하이픈 포함 36자로 전부 판별 문자군 안이지만 **36 < 40** 이라 매칭되지 않는다.
  `<uuid>/<uuid>` 는 `/` 가 문자군 밖이라 각각 36자로 쪼개진다. **현행 코드베이스에 40자 이상 정상
  세그먼트는 존재하지 않는다.** 오탐이 나더라도 방향이 fail-safe(로그 가독성만 손해)라 무해.
- **퍼센트 인코딩 우회.** `$uri` 는 디코딩·정규화된 값이라 인코딩으로 판별식을 피할 수 없다.
- **공격자 우회 프레임.** 이 결함의 위협 모델은 *정상 사용자의 토큰이 실수로 적재되는 것*이지
  공격자 조작 입력이 아니다. 공격자는 자기 토큰만 로그에 남길 수 있어 이득이 없다.
