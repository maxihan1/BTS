### 4. Jira 를 그대로 베끼지 않는 지점 (의도적 이탈)

- **에픽 패널은 "백로그에 이슈가 있는 에픽"만 보여준다.** Jira 는 프로젝트의 **모든** 에픽을
  나열하지만 BTS 에는 **프로젝트 에픽 목록 API 가 없다.** AQL `MVP_FIELDS` 실측 =
  `{status, label, summary, priority, text}` 로 **`type` 미지원**(`AqlFields.kt:45`), 이슈 목록
  필터(`IssueFilterParams:408`)도 유형 축이 없다. 유일한 백엔드-0줄 경로는 **백로그 응답의
  `epicKey` 를 distinct 로 모으는 파생**이다. → §7 EC5 에서 사용자에게 이 한계를 알린다.
- **에픽 색상 막대 없음.** 에픽 색상 필드가 백엔드에 없다. 키·이름만 표시한다.

## §2. 사용자 시나리오 (Given-When-Then)

### S1. 담당자로 백로그를 좁힌다
- **Given** 백로그에 이슈 40건, 그중 김개발 담당 6건
- **When** 필터바 담당자 입력에 "김개"를 치고 후보에서 김개발을 고른다
- **Then** 백로그·스프린트 **모든 섹션**이 김개발 담당 6건만 남고, 각 섹션 헤더 카드 수가
  그 값으로 갱신되며, 활성 칩 「김개발」과 「적용된 필터 1개」가 보인다

### S2. 에픽 패널로 좁힌다
- **Given** 백로그 이슈들이 에픽 ATLAS-1(로그인 개편)·ATLAS-2(결제) 에 나뉘어 속함
- **When** 에픽 패널에서 「로그인 개편」을 클릭한다
- **Then** ATLAS-1 소속 이슈만 남고, **필터바 활성 칩에 「로그인 개편」이 나타나며**,
  그 칩의 ✕ 로도 해제된다 (패널 체크 해제와 동일 결과)

### S3. 에픽 없는 이슈만 본다
- **Given** 에픽 미지정 이슈 5건 존재
- **When** 에픽 패널의 「에픽 없음」을 선택한다
- **Then** `epicKey === null` 인 5건만 남는다

### S4. 제목으로 찾는다
- **Given** 백로그 이슈 40건
- **When** 필터바 검색 입력에 "결제"를 친다
- **Then** 제목에 "결제"가 포함된 이슈만 남는다 (대소문자 무시, 250ms 디바운스)

### S5. 조건에 맞는 이슈가 없다
- **Given** 필터가 걸려 모든 섹션이 0건
- **When** 화면을 본다
- **Then** `FilteredEmptyState` 안내와 「필터 초기화」가 보이고, 누르면 전량 복귀한다

### S6. 에픽 패널을 접는다
- **Given** 에픽 패널이 펼쳐져 있다
- **When** 접기 토글을 누르고 페이지를 새로고침한다
- **Then** 접힌 상태가 **프로젝트별로** 유지된다 (F15 `use-backlog-collapsed` 동형)

### S7. 스프린트를 백로그 섹션 헤더에서 만든다
- **Given** 백로그 섹션이 보인다
- **When** 섹션 헤더의 스프린트 생성 폼에 이름을 넣고 제출한다
- **Then** 새 스프린트가 생기고, 폼은 **세로 스택 안 백로그 섹션 헤더**에 있다 (G3)

### S8. 잘린 응답에서 필터를 건다 ★
- **Given** 이슈가 1,000건을 넘어 `truncated === true`
- **When** 필터를 걸어 결과가 0건이 된다
- **Then** 빈 상태에 **"일부 이슈가 조회 범위를 넘어 표시되지 않았습니다"** 경고가 **함께** 뜬다.
  「조건에 맞는 이슈가 없음」만 띄우면 **거짓말**이다 (§8 C5)

## §8. 제약 조건

### C1. 백엔드 0줄
`backend/` 아래 한 줄도 고치지 않는다. D3·D4·D5 는 「해당 없음」.

### C2. B3 는 범위 밖 — 필터는 `truncated` 를 풀지 못한다
정본 `:439` 명시. **필터 UI 가 `truncated` 를 내리는 것처럼 보이게 만들면 가짜 그린이다.**
`truncated` 플래그와 F15 의 완료 차단은 **이 PR 에서 손대지 않는다**.

### C3. `CreateSprintForm` 이동은 **기존 단언을 뒤집는 작업**이다 ★
`BacklogBoard.test.tsx:1474` 가 `E1: 스프린트 생성 폼은 세로 스택 **바깥** 현행 위치 그대로다` 로
**현행 위치를 못박고 있다.** F15 BLOCKER ②(「테스트가 오히려 그 동작을 못박고 있었다」)와 동형이다.
이동 task 는 **그 테스트를 먼저 새 위치로 뒤집는 RED** 로 시작한다. 조용히 지우지 않는다.
동반 갱신 — `backlog.spec.ts:876,986` 2건.

### C4. 에픽 상태의 단일 소유권 ★
에픽 선택 **입력 컨트롤은 패널 하나뿐**이다. 필터바에는 칩(제거)만 둔다.
두 곳에서 같은 상태를 **입력**하면 F15 의 「봉합이 문제를 옮겼다」가 재현된다.

### C5. 잘림 경고는 필터 결과에도 따라붙는다 ★
`truncated === true` 인 동안 **필터 결과 0건**과 **섹션 카드 수**는 사실을 말하지 않는다.
두 곳 모두에 잘림 경고를 병기한다. 「조건에 맞는 이슈 없음」 단독 표시는 금지.

### C6. 공유 컴포넌트 변경은 기본값 보존으로
`FilterBar` 에 섹션 가시성 옵션을 **선택적 prop(기본 = 표시)** 으로 추가한다.
`BoardFilterBar`·`IssueFilterBar` **2개 소비처는 무변경**이어야 한다.

### C7. 프리미티브만 쓴다 · 토큰 무신설

세 결정(D1 축 4종 · D2 접이식 패널 · D3 폼 이동)은 **각각 합리적이지만 합치면 새 충돌면**이
