## D-1. 에픽 패널의 정체 = **접이식 패널 + 필터바 칩 연동** (Maxi 확정 2026-08-06 D2)

에픽 패널은 세로 스택 **바깥 상단**의 접이식 `role="region"` 이고, 그 안의 에픽 목록에서 고른
선택은 **필터바에 제거 전용 칩**으로 나타난다. 접힘 상태는 F15 가 만든 `use-backlog-collapsed.ts`
(프로젝트별 `localStorage`) 패턴을 그대로 재사용한다.

**핵심은 「입력 컨트롤의 소유자를 하나로 고정」한 것이다.** 에픽 선택 체크박스는 **패널만** 갖고
필터바에는 없다. 둘 다 가지면 같은 상태에 입력구가 두 벌이 되어, 어느 쪽이 진실인지 화면이
스스로 답하지 못한다 (스펙 §8 C4 — 「에픽 상태의 단일 소유권」).

### 대안과 기각 사유

| 대안 | 기각 사유 |
|---|---|
| **필터바 멀티셀렉트만** (패널 없음) | 가장 싸지만 Jira 백로그의 좌측 에픽 패널과 조작감이 갈라진다. 그리고 에픽은 백로그에서 **훑어보는 축**이라 드롭다운 안에 접히면 「이 프로젝트에 어떤 에픽이 있나」를 못 본다 |
| **에픽별 그룹핑** (섹션을 에픽 단위로 재편) | F15 가 막 확정한 **섹션 모델(스프린트 N개 + 백로그)** 과 정면 충돌한다. 스프린트 축과 에픽 축이 같은 자리를 다투게 되고, DnD 의 드롭존 의미(「이 스프린트로 옮긴다」)가 무너진다 |
| 패널과 필터바 **양쪽에 입력 컨트롤** | 상태 이중 입력. 위 「단일 소유권」이 깨진다 |

**채택안의 비용.** 화면 상단이 세로로 길어진다. 그래서 패널은 **기본 접힘이 아니라 영속 접힘**
(마지막 상태를 프로젝트별로 기억)이고, 접었을 때도 선택은 필터바 칩으로 계속 보인다.

## D-2. 필터 축을 **4종으로 한정**하고 공유 `FilterBar` 에 `hiddenSections` 를 더한다 (Maxi 확정 2026-08-06 D1)

축은 **제목 검색 · 담당자 · 미배정 · 에픽** 4종이다. 라벨·컴포넌트 섹션은 백로그에서 **숨긴다.**

### 실측 근거 — 보드와 백로그는 **필터 기전이 다르다**

| | 보드 | 백로그 |
|---|---|---|
| 기전 | **서버 필터** — `buildBoardFilterQuery`(`api/boards.ts:292`)가 `assignee=`·`label=`·`component=` 쿼리를 만든다 | **클라이언트 필터** — `getBacklog(@PathVariable projectKey)` 는 쿼리 파라미터 **0개** |
| 카드에 라벨 필드 | 없어도 된다 (서버가 이미 걸렀다) | **없으면 못 거른다** |

`backlogIssueSchema`(`api/backlog.ts:25-42`) 실측 필드 — `key` · `summary` · `currentStateKey` ·
`assigneeId` · `priority` · `rank` · `version` · `epicKey`. **`labels`·`componentIds`·`typeKey` 부재.**

즉 정본대로 슬롯을 「그대로 쓰면」 라벨·컴포넌트 섹션이 화면에 뜨는데 **무엇을 골라도 목록이
변하지 않는다.** 장식 필터는 기능 없음보다 나쁘다 — 사용자가 「걸었다」고 믿은 채 잘못된 목록을
본다. 라벨·유형은 FR-UX-14 의 백엔드 **B2** 가 `BoardIssueView` 에 실어 줄 예정이나 **B2 는 F16 의
선행이 아니다**(의존 그래프 `F5 → F15 → F16`). 이 PR 시점에 없다.

### 왜 `FilterBar` 를 새로 만들지 않고 **고쳤나**

안 쓰면 담당자 typeahead(`useUsers` + `useUsersByIds` + 디바운스 + 칩 + WCAG 접근명)를 통째로
복제해야 하고, 이는 Jira 패리티 계약 §4(재사용 자산)를 정면으로 어긴다. 그래서 **정본의 「그대로
쓴다」를 「선택적으로 숨긴다」로 최소 폭 수정**했다.

```
hiddenSections?: { labels?: boolean; components?: boolean }   // 기본값 = 표시
```

**기본값 = 표시가 이 결정의 안전장치다.** 소비처 2곳(`BoardFilterBar` · `IssueFilterBar`)은
**diff 0줄**이고, 그 사실이 `git diff` 로 기계 확인된다. 가시성은 **양방향 짝 테스트**로 못박았다 —
숨김 단언만 있으면 컴포넌트가 아무것도 안 그려도 통과하기 때문이다(같은 셀렉터로 「없다」와
「있다」를 둘 다 잰다).

### 파생 결정 — `BacklogFilter` 는 두 필드를 **모델에 갖지 않는다**

`FilterBar<T extends BoardCardFilterParams>` 제약 탓에 백로그 필터가 **항상 빈** `labels`·
`componentIds` 를 끌고 다닐 뻔했다. 모델이 들고 있으면 픽스처가 그것을 채울 수 있고, 그러면
**도달 불가 상태를 지키는 가짜 테스트**가 생긴다 (PR #342 에서 같은 양식을 2회 적발 —
[[unreachable-state-fixture-is-fake-green]]). 두 빈 배열은 `toFilterBarValue` **경계에서만** 만든다.

## D-3. 「표시 집합 ≠ 동작 집합」 — 브랜드 타입과 **그 정직한 한계**

### 결정

필터 결과는 `FilteredBacklogView` 라는 **`BacklogView` 와 호환되지 않는 별개 타입**으로 낸다.
스프린트 완료·DnD 처럼 **동작 대상 집합**을 다루는 함수는 `BacklogView` 만 받는다.

차단 기전은 **`readonly` 배열**이다 — `T[]` 는 `readonly T[]` 에 대입되지만 그 역은 안 된다.
런타임 마커 필드도 캐스팅도 없다.

### 왜 테스트 한 줄이 아니라 타입인가

F15 실측 — 완료된 스프린트의 이슈는 `SprintRepository.unassignIssue` 가 `status <> COMPLETED`
**조건부 DELETE** 라 **조용히 204** 를 주고, `UNIQUE(issue_key)` 때문에 다른 스프린트로도 못 옮긴다.
즉 **영구 동결**된다. 필터로 안 보이는 이슈가 완료 이관 대상에서 빠지면 그 이슈들이 그대로 갇힌다.
**되돌릴 수단이 없는 손상**이라 회귀 테스트 1건에 걸어 둘 수 없다는 것이 plan 리뷰 BLOCKER-1 의
판정이었다. 선례 — `fr-co-01` 「저작자 위조를 **타입으로** 닫음」.

### ★ 한계 — 브랜드는 **전개 연산자에서 한 홉 만에 벗겨진다**

이 방어는 **경계 한 겹에서만** 참이다. `BacklogBoard.tsx` 의 `buildDisplay` 가

```ts
const sections = filtered.sprints.map((group) => ({
  meta: group.sprint,
  issues: [...group.issues],   // ← 여기서 readonly 가 사라진다
}))
```

로 전개하는 순간 `readonly` 표식이 없어진다. **뮤테이션 검증에서 이 자리를
`{ sprint: s.meta, issues: s.issues }` 로 되돌리는 변형이 `tsc` 를 통과했다** — 그것을 red 로
잡은 것은 **타입이 아니라 테스트**였다.

필드 이름을 `sprint` 가 아니라 **`meta` 로 둔 것이 실질 방어의 절반**이다. TypeScript 는 프로퍼티의
`readonly` 를 **대입 가능성 판정에서 무시**하므로, 이름이 `sprint` 였다면 이 배열이
`SprintWithIssues[]` 로 그대로 대입돼 필터 결과가 완료 다이얼로그까지 흘러갈 수 있었다.

**그래서 이 ADR 은 「타입으로 닫았다」고 기록하지 않는다.** 정확한 기록은 —
**필터 함수의 반환 경계는 타입이 닫았고, 그 너머는 여전히 테스트가 유일한 증인이다.**
후속으로 브랜드를 유지하려면 `buildDisplay` 자체가 브랜드 타입을 반환하도록 올려야 한다.

## D-4. **에픽 목록 API 가 없다** — `epicKey` distinct 파생이 유일 경로

### 실측

- AQL(Atlas Query Language — 이슈 검색 질의어) `MVP_FIELDS` =
  `{status, label, summary, priority, text}` (`AqlFields.kt:45`). **`type` 미지원.**
- 이슈 목록 필터(`IssueFilterParams`)에도 **유형 축이 없다.**
- 즉 「이 프로젝트의 에픽을 전부 달라」를 **백엔드 변경 없이 물을 방법이 없다.**

### 결정

**백로그 응답의 `epicKey` 를 distinct 로 모아 파생한다.** 이름은 그 키들로 개별 조회한다
(`hooks/use-backlog-epics.ts`).

### 받아들인 결과 2가지 — 둘 다 사용자에게 보인다

1. **백로그에 이슈가 없는 에픽은 패널에 안 보인다.** Jira 는 프로젝트의 **모든** 에픽을 나열하므로
   이것은 **의도적 이탈**이다. 목록 하단에 그 한계를 한 줄로 알린다(스펙 §7 EC5) — 훑은 뒤에
   읽히도록 상단이 아니라 하단이다.
2. **이름 조회 상한 50** (`EPIC_NAME_LOOKUP_LIMIT`, `use-backlog-epics.ts:20`). plan 리뷰 CONCERN-3 —
   원안은 요청 수를 "distinct 에픽 수" 로만 규정해 **상한이 없었고**, `truncated` 1,000건
   시나리오에서 에픽이 많으면 요청이 폭발한다. 초과분은 **키를 그대로 표시**하는 폴백이며
   테스트가 그 동작을 못박는다.

**에픽 색상 막대는 없다** — 에픽 색상 필드가 백엔드에 없다. 키·이름만 표시한다.

### 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 백엔드에 에픽 목록 API 추가 | 이 PR 이 프론트 전용에서 벗어나고 D3~D5 가 되살아난다. F16 은 FR-UX-13 의 **마감 PR** 이라 범위를 늘리지 않는다 |
| AQL 에 `type` 필드 추가 | shared-kernel + search-export-import 변경. BC 격리 위반(한 PR = 한 BC) |
| 패널에 「에픽 없음」만 두고 이름은 키로 표시 | 이름이 있는데 키를 보이는 것은 **정보 손실**이고, 이름 해석 성공/폴백이 화면에서 구별되지 않는다 |

## 코드 리뷰가 적발한 것 — **둘 다 「두 경로 중 하나만 봉합」**

게이트 2 코드리뷰 BLOCKER 2건. **양식이 같았다** — 방어를 한 경로에만 걸고 나머지 경로를
빠뜨렸다. F15 BLOCKER ④(「그 봉합이 문제를 옮겼다」)와 같은 결이 **PR 3개 연속** 재현됐다.

### ① DnD 칸 경로 — 「표시 집합 ≠ 동작 집합」이 카드 경로에만 걸렸다

`resolveOverToDropZone` 은 드롭 대상을 **칸(column)** 과 **카드** 두 경로로 판정한다.

- **카드 경로** — `extractCardDropZone(overData, (ctx, sid) => orderedKeysOf(view, …))`.
  이웃 키를 **원본 `view`** 에서 다시 뽑는다. ✅ 봉합됨
- **칸 경로** — `extractColumnDropZone(overData)`. `over.data.current.orderedKeys` 를 **그대로**
  쓰는데, 그 값은 칸 컴포넌트가 **필터된 `issues` prop** 으로 만든 것이다
  (`BacklogColumn.tsx` `const orderedKeys = issues.map(i => i.key)`). ❌ 필터가 걸린 채 칸 빈 자리에
  놓으면 rank 이웃이 **보이는 것만으로** 계산된다

D-3 의 브랜드 타입은 이 경로를 **막지 못한다** — 필터 결과가 함수 인자로 넘어가는 것이 아니라
**컴포넌트 prop 을 거쳐 dnd-kit 의 `data` 로 흘러들기** 때문이다. D-3 의 한계 기술과 같은 뿌리다.

### ② 필터바 초기화 되돌림 — 초기화 진입이 두 곳인데 한쪽만 로컬 입력을 비웠다

`BacklogFilterBar` 는 제목 검색어를 **로컬 state 로** 쥐고 250ms 디바운스한다(그래야 키 입력마다
부모가 재렌더되지 않는다). 그래서 **부모가 밖에서 값만 비우면 로컬 입력이 그대로 남아 디바운스가
지운 검색어를 도로 밀어 올린다.**

- **필터바 자체의 「초기화」** — 자기 로컬 입력을 직접 비운다 (`setQueryInput('')`). ✅
- **0건 빈 상태의 「초기화」** — 필터바 바깥이라 로컬 입력에 손이 닿지 않는다. ❌ 초기화가 튕긴다

처방은 **필터바 재마운트 열쇠**(`filterBarKey`)이고, 그 열쇠는 **URL 이 실제로 비워진 렌더**에서
올려야 한다. 초기화 시점에 곧바로 올리면 그 렌더의 `filter` 는 아직 옛 값이라 **새로 마운트된
필터바가 지운 검색어를 그대로 다시 집어 든다.** effect 로 미루는 것도 답이 아니다 — 자식 effect 가
부모보다 **먼저** 돌아 비워진 URL 을 본 필터바가 열쇠가 오르기 전에 낡은 값을 밀어 올린다.
그래서 **렌더 중 조정**(React 공식 「prop 이 바뀔 때 state 조정」 패턴)이다.

> **★ 이 결함은 유닛 테스트가 전부 초록인 채로 살아 있었다.** 브라우저 눈확인이 「눌러도 아무 일이
