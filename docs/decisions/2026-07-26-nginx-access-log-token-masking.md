## 맥락 — 선행 결정이 "불가피" 로 분류한 것을 번복한다

선행 ADR(#310, 어제)은 §잔여 위험 1 에서 이렇게 적었다.

> **경로 기반 토큰 설계 자체.** 토큰이 URI 에 있는 한 브라우저 히스토리·리퍼러·웹서버 접근 로그에는
> 계속 남는다. 이는 선행 ADR D1 이 택한 설계이며 **본 결정의 범위 밖**이다.

이 문장은 세 채널을 **하나의 불가피한 귀결**로 묶었다. 본 결정은 그 묶음을 푼다.
**웹서버 접근 로그는 URL 설계와 직교하며, 인프라 계층에서 봉합할 수 있다.**

### 실증된 결함 (가설 아님)

```
Dockerfile.web:6              FROM nginx:1.27-alpine
이미지 기본 nginx.conf (실측)   log_format main '... "$request" ...'
                              access_log /var/log/nginx/access.log main;
                              include /etc/nginx/conf.d/*.conf;
컨테이너 (실측)                access.log -> /dev/stdout
infra/prod/nginx.conf (54줄)  access_log · log_format 재정의 0건 → 상속
```

`$request` 는 요청 첫 줄 통째(쿼리 포함)다. **오류일 필요가 없다 — 정상 200 요청마다** 원문 토큰이
표준출력 → `docker logs` → 중앙 로그 수집기로 적재됐다. iCal 은 캘린더 클라이언트가 주기 폴링하므로
동일 토큰이 반복 적재된다. 불투명 토큰은 **소지가 곧 인증**이므로(glossary) 로그에 남은 원문은
그대로 유효한 자격증명이다.

## 결정

### D1. 경로 목록이 아니라 **길이 판별식**으로 마스킹한다

실측 길이 분포가 완전 분리를 허용한다.

```
     정상 식별자 최대            토큰 최소
     UUID 36자 ──────┐      ┌────── base64url 43자 (32바이트 무패딩)
                     │  40  │       hex 64자 (32바이트)
                     └──┬───┘
                    임계값 (여백 4자 / 3자)
```

`$uri` 와 `$http_referer` 에서 `[A-Za-z0-9_-]` 연속 **40자 이상** 세그먼트를 `***` 로 치환한다.

**왜 목록이 아닌가.** 목록은 그 자체로 눈가리개다. 본 작업의 초기 열거(API 4경로)는
**SPA 라우트 `/dashboards/shared/{token}` 을 실제로 누락**했다 — 사람이 브라우저로 직접 여는,
트래픽이 가장 많은 경로다. 목록 방식이면 새 토큰 경로가 추가될 때마다 갱신을 잊는 순간 다시 샌다.
길이 규칙은 **설정을 건드리지 않아도 자동으로 가린다**.

**기각한 대안.**
- (a) 경로별 `map` 규칙 하드코딩 — 위 누락 사례가 이 방식의 실패를 이미 증명했다
- (b) `access_log off` — 유출은 막지만 장애 조사 능력을 통째로 버린다
- (c) 토큰을 경로에서 헤더로 이동 — 선행 ADR D1 을 뒤집는 재설계. iCal 구독은 외부 캘린더 앱이
  헤더를 못 붙이므로 애초에 불가능하다. 범위 밖

### D2. 쿼리 문자열 값은 목록 없이 전량 미로깅

`$request`·`$request_uri`·`$args` 를 쓰지 않고 `$request_method` + 마스킹된 `$uri` +
`$server_protocol` 로 조립한다. `$uri` 는 쿼리를 포함하지 않으므로 **규칙 하나 없이** 슬랙 설치
콜백의 `code`, OIDC 콜백의 `code`·`state` 가 전부 빠진다.

### D3. Referer 헤더도 같은 판별식을 적용한다

공유 뷰(`/dashboards/shared/{token}`)를 거쳐 API 를 호출하면 `Referer` 에 토큰이 담긴다.
경로만 가리면 반쪽 봉합이다.

### D4. 관측성은 오히려 늘린다

기본 `main` 포맷에 없던 `$request_time`·`$upstream_response_time` 을 추가한다.
마스킹으로 잃는 것보다 장애 조사에 쓸 정보를 더 남긴다.

### D5. 봉인은 **3축 전부** — 한 축만으로는 봉인이 봉인 대상을 놓친다

`scripts/verify/nginx-log-masking.sh` (`bootjar-no-fakes.sh` 선례를 따른 배치).

| 축 | 단언 | 이 축이 없으면 |
|---|---|---|
| A 길이 | 토큰 발급 길이 > 임계값 | 누가 토큰을 짧게 줄이면 조용히 샌다 |
| B 알파벳 | 인코딩 문자군 ⊆ `[A-Za-z0-9_-]` | **표준 base64(`+`·`/`)·JWT(`.`) 는 구분자가 세그먼트를 쪼개 마스킹을 빠져나가는데 길이 검사는 통과한다** |
| C 설정 실효 | nginx.conf 가 실제로 마스킹한다 | **`map` 블록을 지워도 A·B 는 그대로 통과한다** |

임계값은 **하드코딩하지 않고 `nginx.conf` 에서 파싱**한다. 두 곳에 하드코딩하면 드리프트 시
봉인이 존재하지 않는 문을 점검하게 된다(plan-eng-review 발견 2).

**뮤테이션으로 판별력을 확인했다.** 축마다 다른 종료코드가 나온다 — 하나 건드렸는데 전부 red 면 과잉결합이다.

| 주입 | 종료코드 |
|---|---|
| 토큰 32→8바이트 | 1 (축 A) |
| base64url→표준 base64 | 2 (축 B) |
| `access_log` 삭제 | 3 (축 C) |
| Referer 마스킹 제거 | 3 (축 C) |
| 파생기 고장(0건) | 4 (하한) |
| 원복 | 0 |

### D6. 배포 게이트를 이미지 빌드로 끌어올린다

`Dockerfile.web` 에 `RUN nginx -t`. CI 검증은 우회 가능하지만 이 게이트는 **이미지를 만들 수 없게** 한다.
설정 오류로 nginx 가 기동 실패하면 프론트 전체가 내려가고, "백엔드 다운과 무관하게 서빙" 이라는
기존 설계가 통째로 무의미해진다.

### D7. CI 경로 필터에 `backend/**` 를 포함한다

축 A·B 가 Kotlin 토큰 발급기 소스를 읽는다. `infra/**` 만 걸면 **토큰을 짧게 바꾸는 변경이
검사를 우회**한다. 워크플로우에 그 사유를 주석으로 못박았다.

## 잔여 위험 — ★후속으로 명시 등재한다

> ⚠️ 선행 #310 ADR 이 "범위 밖" 으로만 적어둔 항목이 그대로 방치돼 3주 잠복한 끝에 이 PR 이 됐다.
> 같은 실패를 반복하지 않도록, 아래는 **"범위 밖" 이 아니라 "후속 작업" 으로 등재**한다.

1. **`error_log` 채널 (Maxi 확정 D1=A).** nginx 는 **error_log 포맷 커스터마이즈를 지원하지 않는다.**
   오류 항목에 `request: "GET /path…"` 로 URI 가 실린다. 접속 로그(상시·전요청)와 달리 **오류 시에만**
   발생하지만 본 PR 로 봉합되지 않는다. 가능한 완화는 로그 레벨 상향뿐이며 장애 조사 능력과 정면 상충한다.
   → **후속 작업으로 등재.** 판단 재개 시 (A) 수용 (B) 레벨 상향 (C) 수집 경로 분리 중 택일

2. **`Referrer-Policy` 헤더 부재.** `infra/prod/nginx.conf` · `apps/web/index.html` 모두 0건.
   공유 뷰가 외부 리소스를 참조하면 브라우저가 **제3자에게** 토큰이 담긴 Referer 를 보낸다.
   본 PR 의 Referer 마스킹은 *우리 로그* 만 덮는다. → **후속 작업으로 등재**

3. **브라우저 히스토리.** 클라이언트 소관, 봉합 불가. 선행 ADR 판단 유지

4. **교차모델 검증 부재.** `codex` CLI 미설치로 outside voice 미실행 (#308·#309·#310 동일).
   구현자가 자기 계획을 리뷰한 편향이 남는다. 붙이려면 `npm install -g @openai/codex`

## 확인된 무해 항목

- **과잉마스킹 없음 (실측).** UUID(36자)·이슈키·프로젝트키는 임계값 미만이라 로그에 그대로 남는다.
  39자 대조군도 마스킹되지 않음을 확인했다
- **성능.** `map` 은 기동 시 컴파일, 요청당 앵커된 정규식 2회 평가
- **다중 토큰 경로 부재.** nginx `map` 은 전역 치환을 못 하므로 한 경로에 토큰이 2개면 하나만 가려진다.
  현재 그런 라우트가 없음을 봉인이 단언한다
