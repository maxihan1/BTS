# ADR — CFD (Cumulative Flow Diagram) 데이터 모델 (FR-RP-03)

> 날짜: 2026-07-03
> 상태: 채택
> 관련 FR: FR-RP-03 (CFD — Cumulative Flow Diagram, 누적 흐름 다이어그램)
> 관련 SDD: §13.5 (리포트), §14 (dashboard-reports)
> 선행: FR-RP-01(번다운, ADR `2026-07-02-fr-rp-01-burndown-burnup`) · FR-RP-02(벨로시티, ADR `2026-07-02-fr-rp-02-velocity`)
> 관련 PR: #225

## 맥락

FR-RP-03은 프로젝트의 이슈들이 시간축 위에서 각 워크플로우 상태 카테고리에 얼마나 쌓여 있는지를
누적 영역 차트로 시각화한다. 특정 카테고리 띠가 넓어지면 병목(WIP 누적)을 눈으로 잡아낸다.
엔드포인트는 `GET /api/v1/projects/{projectKey}/cfd?from=&to=`(**프로젝트 스코프** — 번다운/벨로시티의
스프린트 스코프와 다름).

CFD는 번다운/벨로시티와 근본적으로 다르다. 번다운은 worklog 시간 누적을, 벨로시티는 현재 상태(on-the-fly)만
읽으면 됐지만, **CFD는 과거 각 날짜의 이슈 상태 분포**를 알아야 한다 — 즉 각 이슈의 상태 타임라인을
재구성해야 한다. BTS에는 상태 스냅샷 테이블이 없고, 상태 변경 이력만 `issue_change_group`/`issue_change_item`
(V018, FR-HS-01)에 append-only로 기록된다.

**이력 기록의 핵심 사실** (`IssueChangeDetector`).
- 이슈 **생성** 시 `field='lifecycle', to_value='created'` 마커만 기록 — **초기 상태(status)는 이력에 남지 않음**.
- 상태 **전이** 시 `field='status', from_value=이전키, to_value=이후키` 기록.
- 따라서 초기 상태 = "첫 status 전이의 `from_value`", 전이가 전혀 없으면 = 현재 `issues.current_state_key`.

## 결정

### D1. 누적 띠 단위 — 카테고리 3띠 (TODO / IN_PROGRESS / DONE) (Maxi 확정)

워크플로우 상태별 N띠(전통적 Jira CFD)가 아니라 **카테고리 3띠**로 누적한다.

**근거**.
- 프로젝트마다 워크플로우 상태 개수·순서가 다르고 상태는 삭제될 수 있다. 카테고리 3종은 모든 프로젝트에
  균일해 비교 가능하고, `WorkflowStateCatalog.category`로 깔끔히 매핑된다.
- BTS 선례가 일관되게 3카테고리다 — 칸반 보드 컬럼(BoardColumn.category), 벨로시티 DONE 판정,
  에픽 진행률(`EpicProgress.NormalizedCategory` TODO/IN_PROGRESS/DONE).
- 삭제된(카탈로그에 없는) 상태 키는 TODO로 폴백(`EpicProgress` EC2/EC3 동형).
- **한계(수용)**. 특정 상태('리뷰' 등)의 개별 병목은 3띠로는 안 보임. v1 단순화, product 명세에 명시.

### D2. 시계열 재구성 — on-the-fly in-memory 역산 (Maxi 확정, 신규 스키마 0)

번다운 D3 선례를 따라 **스냅샷 테이블·@Scheduled 잡을 채택하지 않는다**. 요청 시 각 이슈의 status 전이
이력을 시간순으로 재구성해 날짜별 카테고리 분포를 계산한다.

- 이슈별 상태 타임라인. 초기 상태(= 첫 status 전이의 `from_value`, 없으면 `current_state_key`) →
  status 전이들을 `group.created_at` 오름차순 적용. day D의 상태 = `created_at::date <= D`인 마지막 전이의
  `to_value`, 없으면 초기 상태.
- day D 존재 판정. `issues.created_at::date <= D` AND (`deleted_at IS NULL` OR `deleted_at::date > D`).
  소프트 삭제 이슈는 삭제일 다음부터 어느 띠에도 안 잡힘(카운트 감소).
- 날짜별로 각 이슈의 상태 → 카테고리 → 해당 띠 +1.

**근거**.
- 신규 마이그레이션·스케줄러 0 (모듈 첫 @Scheduled 함정 회피, learnings 2026-06-27).
- 과거 소급 계산 가능 (스냅샷은 출시 후 데이터만).
- **한계(수용)**. V018(FR-HS-01) 이전 생성 이슈는 status 전이 이력이 없어 '항상 현재 상태'로 계산됨
  (번다운의 추정치 미입력 갭과 동종). product 명세 D2에 명시.

### D3. 모듈 배치 — issue-tracking

CFD는 `issue-tracking` 모듈에 구현한다(번다운/벨로시티의 agile-planning과 다름).

**근거**.
- 필요한 데이터(`issues` + `issue_change_group`/`issue_change_item`)가 모두 issue-tracking BC 소유.
  스프린트를 읽지 않으므로 cross-BC 조회 포트가 불필요하다(번다운은 sprint→issue 포트 필요했음).
- 상태→카테고리 매핑에 필요한 `WorkflowStateCatalog`(shared-kernel SPI)는 issue-tracking이 이미
  소비 중(`SprintVelocityLookupAdapter`, `IssueEpicService`가 `IsolatedWorkflowStateLookup` 사용).
- 엔드포인트가 프로젝트 스코프(`/projects/{projectKey}/cfd`) → 프로젝트 이슈를 로컬로 읽는다.
- **fr-index 논리 BC 라벨(notification-dashboard)은 유지**(물리 모듈 ≠ 논리 라벨, FR-RP-01/02·FR-TT 선례).
  notification-dashboard=14 카운트 불변, `verify-master-plan.sh`는 BC↔모듈 매핑을 강제하지 않는다.

### D4. 보안 그레인 — 이슈별 가시성 필터 (번다운 D6 · 벨로시티 동형)

프로젝트 BROWSE 통과만으로는 부족하다 — 카테고리별 이슈 **개수**로 기밀 이슈 존재를 간접 추론할 수 있다.
집계 전 이슈 키를 뷰어 가시 집합으로 좁힌다.

**결정**. 2단 필터 — (1) 프로젝트 BROWSE + (2) 집계 전 `IssueRepository.filterVisibleIssueKeys`로
뷰어 가시 이슈만. 정본 보안 술어 `buildActiveSecureWhere`를 **재사용**(복제 금지 —
isomorphic-clone-permission-guard-gap 회귀 방지). `IssueSecurityDirectory.accessibleLevels` → 필터 위임
(`SprintVelocityLookupAdapter` 선례 그대로).

**트레이드오프(수용)**. 차트가 뷰어 스코프라 기밀 이슈가 걸린 프로젝트에서 뷰어별 부분값이 될 수 있음.

### D5. 시간 창(window) — from/to + 일 단위 + 상한

- `from`/`to`는 UTC 날짜(ISO `yyyy-MM-dd`). 둘 다 생략 가능, 기본값·상한은 spec(D2)에서 확정.
- 일 단위(하루 1점). UTC 벽시계 날짜(`(ts AT TIME ZONE 'UTC')::date`, 번다운 `utcDateField` 선례) —
  세션 TZ 무관 결정성.
- 창 길이 상한을 둬 계산량을 유계로 만든다(spec 확정 = 180일). 잘못된 범위(`from > to`, 파싱 실패, 상한 초과)는 400
  (WorklogAggregate 형제 엔드포인트 일관 — 쿼리 파라미터 검증은 400. spec S7 정본).

## 새 도메인 개념

- **CFD (Cumulative Flow Diagram, 누적 흐름 다이어그램)** — 시간축 위에서 각 워크플로우 상태 카테고리
  (TODO/IN_PROGRESS/DONE)에 머문 이슈 개수를 누적 영역으로 쌓아 WIP·병목을 시각화하는 애자일 리포트. (FR-RP-03)
- **CfdPoint** (VO, 영속 아님) — CFD 시계열의 한 점. `{ date, todoCount, inProgressCount, doneCount }`.
  read-model, 애그리거트/테이블 없음. (번다운 `BurndownPoint`·벨로시티 `VelocityPoint` 동형)
