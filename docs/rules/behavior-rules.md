# 행동 규칙 배치표

> **읽는 법 — 「강제 수단」이 비면 그 규칙은 지켜지지 않을 수 있다.** 자연어 지시는 강제가 아니다.
> 이 표는 「무엇을 지켜야 하나」가 아니라 **「무엇이 실제로 막히나」**를 적는다.

## 티어의 정본은 넷으로 나뉜다 — 각자 소유하는 것이 다르다

2026-09-04 진단. 티어를 기술하는 곳이 10군데였고 그중 **셋이 각각 「내가 정본이다」**라고
선언하고 있었다. 셋 다 틀린 말은 아니었다 — 서로 **다른 것**의 정본이었기 때문이다.
그런데 무엇의 정본인지를 안 적어서, 읽는 쪽은 어느 것을 따라야 할지 알 수 없었다.

| 무엇 | 정본 | 여기에 없는 것 |
|---|---|---|
| **글로브** (어느 경로가 어느 표면인가) | `scripts/workflow/surfaces.ts` | 이름·티어는 있으나 절차는 없다 |
| **표면 이름 ↔ 티어** (표면 표) | 이 파일 §1 | 글로브를 다시 적지 않는다 |
| **티어 요약** (사람이 먼저 읽는 4행표) | `CLAUDE.md §작업 티어` | 요약이다. 상세 절차는 없다 |
| **티어별 절차** (단계·리뷰 종수·게이트) | `.claude/skills/bts/SKILL.md §티어별 절차` | 표면 정의를 다시 적지 않는다 |

**규칙 — 자기 것이 아닌 축은 옮겨 적지 않고 가리킨다.** 사본을 두는 순간
두 목록이 서로를 안 보게 되고, 이 저장소가 반복해 물린 결함 양식이 된다.
`verify-master-plan.sh` 룰 J 가 글로브 ↔ 표면 이름의 차집합을 이미 검사한다.

문서가 글로브를 다시 적으면 그것이 **세 번째 목록**이 된다. 이 표는 **이름과 뜻만** 갖는다.
`verify-master-plan.sh` 룰 J 가 두 목록의 차집합 0 과 개수 하한을 강제한다 (EXIT 4).

## 2. 티어 판정 — `CLAUDE.md` 가 갖지 않는 조항

`CLAUDE.md` 에 ① 혼합은 최고 티어 ② 기본 T1·Maxi 지정 우선 ③ 미분류는 T1 + `UNMAPPED:` 표기가 있다. 나머지 둘.

- **④ `TEST` 단독 변경은 티어를 올리지 않는다.** 테스트만 고치는 PR 에 T2 절차를 씌우면
  「테스트를 늘리면 손해」라는 역유인이 생긴다.
- **⑤ 실측 티어 > 선언 티어면 자동 승격하지 않는다.** 게이트 2 에서 **정지하고 사람이 결정**한다.
  자동 승격은 「구현이 끝난 뒤 계획을 승인」하는 절차 역전이다. 게이트 2 는 전 티어 필수라 왕복은 늘지 않는다.
  선언 티어와 `detect-tier` 실측 티어를 게이트 2 요약에 **나란히** 출력한다.

**선언의 소재는 PR 본문이 아니라 저장소 파일이다.** 새 `docs/plans/*.md` 유무가 T0/T1 ↔ T2+ 를 가르고,
그 파일 머리 `티어:` · `타입:` 2행이 T2/T3 와 ui 면제를 가른다. PR 본문을 쓰면 판별식이 워크플로우 주입에
묶여 로컬에서 돌지 않는다.

T0/T1 에서 3회에 도달하면 보고에 **「티어 재판정 제안」**을 포함한다 — 티어 가정이 틀렸다는 신호다.

## 4. 차단 장치 정본 — 실제로 막는 것만

| 장치 | 시점 | 비고 |
|---|---|---|
| `.husky/pre-commit` — `build-doc-index.mjs --check` | 커밋 | **강등 금지.** 저장소 밖 메모리의 유일한 봉인 |
| `.husky/pre-commit` — lint-staged | 커밋 | worktree 가 훅을 침묵 무력화한 실측이 있다 — 로컬 훅은 **보조**다 |
| `scripts/verify-master-plan.sh` EXIT 3/4 | PR (CI 잡) | FR 정합 · 카운트 drift · 표면 차집합(룰 J) · 줄수 규칙(룰 I) |
| `scripts/workflow/*.test.ts` 판별식 | PR | 하네스·CI·문서 배선의 차집합 0 |
| `frontend-ci.yml` `visual` 잡 | PR | 파일럿 기간은 `continue-on-error` — **비차단** |

**스냅샷 baseline 갱신은 ① `apps/web/src/**` 변경을 동반하고 ② 그 변경이 의도된 시각 변경일 때만** 허용한다.
원인 미상 상태의 갱신은 이 저장소의 가짜초록 양식 그 자체다. 판별식 ② 가 ① 을 기계로 막는다.
**파일럿 중단** — 무변경 상태 연속 20회 중 diff 0회면 채택 · 1회면 보강 후 재측정 · **2회 이상이면 그 화면 미채택**.
실패 회수만이 아니라 **diff 픽셀 수**를 함께 기록한다. 회수만 세면 임계를 정할 수 없다.
