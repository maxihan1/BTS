# 출력 서식

> **정본. 이 파일.** 스킬 본문은 이 파일을 가리키고 사본을 두지 않는다.

## 왜 이 파일이 생겼나

2026-09-04 진단. bts 체인 4곳이 「**i-have-adhd 규칙**을 따른다」고 지시하는데
그 규칙의 정의가 **저장소 어디에도 없었다**. 실제로는 Maxi 개인 설정
(`~/.claude/.i-have-adhd-always`)이 세션 시작 시 주입하고 있었다.

두 가지가 문제였다.

1. **그 파일을 지우면 4개 스킬의 출력 규칙이 조용히 사라진다.** 저장소만 클론한
   사람이나 다른 기계의 세션은 애초에 규칙 없이 돈다.
2. **4곳이 각자 다른 부분집합을 인라인으로 재기술해 경쟁 정본이 셋 생겼다** —
   `bts` 는 「번호·인사 없음 + 티어별 줄 수」, `bts-codereview` 는 「첫 줄 판정 · 최대 5건 ·
   약어 풀이 · 2분 행동」, `bts-merge` 는 「요약·인사 없음」.

정의를 저장소 안으로 가져온다. 개인 설정은 그대로 두되, **의존하지 않는다.**

## 서식 규칙

### 1. 다음 행동으로 시작한다

첫 줄은 읽는 사람이 **할 수 있는 것**이다. 배경도 계획도 아니다.
명령·경로·코드가 답이면 그것을 먼저 쓴다.

### 2. 여러 단계는 번호를 매긴다

한 단계 = 하나의 끝나는 행동. 한 단계 안에 「그리고」가 두 번 들어가지 않는다.
필요한 최소 단계만 남긴다 — 짧은 길을 끝내는 편이 완전한 길을 포기하는 것보다 낫다.

### 3. 마지막은 2분 안에 할 수 있는 행동 하나

열린 것이 남았으면 **하나만** 지목한다. 「파일을 연다」도 행동이다.

### 4. 곁가지는 뒤로 뺀다

두 번째 문제가 보이면 첫 번째를 끝내고 별도 질문으로 낸다.
작업 중에 생긴 의문은 스스로 답할 수 있으면 답해서 본문에 녹인다.

### 5. 지금 어디인지 매번 다시 말한다

「5단계 중 3단계」를 기억하게 하지 않는다. 매 응답에서 다시 적는다.

### 6. 시간은 구체적 단위로

「좀 걸린다」가 아니라 「테스트가 이미 있으면 15분, 없으면 반나절」.

### 7. 오류는 담담하게

「어이쿠」「문제가 있는 것 같습니다」를 쓰지 않는다. 원인과 처방만 적는다.

> `auth.spec.ts:42` 실패. 200 을 기대했는데 401. 원인은 인증 헤더 누락.
> 처방은 요청에 `Authorization: Bearer ${token}` 추가.

### 8. 서두·요약·마무리 인사를 붙이지 않는다

금지 — 「좋은 질문입니다」 「~해 보겠습니다」 「도움이 되었길 바랍니다」
「추가로 필요하시면 말씀해 주세요」. 답으로 시작하고 답이 끝나면 멈춘다.

### 9. 목록은 5개까지

넘으면 「지금 할 것 / 나중」 또는 「필수 / 있으면 좋음」으로 가른다.

### 10. 처음 나온 약어는 괄호로 푼다

ReDoS · OCC · nullable 같은 것. 한 번 풀면 그 응답 안에서는 다시 안 푼다.

## 단계별 추가 규칙

| 단계 | 추가로 지키는 것 |
|---|---|
| `bts` | T0/T1 은 바꾼 파일과 확인 방법 각 1줄. T2/T3 은 무엇을 왜 · 확인 방법 · 남은 위험 · 다음 할 일 각 1줄 |
| `bts-impl` · `bts-merge` | 진행 트리 **위에** 결과 줄을 먼저 얹는다. 트리의 내부 용어(wave · dispatch · DRIFT · orphan kill)를 안 읽어도 무엇을 왜 했는지 알게 한다 |
| `bts-codereview` | 첫 줄은 **판정**(승인 가능 / 차단 사유). 지적은 심각도 순 최대 5건 |

## 결과 줄 서식

```
✅ 한 줄  <비전문가 한 문장 — 무엇이 됐나>
💡 의미  <Maxi 에게 무슨 뜻인지 + 다음 단계>
🔧 기술 상세 (안 봐도 됨)
```

## 한국어 규칙

문장은 마침표·물음표·느낌표로 끝낸다. **다음 줄이 목록이나 예시여도 콜론으로 끝내지 않는다** —
영어 문서 습관이 새어 든 것이다. 코드·키값·표 레이블 안의 콜론은 무관하다.
