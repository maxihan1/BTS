# BTS 개발 진척도 대시보드 — 설계 문서

> **작성일**. 2026-05-26
> **작성자**. Claude Code (Maxi와의 brainstorming 결과)
> **상태**. 설계 합의 완료, 구현 대기

## §1 목표 / 비-목표

### 목표

1. **비개발자(Maxi)가 한눈에 BTS 개발 진척을 파악**할 수 있는 정적 HTML 페이지 제공
2. **프로젝트에서 쓰는 용어 + 일반 개발 용어**를 비개발자 친화 설명과 함께 정리
3. **에이전트가 작업 완료(main 머지) 시 자동 갱신** — 수동 갱신 명령 불필요
4. 본문 어디서나 전문용어 호버 시 즉시 풀이 표시

### 비-목표 (이 문서가 다루지 않는 것)

- BTS 제품의 기능이 아님. **개발 추적용 보조 도구** 페이지
- 실시간 협업/편집 기능 없음 (정적 HTML)
- 인증/권한 없음 (로컬 파일 또는 GitHub 저장소 내 정적 자산)
- 새로운 진척 데이터를 만들지 않음. 기존 `docs/plan/product/*.md`의 체크박스를 읽어서 렌더링만 함

## §2 사용자 / 제약

- **사용자**. Maxi 1인. 비개발자. 매일 1~수회 열어볼 도구
- **사용 환경**. macOS, Chrome/Safari. 더블클릭으로 열기. 인터넷 불필요
- **갱신 빈도**. PR이 main에 머지될 때마다 (일 1~5회 추정)
- **데이터 규모**. 117 FR × 9 BC, 용어 ~50개 — 단일 HTML로 충분

## §5 호버 툴팁 메커니즘

본문 어디서나 전문용어를 자동으로 점선 밑줄 + 호버 시 풀이 표시.

### 처리 흐름 (빌드 시점)

1. 두 용어집 파싱 → 통합 `{ 용어, 카테고리, 정의 }` 배열
2. 본문 HTML 생성 시 텍스트 안에서 용어 사전 등록 단어 매칭
3. 매칭된 단어를 `<span class="term" data-def="...">단어</span>` 으로 감싸기

### 매칭 규칙

- **우선순위**. 문자 길이 내림차순 정렬. 긴 단어 먼저 매칭 (예. "Pull Request" 11자 > "PR" 2자, 그래서 "Pull Request"가 먼저 마킹되어 그 안의 "PR"이 중복 매칭되지 않음)
- **중복 방지 단위**. 동일 FR 항목(리스트 한 줄) 또는 동일 문단 안에서 같은 용어가 여러 번 나와도 **첫 등장만** 마킹. 단위는 DOM 노드 기준 부모 `<li>` 또는 `<p>`
- **대소문자 무시**. "PR" 과 "pr" 모두 매칭. 단, 표시는 원문 그대로

### CSS (외부 의존 0)

```css
.term {
  border-bottom: 1px dashed #888;
  cursor: help;
}
.term:hover::after {
  content: attr(data-def);
  position: absolute;
  background: #333;
  color: white;
  padding: 8px 12px;
  border-radius: 4px;
  white-space: nowrap;
  z-index: 100;
}
```

JS 없이 순수 CSS만으로 동작.

## §6 자동 갱신 — husky post-merge

### 트리거 시점

PR이 GitHub에서 main에 머지된 직후, Maxi가 로컬에서 `git pull origin main` 실행 시 자동 발화.

### `.husky/post-merge`

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

# main 머지 시점에만 동작 (dev 브랜치 머지는 무시)
[ "$(git rev-parse --abbrev-ref HEAD)" = "main" ] || exit 0

node scripts/build-dashboard.mjs

# HTML이 실제로 바뀌었으면 별도 커밋 + 푸시
if ! git diff --quiet docs/progress.html; then
  git add docs/progress.html
  git commit -m "[chore] dashboard regen [skip ci]"
  git push
  echo "✅ docs/progress.html 갱신 + 푸시 완료"
fi
```

- `[skip ci]` 표시로 후속 CI 트리거 방지 (무한 루프 차단)
- HTML이 안 바뀌었으면 (예. 머지된 PR이 진척과 무관한 변경) 그냥 종료

### 왜 main 머지 시점인가

- dev 브랜치 작업 중 `[~]` (진행중) 마커는 곧 뒤집힘 — 노이즈
- main = "공식 완료" 의미. main의 `docs/progress.html` = 진짜 현재 진척
- 진척과 무관한 Edit/Write에서 후크가 안 돌아 깔끔

## §7 빌드 스크립트 — `scripts/build-dashboard.mjs`

### 입출력

```
입력:
  docs/plan/product/*.md       (9 BC 진척 마크다운)
  docs/plan/fr-index.md        (117 FR 한 줄 설명 + 카테고리)
  Maxi_wiki/BTS/glossary.md    (도메인 용어)
  Maxi_wiki/BTS/용어 정리.md   (개발 용어 + 비개발자 풀이)

처리 (5단계):
  1. 체크박스 마커 정규식 추출 → 통계 계산 (완료/진행/차단/대기)
  2. FR ID + 한 줄 설명 추출 → 카테고리(BC)별 묶기
  3. 두 용어집 파싱 → { 용어, 카테고리, 정의 } 통합
  4. 본문 텍스트에 용어 자동 마킹 (긴 단어 먼저, 중복 방지)
  5. HTML 템플릿에 모든 데이터 인라인 → docs/progress.html 출력

출력:
  docs/progress.html (자기완결형 ~50KB, 외부 의존 0)
```

### 기술 선택

- **Node.js ESM** (`.mjs`). BTS의 `scripts/workflow/*.ts` 와 같은 패밀리
- **마크다운 파싱**. 정규식 + 가벼운 파싱 (전체 마크다운 변환 불필요, 체크박스 + 리스트만 필요)
- **HTML 템플릿**. 백틱 템플릿 리터럴. 외부 템플릿 엔진 무사용
- **외부 의존 0**. `package.json` 변경 없음

### 에러 처리

- 입력 파일 누락 시 명확한 에러 메시지 후 `exit 1`
- FR ID가 fr-index.md에는 있는데 product/*.md에는 없을 때 경고 출력 (스크립트는 계속 진행)
- `scripts/verify-master-plan.sh` 와 같은 원리로 검증
